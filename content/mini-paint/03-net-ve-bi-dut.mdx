# Đo nguyên nhân nét bị đứt

## Vấn đề cần giải quyết

Một dấu bút đúng chưa tạo thành một nét đúng. Khi chuột đi xa giữa hai mẫu mà chương trình nhận, hai hình tròn có thể không chạm nhau. Tăng bán kính chỉ che lỗ hổng bằng một nét dày hơn yêu cầu.

Bài này thêm đối chứng lặp lại được. S chọn giữ 1/1, 1/2, 1/4 hoặc 1/8 motion; D **xóa ảnh hiện tại rồi vẽ cùng một bộ điểm**. Chưa có nội suy. Nhờ vậy bạn không phải cố kéo giống hệt nhau ở mỗi lần thử. D chỉ là phép thử có chủ ý, không phải chức năng tự vẽ của sản phẩm cuối.

## Hiểu ý tưởng trước khi viết code

Với hai dấu bán kính r, khoảng tâm lớn hơn 2r tạo hai hình tách rời. Khi vừa chạm nhau, mép nét vẫn có thể lõm. Ta sẽ dùng khoảng nhỏ hơn, 0,8r, ở bài sau.

“Giữ 1 trên N mẫu” là **thí nghiệm bỏ bớt event**, không phải phép đo Hz của chuột hoặc FPS. Số lần present và số motion không phải cùng một đại lượng.

Chọn đường thẳng rồi tăng N. Các tâm trắng thưa đi và khoảng input tăng. Trong bài này nội suy bị khóa tắt để giữ đúng đối chứng; bài sau mới bật được.

## Viết code từng bước

### Bước 1 — Thêm khoảng cách và bộ đếm của một nét

Trong `include/lab.hpp`, thêm:


```cpp title="include/lab.hpp — khoảng cách giữa hai mẫu"
inline double distance(Point start, Point end) {
    return std::hypot(end.x - start.x, end.y - start.y);
}
```


Thêm các trường sau vào `PaintState`. Chúng được đặt lại khi một nét mới bắt đầu:


```cpp title="include/paint.hpp — trạng thái đo và lấy thưa"
int sampleEvery = 1;
    int received = 0;
    int accepted = 0;
    int stamps = 0;
    double maximumGap = 0.0;
```


`received` đếm motion trước khi lấy thưa, `accepted` đếm các vị trí được giữ gồm down/up, `stamps` đếm lần đặt dấu. `maximumGap` đo khoảng cách lớn nhất giữa **mẫu được giữ**, không phải giữa các pixel trong dấu tròn.

### Bước 2 — Bỏ motion có chủ ý nhưng không bỏ down/up

Hàm `moveStroke` có thêm đối số `bool forceEndpoint = false`. Sau kiểm tra drawing và vùng ảnh, thêm:


```cpp title="include/paint.hpp — phân biệt motion với endpoint bắt buộc"
if (!forceEndpoint) {
        ++state.received;
        const int interval = std::max(1, state.sampleEvery);
        if (state.received % interval != 0) {
            return false;
        }
    }
```


`endStroke` truyền true để thả nút luôn đi qua phần lấy thưa:


```cpp title="include/paint.hpp — endpoint không phụ thuộc N"
inline bool endStroke(Framebuffer& framebuffer, PaintState& state, Point endpoint) {
    const bool changed = moveStroke(framebuffer, state, endpoint, true);
    cancelStroke(state);
    return changed;
}
```


Những mẫu bị bỏ **không cập nhật previous**. Nó phải giữ điểm đã xử lý gần nhất, nếu không khoảng cách đo và đoạn sẽ nội suy ở bài sau đều sai.

### Bước 3 — Đo rồi vẫn chỉ đặt một dấu mới


```cpp title="include/paint.hpp — đối chứng chưa nội suy"
state.maximumGap = 0.0;
    applyStamp(framebuffer, state, point);
    return true;
}

inline bool moveStroke(Framebuffer& framebuffer, PaintState& state, Point current, bool forceEndpoint = false) {
    if (!state.drawing) {
        return false;
    }
    if (!insideCanvas(current)) {
        cancelStroke(state);
        return false;
    }
    if (!forceEndpoint) {
        ++state.received;
        const int interval = std::max(1, state.sampleEvery);
        if (state.received % interval != 0) {
            return false;
        }
    }
    if (current == state.previous) {
        return false;
    }
    state.maximumGap = std::max(state.maximumGap, distance(state.previous, current));
    ++state.accepted;
    // Bài 1–3 cố ý chỉ đặt dấu ở mẫu mới, chưa nối khoảng giữa hai mẫu.
    applyStamp(framebuffer, state, current);
    state.previous = current;
```


`applyStamp` tăng `state.stamps` mỗi lần tạo dấu. `beginStroke` đặt lại bộ đếm rồi vẽ dấu đầu. Một lần click không kéo chỉ có một dấu vì up trùng previous được bỏ sớm.

### Bước 4 — Tạo cùng một bộ mẫu bằng phím D


```cpp title="include/paint.hpp — mẫu thử chạy qua đúng begin move end"
inline void drawDemo(Framebuffer& framebuffer, PaintState& state) {
    cancelStroke(state);
    framebuffer.clear(kBackground);
    beginStroke(framebuffer, state, {80.0, 270.0});
    for (int x = 280; x <= 880; x += 200) {
        moveStroke(framebuffer, state, {static_cast<double>(x), 270.0});
    }
    endStroke(framebuffer, state, {880.0, 270.0});
}
```


Năm vị trí là X = 80, 280, 480, 680, 880; tất cả ở Y = 270. Chạy S ở 1/1 rồi D: khoảng tâm 200 pixel. Chuyển sang 1/4 rồi D: các motion giữa bị bỏ, còn đầu/cuối cách nhau 800 pixel. Mỗi D xóa ảnh trước nên kết quả cũ không che khoảng hở của lần sau. Không dùng D trên tranh muốn giữ.

### Bước 5 — Đưa S/D vào sự kiện và xem số đo

Trong nhánh KEY_DOWN không repeat, phím D gọi demo và báo ảnh đã đổi:


```cpp title="src/main.cpp — gọi phép thử từ bàn phím"
if (event.key.key == SDLK_D) {
                    SDL_CaptureMouse(false);
                    lab::drawDemo(framebuffer, state);
                    dirty = true;
                }
```



```cpp title="src/main.cpp — đổi tỷ lệ lấy mẫu"
if (event.key.key == SDLK_S) {
                    lab::cancelStroke(state);
                    SDL_CaptureMouse(false);
                    state.sampleEvery *= 2;
                    if (state.sampleEvery > 8) {
                        state.sampleEvery = 1;
                    }
                    dirty = true;
                }
```


Trước khi đổi mức, S cancel nét và nhả capture; muốn thử cùng điều kiện thì bấm D sau khi chọn S. Khi ảnh thay đổi, title hiển thị số mẫu giữ, số dấu và input gap:


```cpp title="src/main.cpp — số đo không được gọi nhầm là FPS"
char title[256]{};
            std::snprintf(title, sizeof(title), "Mini Paint | r=%d | 1/%d samples | %d kept | %d stamps | input gap %.1fpx | S sampling | D demo", state.radius, state.sampleEvery, state.accepted, state.stamps, state.maximumGap);
```


`std::snprintf` nhận kích thước bộ đệm title, `%d` in số nguyên, `%.1f` in số thực một chữ số thập phân. App kiểm tra `SDL_SetWindowTitle` như các lời gọi SDL khác; xem đầy đủ nhánh báo lỗi trong source cuối trang.

## Ghép các phần lại

Chạy `project_3_checkpoint_3`. Bấm D ở các mức S khác nhau, ghi số mẫu giữ và input gap. Với bán kính 12, khoảng 200 hoặc 800 pixel đều lớn hơn đường kính nên phải thấy dấu rời.

Số dấu và số mẫu còn gần nhau ở phiên bản này. Bài sau giữ nguyên dữ liệu đầu vào nhưng tăng số dấu bằng nội suy. Đây mới là cách sửa nguyên nhân, không phải tăng FPS hoặc làm bút dày lên.

## Thử làm sai để hiểu đúng

1. Cập nhật previous ngay cả khi motion bị bỏ. Khoảng input đo được không còn là khoảng giữa các mẫu thực sự dùng để vẽ.
2. Áp dụng lấy thưa cả cho up. Một số lần thả mất vị trí cuối.
3. Bỏ clear trước D rồi so preset khác. Tranh cũ chồng lên làm thí nghiệm không còn điều kiện ban đầu giống nhau.
4. In từng motion ra terminal. Chính việc ghi log có thể ảnh hưởng nhịp event; chỉ xem bộ đếm tổng hợp.

## Tự kiểm tra kết quả

- S có bốn mức và D lặp lại trên ảnh trống.
- 1/1 cho input gap 200 px, 1/4 cho 800 px với mẫu D.
- Chưa có nội suy; không chỉnh bán kính để che khoảng hở.
- Down/up vẫn được giữ, các motion bị bỏ không đổi previous.
- Bạn không gọi tỷ lệ 1/N là Hz của chuột.
