# Tiến thời gian mà không trộn hai snapshot

## Vấn đề cần giải quyết

Bây giờ mới cho state tiến triển. Một frame render không phải một bước vật lý: nó có thể chậm vì vẽ, resize hoặc làm phép đo. Nếu lấy frame time tùy ý làm dt, bạn đã đổi thí nghiệm mỗi khi máy bận.

## Hiểu ý tưởng trước khi viết code

Ta dùng symplectic Euler: tính toàn bộ a từ position cũ, cập nhật velocity, rồi dùng velocity mới cho position. Đây là integrator bậc một, không phải lời hứa bảo toàn energy chính xác.

$$
\mathbf v_{n+1}=\mathbf v_n+\mathbf a(\mathbf p_n)\Delta t,\qquad \mathbf p_{n+1}=\mathbf p_n+\mathbf v_{n+1}\Delta t.
$$

Một accumulator thông thường biến frame time thành nhiều fixed step. Ở hệ lớn, ứng dụng còn chia ngay một force pass qua nhiều frame. Scheduler ưu tiên hoàn tất một bước trên snapshot cố định, có budget mỗi đợt. Simulated time có thể chậm hơn thời gian thực; không cố bù lag bằng vòng lặp vô hạn.

Checkpoint 04 dùng direct ở N=256. Chưa tăng lên hàng nghìn trước khi có Barnes–Hut, nhưng nguyên tắc commit state đã phải đúng ở đây.

## Viết code từng bước

### Giữ thứ tự cập nhật rõ ràng

```cpp title="include/lab.hpp — Giữ thứ tự cập nhật rõ ràng"
inline void integrateSymplecticEuler(
    std::vector<Body>& bodies,
    std::span<const Vec3> accelerations,
    double deltaSeconds
) {
    if (accelerations.size() != bodies.size() || !std::isfinite(deltaSeconds) || deltaSeconds <= 0) {
        throw std::invalid_argument("Invalid integration input");
    }
    for (std::size_t index = 0; index < bodies.size(); ++index) {
        bodies[index].velocity += accelerations[index] * deltaSeconds;
        bodies[index].position += bodies[index].velocity * deltaSeconds;
    }
}
```

Hai dòng không được tùy tiện đảo chỗ. acceleration[index] thuộc snapshot cũ; velocity mới được dùng cho position mới. Kiểm kích thước vector và dt trước khi truy cập.

### Mở bước chưa được commit

```cpp title="include/simulation.hpp — Mở bước chưa được commit"
inline void beginPhysics(Simulation& simulation) {
    // Freeze this snapshot until all accelerations are ready. No in-place update.
    simulation.rebuild();
    simulation.pendingAccelerations.assign(simulation.bodies.size(), {});
    simulation.nextTarget = 0;
    simulation.physicsPending = true;
}
```

pendingAccelerations có một ô cho mỗi target, nextTarget bắt đầu từ 0. Không body nào di chuyển ở đây. Cancel có thể bỏ bước này mà không để nửa hệ ở một thời điểm khác.

### Chia việc nhưng không chia state

```cpp title="include/simulation.hpp — Chia việc nhưng không chia state"
inline bool advancePhysics(Simulation& simulation, double budgetMilliseconds = 6) {
    const auto deadline = std::chrono::steady_clock::now() + std::chrono::duration<double, std::milli>(budgetMilliseconds);
    while (simulation.nextTarget < simulation.bodies.size()) {
        const std::size_t target = simulation.nextTarget;
        simulation.pendingAccelerations[target] = directAcceleration(simulation.bodies, target, gravity, simulation.epsilon).acceleration;
        ++simulation.nextTarget;
        if (std::chrono::steady_clock::now() >= deadline) {
            return false;
        }
    }
    integrateSymplecticEuler(simulation.bodies, simulation.pendingAccelerations, simulation.dt);
    simulation.physicsPending = false;
    simulation.time += simulation.dt;
    ++simulation.steps;
    simulation.rebuild();
    // 24 IDs trải đều toàn bộ hệ × 64 snapshot; không chỉ lấy sao ở lõi.
    std::vector<Vec3> trail{};
    for (std::size_t i = 0; i < std::min<std::size_t>(24, simulation.bodies.size()); ++i) {
        const std::size_t index = i * simulation.bodies.size() / std::min<std::size_t>(24, simulation.bodies.size());
        trail.push_back(simulation.bodies[index].position);
    }
    simulation.trails.push_back(std::move(trail));
    if (simulation.trails.size() > 64) {
        simulation.trails.pop_front();
    }
    return true;
}
```

Mỗi lần gọi có khoảng 6 ms để tính các target. Nếu chưa đủ, hàm trả false để event loop tiếp tục nhận input. Chỉ sau target cuối mới integrate toàn vector, tăng time đúng một dt và lưu trail có giới hạn.

## Ghép các phần lại

Trong runApplication, N gọi beginPhysics và bật singleStep. Ở các lượt event loop tiếp theo, advancePhysics làm tiếp công việc; không có vòng while chờ khóa cửa sổ. Khi hàm trả true, singleStep tắt. Space cho chạy/dừng, camera vẫn dùng được.

Đổi dt từ 1/240 sang 1/120. Mỗi lần N vẫn là một bước, nhưng khoảng thời gian vật lý lớn gấp đôi. Đó không phải tăng tốc kernel tính lực.

```bash title="Terminal — checkpoint 04"

```

Trên Windows chạy ./build/Debug/project_31_checkpoint_4.exe; với Ninja/macOS/Linux, executable nằm trực tiếp trong build. Toàn bộ source và phần so sánh với bài trước ở cuối trang.

## Thử làm sai để hiểu đúng

1. Integrate mỗi body ngay sau khi có acceleration của nó. Lỗi phụ thuộc thứ tự ở bài 03 sẽ quay lại. Khôi phục cách tính acceleration của toàn snapshot trước khi cập nhật state.
2. Tăng dt ở preset hai vật, giữ force model và solver không đổi. Quỹ đạo có thể xấu dù direct force vẫn đúng: đây là integration error, chưa liên quan Octree. Giảm dt và so tại cùng thời gian.

## Tự kiểm tra kết quả

- Single-step tăng step đúng 1 và time đúng dt, kể cả force pass đi qua nhiều frame.
- Tất cả body commit cùng lúc; Cancel trước commit giữ nguyên snapshot.
- Pause không khóa camera; Reset bỏ pending force và tạo lại đúng seed.
- Trail không vượt 64 snapshot × 24 body; toàn bộ N vẫn nhận gravity.
