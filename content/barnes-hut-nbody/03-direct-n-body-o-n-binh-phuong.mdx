# Cộng tất cả lực và giữ một lời giải đối chứng

## Vấn đề cần giải quyết

Một cặp đúng chưa có nghĩa là một hệ nhiều vật thể đúng. Bước tiếp theo không phải cây: ta đọc từng source thật cho từng target. Bản direct này cố ý đơn giản, vì nó là lời giải đối chứng cho mọi tối ưu sau đó.

## Hiểu ý tưởng trước khi viết code

Với N body, một target đọc N−1 source. Tính cho mọi target tạo N(N−1) tương tác có hướng; i→j và j→i đều được tính. Đó là lý do lượng việc tăng theo N², không phải cứ FPS thấp là đã chứng minh được độ phức tạp.

Chỉ bỏ self interaction theo index, không bỏ mọi nguồn trùng position. Hai body khác nhau vẫn là hai nguồn của hệ. Cũng không cập nhật position khi đang tính lực: mọi target phải nhìn cùng một snapshot.

Với N=256, một target đọc 255 nguồn; full pass có 65.280 interactions. Bản tương tác direct giữ N≤256 để không khóa UI. Reference của hệ lớn về sau vẫn đọc đủ mọi source cho tập target được công bố.

## Viết code từng bước

### Giải cho một target trước

```cpp title="include/lab.hpp — Giải cho một target trước"
inline AccelerationResult directAcceleration(
    std::span<const Body> bodies,
    std::size_t targetIndex,
    double gravitationalConstant,
    double softening
) {
    AccelerationResult result{};
    if (targetIndex >= bodies.size()) {
        return result;
    }
    for (std::size_t sourceIndex = 0; sourceIndex < bodies.size(); ++sourceIndex) {
        if (sourceIndex == targetIndex) {
            continue;
        }
        result.acceleration += softenedAcceleration(
            bodies[targetIndex].position,
            bodies[sourceIndex].position,
            bodies[sourceIndex].mass,
            gravitationalConstant,
            softening
        );
        ++result.metrics.exactInteractions;
    }
    return result;
}
```

sourceIndex chạy qua toàn vector. continue chỉ bỏ chính target. exactInteractions tăng đúng tại nơi cộng một nguồn, không được suy từ số node hoặc số pixel.

### Mở rộng thành pass toàn hệ

```cpp title="include/lab.hpp — Mở rộng thành pass toàn hệ"
inline std::vector<Vec3> directAccelerations(
    std::span<const Body> bodies,
    double gravitationalConstant,
    double softening,
    std::size_t* interactionCount = nullptr
) {
    std::vector<Vec3> accelerations(bodies.size());
    std::size_t interactions = 0;
    for (std::size_t targetIndex = 0; targetIndex < bodies.size(); ++targetIndex) {
        const AccelerationResult result = directAcceleration(
            bodies,
            targetIndex,
            gravitationalConstant,
            softening
        );
        accelerations[targetIndex] = result.acceleration;
        interactions += result.metrics.exactInteractions;
    }
    if (interactionCount) {
        *interactionCount = interactions;
    }
    return accelerations;
}
```

Vector acceleration mới có cùng thứ tự với bodies. Ta trả hết kết quả ra ngoài, chưa cho integrator sửa position. Nhờ vậy còn có thể kiểm output trước khi state đổi.

## Ghép các phần lại

Trên preset ba vật, target phía trên phải bị hai vật phía dưới hút xuống. Hai thành phần X triệt tiêu. Đó là fixture độc lập; gọi directAcceleration hai lần rồi so hai kết quả giống nhau không phải oracle.

Kiểm counters trước khi bật chuyển động. Bài 04 sẽ đưa vector acceleration vào integrator, không viết một công thức gravity thứ hai bên trong event loop.

## Thử làm sai để hiểu đúng

1. Thử cập nhật position ngay sau khi tính xong target đầu. Target tiếp theo sẽ nhìn một phần state mới và phần còn lại state cũ; so với bản tính mọi acceleration từ cùng snapshot.
2. Giữ bản thử đó rồi đảo thứ tự target. Dự đoán kết quả có đổi không: sự phụ thuộc thứ tự không đến từ physics. Khôi phục hai bước tính lực và commit riêng, rồi lặp lại phép so.

## Tự kiểm tra kết quả

- N=1 trả acceleration 0 và exactInteractions=0.
- Các ca N=2, N=3 khớp tính tay; expected value không gọi production gravity helper.
- Một target có N−1 interactions, full pass có N(N−1).
- Hàm tính lực không sửa position, velocity hoặc mass của input.

## Bài tập mở rộng

Viết bản cặp $i<j$ cập nhật hai lực đối nghịch rồi so với oracle hiện tại. Lưu ý acceleration hai body không đối nhau khi mass khác nhau, dù force của chúng đối nhau.
