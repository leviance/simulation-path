# Đo chi phí thật của hai cách tính lực

## Vấn đề cần giải quyết

Barnes–Hut đọc ít nguồn hơn chưa chắc nhanh hơn. Dựng cây, duyệt node và quản lý dữ liệu cũng tốn thời gian. Ta sẽ đo đúng phần công việc cần so, giữ kết quả lực có thể quan sát và công bố cả những ca cây không có lợi.

## Hiểu ý tưởng trước khi viết code

Một benchmark công bằng giữ cùng bodies, seed, theta, epsilon và số target. Bản C++ đo full force pass ở N=256/1.024/4.096; Canvas đo 256/512/1.024 để giữ phản hồi. Cả hai đều không dùng số đo JavaScript để suy ra thời gian C++.

Tách ba thứ: tree build, force kernel và render. Clock bao từng lời gọi tính lực; thời gian chờ frame không được cộng vào kernel. Bỏ một warm-up, lấy median cùng min/max của năm mẫu. Direct work của full pass vẫn phải đúng N(N−1).

Số lần tính nguồn không phải milliseconds. Cây có thể giảm work nhưng vẫn chậm ở N nhỏ; CPU, build configuration và cost truy cập dữ liệu đều ảnh hưởng. Kết quả không đủ để kết luận một solver luôn thắng.

### Đo nhiều pass với tiến độ hữu hạn

```cpp title="include/benchmark.hpp — Đo nhiều pass với tiến độ hữu hạn"
struct RuntimeJob {
    std::vector<Body> bodies{};
    BarnesHutTree tree{};
    std::vector<RuntimeRow> rows{};
    std::array<double, 5> directTimes{};
    std::array<double, 5> treeTimes{};
    std::size_t target{};
    int sizeIndex{};
    int sample{};
    int method{};
    double elapsedMicroseconds{};
    double checksum{};
    std::size_t work{};
    std::size_t directWork{};
    double theta{0.5};
    double epsilon{0.02};
    bool active{};
    bool timedOut{};
    std::chrono::steady_clock::time_point deadline{};

    void prepareSize() {
        constexpr std::array<std::size_t, 3> counts{256, 1024, 4096};
        bodies = makeGalaxyBodies(counts[std::size_t(sizeIndex)], galaxySeed);
        tree = buildMassOctree(bodies);
        sample = 0;
        method = 0;
        target = 0;
        checksum = 0;
        work = 0;
        elapsedMicroseconds = 0;
    }

    void start(double selectedTheta, double selectedEpsilon) {
        *this = {};
        theta = selectedTheta;
        epsilon = selectedEpsilon;
        active = true;
        deadline = std::chrono::steady_clock::now() + std::chrono::seconds(30);
        prepareSize();
    }

    void tick() {
        const auto until = std::chrono::steady_clock::now() + std::chrono::milliseconds(6);
        while (active && std::chrono::steady_clock::now() < until) {
            if (std::chrono::steady_clock::now() >= deadline) {
                active = false;
                timedOut = true;
                return;
            }
            const auto started = std::chrono::steady_clock::now();
            AccelerationResult force{};
            if (method == 0) {
                force = directAcceleration(bodies, target, gravity, epsilon);
            } else {
                force = barnesHutAcceleration(tree, bodies, target, theta, gravity, epsilon);
            }
            elapsedMicroseconds += std::chrono::duration<double, std::micro>(std::chrono::steady_clock::now() - started).count();
            checksum += force.acceleration.x + force.acceleration.y + force.acceleration.z;
            work += force.metrics.exactInteractions + force.metrics.approximatedNodes;
            ++target;
            if (target < bodies.size()) {
                continue;
            }
            if (sample > 0) {
                if (method == 0) {
                    directTimes[std::size_t(sample - 1)] = elapsedMicroseconds;
                } else {
                    treeTimes[std::size_t(sample - 1)] = elapsedMicroseconds;
                }
            }
            if (method == 0) {
                directWork = work;
            }
            ++method;
            if (method == 2) {
                method = 0;
                ++sample;
            }
            if (sample == 6) {
                std::sort(directTimes.begin(), directTimes.end());
                std::sort(treeTimes.begin(), treeTimes.end());
                RuntimeRow row{};
                row.count = bodies.size();
                row.directMedian = directTimes[2];
                row.directMinimum = directTimes[0];
                row.directMaximum = directTimes[4];
                row.treeMedian = treeTimes[2];
                row.treeMinimum = treeTimes[0];
                row.treeMaximum = treeTimes[4];
                row.buildMicroseconds = tree.rebuildMicroseconds;
                row.checksum = checksum;
                row.directWork = directWork;
                row.treeWork = work;
                rows.push_back(row);
                ++sizeIndex;
                if (sizeIndex == 3) {
                    active = false;
                    return;
                }
                prepareSize();
            }
            target = 0;
            elapsedMicroseconds = 0;
            checksum = 0;
            work = 0;
        }
    }
};
```

Job giữ sizeIndex, sample, method và target giữa các lượt tick. Mỗi target đọc cùng dataset ở hai mode; sau warm-up mới ghi mẫu. Output acceleration đi vào checksum để compiler không xem kernel là công việc thừa.

## Ghép các phần lại

Build Release trước khi đọc runtime, nhưng vẫn chạy correctness ở cả Debug/Release. Bấm B ở C++ hoặc Chạy scaling study trên Canvas. Không đổi seed giữa Direct và BH; nếu report dừng ở deadline 30 giây, ghi chưa hoàn tất, không điền một timing giả cho phần thiếu.

Đường force error ở bài 08 và bảng runtime ở đây là hai thí nghiệm liên quan nhưng khác nhau. Một theta nhanh hơn chỉ có ý nghĩa sau khi bạn biết sai số của nó trên workload cần dùng.

```bash title="Terminal — checkpoint 09"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_31_checkpoint_9
```

Trên Windows chạy ./build/Debug/project_31_checkpoint_9.exe; với Ninja/macOS/Linux, executable nằm trực tiếp trong build. Toàn bộ source và phần so sánh với bài trước ở cuối trang.

## Thử làm sai để hiểu đúng

1. Đặt timer quanh cả thao tác click, các frame chờ và render. Thay kích thước cửa sổ: runtime có thể đổi dù kernel không đổi, vì phép đo đã lẫn chi phí. Khôi phục timer cho đúng phạm vi.
2. Chỉ lấy một pass lạnh rồi so với median có warm-up. Một mẫu thiếu ổn định không đủ xếp hạng thuật toán. Trở lại cùng dữ liệu, warm-up và số lần lặp trước khi kết luận.

## Tự kiểm tra kết quả

- C++/Canvas ghi riêng N, seed, theta/epsilon và đơn vị thời gian.
- Direct full pass có N(N−1) work; BH work là exact+aggregate, không phải visitedNodes.
- Có warm-up, năm mẫu, median/min/max và tree build riêng.
- Job có tiến độ, dừng được; report timeout không được coi là đã đo đủ.
- Không assert thứ hạng runtime phụ thuộc phần cứng.
