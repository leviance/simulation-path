# Explicit Euler — thí sinh đầu tiên

## Vấn đề cần giải quyết

Khung trắng đã cho biết vật đúng ra phải ở đâu. Bây giờ ta thêm khối đỏ chạy bằng Euler, không được lấy vị trí từ sin/cos. Với lò xo, gia tốc phải được tính lại tại mỗi bước vì nó phụ thuộc vị trí hiện tại.

Bài này chỉ làn 1 có solver số; hai làn còn lại tiếp tục hiện bản đối chứng. Đừng cho phương pháp chưa học chạy ngầm rồi gọi đó là một checkpoint hoàn chỉnh.

## Hiểu ý tưởng trước khi viết code

Nếu biết vị trí xₙ, vận tốc vₙ và bước thời gian h, Euler xem vận tốc và gia tốc ở đầu bước như không đổi trong cả khoảng h:

$$
a_n=-\frac{k}{m}x_n,\qquad x_{n+1}=x_n+h v_n,\qquad v_{n+1}=v_n+h a_n.
$$

Cả hai vế phải đều dùng **state cũ**. Với m=1, k=4, x₀=1, v₀=0, h=0.1: a₀=−4, x₁=1, v₁=−0.4. Việc x chưa đổi trong bước đầu không phải lỗi: Euler dùng v₀=0 cho cả khoảng.

Trong mặt phẳng (x,v/ω), nghiệm đúng là một đường tròn. Euler đi theo tiếp tuyến nên bước ra ngoài đường tròn. Đây là lý do biên độ và năng lượng tăng, không phải lỗi pixel.

### Bước 1 — Giữ state cũ và trả thêm lượng công việc

IntegratorStepResult đã có trong Starter: state mới và forceEvaluations. Giá trị 0 nghĩa là bước bị từ chối, không phải một bước hợp lệ “miễn phí”. validStep và checkedStep kiểm dữ liệu đầu/cuối để state lỗi không đi tiếp vào renderer.

Thêm hàm này vào lab.hpp:

```cpp title="include/lab.hpp — hai phép cập nhật đều dùng state đầu bước"
inline IntegratorStepResult explicitEulerStep(const OscillatorState& current, const OscillatorParameters& parameters, double dt) {
    if (!validStep(current, parameters, dt)) {
        return {current, 0};
    }
    const double acceleration = oscillatorAcceleration(current.position, parameters);
    OscillatorState next;
    // Cả hai dòng đều đọc trạng thái đầu bước, không đọc next.velocity.
    next.position = current.position + current.velocity * dt;
    next.velocity = current.velocity + acceleration * dt;
    next.elapsed = current.elapsed + dt;
    return checkedStep(current, next, 1);
}
```


### Bước 2 — Đưa Euler vào bộ chọn

Sau bài 1, Starter chưa có hàm chọn phương pháp tích phân. Thêm stepIntegrator ngay sau explicitEulerStep trong lab.hpp. Hiện tại hàm chỉ biết Euler; hai case còn lại sẽ được thêm ở các bài sau:

```cpp title="include/lab.hpp — chỉ phương pháp đã viết mới chạy"
inline IntegratorStepResult stepIntegrator(IntegratorKind kind, const OscillatorState& current, const OscillatorParameters& parameters, double dt) {
    switch (kind) {
    case IntegratorKind::explicitEuler:
        return explicitEulerStep(current, parameters, dt);
    default:
        (void)parameters;
        (void)dt;
        return {current, 0};
    }
}
```


### Bước 3 — Nối solver vào mỗi bước physics

Thay toàn bộ stepScene trong scene.hpp bằng hàm dưới. laneCount=1 là có chủ đích: chỉ làn đỏ được tích phân. beforeLast giữ trạng thái đầu bước. Bản Canvas cũng lưu dữ liệu tương ứng để minh họa đúng bước vừa tính; nó không đọc state trực tiếp từ ứng dụng C++.

```cpp title="include/scene.hpp — một bước của làn đầu"
inline bool stepScene(Scene& scene) {
    if (scene.warning[0] != '\0') {
        return false;
    }
    const double dt = fixedDelta(scene);
    const IntegratorRace before = scene.race;
    // Các bài đầu chỉ chạy những phương pháp người học đã viết.
    auto next = scene.race;
    constexpr std::size_t laneCount = 1;
    for (std::size_t index = 0; index < laneCount; ++index) {
        const auto result = stepIntegrator(next.lanes[index].kind, next.lanes[index].state, scene.parameters, dt);
        if (result.forceEvaluations == 0) {
            scene.warning = "Invalid numerical step.";
            stopJobs(scene);
            return false;
        }
        next.lanes[index].state = result.state;
        next.lanes[index].forceEvaluations += static_cast<std::size_t>(result.forceEvaluations);
    }
    ++next.stepCount;
    scene.race = next;
    scene.beforeLast = before;
    scene.elapsed += dt;
    ++scene.substeps;
    // Không clamp state vật lý để che việc Euler đang phân kỳ.
    for (const auto& lane : scene.race.lanes) {
        if (std::abs(lane.state.position) > 1e6 || std::abs(lane.state.velocity) > 1e6) {
            scene.warning = "Divergence exceeds safety range (1e6). Reset or reduce dt.";
            stopJobs(scene);
            return false;
        }
    }
    return true;
}
```


Trong view.hpp, thay laneAvailable để phần vẽ biết làn đỏ đã có numerical state. Đây chỉ là chọn nguồn dữ liệu để vẽ, không quyết định phương pháp tích phân:

```cpp title="include/view.hpp — bật khối màu của làn đầu"
inline bool laneAvailable(std::size_t index) {
    return index == 0;
}
```

## Thử làm sai để hiểu đúng

1. Viết next.position bằng next.velocity thay cho current.velocity. Kết quả bước đầu thành x=0.96. Bạn vừa đổi sang một quy tắc cập nhật khác, không phải “sửa Euler”; hoàn tác để giữ phép so đúng tên.

2. Giữ điều kiện đầu, chạy với 1/30 rồi 1/60 s. Sai số tích lũy chậm hơn ở dt nhỏ nhưng Euler vẫn tăng năng lượng trong oscillator không lực cản.

3. Cố gọi bước với dt=0 hoặc NaN trong test. Kết quả phải giữ nguyên state và forceEvaluations=0.

## Tự kiểm tra kết quả

- Euler không đọc nghiệm chính xác.
- Ví dụ một bước cho x₁=1, v₁=−0.4, một lần tính lực.
- Chỉ làn đỏ thay đổi numerical state; hai làn chưa học không tăng evaluation count.
- Đổi dt làm cả thí nghiệm bắt đầu lại, không trộn lịch sử của hai dt.

## Bài tập mở rộng

Tự khai triển E₁=½mv₁²+½kx₁² từ hai công thức Euler. Bạn sẽ thu được E₁=E₀(1+ω²h²). Với h>0 và ω>0, năng lượng luôn tăng, dù h rất nhỏ.
