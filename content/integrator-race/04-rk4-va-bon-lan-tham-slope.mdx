# RK4: đánh giá đạo hàm tại bốn trạng thái

## Vấn đề cần giải quyết

Ta đã thấy lợi ích của việc dùng thêm thông tin trong một bước. RK4 đi xa hơn: thử đạo hàm ở đầu bước, hai lần ở nửa bước và một lần ở cuối bước. Bài này đưa phương pháp thứ ba vào làn tím.

Điều dễ nhầm là cộng position của các trạng thái thử. RK4 không làm vậy: nó lấy trung bình có trọng số của **đạo hàm**.

## Hiểu ý tưởng trước khi viết code

Gộp state thành y=(x,v). Khi đó y′=(v,−kx/m). Mỗi kᵢ cũng có hai thành phần: dx/dt mang m/s, dv/dt mang m/s².

$$
k_1=f(y_n),\quad k_2=f(y_n+\tfrac h2 k_1),\quad
k_3=f(y_n+\tfrac h2 k_2),\quad k_4=f(y_n+h k_3),
$$
$$
y_{n+1}=y_n+\frac h6(k_1+2k_2+2k_3+k_4).
$$

Hai lần lấy mẫu ở nửa bước không trùng nhau: k₂ dùng dự đoán từ k₁, còn k₃ dùng dự đoán từ k₂. Các trạng thái thử chỉ phục vụ tính một bước; chúng không phải bốn lần tiến thời gian thật.

### Bước 1 — Mô tả đạo hàm của cả state

Thêm kiểu và hai helper sau vào lab.hpp. offsetState tạo trạng thái thử, không ghi đè state đang mô phỏng:

```cpp title="include/lab.hpp — hai đại lượng có đơn vị khác nhau"
struct PhaseDerivative {
    double positionRate = 0.0;
    double velocityRate = 0.0;
};
```


```cpp title="include/lab.hpp — đạo hàm của position và velocity"
inline PhaseDerivative oscillatorDerivative(const OscillatorState& state, const OscillatorParameters& parameters) {
    return {state.velocity, oscillatorAcceleration(state.position, parameters)};
}
```


```cpp title="include/lab.hpp — một trạng thái thử cách đầu bước amount giây"
inline OscillatorState offsetState(const OscillatorState& state, const PhaseDerivative& derivative, double amount) {
    return {state.position + derivative.positionRate * amount, state.velocity + derivative.velocityRate * amount, state.elapsed + amount};
}
```


### Bước 2 — Giữ riêng bốn stage

Viết hàm RK4 bằng những biến có tên; chưa gộp thành một biểu thức dài:

```cpp title="include/lab.hpp — bốn đạo hàm rồi mới cập nhật state"
inline IntegratorStepResult rungeKutta4Step(const OscillatorState& current, const OscillatorParameters& parameters, double dt) {
    if (!validStep(current, parameters, dt)) {
        return {current, 0};
    }
    const PhaseDerivative k1 = oscillatorDerivative(current, parameters);
    const PhaseDerivative k2 = oscillatorDerivative(offsetState(current, k1, 0.5 * dt), parameters);
    const PhaseDerivative k3 = oscillatorDerivative(offsetState(current, k2, 0.5 * dt), parameters);
    const PhaseDerivative k4 = oscillatorDerivative(offsetState(current, k3, dt), parameters);

    const double positionRate = (k1.positionRate + 2.0 * k2.positionRate + 2.0 * k3.positionRate + k4.positionRate) / 6.0;
    const double velocityRate = (k1.velocityRate + 2.0 * k2.velocityRate + 2.0 * k3.velocityRate + k4.velocityRate) / 6.0;
    const OscillatorState next{current.position + positionRate * dt, current.velocity + velocityRate * dt, current.elapsed + dt};
    return checkedStep(current, next, 4);
}
```


### Bước 3 — Nối làn tím

Thêm case RK4 vào dispatcher rồi đổi laneCount trong stepScene thành 3:

```cpp title="include/lab.hpp — đủ ba phương pháp"
inline IntegratorStepResult stepIntegrator(IntegratorKind kind, const OscillatorState& current, const OscillatorParameters& parameters, double dt) {
    switch (kind) {
    case IntegratorKind::explicitEuler:
        return explicitEulerStep(current, parameters, dt);
    case IntegratorKind::velocityVerlet:
        return velocityVerletStep(current, parameters, dt);
    case IntegratorKind::rungeKutta4:
        return rungeKutta4Step(current, parameters, dt);
    default:
        (void)parameters;
        (void)dt;
        return {current, 0};
    }
}
```


```cpp title="include/scene.hpp — ba phương pháp đã được viết"
constexpr std::size_t laneCount = 3;
```


Cuối cùng cập nhật laneAvailable trong view.hpp:

```cpp title="include/view.hpp — cả ba làn đều có numerical state"
inline bool laneAvailable(std::size_t index) {
    return index < 3;
}
```


## Ghép các phần lại

Với preset Nhìn rõ một bước, m=1, k=4, x₀=1, v₀=0, h=0.1, bốn cặp đạo hàm phải là k₁=(0,−4), k₂=(−0.2,−4), k₃=(−0.2,−3.96), k₄=(−0.396,−3.92). Từ đó x₁≈0.9800666667, v₁≈−0.3973333333.

Canvas nối các trạng thái thử trên mặt phẳng (x,v/ω) để bạn thấy chỗ lấy mẫu. Đó không phải đường vật đi ngoài đời và không có nghĩa RK4 chạy nhanh gấp bốn lần. Numerical elapsed chỉ tăng h một lần; force evaluations tăng 4.

## Thử làm sai để hiểu đúng

1. Tính k₃ từ k₁ thay vì k₂. Các con số ở nửa bước sẽ không còn khớp bảng tính tay; đọc từng stage trước khi xem kết quả cuối.

2. Quên hệ số h trong bước cộng vào current.position/current.velocity. Bạn đang cộng đạo hàm với state dù đơn vị khác nhau.

3. Cộng bốn đạo hàm với trọng số bằng nhau. Thuật toán đó không còn là classical RK4 và sẽ không cho bậc hội tụ bốn ở bài 7.

## Tự kiểm tra kết quả

- k₁–k₄ là đạo hàm, không phải position.
- k₂ và k₃ lấy tại hai trạng thái thử khác nhau ở nửa bước.
- Numerical elapsed tăng đúng h; bốn lần tính lực được đếm riêng.
- Ví dụ một bước khớp expected độc lập; không dùng exact solution để chỉnh state tím.

## Bài tập mở rộng

Thử đổi tên positionRate và velocityRate thành đơn vị của chúng khi tính trên giấy. Viết ra đơn vị của h×positionRate và h×velocityRate để tự kiểm công thức.
