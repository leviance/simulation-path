# Dựng đường đua harmonic oscillator

## Vấn đề cần giải quyết

Ở Project 22, ta so một quỹ đạo Euler với nghiệm giải tích. Lần này lực không còn là một vector không đổi: lò xo kéo mạnh hay yếu tùy vị trí của vật. Ta sẽ cho ba cách cập nhật cùng giải bài toán đó, để nhìn thấy vì sao chúng cho kết quả khác nhau.

Trước khi so thuật toán, cần một bàn thí nghiệm nhìn thấy được. Tải ZIP ở trang tổng quan rồi mở thư mục có CMakeLists.txt. Starter đã có window SDL3, renderer, texture, framebuffer và ba đường ray. Input cơ bản cũng được nối sẵn từ Project 22. Mỗi file có một việc: lab.hpp tính toán; scene.hpp giữ thí nghiệm; view.hpp vẽ pixel; presentation.hpp vẽ chữ và đưa ảnh lên SDL; main.cpp nhận input và gọi vòng lặp.

Starter chưa có phương trình nên các khối chỉ đứng yên. Bài này cho khung trắng chuyển động bằng nghiệm chính xác; các khối màu chỉ bắt đầu tích phân số từ bài 2.

## Hiểu ý tưởng trước khi viết code

x là **độ lệch khỏi vị trí cân bằng**, không phải chiều dài lò xo hay tọa độ của bức tường. Khi x dương, lực phải hướng âm; khi x âm, lực phải hướng dương.

$$
F=-kx,\qquad a(x)=-\frac{k}{m}x,\qquad \omega=\sqrt{k/m}.
$$

Với x₀ và v₀ tại thời điểm bắt đầu, nghiệm không có lực cản là:

$$
x(t)=x_0\cos(\omega t)+\frac{v_0}{\omega}\sin(\omega t),\qquad
v(t)=-x_0\omega\sin(\omega t)+v_0\cos(\omega t).
$$

Năng lượng tổng là E=½mv²+½kx². Nó phải giữ nguyên trong nghiệm chính xác. Khi k=0, không dùng công thức có phép chia cho ω=0: vật chuyển động thẳng đều x=x₀+v₀t.

Ở đây position dùng mét, velocity dùng m/s, stiffness dùng N/m, mass dùng kg. Chỉ phần vẽ mới đổi sang pixel. Kéo khối hoặc dùng mũi tên trái/phải để chọn x₀, rồi thử dấu của gia tốc.

```cpp title="include/view.hpp — lò xo là hình minh họa của state"
inline void drawSpring(Framebuffer& image, double massX, double centerY, std::uint32_t color) {
    double previousX = 55.0;
    double previousY = centerY;
    for (int segment = 1; segment <= 12; ++segment) {
        const double x = 55.0 + (massX - 16.0 - 55.0) * static_cast<double>(segment) / 12.0;
        double y = centerY;
        if (segment < 12) {
            if (segment % 2 == 0) {
                y -= 8.0;
            } else {
                y += 8.0;
            }
        }
        drawLine(image, previousX, previousY, x, y, color);
        previousX = x;
        previousY = y;
    }
}
```


### Bước 2 — Viết lực và năng lượng

Thêm các hàm sau vào namespace lab trong lab.hpp. validParameters và finiteState đã có trong Starter; chúng từ chối dữ liệu không hữu hạn. Dữ liệu lỗi không được trả gia tốc 0 rồi bị hiểu nhầm là một vật chuyển động tự do.

```cpp title="include/lab.hpp — tần số góc"
inline double angularFrequency(const OscillatorParameters& parameters) {
    if (!validParameters(parameters)) {
        return std::numeric_limits<double>::quiet_NaN();
    }
    return std::sqrt(parameters.stiffness / parameters.mass);
}
```


```cpp title="include/lab.hpp — gia tốc luôn kéo về gốc"
inline double oscillatorAcceleration(double position, const OscillatorParameters& parameters) {
    if (!std::isfinite(position) || !validParameters(parameters)) {
        return std::numeric_limits<double>::quiet_NaN();
    }
    return -(parameters.stiffness / parameters.mass) * position;
}
```


```cpp title="include/lab.hpp — động năng cộng thế năng"
inline double oscillatorEnergy(const OscillatorState& state, const OscillatorParameters& parameters) {
    if (!validParameters(parameters) || !finiteState(state)) {
        return std::numeric_limits<double>::quiet_NaN();
    }
    const double kinetic = 0.5 * parameters.mass * state.velocity * state.velocity;
    const double potential = 0.5 * parameters.stiffness * state.position * state.position;
    return kinetic + potential;
}
```


### Bước 3 — Cho khung đối chứng chuyển động

Thêm analyticOscillatorState sau các hàm trên. Tham số time là khoảng thời gian kể từ initial; elapsed của kết quả cộng thêm mốc ban đầu:

```cpp title="include/lab.hpp — nghiệm chính xác không phụ thuộc integrator"
inline OscillatorState analyticOscillatorState(const OscillatorState& initial, const OscillatorParameters& parameters, double time) {
    if (!finiteState(initial) || !validParameters(parameters) || !std::isfinite(time) || time < 0.0) {
        return invalidState();
    }
    const double omega = angularFrequency(parameters);
    if (omega == 0.0) {
        return {initial.position + initial.velocity * time, initial.velocity, initial.elapsed + time};
    }
    const double phase = omega * time;
    const double position = initial.position * std::cos(phase) + initial.velocity * std::sin(phase) / omega;
    const double velocity = -initial.position * omega * std::sin(phase) + initial.velocity * std::cos(phase);
    return {position, velocity, initial.elapsed + time};
}
```

Trong scene.hpp, thay hàm stepScene còn đang trả false bằng:

```cpp title="include/scene.hpp — bài đầu chỉ tiến đồng hồ đối chứng"
inline bool stepScene(Scene& scene) {
    if (scene.warning[0] != '\0') {
        return false;
    }
    const double dt = fixedDelta(scene);
    scene.elapsed += dt;
    ++scene.substeps;
    // Không clamp state vật lý để che việc Euler đang phân kỳ.
    for (const auto& lane : scene.race.lanes) {
        if (std::abs(lane.state.position) > 1e6 || std::abs(lane.state.velocity) > 1e6) {
            scene.warning = "Divergence exceeds safety range (1e6). Reset or reduce dt.";
            stopJobs(scene);
            return false;
        }
    }
    return true;
}
```


Trong view.hpp, thay displayedPosition và renderScene của Starter bằng hai hàm dưới. Nếu giữ bản cũ chỉ trả initial.position, đồng hồ đã chạy nhưng hình vẫn đứng yên:

```cpp title="include/view.hpp — lấy vị trí của khung đối chứng"
inline double displayedPosition(const Scene& scene, std::size_t index) {
    if (laneAvailable(index)) {
        return scene.race.lanes[index].state.position;
    }
    return analyticOscillatorState(scene.initial, scene.parameters, scene.elapsed).position;
}
```


```cpp title="include/view.hpp — đưa vị trí mới vào ảnh"
inline void renderScene(Framebuffer& image, const Scene& scene) {
    image.clear();
    double exactPosition = scene.initial.position;
    exactPosition = analyticOscillatorState(scene.initial, scene.parameters, scene.elapsed).position;
    for (std::size_t index = 0; index < 3; ++index) {
        drawLane(image, index, displayedPosition(scene, index), exactPosition, laneAvailable(index), scene.debug);
    }
}
```


## Ghép các phần lại

advanceFrame đã dùng fixed-step planner từ Project 22 và gọi stepScene. Nhánh Space/N trong main.cpp cũng đã nối sẵn. Vì vậy sau khi thêm các hàm trên, Space làm khung trắng chuyển động, N tiến đúng một dt.

renderScene lấy exactPosition rồi gọi drawLane. Ba làn cùng dùng một nghiệm, nên cả ba khung trắng phải trùng nhau theo chiều ngang. Đây mới là bản đối chứng, chưa phải ba solver khác nhau. Không dùng sin/cos để sửa các khối màu ở những bài tiếp theo.

Thử preset Nhìn rõ một bước: x₀=1, v₀=0, m=1, k=4. Khi t=π/4 s, khung trắng phải đi qua x=0 với v=−2 m/s; năng lượng bằng 2 J. Đó là đáp án tính trước để kiểm code, không phải số do solver tự xác nhận.

## Thử làm sai để hiểu đúng

1. Đổi dấu âm trong gia tốc thành dương rồi đặt x₀>0. Readout lực sẽ hướng ra xa vị trí cân bằng, trái với mô hình lò xo. Khôi phục dấu trước khi học tiếp.

2. Chọn v₀ khác 0. Nếu bỏ hạng v₀/ω trong nghiệm, vị trí ở t=0 vẫn có thể đúng nhưng chuyển động ngay sau đó sai. Đối chiếu cả x(0) lẫn v(0).

3. Đặt k=0 và v₀=1. Vật phải đi thẳng đều, không xuất hiện NaN do chia cho ω.
