# Kiểm chứng solver trước khi đo tốc độ

## Vấn đề cần giải quyết

Một implementation sai đôi khi vẫn vẽ được ba lò xo khá đẹp. Trước khi đo tốc độ ở bài 8, ta cần một bộ kiểm có đáp án được tính độc lập, thay vì chỉ khẳng định “RK4 gần ghost hơn Euler”.

Ở đây ta kiểm ba việc khác nhau: công thức một bước, bậc hội tụ khi giảm dt và hành vi năng lượng dài hạn. Không dùng một ảnh chụp làm kết luận cho cả ba.

## Hiểu ý tưởng trước khi viết code

Với phương pháp có sai số toàn cục bậc p, ở một thời điểm T cố định và trong vùng dt đủ nhỏ:

$$
e(h)\approx Ch^p,\qquad \frac{e(h)}{e(h/2)}\approx 2^p.
$$

Euler, Verlet, RK4 có các tỉ lệ kỳ vọng gần 2, 4 và 16. Đây là kiểm bậc hội tụ, không phải lời hứa rằng chia dt đôi luôn cho đúng tỉ lệ đó ở mọi trường hợp.

Với oscillator, Euler còn có một đối chứng độc lập rất mạnh:

$$
E_N=E_0(1+\omega^2h^2)^N.
$$

Công thức đến từ việc thế xₙ₊₁=xₙ+h vₙ và vₙ₊₁=vₙ−hω²xₙ vào năng lượng; hai hạng chéo triệt tiêu. Nó không gọi lại solver để tự tạo expected. Không áp dụng công thức này cho các integrator khác.

### Bước 1 — Viết một runner có giới hạn công việc

Thêm kiểu và hàm sau vào lab.hpp. Runner không dùng SDL, không render và không sửa state bằng nghiệm chính xác:

```cpp title="include/lab.hpp — kết quả của một lần tích phân"
struct IntegratorRunResult {
    OscillatorState state{};
    std::size_t steps = 0;
    std::size_t forceEvaluations = 0;
};
```


```cpp title="include/lab.hpp — kiểm số bước trước khi chạy"
inline IntegratorRunResult runIntegrator(IntegratorKind kind, const OscillatorState& initial, const OscillatorParameters& parameters, double duration, double dt) {
    IntegratorRunResult run{initial, 0, 0};
    if (!validStep(initial, parameters, dt) || !std::isfinite(duration) || duration < 0.0) {
        return run;
    }
    const double count = std::floor((duration + kIntegratorEpsilon) / dt);
    if (!std::isfinite(count) || count > 10000.0) {
        return run;
    }
    for (std::size_t index = 0; index < static_cast<std::size_t>(count); ++index) {
        const auto result = stepIntegrator(kind, run.state, parameters, dt);
        if (result.forceEvaluations == 0) {
            break;
        }
        run.state = result.state;
        run.forceEvaluations += static_cast<std::size_t>(result.forceEvaluations);
        ++run.steps;
    }
    return run;
}
```

Nếu duration không chia hết cho dt, hàm chỉ chạy floor(duration/dt) bước. Khi kiểm hội tụ, chọn T chia hết cho cả hai dt để không so hai thời điểm khác nhau.

### Bước 2 — Kiểm công thức bằng ví dụ tính tay

Trong tests/tests.cpp của ZIP đã có bộ kiểm final. Đọc hàm dưới để biết expected đến từ đâu; không dán thêm một bản cùng tên:

```cpp title="tests/tests.cpp — expected độc lập cho nghiệm và từng bước"
void analyticAndSteps() {
    check(lab::validParameters(parameters), "positive mass and stiffness");
    check(!lab::validParameters({0.0, 4.0}) && !lab::validParameters({1.0, -1.0}), "invalid physical parameters");
    check(closeEnough(lab::angularFrequency(parameters), 2.0), "omega=sqrt(k/m)");
    const auto quarter = lab::analyticOscillatorState(initial, parameters, lab::kPi / 4.0);
    check(closeEnough(quarter.position, 0.0) && closeEnough(quarter.velocity, -2.0), "independent quarter-period oracle");
    check(closeEnough(lab::oscillatorEnergy(quarter, parameters), 2.0), "exact energy at quarter period");
    const auto arbitrary = lab::analyticOscillatorState({1.5, -0.75, 3.0}, parameters, 0.0);
    check(arbitrary.position == 1.5 && arbitrary.velocity == -0.75 && arbitrary.elapsed == 3.0, "analytic initial condition includes nonzero velocity and start time");
    const auto free = lab::analyticOscillatorState({1.0, 2.0, 0.0}, {1.0, 0.0}, 3.0);
    check(free.position == 7.0 && free.velocity == 2.0, "zero stiffness is free motion, not invalid data");
    const auto euler = lab::explicitEulerStep(initial, parameters, 0.1);
    check(euler.state.position == 1.0 && euler.state.velocity == -0.4 && euler.forceEvaluations == 1, "Euler independent one-step oracle");
    const auto verlet = lab::velocityVerletStep(initial, parameters, 0.1);
    check(closeEnough(verlet.state.position, 0.98) && closeEnough(verlet.state.velocity, -0.396) && verlet.forceEvaluations == 2, "Verlet independent one-step oracle");
    const auto rk4 = lab::rungeKutta4Step(initial, parameters, 0.1);
    check(closeEnough(rk4.state.position, 0.9800666666666667) && closeEnough(rk4.state.velocity, -0.3973333333333333) && rk4.forceEvaluations == 4, "RK4 independent polynomial oracle");
}
```

Một bước RK4 ở h=0.1 được đối chiếu với đa thức đã tính tay, không chỉ với một lời gọi RK4 khác.

### Bước 3 — Tách kiểm hội tụ khỏi kiểm năng lượng

Hàm kiểm sau giữ T=2 s cho hội tụ, rồi chạy riêng tới 20 s để kiểm năng lượng dài hạn:

```cpp title="tests/tests.cpp — các phép kiểm không thay thế cho nhau"
void convergenceAndEnergy() {
    for (std::size_t lane = 0; lane < 3; ++lane) {
        const auto coarse = lab::runIntegrator(lab::kDefaultKinds[lane], initial, parameters, 2.0, 0.05);
        const auto fine = lab::runIntegrator(lab::kDefaultKinds[lane], initial, parameters, 2.0, 0.025);
        const double ratio = lab::integratorMetrics(coarse.state, initial, parameters).phaseSpaceError / lab::integratorMetrics(fine.state, initial, parameters).phaseSpaceError;
        const std::array<double, 3> lower{1.7, 3.5, 12.0};
        const std::array<double, 3> upper{2.5, 4.5, 20.0};
        check(ratio > lower[lane] && ratio < upper[lane], "first/second/fourth-order convergence, not just decreasing error");
    }
    const auto euler = lab::runIntegrator(lab::IntegratorKind::explicitEuler, initial, parameters, 20.0, 0.05);
    const double expectedEnergy = 2.0 * std::pow(1.01, 400.0);
    check(closeEnough(lab::oscillatorEnergy(euler.state, parameters), expectedEnergy, 1e-8), "Euler energy follows independent recurrence E0*(1+omega^2*h^2)^N");
    const auto verlet = lab::runIntegrator(lab::IntegratorKind::velocityVerlet, initial, parameters, 20.0, 0.05);
    check(std::abs(lab::integratorMetrics(verlet.state, initial, parameters).relativeEnergyDrift) < 0.01, "Verlet energy bounded in stable regime");
}
```

Các thông báo first/second/fourth-order convergence nói về sai số state ở cùng T. Điều kiện năng lượng của Verlet chỉ áp dụng trong vùng bước thời gian ổn định.

## Ghép các phần lại

Build Starter để xem thí nghiệm bạn vừa viết. Sau đó có thể chạy CTest của **bản final tham khảo**:

```powershell title="Kiểm bộ nghiệm thu tham khảo, chưa phải code Starter"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON -DBUILD_TESTING=ON
cmake --build build --config Debug --target project_23_tests --parallel 2
ctest --test-dir build -C Debug --output-on-failure --timeout 30
cmake --build build --config Release --target project_23_tests --parallel 2
ctest --test-dir build -C Release --output-on-failure --timeout 30
```

Mặc định target tests include final/include. Vì bộ kiểm còn bao gồm benchmark của bài 8, **chưa dùng kết quả CTest này để xác nhận Starter mới học tới bài 7**. Cuối bài 8 sẽ đổi include sang Starter hoàn chỉnh để kiểm chính bài làm của bạn.

Trên Canvas/SDL3, thử cùng initial state với 1/30 rồi 1/60 s tại cùng t=2 s. Với stress preset, Euler có thể vượt giới hạn an toàn; chương trình dừng và báo rõ, không clamp state để giấu phân kỳ. Khối chỉ báo ngoài khung vẫn giữ giá trị vật lý thật trong readout.

Nếu một test sai, ghi cả actual và expected. Không nới tolerance chỉ để test chuyển xanh; kiểm trước xem bạn có đang so cùng thời điểm và đúng đơn vị không.

## Thử làm sai để hiểu đúng

1. Cho mỗi solver chạy cùng số bước nhưng dt khác nhau. Chúng kết thúc ở thời điểm khác nhau, nên bảng error không còn là phép so accuracy công bằng.

2. Tính expected bằng chính runIntegrator rồi so nó với runIntegrator. Test đó kiểm tính lặp lại, chưa kiểm công thức đúng.

3. Dùng assert cho mọi kiểm tra rồi build Release có NDEBUG. Các kiểm tra có thể biến mất. Bộ tests dùng check và trả EXIT_FAILURE tường minh.

## Tự kiểm tra kết quả

- Một bước Euler/Verlet/RK4 khớp expected tính tay.
- Giảm dt cho tỉ lệ sai số gần 2/4/16 ở cùng T và vùng thích hợp.
- Năng lượng Euler khớp công thức lũy thừa độc lập; Verlet không bị mô tả là bảo toàn năng lượng tuyệt đối.
- Invalid state/dt không làm một làn chạy trước; workload vô hạn bị từ chối trước vòng lặp.
- Debug và Release đều thực sự chạy check, không chỉ tạo executable thành công.
