# Cho ba integrator chạy lockstep

## Vấn đề cần giải quyết

Cả ba phương pháp đã chạy được. Giờ ta cần một cuộc so sánh có thể thay đổi cấu hình mà vẫn công bằng: cùng initial state, cùng parameters, cùng fixed dt và cùng step count.

Bài này gom bước chạy thành một hàm thuần và cho người dùng chọn integrator của từng làn khi ứng dụng đang mở. Mặc định vẫn là Euler–Verlet–RK4. Thử cho cả ba làn cùng dùng Euler là một phép kiểm rất tốt: kết quả phải trùng nhau, không chỉ nhìn gần giống.

## Hiểu ý tưởng trước khi viết code

Lockstep không có nghĩa là ba luồng chạy đồng thời. Nó có nghĩa là ở mỗi nhịp, cả ba cùng nhận một h và cùng tiến từ tₙ tới tₙ₊₁. Chúng được phép cho x/v khác nhau vì công thức khác nhau, nhưng không được có đồng hồ hay điều kiện đầu khác nhau.

Một thay đổi k, m, x₀, v₀, dt hoặc solver sẽ bắt đầu **thí nghiệm mới**: reset cả ba state, số bước, số lần tính lực, accumulator và history. Giữ một làn đã chạy 10 giây rồi so với một làn mới về 0 không còn là phép kiểm integrator.

### Bước 1 — Giữ cấu hình riêng với state của từng làn

IntegratorLane, IntegratorRace và makeIntegratorRace đã có trong Starter để các bài trước lưu state. Đọc lại cách khởi tạo: cả ba lane được sao chép từ đúng một initial, chỉ kind khác nhau.

```cpp title="include/lab.hpp — khởi tạo một thí nghiệm chung"
inline IntegratorRace makeIntegratorRace(const OscillatorState& initial, const std::array<IntegratorKind, 3>& kinds = kDefaultKinds) {
    IntegratorRace race;
    race.initial = initial;
    for (std::size_t index = 0; index < race.lanes.size(); ++index) {
        race.lanes[index] = {kinds[index], initial, 0};
    }
    return race;
}
```

Không dùng solver này để tạo initial state cho solver kia. Nghiệm giải tích vẫn nằm ngoài cuộc cập nhật numerical state.

### Bước 2 — Gom bước cập nhật thành hàm lockstep

Thêm stepIntegratorRace vào lab.hpp. Hàm tính đủ ba kết quả trước rồi mới commit. Nếu một bước bị từ chối, cả race giữ nguyên:

```cpp title="include/lab.hpp — cùng dt và commit nguyên khối"
inline bool stepIntegratorRace(IntegratorRace& race, const OscillatorParameters& parameters, double dt) {
    std::array<IntegratorStepResult, 3> results{};
    for (std::size_t index = 0; index < race.lanes.size(); ++index) {
        results[index] = stepIntegrator(race.lanes[index].kind, race.lanes[index].state, parameters, dt);
        if (results[index].forceEvaluations == 0) {
            return false;
        }
    }
    // Chỉ commit khi cả ba kết quả hợp lệ: không làn nào được chạy trước.
    for (std::size_t index = 0; index < race.lanes.size(); ++index) {
        race.lanes[index].state = results[index].state;
        race.lanes[index].forceEvaluations += static_cast<std::size_t>(results[index].forceEvaluations);
    }
    ++race.stepCount;
    return true;
}
```

Trong stepScene, thay vòng lặp riêng của các bài trước bằng lời gọi hàm mới. Đọc bản đầy đủ dưới để không giữ cả hai đường cập nhật:

```cpp title="include/scene.hpp — chỉ một đường đi cho physics"
inline bool stepScene(Scene& scene) {
    if (scene.warning[0] != '\0') {
        return false;
    }
    const double dt = fixedDelta(scene);
    const IntegratorRace before = scene.race;
    if (!stepIntegratorRace(scene.race, scene.parameters, dt)) {
        scene.warning = "Invalid numerical step: all lanes stopped.";
        stopJobs(scene);
        return false;
    }
    scene.beforeLast = before;
    scene.elapsed += dt;
    ++scene.substeps;
    // Không clamp state vật lý để che việc Euler đang phân kỳ.
    for (const auto& lane : scene.race.lanes) {
        if (std::abs(lane.state.position) > 1e6 || std::abs(lane.state.velocity) > 1e6) {
            scene.warning = "Divergence exceeds safety range (1e6). Reset or reduce dt.";
            stopJobs(scene);
            return false;
        }
    }
    return true;
}
```


### Bước 3 — Đổi solver khi đang mở ứng dụng

Thay cycleLane đang là stub trong scene.hpp bằng:

```cpp title="include/scene.hpp — đổi cấu hình rồi reset toàn bộ"
inline void cycleLane(Scene& scene, std::size_t index) {
    if (index < scene.kinds.size()) {
        const auto kind = static_cast<std::size_t>(scene.kinds[index]);
        scene.kinds[index] = kDefaultKinds[(kind + 1) % kDefaultKinds.size()];
        resetExperiment(scene);
    }
}
```

kinds giữ lựa chọn của người dùng; resetExperiment dùng nó để tạo cả ba state mới. Trong main.cpp, thêm các phím 1/2/3:

## Ghép các phần lại

advanceFrame đã dùng planner từ Project 22. Đây là chỗ frameSeconds biến thành một số nguyên bước physics, không phải dt đưa thẳng vào solver:

```cpp title="include/scene.hpp — accumulator quyết định số lần gọi stepScene"
inline void advanceFrame(Scene& scene, double frameSeconds) {
    scene.substeps = 0;
    if (scene.fastRemaining > 0) {
        const int count = std::min(scene.fastRemaining, 128);
        for (int index = 0; index < count; ++index) {
            if (!stepScene(scene)) {
                return;
            }
            --scene.fastRemaining;
        }
        return;
    }
    if (scene.paused) {
        return;
    }
    const auto plan = planFixedSteps(scene.accumulator, frameSeconds, fixedDelta(scene), 32, 0.1);
    scene.accumulator = plan.remainder;
    scene.droppedTime += plan.droppedTime;
    for (int index = 0; index < plan.steps; ++index) {
        if (!stepScene(scene)) {
            return;
        }
    }
}
```

Nhánh fastRemaining vẫn bằng 0 ở bài này; bài 6 mới cho người dùng yêu cầu tua nhanh. Trong nhánh chạy thường, chỉ frame được chấp nhận mới thêm vào accumulator; thời gian bỏ đi được cộng vào droppedTime.

Nhấn N 10 lần với ba phương pháp mặc định: số lần tính lực phải là 10 / 20 / 40. Đổi làn 2 và 3 thành Euler, chạy lại: ba state và ba counter phải trùng nhau. Màu thuộc về **làn**, còn nhãn mới cho biết phương pháp đang chọn.

## Thử làm sai để hiểu đúng

1. Reset chỉ làn vừa đổi solver, giữ hai làn kia đang ở t>0. Bạn sẽ so hai thời điểm khác nhau. Khôi phục resetExperiment cho toàn race.

2. Dùng frameSeconds cho một làn, fixed dt cho hai làn còn lại. Chạy cùng một giây render với FPS khác nhau sẽ làm phép so đổi theo máy.

3. Cố đưa NaN vào state của làn cuối trong test. Nếu hai làn đầu đã được ghi trước khi phát hiện lỗi, lockstep bị phá. Kiểm cả state lẫn stepCount sau bước bị từ chối.

## Tự kiểm tra kết quả

- Ba làn mặc định có cùng elapsed và stepCount; counter tăng 1/2/4 mỗi bước.
- Chọn cùng solver cho ba làn cho cùng numerical state.
- Thay cấu hình reset tất cả, không chỉ làn đang thao tác.
- Khi không phải bỏ thời gian do frame guard, các chuỗi render frame có cùng tổng cho cùng số bước và cùng state.
- Một bước lỗi không commit dở hai làn đầu.
