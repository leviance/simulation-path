# Đổi gốc tọa độ về vị trí camera

## Vấn đề cần giải quyết

Căn phòng đã có chiều sâu. Ta muốn bước sang phải và tiến về phía trước. Việc phải đổi là **vị trí người nhìn**, không phải vị trí từng thanh tường.

Bài này chỉ tịnh tiến camera, chưa xoay. Tách hai việc giúp bạn nhận ra một dấu trừ sai trước khi sin/cos làm hình khó đoán hơn.

## Hiểu ý tưởng trước khi viết code

Một world point mô tả vị trí so với gốc world. Camera cần biết point nằm ở đâu **so với mắt**:

$$
p_{camera}=p_{world}-camera.position.
$$

Ví dụ camera=(1,1.6,2), world point=(3,2,8) thì vector tương đối là (2,0.4,6). Camera sang +X làm X tương đối nhỏ đi, nên vật trôi sang trái trên ảnh. Đây là hệ quả của đổi gốc tọa độ, không phải ta thật sự kéo vật sang trái.

## Viết code từng bước

### Bước 1 — Giữ state riêng cho camera

Trong `lab.hpp`, `FpsCamera` có position, yaw, pitch. Bài này mới dùng position:

```cpp title="include/lab.hpp — đoạn ghép"
struct FpsCamera {
    Vec3 position{0.0, 1.6, 2.0};
    double yaw = 0.0;
    double pitch = 0.0;
};
```

Tên `position` là tọa độ world của mắt. Nó không phải tọa độ screen, không cần nhân aspect ratio hay pixel ratio.

### Bước 2 — Viết phép đổi gốc thành một hàm nhỏ

```cpp title="include/lab.hpp — worldToCameraTranslation"
inline Vec3 worldToCameraTranslation(Vec3 worldPoint, const FpsCamera& camera) {
    return subtract(worldPoint, camera.position);
}
```

Hàm trả một Vec3 mới. Tham số camera là const; room và camera đều không bị thay trong quá trình tính một point.

Không viết `camera.position-worldPoint`: nó quay ngược cả hướng Z, đẩy phần phòng trước mặt ra sau camera.

### Bước 3 — Đưa state vào renderer ở một chỗ

Trước hết thay `activeCamera` trong `scene.hpp`: ở bài 1 nó luôn trả camera mặc định, nên chỉ sửa `scene.camera` chưa đủ làm ảnh thay đổi.

```cpp title="include/scene.hpp — đoạn ghép"
inline FpsCamera activeCamera(const Scene& scene) {
    FpsCamera camera = scene.camera;
    camera.yaw = 0.0;
    camera.pitch = 0.0;
    return camera;
}
```

Ở bước này ta dùng position từ state, còn ép yaw/pitch về 0 để tách translation khỏi rotation. Sau đó thay `viewPoint`, điểm nối giữa geometry và phép chiếu:

```cpp title="include/scene.hpp — viewPoint"
inline Vec3 viewPoint(Vec3 world, const Scene& scene) {
    const FpsCamera camera = activeCamera(scene);
    return worldToCameraTranslation(world, camera);
}
```

Trong `projectRoomSegment`, cả hai endpoint đều đi qua hàm này rồi mới clip/project. Nếu chỉ đổi cube marker mà quên sàn hoặc tường, mỗi phần cảnh sẽ sống trong một hệ khác nhau.

### Bước 4 — Đi thử bằng phím theo world axes

Ở checkpoint 2, mũi tên chỉ là nấc 0.2 unit để kiểm phép trừ. Đây chưa phải hệ WASD theo hướng nhìn:

```cpp title="src/main.cpp — đoạn ghép"
if (event.key.key == SDLK_LEFT) {
    scene.camera.position.x -= 0.2;
}
if (event.key.key == SDLK_RIGHT) {
    scene.camera.position.x += 0.2;
}
if (event.key.key == SDLK_UP) {
    scene.camera.position.z += 0.2;
}
if (event.key.key == SDLK_DOWN) {
    scene.camera.position.z -= 0.2;
}
```

Phải đổi `scene.camera.position`, không tìm rồi trừ 0.2 vào mọi `Segment3`. Main vẫn truyền `worldRoom` const cho drawRoom.

## Thử làm sai để hiểu đúng

1. Đảo phép trừ. Điểm trước mắt có Z âm; cảnh thường trống thay vì “đi ngược”.
2. Cộng position mỗi frame vào room vertices. Đứng yên một lúc rồi reset camera: căn phòng đã trôi khỏi vị trí gốc.
3. Chỉ dùng camera.position.x, bỏ Y/Z. Bạn có thể strafe nhưng độ cao mắt và khoảng cách lại sai dù HUD vẫn thay số.

## Tự kiểm tra kết quả

- Ví dụ (3,2,8) trừ (1,1.6,2) cho (2,0.4,6).
- Camera +X làm vật trôi trái; camera +Z làm vật trước mặt gần hơn.
- Màu, số segment và world endpoints không đổi theo camera.
- Reset phục hồi pose, không cần tái tạo geometry để “sửa” phòng.
