# Đi bộ theo hướng nhìn với WASD

## Vấn đề cần giải quyết

Camera nhìn đúng rồi; giờ W phải đưa người xem đi về phía đang nhìn. A/D phải strafe theo right chứ không luôn cộng X world như bài 2.

Ta cũng cần giữ tốc độ không phụ thuộc số frame hoặc tốc độ key-repeat. Việc đọc input, đổi hướng và nhân dt sẽ được viết thành ba bước riêng.

## Hiểu ý tưởng trước khi viết code

Với input strafe $s$ và advance $a$:

$$
d=r\,s+groundForward\,a.
$$

Digital input chỉ có các nấc −1/0/+1. Khi $d\ne0$, lấy hướng unit rồi cập nhật:

$$
position_{new}=position_{old}+\frac{d}{\lVert d\rVert}\ speed\ \Delta t.
$$

W+D trước chuẩn hóa dài $\sqrt2$; nếu không chia length, đi chéo sẽ nhanh hơn. Walk bỏ pitch khỏi forward nên ngẩng đầu không làm camera bay hoặc bước chậm.

## Viết code từng bước

### Bước 1 — Đọc state sau vòng PollEvent

`SDL_GetKeyboardState` dùng **scancode** để index mảng bool. Ta đọc sau khi đã xử lý hết event trong frame.

```cpp title="src/main.cpp — đoạn ghép"
if ((SDL_GetWindowFlags(window) & SDL_WINDOW_INPUT_FOCUS) != 0) {
    const bool* keys = SDL_GetKeyboardState(nullptr);
    bool down = false;
    bool up = false;
    const bool held = keys[SDL_SCANCODE_A] || keys[SDL_SCANCODE_D] || keys[SDL_SCANCODE_S] || keys[SDL_SCANCODE_W] || down || up;
    if (!held) {
        inputArmed = true;
    }
    if (inputArmed && !scene.paused) {
        movement = lab::makeMoveInput(keys[SDL_SCANCODE_A], keys[SDL_SCANCODE_D], keys[SDL_SCANCODE_S], keys[SDL_SCANCODE_W], down, up);
        if (held) {
            scene.demo = false;
        }
    }
}
```

Hai biến down/up đang false, dành cho bài Fly sau. `inputArmed` ngăn phím giữ từ trước reset/focus change tự khởi động lại: phải thả hết phím rồi mới nhận một phiên mới. Chỉ window có input focus được đọc movement.

Từng `if` tạo axis rõ ràng; A+D triệt tiêu, W+S cũng vậy:

```cpp title="include/lab.hpp — makeMoveInput"
inline MoveInput makeMoveInput(bool left, bool right, bool backward, bool forward, bool down, bool up) {
    MoveInput input;
    if (left) {
        input.strafe -= 1.0;
    }
    if (right) {
        input.strafe += 1.0;
    }
    if (backward) {
        input.advance -= 1.0;
    }
    if (forward) {
        input.advance += 1.0;
    }
    if (down) {
        input.lift -= 1.0;
    }
    if (up) {
        input.lift += 1.0;
    }
    return input;
}
```

### Bước 2 — Đổi input sang direction trong world

```cpp title="include/lab.hpp — movementDirection"
inline Vec3 movementDirection(const FpsCamera& camera, MoveInput input, MovementMode mode) {
    const CameraBasis basis = cameraBasis(camera);
    Vec3 forward = groundForward(camera);
    static_cast<void>(mode);
    Vec3 direction = add(scale(basis.right, input.strafe), scale(forward, input.advance));
    return direction;
}
```

Ta chưa dùng Fly nên mode chưa làm thay đổi hướng. Giữ tên mode ở interface để bài sau thêm nhánh mà không phải đổi cách main gọi hàm.

Đây là nơi input-space trở thành world-space. Không đem strafe/advance trực tiếp cộng vào X/Z nếu camera đã quay yaw.

### Bước 3 — Chuẩn hóa và nhân đúng một lần với dt

```cpp title="include/lab.hpp — advanceCamera"
inline FpsCamera advanceCamera(FpsCamera camera, MoveInput input, MovementMode mode, double speed, double deltaTime) {
    if (!finiteCamera(camera) || !std::isfinite(input.strafe) || !std::isfinite(input.advance) || !std::isfinite(input.lift) || !std::isfinite(speed) || speed < 0.0 || !std::isfinite(deltaTime) || deltaTime <= 0.0) {
        return camera;
    }
    const Vec3 direction = movementDirection(camera, input, mode);
    const double length = magnitude(direction);
    if (!finite(direction) || !std::isfinite(length) || length <= 1e-12) {
        return camera;
    }
    // Digital input: chuẩn hóa tổng hướng world, kể cả forward và lift không vuông góc khi fly.
    const Vec3 unitDirection = scale(direction, 1.0 / length);
    const double distance = speed * std::min(deltaTime, 0.1);
    const Vec3 candidate = add(camera.position, scale(unitDirection, distance));
    if (finite(candidate)) {
        camera.position = candidate;
    }
    return camera;
}
```

Input số lỗi bị bỏ qua. Direction gần zero không được chia length. `std::min(dt,0.1)` chỉ bảo vệ một frame khựng; sau khi chương trình bị treo một giây, ta không cố “bù” toàn bộ bằng một bước lớn.

Đây là digital movement. Nếu sau này thêm joystick analog, cần định nghĩa riêng cách giữ cường độ input nhỏ; không ngầm cho mọi giá trị analog chạy tối đa.

### Bước 4 — Tính dt ở main loop

Trước loop lưu `previousTicks`; mỗi frame tính:

```cpp title="src/main.cpp — đoạn ghép"
const auto now = SDL_GetTicks();
const double deltaTime = std::min(0.1, static_cast<double>(now - previousTicks) / 1000.0);
previousTicks = now;
```

`advanceScene` gọi update đúng một lần với dt này. Không nhân dt thêm vào `movement`, cũng không gọi move một bước nữa ngay trong key-down. IJKL vẫn là nấc góc rời rạc để nhìn quanh.

## Thử làm sai để hiểu đúng

1. Di chuyển trong `SDL_EVENT_KEY_DOWN` thay vì đọc state. Tốc độ phụ thuộc key-repeat của hệ điều hành và có quãng dừng đầu tiên khi giữ phím.
2. Không normalize direction. W+D nhanh hơn W dù cùng speed.
3. Dùng full forward trong Walk. Nhìn lên rồi giữ W làm tăng Y; bạn vô tình viết Fly.
4. Nhân dt ở cả input lẫn update. Quãng đường một giây thay đổi theo số frame.

## Tự kiểm tra kết quả

- 30/60/144 bước trong một giây cho cùng quãng đường 3.5, khi không chạm biên.
- Yaw=90° và W đi theo +X; A/D strafe theo camera right.
- Pitch không đổi tốc độ/hướng đi trên XZ.
- Phím đối nghịch triệt tiêu; mất focus không tiếp tục bước từ một key-up bị thất lạc.

## Bài tập mở rộng

Thử W+D đúng một giây ở yaw=0. Dự đoán mỗi thành phần X/Z tăng $3.5/\sqrt2$ thay vì 3.5, rồi kiểm số đọc. Tổng quãng đường vẫn là 3.5.
