# Chọn và kéo đúng điểm cuối

## Vấn đề cần giải quyết

Bây giờ bạn muốn tự đổi A hoặc B bằng chuột. Không thể gán A bằng vị trí chuột ở mọi motion: khi đó cả bảng chỉ còn một vector bám theo con trỏ, và chương trình không biết bạn định sửa đầu nào.

Một lần kéo phải có lúc bắt đầu, một endpoint được chọn, các lần cập nhật và lúc kết thúc. Bài này bổ sung đúng phần tương tác đó, chưa thêm phép cộng/trừ.

## Hiểu ý tưởng trước khi viết code

Chuột được báo bằng vị trí trên window; A/B được lưu trong world. Muốn chọn điểm, đưa **cả hai** về cùng screen space rồi đo khoảng cách. Trong phạm vi bán kính hit-test 14 pixel logic quanh endpoint, điểm có thể được chọn.

Nếu vùng chọn chồng nhau, ưu tiên điểm gần hơn. Khi khoảng cách bằng nhau, ưu tiên vector đang chọn bằng Tab hoặc danh sách A/B. Nhờ đó, cả hai vẫn chỉnh được khi trùng điểm tại gốc.

Click lệch tâm không nên làm điểm nhảy vào giữa chuột. Ta giữ grabOffset:

$$
G=P_{old}-screenToWorld(S_{down}),\qquad
P_{new}=screenToWorld(S_{move})+G
$$

Kéo từ sát mép chấm và quan sát endpoint có nhảy hay không. Sau đó chọn “Cả hai bằng zero”, chọn B trong danh sách rồi kéo ra: B phải di chuyển, A vẫn ở gốc.

## Viết code từng bước

### Bước 1 — Tìm endpoint trong cùng hệ tọa độ

```cpp title="include/scene.hpp — quy tắc hit-test và trường hợp hòa"
inline int hitTarget(const Scene& scene, Vec2 screen) {
    const double distanceA = distance(worldToScreen(scene.vectorA), screen);
    const double distanceB = distance(worldToScreen(scene.vectorB), screen);
    if (std::min(distanceA, distanceB) > 14.0) {
        return -1;
    }
    if (std::abs(distanceA - distanceB) < 1e-9) {
        return scene.selected;
    }
    if (distanceA < distanceB) {
        return 0;
    }
    return 1;
}
```

distance của hai screen point mang đơn vị pixel logic. Trong core math, distance vẫn chỉ là độ dài hiệu:

```cpp title="include/lab.hpp — đo khoảng cách giữa hai điểm"
inline double distance(Vec2 start, Vec2 end) {
    return length(end - start);
}
```

Đơn vị do đầu vào quyết định. Không dùng world point của A so trực tiếp với pixel chuột.

### Bước 2 — Ghi nhớ vector và chỗ đang nắm

```cpp title="include/scene.hpp — bắt đầu kéo nhưng không sửa tọa độ ngay"
inline bool beginDrag(Scene& scene, Vec2 screen) {
    cancelDrag(scene);
    if (!finite(screen)) {
        return false;
    }
    scene.dragged = hitTarget(scene, screen);
    if (scene.dragged < 0) {
        return false;
    }
    scene.selected = scene.dragged;
    Vec2 endpoint = scene.vectorA;
    if (scene.dragged == 1) {
        endpoint = scene.vectorB;
    }
    scene.grabOffset = endpoint - screenToWorld(screen);
    return true;
}
```

dragged = −1 nghĩa là không kéo gì. selected ghi A/B đang chọn, còn grabOffset chỉ phục vụ lần kéo hiện tại. Click vùng trống trả false, không tạo vector thứ ba.

Main chỉ cho bắt đầu bằng chuột trái khi chưa có thao tác đang giữ. Trước khi gọi beginDrag, nó dùng SDL_ConvertEventToRenderCoordinates để đưa event về bảng 1100×760. Mouse down ở phần letterbox bị từ chối vì không nằm trong bảng.

### Bước 3 — Cập nhật đúng endpoint

```cpp title="include/scene.hpp — đổi chuột về world và cộng grab offset"
inline void moveEndpoint(Scene& scene, Vec2 screen) {
    if (scene.dragged < 0 || !finite(screen)) {
        return;
    }
    const Vec2 endpoint = boundedEndpoint(screenToWorld(screen) + scene.grabOffset);
    if (scene.dragged == 0) {
        scene.vectorA = endpoint;
    } else {
        scene.vectorB = endpoint;
    }
}
```

boundedEndpoint giữ X trong [−4,4], Y trong [−3,3]. Đây là miền thao tác của sản phẩm, không phải định nghĩa vector. Miền này dành đủ chỗ cho các kết quả ±2A và A±B xuất hiện cùng lúc về sau.

Vòng SDL chỉ nhận motion của mouse trùng owner:

```cpp title="src/main.cpp — chỉ motion của mouse đang giữ được sửa endpoint"
if (event.type == SDL_EVENT_MOUSE_MOTION && scene.dragged >= 0 && event.motion.which == owner) {
    if ((event.motion.state & SDL_BUTTON_LMASK) == 0) {
        cancelDrag();
    } else {
        lab::moveEndpoint(scene, {event.motion.x, event.motion.y});
        dirty = true;
    }
}
```

Nếu SDL báo nút trái không còn giữ, hủy drag thay vì kéo tiếp bằng một trạng thái cũ. Native nhận mouse ID; Canvas giữ pointerId tương ứng của browser.

### Bước 4 — Không làm mất mẫu cuối

```cpp title="src/main.cpp — áp dụng endpoint cuối trước khi release"
if (event.type == SDL_EVENT_MOUSE_BUTTON_UP && event.button.button == SDL_BUTTON_LEFT && scene.dragged >= 0 && event.button.which == owner) {
    lab::moveEndpoint(scene, {event.button.x, event.button.y});
    cancelDrag();
    dirty = true;
}
```

Button-up có thể mang vị trí mới hơn motion cuối. Vì thế moveEndpoint chạy trước cancelDrag, rồi mới nhả capture.

Focus loss, hidden, resize, Space, R hoặc chọn preset cũng hủy capture. Chỉ nút trái của đúng owner kết thúc thao tác; một mouse khác hoặc nút phải không được chiếm lần kéo đang có.

## Ghép các phần lại

SDL input → đổi về bảng logic → hitTarget chọn A/B → beginDrag lưu offset → moveEndpoint sửa world state → renderScene dựng ảnh mới.

Trong ứng dụng desktop, Tab đổi selected, mũi tên di chuyển mỗi lần 0.1 world unit; F1–F5 chọn các trường hợp mẫu. Canvas dùng danh sách HTML để chọn A/B, không giữ Tab bên trong vùng vẽ. Các giá trị screen/world dưới Canvas giúp bạn nhìn rõ chỗ đổi đơn vị.

## Thử làm sai để hiểu đúng

1. Gán event.motion.x/y thẳng vào vectorA. Một tọa độ vài trăm pixel bị hiểu thành vài trăm world unit; miền thao tác sẽ liên tục chặn nó ở biên.
2. Bỏ grabOffset. Điểm nhảy vào tâm con trỏ ngay khi kéo từ mép chấm.
3. Chỉ tắt dragged ở button-up mà không áp dụng vị trí event cuối. Thử kéo nhanh rồi thả: endpoint dễ hụt đoạn cuối.
4. Bỏ kiểm tra owner và nút còn giữ. Một pointer khác hoặc motion sau khi mất nút có thể sửa nhầm vector.

## Tự kiểm tra kết quả

- Nhấn vùng trống không thay A/B và không tạo thêm dữ liệu.
- Chỉ endpoint đã chọn di chuyển; click lệch tâm không làm nhảy điểm.
- Khoảng cách 14 px được nhận, lớn hơn biên bị từ chối.
- Trùng A/B vẫn sửa riêng được bằng selected.
- Button-up giữ mẫu cuối; cancel/blur không tự thêm mẫu mới.
- Resize và DPI không làm lệch hit-test; keyboard chỉnh được cả A lẫn B.
