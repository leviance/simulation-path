# Đo độ dài và dựng đầu mũi tên

## Vấn đề cần giải quyết

Hai đoạn màu đã hiện lên, nhưng chúng chưa cho biết rõ chiều đi. Ta cần đầu mũi tên. Để đặt hai cánh đúng hướng, trước hết phải biết hướng của thân đoạn, tách khỏi độ dài của nó.

Cùng lúc, HUD sẽ hiện |A| và |B| để bạn đối chiếu số đo với hình. Đừng nhầm độ dài vector trong world với chiều dài vài pixel của đầu tên.

## Hiểu ý tưởng trước khi viết code

Hai thành phần X/Y là hai cạnh vuông góc. Với v = (3,4), Pythagoras cho độ dài 5:

$$
|v|=\sqrt{v_x^2+v_y^2}
$$

Chia v cho độ dài sẽ cho một hướng dài một đơn vị. Đối với hình mũi tên, ta làm điều đó **sau khi đổi sang screen**: hướng từ start tới end quyết định vị trí hai cánh; đầu tên dài tối đa 14 pixel logic, rộng một nửa 6 pixel.

Một hướng vuông góc với (u_x,u_y) là (−u_y,u_x). Dùng nó để đi sang hai phía từ chân đầu tên. Không cần sin/cos ở project này.

## Viết code từng bước

### Bước 1 — Viết length và phân biệt lengthSquared

```cpp title="include/lab.hpp — bình phương độ dài cho dữ liệu có miền nhỏ"
inline double lengthSquared(Vec2 vector) {
    return vector.x * vector.x + vector.y * vector.y;
}
```

```cpp title="include/lab.hpp — độ lớn Euclid"
inline double length(Vec2 vector) {
    return std::hypot(vector.x, vector.y);
}
```

std::hypot tính cùng đại lượng Pythagoras nhưng tránh bình phương trực tiếp những số quá lớn hoặc quá nhỏ. lengthSquared vẫn hữu ích cho dữ liệu trong miền an toàn; không dùng nó làm nền cho normalize ở mọi giá trị double.

### Bước 2 — Lấy hướng một cách an toàn

```cpp title="include/lab.hpp — normalize không mất hướng ở biên số thực"
inline Vec2 normalize(Vec2 vector) {
    if (!finite(vector)) {
        return {};
    }
    const double largest = std::max(std::abs(vector.x), std::abs(vector.y));
    if (largest == 0.0) {
        return {};
    }
    const Vec2 scaled{vector.x / largest, vector.y / largest};
    const double magnitude = length(scaled);
    return {scaled.x / magnitude, scaled.y / magnitude};
}
```

Đừng bỏ qua phần largest. Ta chia cả X và Y cho cùng một số dương, nên hướng không đổi. Sau bước ấy, thành phần lớn nhất có độ lớn 1, độ dài scaled nằm từ 1 tới căn 2; lần chia tiếp không tràn hoặc hụt về zero.

Ví dụ (3,4) → (0.75,1) → (0.6,0.8). Với vector rất nhỏ hoặc gần giới hạn double, ta vẫn làm đúng chuỗi đó. Chỉ vector zero hoặc đầu vào không hữu hạn trả về (0,0); không dùng một ngưỡng tùy ý để xóa hướng của mọi vector nhỏ.

### Bước 3 — Tính hai cánh đầu tên

```cpp title="include/lab.hpp — hình học đầu mũi tên trong screen space"
inline ArrowHead arrowHead(Vec2 start, Vec2 end) {
    const Vec2 delta = end - start;
    const double screenLength = length(delta);
    if (!std::isfinite(screenLength) || screenLength < 1e-6) {
        return {};
    }
    const Vec2 direction = normalize(delta);
    const Vec2 perpendicular{-direction.y, direction.x};
    const double headLength = std::min(14.0, screenLength * 0.6);
    const double halfWidth = headLength * (6.0 / 14.0);
    const Vec2 base = end - direction * headLength;
    return {base + perpendicular * halfWidth, base - perpendicular * halfWidth, true};
}
```

base lùi từ end theo direction. Cộng/trừ perpendicular × halfWidth tạo hai cánh đối xứng. Với đoạn dài 100 px đi ngang, hai cánh ở (86,6) và (86,−6).

headLength lấy nhỏ hơn giữa 14 và 60% chiều dài đoạn. Nhờ vậy, một đoạn chỉ dài 5 px không mang đầu tên lùi ra sau cả điểm đầu. screenLength cực nhỏ thì không có đầu tên; đây là quyết định rasterization, không phải quy tắc xóa vector world.

### Bước 4 — Ghép thân và hai cánh

```cpp title="include/view.hpp — vẽ mũi tên bằng ba đoạn CPU"
inline void drawArrow(Framebuffer& image, Vec2 start, Vec2 end, std::uint32_t color) {
    if (!finite(start) || !finite(end)) {
        return;
    }
    drawScreenLine(image, start, end, color);
    const ArrowHead head = arrowHead(start, end);
    if (!head.visible) {
        drawHandle(image, end, color);
        return;
    }
    drawScreenLine(image, end, head.leftWing, color);
    drawScreenLine(image, end, head.rightWing, color);
}
```

drawScreenLine vẽ thân, arrowHead tính hai cánh, rồi cùng rasterizer vẽ tiếp. Zero arrow được đánh dấu bằng chấm; không chia cho zero.

## Ghép các phần lại

Phép đo |A| vẫn dùng A trong world. Còn arrowHead nhận start/end đã ở screen, nên các số 14 và 6 mang đơn vị pixel của bảng logic.

Khi SDL thu/phóng cả bảng để vừa window, đầu tên cũng được trình bày theo bảng ấy. “Không đổi theo độ dài vector” không có nghĩa luôn đúng 14 pixel vật lý trên mọi màn hình.

## Thử làm sai để hiểu đúng

1. Dùng end−start mà không chia độ dài khi dựng cánh. Mũi tên dài sẽ có đầu tên rất lớn.
2. Chuẩn hóa bằng cách chia từng thành phần cho chính nó. Hướng bị đổi thành (1,1), còn thành phần zero gây phép chia lỗi.
3. Bỏ giới hạn 60% cho headLength. Thử đoạn dài 5 px: đầu tên có thể vượt về phía sau tail.
4. Bỏ kiểm tra zero ở normalize. Preset zero tạo giá trị không xác định thay vì một chấm an toàn.

## Tự kiểm tra kết quả

- length(3,4) = 5; normalize(3,4) ≈ (0.6,0.8).
- Normalize dùng cùng tỉ lệ cho cả hai thành phần, giữ hướng và chiều.
- Đầu tên đoạn ngang 100 px có hai cánh tại (86,±6).
- Đầu tên ngắn theo đoạn ngắn, zero không tạo NaN.
- Bạn phân biệt được world unit, pixel logic và pixel vật lý của window.
