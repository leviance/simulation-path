# Đọc tọa độ dưới con trỏ

## Vấn đề cần giải quyết

Bạn nhìn được điểm trên bản đồ, nhưng SDL chỉ báo chuột ở một vị trí trong window. Muốn biết người dùng đang trỏ tới world point nào, ta cần đi ngược đường vừa học.

Bài này chỉ thêm HUD tọa độ. Chưa click để đặt điểm: tách hai việc ra sẽ giúp bạn kiểm tra phép đổi nghịch trước khi nó điều khiển dữ liệu.

## Hiểu ý tưởng trước khi viết code

Hoàn tác công thức bài trước: với X, trừ W/2, chia s, cộng tâm camera. Với Y, lấy H/2 trừ screen Y để đổi chiều, chia s, cộng tâm:

$$
x_w = c_x + \frac{x_s-W/2}{s},\qquad
y_w = c_y - \frac{y_s-H/2}{s}
$$

Ở camera mặc định, screen (590,215) phải trở về world (2,1). Giữa window trả về centerWorld, không phải lúc nào cũng (0,0).

## Viết code từng bước

### Bước 1 — Viết screenToWorld bên cạnh chiều thuận

```cpp title="include/lab.hpp — hoàn tác worldToScreen"
[[nodiscard]] Vec2 screenToWorld(Vec2 screen) const {
    return {
        centerWorld.x + (screen.x - viewportPixels.x * 0.5) / scale(),
        centerWorld.y - (screen.y - viewportPixels.y * 0.5) / scale(),
    };
}
```

Hai hàm dùng cùng scale() và viewportPixels. Một bên dùng 55, bên kia dùng 50 sẽ không thể là hai phép nghịch.

### Bước 2 — Đưa input về đúng hệ của ảnh

Mouse event có tọa độ window; renderer còn có logical presentation. Main gọi SDL_ConvertEventToRenderCoordinates trước khi đọc x/y:

```cpp title="src/main.cpp — chuẩn hóa input trước camera"
const bool mouseEvent = event.type == SDL_EVENT_MOUSE_BUTTON_DOWN || event.type == SDL_EVENT_MOUSE_BUTTON_UP || event.type == SDL_EVENT_MOUSE_MOTION || event.type == SDL_EVENT_MOUSE_WHEEL;
if (mouseEvent && !SDL_ConvertEventToRenderCoordinates(renderer, &event)) {
    std::cerr << SDL_GetError() << '\n';
    failed = true;
    running = false;
    break;
}
```

SDL biết window dimensions, render scale và logical presentation. Không nhân thêm DPI sau bước này. Công thức World ↔ Screen chỉ bắt đầu sau khi input đã về đúng hệ của ảnh.

Framebuffer dùng kích thước logic của window; presentation đặt SDL_LOGICAL_PRESENTATION_STRETCH cùng kích thước. Texture xuất lên màn hình HiDPI nhưng world math vẫn thống nhất theo pixel logic.

### Bước 3 — Lưu vị trí chuột, không sửa điểm

```cpp title="src/main.cpp — lưu vị trí chuột từ event đã đổi hệ"
if (event.type == SDL_EVENT_MOUSE_MOTION) {
    scene.cursorScreen = {event.motion.x, event.motion.y};
    dirty = true;
}
```

dirty yêu cầu cập nhật ảnh/nhãn. Không có points.push_back trong handler: P1 vẫn tại (2,1).

### Bước 4 — Hiện số đo trong viewport

```cpp title="include/presentation.hpp — đọc tọa độ con trỏ"
const Vec2 world = scene.camera.screenToWorld(scene.cursorScreen);
std::snprintf(label, sizeof(label), "screen (%.1f, %.1f) | world (%.4f, %.4f)", scene.cursorScreen.x, scene.cursorScreen.y, world.x, world.y);
if (!text(renderer, 12, 60, label)) {
    return false;
}
```

SDL_RenderDebugText chỉ vẽ chữ ASCII nhỏ, phù hợp số và nhãn của bài này; nó không phải hệ thống font tiếng Việt. Hình học vẫn do ảnh CPU vẽ.

## Ghép các phần lại

Mouse event → SDL đổi sang render coordinates → cursorScreen → screenToWorld → HUD. Chiều vẽ: points world → worldToScreen → framebuffer.

Hai luồng gặp nhau ở camera, không gặp nhau ở một công thức DPI tự viết trong mouse handler. Đưa chuột tới điểm xanh, HUD phải đọc gần (2,1); sai lệch nhỏ do bạn chưa đặt đúng tâm pixel.

## Thử làm sai để hiểu đúng

1. Bỏ chia scale trong screenToWorld. Một pixel bị hiểu thành một đơn vị world.
2. Đổi dấu trừ ở Y thành cộng. Chuột đi lên nhưng world Y giảm.
3. Sau SDL_ConvertEventToRenderCoordinates, nhân x/y thêm hai lần trên màn hình 200%. So vị trí đọc với điểm xanh để phát hiện input bị đổi hệ hai lần.

## Tự kiểm tra kết quả

- Giữa window trả về centerWorld.
- (590,215) trở về (2,1) ở camera mặc định.
- P1 không đi theo khi chuột di chuyển.
- screenToWorld(worldToScreen(p)) trở về gần p.
- Bạn phân biệt được window coordinate, screen coordinate của ảnh và world coordinate.
