# Đưa GLSL ra file và phủ kín cửa sổ

## Vấn đề cần giải quyết

Ở Project 34, ta dùng shader để vẽ một mô hình 3D. Lần này, mục tiêu khác hẳn: biến cả cửa sổ thành vùng thử nghiệm. Bạn sửa GLSL trong editor, lưu lại và nhìn thấy màu sắc, hình dạng thay đổi mà không phải build lại C++.

Trước khi đọc hướng dẫn, hãy thử tự dựng một cửa sổ OpenGL có dải màu phủ kín, rồi đưa vertex shader và fragment shader ra hai file riêng. Bản cuối sẽ có bốn hiệu ứng trong cùng một ứng dụng: gradient, vòng tròn, Mandelbrot và noise. Bài đầu chỉ cần hoàn thành nền móng: đọc được file và vẽ đúng dải màu tĩnh.

Bạn cần kiến thức tạo SDL window, OpenGL context và nạp hàm OpenGL từ Project 33–34. Starter đã có các phần đó trong shader_application.hpp và gl_api.hpp. Hãy mở chúng trước khi chạy; không cần chép lại mesh loader hay camera vì ta không vẽ mô hình 3D ở đây.

Toàn project dự kiến 28–38 giờ: khoảng 6–8 giờ đọc và thử công thức, 17–23 giờ tự viết, 5–7 giờ kiểm chứng và làm bài tập. Thời gian cài công cụ, tải SDL và chờ build không tính vào các mốc này. Đây là gợi ý để chia buổi học, không phải thang chấm tốc độ học của bạn.

## Hiểu ý tưởng trước khi viết code

Fragment shader cần chạy trên mọi pixel. Ta vẫn gửi một tam giác cho GPU, nhưng ba đỉnh của nó nằm ở NDC (-1,-1), (3,-1), (-1,3). Tam giác lớn hơn cửa sổ; sau clipping, nó phủ trọn hình vuông NDC từ -1 đến 1. Không cần vertex buffer vì vertex shader lấy vị trí theo gl_VertexID.

Đường đi của một frame là: đọc hai file GLSL → compile/link → bind program → vẽ tam giác → fragment shader tính màu từng pixel. Bài này đọc file một lần lúc khởi động, chưa đọc lại khi bạn bấm Save.

Canvas dùng công thức của hiệu ứng hoàn chỉnh để bạn xem trước. Nó tính màu bằng TypeScript/Canvas 2D, không thực thi GLSL trong editor. Bản C++ tải về mới gọi compiler thật của driver.

## Viết code từng bước

### Bước 1 — Bắt đầu từ ứng dụng đã chạy được

```cpp title="src/main.cpp — điểm vào chương trình"
#include "shader_application.hpp"

int main(int argc, char** argv) {
    return lab::runShaderApplication(argc, argv);
}
```

main ngắn vì công việc cụ thể nằm trong các file có tên rõ ràng: shader_application.hpp quản lý cửa sổ và event loop; shader_renderer.hpp quản lý program/VAO; shader_files.hpp đọc file. Khi học một thay đổi, ta mở đúng file đó thay vì tìm giữa một main.cpp khổng lồ.

Chạy starter trước. Bạn sẽ thấy gradient nhúng sẵn trong shader_defaults.hpp. Đây là bản dự phòng: nếu file ngoài hỏng, chương trình vẫn có hình để hiển thị cùng thông báo lỗi.

### Bước 2 — Tạo tam giác phủ toàn cửa sổ

```glsl title="shaders/lab.vert — ba đỉnh không cần vertex buffer"
#version 330 core

void main() {
    vec2 positions[3] = vec2[3](vec2(-1.0, -1.0), vec2(3.0, -1.0), vec2(-1.0, 3.0));
    gl_Position = vec4(positions[gl_VertexID], 0.0, 1.0);
}
```

gl_VertexID lần lượt nhận 0, 1, 2 từ draw call. Mỗi lượt lấy một phần tử trong positions. w bằng 1 nên phép chia perspective không đổi x/y. Core profile vẫn yêu cầu bind VAO, dù VAO này không có attribute nào.

### Bước 3 — Giữ source và tên file đi cùng nhau

```cpp title="include/pipeline.hpp — source của hai shader"
struct ShaderSources {
    std::string vertex;
    std::string fragment;
    std::string vertexLabel{"embedded.vert"};
    std::string fragmentLabel{"embedded.frag"};
};
```

vertex/fragment chứa văn bản; vertexLabel/fragmentLabel chứa tên file để báo lỗi. Tên file không phải source code: nó giúp ta biết lỗi đến từ đâu khi driver chỉ trả về số dòng hoặc mã nguồn số 0.

### Bước 4 — Đọc file có giới hạn, không cập nhật nửa chừng

```cpp title="include/shader_files.hpp — đọc văn bản shader"
inline bool readTextFile(const std::filesystem::path& path, std::string& result, std::string& diagnostics, std::size_t maximumBytes = 1024 * 1024) {
    std::ifstream input(path, std::ios::binary | std::ios::ate);
    if (!input) {
        diagnostics = "Cannot open shader file: " + shaderPathText(path);
        return false;
    }
    const auto length = input.tellg();
    if (length <= 0 || std::uintmax_t(length) > maximumBytes) {
        diagnostics = "Empty, unreadable or oversized shader file: " + shaderPathText(path);
        return false;
    }
    std::string temporary(std::size_t(length), '\0');
    input.seekg(0);
    input.read(temporary.data(), std::streamsize(temporary.size()));
    if (!input || std::size_t(input.gcount()) != temporary.size() || temporary.find('\0') != std::string::npos) {
        diagnostics = "Incomplete read or embedded NUL in shader: " + shaderPathText(path);
        return false;
    }
    if (temporary.starts_with("\xEF\xBB\xBF"))
        temporary.erase(0, 3);
    result = std::move(temporary);
    diagnostics.clear();
    return true;
}
```

ios::ate đặt con trỏ ở cuối để lấy kích thước trước khi cấp bộ nhớ; seekg(0) đưa nó về đầu để đọc. Mức 1 MiB là giới hạn của ứng dụng, không phải giới hạn GLSL. temporary giữ kết quả tạm: chỉ khi đọc đủ byte và không có NUL, ta mới chuyển nó sang result.

Shader là văn bản UTF-8. Nếu editor thêm BOM, ta bỏ ba byte BOM trước khi đưa source cho driver. Binary mode giúp giữ nguyên line ending.

### Bước 5 — Tính màu từ vị trí pixel

```glsl title="shaders/gradient.frag — gradient đầu tiên"
#version 330 core
uniform float uTime;
uniform vec2 uResolution;
uniform vec2 uMouse;
uniform float uZoom;
out vec4 fragColor;

const float SPEED = 0.65;

void main() {
    vec2 uv = gl_FragCoord.xy / max(uResolution, vec2(1.0));
    fragColor = vec4(uv.x, uv.y, 0.3, 1.0);
}
```

gl_FragCoord.xy là vị trí tâm pixel trong framebuffer, gốc dưới trái. Chia cho uResolution đưa vị trí về khoảng xấp xỉ 0–1. Chỉ nhìn dải màu theo hai trục, ta đã kiểm được shader có phủ đủ cửa sổ và có đúng chiều hay không.

## Ghép các phần lại

Trong thư mục project giải nén, dùng CMake 3.24 trở lên và compiler hỗ trợ C++20:

```bash title="Terminal — starter và checkpoint 1"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_35_starter project_35_checkpoint_1 --parallel 2
```

Trên Windows, chạy build/Debug/project_35_checkpoint_1.exe. Với generator một cấu hình, executable nằm trực tiếp trong build. CMake tự lấy SDL 3.4.8 khi chưa có bản SDL được chỉ định.

Terminal in SHADER DIRECTORY: kèm đường dẫn thực sự đang dùng. Trong lúc học, đó là checkpoints/01/shaders. Mỗi executable còn có thư mục shader dự phòng riêng cạnh nó; các target không chép đè shader của nhau khi build song song. Có thể chỉ rõ thư mục bằng --shader-dir.

Đổi màu trong gradient.frag rồi khởi động lại executable. Chỉ sửa file shader, không build lại C++. Muốn xem bản hoàn chỉnh ngay, build project_35_final; các bài tiếp theo sẽ giải thích lần lượt những gì bản đó làm thêm.

## Thử làm sai để hiểu đúng

1. Đổi tên gradient.frag rồi chạy lại. Terminal phải báo đúng file không mở được; gradient dự phòng vẫn xuất hiện. Khôi phục tên trước khi thử tiếp.
2. Chạy executable từ working directory khác. Đường source CMake truyền vào không phụ thuộc nơi terminal đang đứng.
3. Bỏ dấu chấm phẩy trong gradient.frag. File vẫn đọc được nhưng compile thất bại: lỗi I/O và lỗi GLSL là hai việc khác nhau.

Nếu đổi file mà hình không đổi, kiểm tra SHADER DIRECTORY trước. Có thể bạn đang sửa final/shaders nhưng chạy checkpoint 1.
