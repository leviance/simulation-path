# Mandelbrot trong fragment shader

## Vấn đề cần giải quyết

Gradient và circle cho thấy mỗi pixel có thể tự tính màu. Bài này dùng cùng cách làm cho một hình có cấu trúc phức tạp hơn: Mandelbrot. Không cần gửi hàng nghìn đỉnh; mỗi fragment lặp một công thức để quyết định màu của mình.

Ta thêm effect thứ ba mà không đổi renderer, watcher hay cơ chế last-good. Đó là lợi ích của việc giữ interface uniform ổn định giữa các shader.

## Hiểu ý tưởng trước khi viết code

Mỗi pixel được ánh xạ thành một số phức c. Bắt đầu z bằng 0, rồi lặp z mới = z² + c. Với z = x + iy, bình phương cho phần thực x² - y² và phần ảo 2xy; vec2 đủ để lưu chúng.

Nếu độ lớn z vượt 2, điểm đã thoát. Ta kiểm bình phương độ lớn vượt 4 để không phải lấy căn trong mỗi vòng. Nếu chưa thoát sau 128 lượt, shader tô tối. Đây là giới hạn tính toán của bản demo, không phải chứng minh điểm chắc chắn thuộc tập Mandelbrot.

Time chỉ đổi palette, không đổi phép lặp. Vì thế khi chạy time, hình biên giữ nguyên còn màu bên ngoài chuyển động. Mouse dịch miền c và zoom thu hẹp miền khảo sát quanh tâm đã chọn.

## Viết code từng bước

### Bước 1 — Ánh xạ pixel và viết vòng lặp hữu hạn

```glsl title="shaders/mandelbrot.frag — Mandelbrot hoàn chỉnh"
#version 330 core
uniform float uTime;
uniform vec2 uResolution;
uniform vec2 uMouse;
uniform float uZoom;
out vec4 fragColor;

const float SPEED = 0.12;

void main() {
    vec2 uv = gl_FragCoord.xy / max(uResolution, vec2(1.0));
    vec2 p = (2.0 * gl_FragCoord.xy - uResolution) / min(uResolution.x, uResolution.y);
    vec2 mouse = uMouse / uResolution - 0.5;
    vec2 c = vec2(-0.60, 0.0) + p * (1.35 / uZoom) + mouse * vec2(0.70, 0.50);
    vec2 z = vec2(0.0);
    int escaped = 0;
    for (int iteration = 0; iteration < 128; ++iteration) {
        z = vec2(z.x * z.x - z.y * z.y, 2.0 * z.x * z.y) + c;
        if (dot(z, z) > 4.0) { escaped = iteration + 1; break; }
    }
    vec3 color = vec3(0.012, 0.018, 0.045);
    if (escaped > 0) {
        float smoothCount = float(escaped) + 1.0 - log2(max(0.001, log2(length(z))));
        float phase = 0.035 * smoothCount + uTime * SPEED;
        color = 0.5 + 0.5 * cos(6.2831853 * (phase + vec3(0.0, 0.18, 0.39)));
        color *= 0.45 + 0.55 * (1.0 - exp(-float(escaped) * 0.08));
    }
    fragColor = vec4(color, 1.0);
}
```

p đã sửa aspect ratio giống circle. Tâm (-0.60,0) đặt hình ở vị trí dễ xem; 1.35/uZoom quyết định phạm vi miền phức. Mouse chuẩn hóa được trừ 0.5 để vị trí giữa cửa sổ không dịch hình.

Biểu thức vec2 ở vế phải dùng x/y cũ cùng lúc. Nếu tách hai phép gán và cập nhật z.x trước, rồi dùng z.x mới để tính z.y, bạn đã đổi công thức. Đây là lỗi rất dễ gặp khi chuyển giữa GLSL và C++.

escaped lưu số lượt lặp tại lúc thoát. Giới hạn 128 giúp mọi fragment kết thúc; không viết vòng while không có chặn trên chỉ để “vẽ chính xác hơn”.

### Bước 2 — Tô màu mà không thành từng bậc quá rõ

Chỉ dùng escaped nguyên để tô màu sẽ tạo các dải rời. smoothCount dùng độ lớn z sau khi thoát để nội suy một giá trị liên tục hơn, rồi đưa nó vào cosine palette. Hai lớp log2 chỉ chạy trong nhánh đã thoát; max giữ đối số lớp ngoài có cận dưới.

SPEED điều khiển tốc độ palette. Tăng SPEED không tăng số lần lặp và không làm zoom sâu hơn. Với dữ liệu float/OpenGL 3.3 và giới hạn zoom của project, đây là công cụ học công thức, không phải trình khám phá fractal chính xác tùy ý.

### Bước 3 — Viết reference CPU để kiểm ý tưởng

```cpp title="include/shader_effects.hpp — phép lặp đối chiếu trên CPU"
inline MandelbrotOrbit mandelbrotOrbit(double cx, double cy) {
    MandelbrotOrbit orbit{};
    for (int iteration = 0; iteration < 128; ++iteration) {
        const double nextX = orbit.x * orbit.x - orbit.y * orbit.y + cx;
        orbit.y = 2 * orbit.x * orbit.y + cy;
        orbit.x = nextX;
        if (orbit.x * orbit.x + orbit.y * orbit.y > 4) {
            orbit.escaped = iteration + 1;
            break;
        }
    }
    return orbit;
}
```

nextX giữ phần thực mới trong khi y vẫn được tính bằng x/y cũ. Cấu trúc MandelbrotOrbit trả cả số lượt thoát và z cuối để reference tính màu giống shader.

Các điểm dễ kiểm bằng tay: c = 0 luôn cho z = 0; c = -1 luân phiên 0 và -1; c = 2 đi 0 → 2 → 6 nên thoát ở lượt 2; c = 3 thoát ngay lượt 1. Đây là mốc độc lập trước khi tin vào một bức ảnh fractal trông có vẻ đúng.

## Thử làm sai để hiểu đúng

1. Cập nhật x trước rồi dùng x mới trong công thức y ở bản CPU thử: các điểm kiểm bằng tay sẽ lộ sự khác biệt.
2. Thay điều kiện lớn hơn 4 bằng lớn hơn 2: bạn đã đổi ngưỡng bình phương, không chỉ đổi cách viết tương đương.
3. Giảm giới hạn lặp xuống 16 trong GLSL: vùng chưa thoát bị tô tối nhiều hơn; đừng coi toàn bộ vùng tối là tập Mandelbrot đã được xác định chính xác.

Khôi phục shader và reference chuẩn trước khi chạy verifier của bản final: verifier đối chiếu đúng công thức và giới hạn 128, không tự hiểu mọi biến thể bạn viết.
