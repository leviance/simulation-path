# Tự reload sau khi file đã ổn định

## Vấn đề cần giải quyết

F5 đã giúp thử shader mà không restart. Bây giờ ta muốn Save trong editor là ứng dụng tự đọc lại. Tuy nhiên, editor có thể ghi một file qua nhiều bước: cắt nội dung cũ, ghi nội dung mới hoặc đổi tên file tạm.

Nếu compile ngay khi thấy một thay đổi, ta có thể đọc trúng file chưa ghi xong. Nếu compile lại mỗi frame khi file vẫn hỏng, terminal sẽ ngập lỗi và ứng dụng bị khựng.

## Hiểu ý tưởng trước khi viết code

Watcher của project là polling nhẹ: cứ khoảng 50 ms hỏi trạng thái hai file. Một stamp gồm trạng thái tồn tại/truy cập, kích thước và last_write_time. So cả kích thước giúp phát hiện một số thay đổi không làm timestamp khác đi; đây không phải watcher tuyệt đối cho mọi filesystem. F5 vẫn có để buộc đọc lại.

Khi stamp đổi, ta ghi thời điểm và đánh dấu pending. Chỉ sau ít nhất 140 ms không có thay đổi mới, watcher mới yêu cầu một lần reload. Đây là debounce, không phải sleep 140 ms: event loop vẫn tiếp tục vẽ và nhận input.

Canvas phân biệt bản đang gõ, bản đã lưu và bản đang chạy. Bật tự thử, sửa SPEED rồi chờ nhưng chưa bấm Lưu: ảnh không đổi. Chỉ bản đã lưu mới đi qua debounce.

## Viết code từng bước

### Bước 1 — Mô tả trạng thái watcher

```cpp title="include/shader_files.hpp — dữ liệu theo dõi file"
struct ShaderWatchState {
    bool initialized{}, pending{};
    ShaderFileStamps observed{};
    std::uint64_t changedAtMilliseconds{};
};
```

initialized giúp lần đầu chỉ đặt mốc so sánh, không coi đó là một lần Save. observed là cặp stamp mới nhất; pending cho biết đang đợi chúng ổn định. Không dùng activeFingerprint làm stamp vì đọc/hash toàn file mỗi frame không cần thiết.

### Bước 2 — Quyết định khi nào được reload

```cpp title="include/shader_files.hpp — debounce không chặn event loop"
inline bool updateShaderWatch(ShaderWatchState& state, const ShaderFileStamps& stamps, std::uint64_t now, std::uint64_t debounce = 140) {
    if (!state.initialized) {
        state = {true, false, stamps, now};
        return false;
    }
    if (stamps != state.observed || now < state.changedAtMilliseconds) {
        state.observed = stamps;
        state.pending = true;
        state.changedAtMilliseconds = now;
        return false;
    }
    if (!state.pending || now - state.changedAtMilliseconds < debounce)
        return false;
    state.pending = false;
    return true;
}
```

Nếu stamp đổi, đồng hồ chờ được bắt đầu lại. Nếu chưa pending hoặc chưa đủ thời gian, trả false ngay. Khi đủ thời gian, xóa pending rồi trả true đúng một lần.

now nhỏ hơn changedAtMilliseconds là trường hợp đồng hồ bị lùi trong test hoặc dữ liệu đầu vào không còn cùng mốc. Ta đặt lại mốc thay vì để phép trừ unsigned thành một số rất lớn.

shaderFileStamp dùng các overload filesystem có error_code để phân biệt missing và inaccessible. Khi file bị xóa rồi tạo lại, stamp thay đổi; ứng dụng sẽ thử lại sau khi ổn định. File hỏng nhưng không thay đổi sẽ không bị thử lại liên tục.

### Bước 3 — F5 và auto reload đi chung một đường

```cpp title="include/shader_application.hpp — tiêu thụ đúng lần thay đổi đã đọc"
            if (reloadRequested) {
                const auto beforeRead = readShaderFileStamps(shaderDirectory, scene.requestedEffect);
                reloadFromDisk(gl, renderer, shaderDirectory, scene.requestedEffect);
                logOffset = 0;
                // Consume this attempt, not a newer save that may happen while
                // the driver compiles. That newer stamp must still be noticed.
                watcher = {};
                updateShaderWatch(watcher, beforeRead, SDL_GetTicks());
            }
```

Ta chụp beforeRead trước khi đọc/compile, rồi dùng stamp đó làm mốc watcher. Nếu editor Save thêm trong lúc driver đang compile, lần quét sau vẫn thấy stamp mới; không nuốt mất lần Save ấy.

F5 cũng đặt cùng reloadRequested. Sau lần thử thủ công, watcher coi phiên bản vừa đọc đã được xử lý, tránh compile trùng thêm một lần do pending cũ.

## Ghép các phần lại

```bash title="Terminal — checkpoint 5"
cmake --build build --config Debug --target project_35_checkpoint_5 --parallel 2
./build/Debug/project_35_checkpoint_5.exe
```

Auto reload mặc định bật trong C++; phím A bật/tắt, F5 luôn thử thủ công. Sửa gradient.frag tại thư mục terminal in ra, Save và quan sát dải màu đổi. Chưa có time animation ở checkpoint này, nên đổi màu là phép thử dễ thấy nhất.

Đừng coi 140 ms là lời hứa “Save xong đúng 140 ms có hình”. Polling, thời gian compile/link và lịch hệ điều hành đều cộng thêm độ trễ.

## Thử làm sai để hiểu đúng

1. Save liên tiếp vài lần trong một khoảng ngắn: watcher phải chờ lần thay đổi cuối.
2. Để shader lỗi nhưng không Save thêm: ứng dụng báo một lần thử, không tạo retry storm.
3. Xóa fragment rồi tạo lại bằng bản đúng: chương trình phải phục hồi, không cần restart.
4. Tắt A, Save: ảnh chưa đổi; bấm F5 để buộc đọc lại.

Trong Canvas, gõ chưa lưu, lưu rồi thử ngay F5 và chờ hơn 140 ms: không được tự sinh thêm lần thử trùng. Đây là mô hình của hành vi watcher, không phải truy cập filesystem từ trình duyệt.
