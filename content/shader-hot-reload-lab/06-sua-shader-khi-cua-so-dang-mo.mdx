# Sửa shader mà không đóng cửa sổ

## Vấn đề cần giải quyết

Muốn thử sửa màu phần sàn nằm trong nắng, bạn có thể đóng ứng dụng và chạy lại, nhưng lúc ấy góc nhìn dùng để so sánh đã mất. Ta cần sửa trực tiếp file vật liệu trong khi vẫn nhìn được cùng một mép bóng, kể cả khi lần sửa đầu tiên viết sai.

## Hiểu ý tưởng trước khi viết code

C++ giữ riêng hai thứ: trạng thái phòng (lá, hộp, camera) và program OpenGL. Khi lưu GLSL, ứng dụng dựng một program thử bên cạnh bản đang vẽ. Driver phải biên dịch được cả hai stage, liên kết được chúng và xác nhận tên/kiểu uniform còn hoạt động. Chỉ sau đó mới thay program. Đây cũng là phần mang sang Project 36; ta không viết một compiler GLSL trong trình duyệt.

## Viết code từng bước

### Bước 1. Tìm đúng cặp file để sửa

Mở thư mục in sau chữ Shaders trong terminal của bản work. Giữ nguyên phòng rồi sửa một hệ số màu của ánh nắng trong room.frag. Nếu một trong hai file đọc lỗi hoặc đang rỗng, hàm dưới đây giữ program cũ; đừng sửa nhầm một bản .frag trong final hoặc checkpoint khác.

{/* snippet include/shader_application.hpp#reload-material */}

```cpp title="include/shader_application.hpp — Tìm đúng cặp file để sửa"
inline bool reloadMaterial(GlApi& gl, RoomProgram& material, const std::filesystem::path& directory) {
    ShaderSources candidate{};
    std::string error;
    if (readShaderFiles(directory, candidate, error)) {
        return material.replace(gl, candidate);
    }

    ++material.reload.attempts;
    material.reload.lastReloadSucceeded = false;
    material.reload.diagnostics = error;
    return false;
}
```

### Bước 3. Đừng biên dịch một file đang ghi dở

Editor có thể lưu bằng cách đổi tên file tạm. Watcher quan sát kích thước và thời điểm sửa; chỉ khi file đã ổn định mới thử một lần. Một lần lưu sai không được gây ra hàng trăm lần compile liên tục lúc chương trình vẫn đang vẽ.

{/* snippet include/shader_files.hpp#debounce */}

```cpp title="include/shader_files.hpp — Đừng biên dịch một file đang ghi dở"
inline bool updateShaderWatch(ShaderWatchState& state, const ShaderFileStamps& stamps, std::uint64_t now, std::uint64_t debounce = 140) {
    if (!state.initialized) {
        state = {true, false, stamps, now};
        return false;
    }
    if (stamps != state.observed || now < state.changedAtMilliseconds) {
        state.observed = stamps;
        state.pending = true;
        state.changedAtMilliseconds = now;
        return false;
    }
    if (!state.pending || now - state.changedAtMilliseconds < debounce)
        return false;
    state.pending = false;
    return true;
}
```

## Thử làm sai để hiểu đúng

Bỏ một dấu chấm phẩy trong room.frag. Giữ bản sai tại chỗ đủ lâu để đọc file và stage trong log; cảnh vẫn vẽ được bằng program cũ. Khôi phục dấu rồi lưu. Lần sau thử cho một stage nhận vec2 trong khi stage kia gửi vec3: lỗi bây giờ đến khi link, không phải lỗi cú pháp.

## Tự kiểm tra kết quả

Bản sửa hợp lệ làm màu thay đổi; bản lỗi không làm mất hình hoặc reset camera. Sau khi sửa lại, generation tăng. Chỉ xoay lá hoặc nhấn H không tạo program mới.
