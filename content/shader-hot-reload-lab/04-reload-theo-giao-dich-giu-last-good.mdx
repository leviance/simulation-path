# Thử bản mới, giữ bản tốt gần nhất

## Vấn đề cần giải quyết

Từ bài này, bạn không cần đóng cửa sổ mỗi lần đổi shader. Bấm F5 để đọc lại file và thử bản mới ngay trong ứng dụng.

Nhưng có một yêu cầu quan trọng hơn tốc độ reload: gõ sai GLSL không được làm mất program đang vẽ. Nếu xóa program cũ trước rồi mới compile bản mới, một dấu chấm phẩy bị thiếu cũng đủ biến cửa sổ thành màn hình đen.

## Hiểu ý tưởng trước khi viết code

Ta giữ hai đối tượng riêng: active program đang dùng và candidate đang thử. Chỉ khi compile, link và kiểm interface đều thành công, candidate mới trở thành active. Nếu bất kỳ bước nào thất bại, chỉ hủy candidate.

Đây là một transaction nhỏ: chuẩn bị → kiểm tra → commit. “Last-good” nghĩa là program tốt gần nhất, không phải ảnh chụp màn hình. Về sau khi time tiếp tục chạy, hình cũ vẫn chuyển động dù candidate bị lỗi.

Trong Canvas, hãy thử lỗi rồi nhìn Program generation và Reload attempts. attempts tăng mỗi lần thử; generation chỉ tăng khi mẫu mới được áp dụng. Các lỗi ở đây được mô phỏng rõ ràng, không thay thế log driver của bản C++.

## Viết code từng bước

### Bước 1 — Đổi program sau khi candidate đã qua mọi kiểm tra

```cpp title="include/shader_renderer.hpp — transaction reload"
    bool reload(GlApi& gl, const ShaderSources& sources, std::size_t effect, std::string& diagnostics, ProgramBuildAudit* audit = nullptr) {
        ProgramCandidate candidate{};
        const auto fingerprint = fingerprintShaderSources(sources);
        if (!buildProgramCandidate(gl, sources, candidate, diagnostics, audit)) {
            recordReloadAttempt(reloadState, fingerprint, effect, false, diagnostics);
            return false;
        }
        const GLuint previousProgram = activeProgram;
        activeProgram = std::exchange(candidate.program, 0);
        locations = candidate.locations;
        // A currently bound old program is only flagged for deletion. Bind
        // the replacement first so deleting previousProgram really releases it.
        gl.UseProgram(activeProgram);
        if (previousProgram)
            gl.DeleteProgram(previousProgram);
        diagnostics = "Reload OK: " + sources.fragmentLabel;
        recordReloadAttempt(reloadState, fingerprint, effect, true, diagnostics);
        return true;
    }
```

buildProgramCandidate dùng lại các hàm đã học. Nhánh thất bại không sửa activeProgram hay locations. Nhánh thành công mới lấy ID bằng std::exchange: candidate.program trở thành 0, còn renderer nhận quyền sở hữu ID đó.

previousProgram giữ ID cũ để hủy sau khi đổi sang bản mới. Ta gọi UseProgram(activeProgram) trước DeleteProgram(previousProgram): OpenGL chỉ đánh dấu xóa một program còn đang bind, nên bind bản mới trước giúp giải phóng bản cũ ngay.

locations cũng được thay cùng program. Chỉ thay ID mà giữ locations cũ là lỗi khó thấy: vị trí uniform có thể khác sau mỗi lần link.

### Bước 2 — Tách số lần thử khỏi số bản thành công

```cpp title="include/pipeline.hpp — ghi kết quả reload"
inline void recordReloadAttempt(ReloadState& state, std::uint64_t fingerprint, std::size_t effect, bool succeeded, std::string diagnostics) {
    ++state.attempts;
    state.candidateFingerprint = fingerprint;
    state.lastReloadSucceeded = succeeded;
    state.diagnostics = std::move(diagnostics);
    if (succeeded) {
        ++state.generation;
        state.activeFingerprint = fingerprint;
        state.activeEffect = effect;
    }
}
```

attempts luôn tăng, kể cả đọc file/compile/link thất bại. generation, activeFingerprint và activeEffect chỉ đổi trong nhánh succeeded. Fingerprint nhận diện nội dung hai shader, không phải bằng chứng rằng shader đã compile đúng và cũng không phải hash bảo mật.

Tham số effect chỉ được ghi nhận khi commit. Nếu bạn đang xem gradient rồi thử chuyển sang một shader hỏng, ảnh vẫn là gradient; giao diện phải phân biệt hiệu ứng đang yêu cầu với hiệu ứng thực sự đang chạy.

### Bước 3 — Nối phím F5 vào cùng một đường reload

shader_input.hpp chuyển F5 thành cờ reload. shader_application.hpp xử lý cờ sau khi đọc event, gọi reloadFromDisk; hàm này đọc cả hai file rồi chuyển ShaderSources cho renderer.reload. Không đặt logic compile riêng trong từng nhánh bàn phím.

F5 không khởi tạo lại ShaderScene: time, mouse, zoom và trạng thái pause nằm ngoài renderer nên không bị reset khi program thay đổi.

Tiếp theo bỏ dấu chấm phẩy, lưu, F5. Terminal phải in lỗi còn dải màu cũ vẫn hiện. Sửa lại và F5 lần nữa: chương trình phải áp dụng được bản tốt mà không restart.

## Thử làm sai để hiểu đúng

1. Cố ý đặt DeleteProgram trước buildProgramCandidate trong bản thử riêng: bạn sẽ thấy vì sao thứ tự transaction quan trọng. Sau đó khôi phục source chuẩn.
2. Thử nhiều candidate lỗi liên tiếp. attempts tăng; active fingerprint và generation không đổi.
3. Xóa file rồi F5: lỗi I/O cũng phải giữ last-good, không chỉ lỗi compile.

Khi so hình trước/sau một lần lỗi ở các bài có animation, hãy pause tại cùng time trước. So hai frame ở hai thời điểm khác nhau không kiểm chứng được việc giữ nguyên program.

## Tự kiểm tra kết quả

- [ ] F5 đọc lại file đã lưu, không build lại executable.
- [ ] Candidate lỗi không thay active ID, locations hoặc metadata đã commit.
- [ ] Candidate tốt cập nhật cả program lẫn locations.
- [ ] Shader/program tạm được hủy ở cả nhánh thành công và thất bại.
- [ ] Sửa lỗi rồi F5 tiếp được mà không đóng cửa sổ.
