# Compile từng shader và đọc lỗi đúng stage

## Vấn đề cần giải quyết

Bạn vừa sửa một công thức màu, nhưng hình không đổi. Có thể bạn quên Save, sửa nhầm file hoặc shader không compile được. Nếu chương trình chỉ in “shader error”, bạn vẫn chưa biết phải sửa ở đâu.

Bài này giữ nguyên gradient. Việc mới là viết hàm compile có trách nhiệm rõ ràng: thành công thì trả về shader object; thất bại thì giữ log driver, ghi rõ vertex/fragment và tên file, rồi hủy object không dùng được.

## Hiểu ý tưởng trước khi viết code

Compile kiểm tra riêng từng stage. Vertex shader hợp lệ chưa chắc ghép được với fragment shader; việc ghép đó gọi là link, sẽ học ở bài 03.

GL_COMPILE_STATUS quyết định thành công/thất bại, còn info log giúp giải thích nguyên nhân. Đừng lấy “log rỗng” làm điều kiện thành công: driver có thể trả warning khi thành công, hoặc không có lời giải thích khi thất bại.

Nút thử lỗi trong Canvas chỉ minh họa việc candidate bị từ chối và giữ hình cũ, không phải kết quả compiler. Muốn xem số dòng và log thật, hãy sửa file rồi chạy checkpoint C++.

## Viết code từng bước

### Bước 1 — Lấy log từ shader object

```cpp title="include/shader_renderer.hpp — đọc shader info log"
inline std::string shaderInfoLog(GlApi& gl, GLuint shader) {
    GLint length = 0;
    gl.GetShaderiv(shader, GL_INFO_LOG_LENGTH, &length);
    const auto limit = std::clamp(length, 1, 65536);
    std::vector<GLchar> text(std::size_t(limit), '\0');
    gl.GetShaderInfoLog(shader, limit, nullptr, text.data());
    std::string result(text.data());
    if (length > limit)
        result += "\n[Driver log truncated at 64 KiB]";
    if (result.empty())
        result = "Driver supplied no shader info log.";
    return result;
}
```

Ta hỏi GL_INFO_LOG_LENGTH trước, cấp buffer ít nhất một byte và chặn ở 64 KiB. Buffer ban đầu chứa NUL nên kết thúc chuỗi an toàn khi driver không viết gì. Nếu phải cắt log, thêm thông báo để người dùng biết chưa thấy toàn bộ nội dung.

GlApi là bảng hàm OpenGL do gl_api.hpp nạp bằng SDL_GL_GetProcAddress. gl.GetShaderiv chính là lời gọi OpenGL, không phải bộ phân tích GLSL tự viết.

### Bước 2 — Tạo object, gửi source và compile

```cpp title="include/shader_renderer.hpp — compile một stage"
inline GLuint compileShader(GlApi& gl, GLenum stage, const std::string& source, const std::string& file, std::string& diagnostics, ProgramBuildAudit* audit = nullptr) {
    const auto shader = gl.CreateShader(stage);
    if (!shader) {
        diagnostics = file + ": glCreateShader failed";
        return 0;
    }
    if (audit)
        audit->shaders.push_back(shader);
    const char* bytes = source.c_str();
    const GLint length = static_cast<GLint>(source.size());
    gl.ShaderSource(shader, 1, &bytes, &length);
    gl.CompileShader(shader);
    GLint compiled = GL_FALSE;
    gl.GetShaderiv(shader, GL_COMPILE_STATUS, &compiled);
    if (compiled == GL_TRUE)
        return shader;
    std::string label = "fragment";
    if (stage == GL_VERTEX_SHADER) {
        label = "vertex";
    }
    diagnostics = "[" + label + " compile] " + file + "\n" + shaderInfoLog(gl, shader);
    gl.DeleteShader(shader);
    return 0;
}
```

ShaderSource nhận mảng con trỏ source; ta chỉ có một chuỗi nên count bằng 1. length là số byte, không phải số dòng. CompileShader không trả bool: sau khi gọi nó, phải hỏi trạng thái qua GetShaderiv.

Nếu thành công, người gọi sở hữu shader ID và phải hủy nó sau khi link. Nếu thất bại, hàm tự hủy object và trả 0. Cách chia trách nhiệm này tránh quên DeleteShader ở mỗi nhánh lỗi.

audit mặc định là nullptr. Nó chỉ ghi ID để bản final kiểm tài nguyên; bạn có thể theo dõi luồng chính mà chưa cần đọc phần audit.

### Bước 3 — Giữ nguyên thông tin mà driver trả về

Biến `label` chọn tên stage trước khi ghép thông báo. Hàm này chỉ được gọi với vertex hoặc fragment shader: mặc định là “fragment”, còn `GL_VERTEX_SHADER` chọn “vertex”. Nhãn giúp xác định phần source đang lỗi; trạng thái compile vẫn phải lấy từ OpenGL, không suy ra từ nhãn hay nội dung log.

Thông báo bắt đầu bằng stage và đường dẫn, sau đó nối nguyên log. Mỗi hãng GPU có cách ghi số dòng khác nhau. Ví dụ “0:18” thường chỉ source số 0, dòng 18; không được coi đây là định dạng chung hay tự tạo số dòng bằng cách tìm một từ khóa.

Thiếu dấu ngoặc có thể khiến compiler báo tại cuối file. Đọc từ lỗi đầu tiên, sửa một lỗi rồi thử lại; những lỗi tiếp theo đôi khi chỉ là hệ quả.

## Ghép các phần lại

```bash title="Terminal — checkpoint 2"
cmake --build build --config Debug --target project_35_checkpoint_2 --parallel 2
./build/Debug/project_35_checkpoint_2.exe
```

Mở gradient.frag tại SHADER DIRECTORY. Bỏ dấu chấm phẩy của một phép gán rồi khởi động lại chương trình. Checkpoint 2 chưa có phím reload, nên mỗi lần thử cần chạy lại executable; không cần build lại khi chỉ sửa GLSL.

Program dự phòng vẫn vẽ được, còn stderr chỉ rõ fragment compile thất bại. Khôi phục dấu chấm phẩy và chạy lại để xác nhận chính lỗi vừa tạo đã biến mất.

## Thử làm sai để hiểu đúng

1. Viết sai tên gl_Position trong lab.vert: lỗi phải thuộc vertex stage.
2. Viết sai tên fragColor trong gradient.frag: lỗi phải thuộc fragment stage.
3. Bỏ dấu ngoặc cuối main: quan sát vị trí driver báo, rồi lần ngược đến chỗ đã xóa.

Sau mỗi lần thử, khôi phục source gốc. Đừng build lại C++ để “chữa” lỗi GLSL: source ngoài executable đã được đọc mỗi lần khởi động.
