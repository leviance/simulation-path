# GPU của máy có chạy được workload này không?

## Bài toán của chúng ta

Project 33 dùng OpenGL để vẽ không có nghĩa là máy đã hỗ trợ compute shader. Ta cần OpenGL 4.3, đủ lane trong một workgroup, đủ group theo trục X và đủ dung lượng cho mỗi SSBO. Một request thành công cũng chưa thay cho việc đọc các giới hạn thật.

Bài này chưa dispatch. Mục tiêu là biết sớm vì sao một cấu hình không chạy được, trước khi driver nhận một allocation hoặc lệnh compute không hợp lệ.

## Hiểu ý tưởng trước khi viết code

Local size là số invocation trong một group; group count là số group được dispatch. Hai giới hạn này khác nhau. Tổng invocations trong group còn bị chặn bởi `maximumInvocations`, kể cả khi từng chiều riêng lẻ có vẻ hợp lệ.

Ta còn cần ba binding và ba compute storage block cho A, B, output. Dung lượng block được kiểm có cả 256 Vec4 padding dùng làm canary sau N. Budget ứng dụng 2.000.003 phần tử là giới hạn an toàn của bài học, không phải tuyên bố về mọi GPU.

## Bắt tay vào code

### 1. Yêu cầu đúng context trước khi tạo window

`ComputeApplication::run` request OpenGL 4.3 Core trước khi tạo hidden window/context. Cửa sổ dashboard vẫn dùng SDL surface trên CPU. Context compute được gỡ khỏi main thread rồi mới giao cho worker; không để hai thread cùng current một context.

```cpp title="include/compute_application.hpp — yêu cầu OpenGL 4.3 Core"
if (!SDL_GL_SetAttribute(SDL_GL_CONTEXT_MAJOR_VERSION, 4) ||
    !SDL_GL_SetAttribute(SDL_GL_CONTEXT_MINOR_VERSION, 3) ||
    !SDL_GL_SetAttribute(SDL_GL_CONTEXT_PROFILE_MASK, SDL_GL_CONTEXT_PROFILE_CORE)) {
    throw std::runtime_error(std::string("OpenGL 4.3 request: ") + SDL_GetError());
}
```

Các attribute chỉ là yêu cầu tạo context. Nếu driver từ chối, báo lỗi tại đây; nếu tạo được, vẫn phải đọc version và limits thật.

### 2. Đọc từng loại giới hạn

Sau `SDL_GL_MakeCurrent`, bảng `GlApi` nạp các hàm qua `SDL_GL_GetProcAddress`. Nếu thiếu hàm, báo đúng tên hàm và dừng; không gọi qua function pointer null.

```cpp title="include/vector_compute_engine.hpp — đọc giới hạn compute"
api.GetIntegerv(GL_MAX_COMPUTE_WORK_GROUP_INVOCATIONS, &limits.maximumInvocations);
api.GetIntegerv(GL_MAX_SHADER_STORAGE_BUFFER_BINDINGS, &limits.maximumStorageBindings);
api.GetIntegerv(GL_MAX_COMPUTE_SHADER_STORAGE_BLOCKS, &limits.maximumComputeStorageBlocks);
api.GetInteger64v(GL_MAX_SHADER_STORAGE_BLOCK_SIZE, &limits.maximumShaderStorageBlockBytes);
for (GLuint axis = 0; axis < 3; ++axis) {
    api.GetIntegeri_v(GL_MAX_COMPUTE_WORK_GROUP_COUNT, axis, &limits.maximumWorkgroupCount[axis]);
    api.GetIntegeri_v(GL_MAX_COMPUTE_WORK_GROUP_SIZE, axis, &limits.maximumWorkgroupSize[axis]);
}
```

`GetIntegeri_v` đọc giá trị indexed theo X/Y/Z; không đọc một lần rồi dùng cùng số cho cả ba chiều. Block size dùng kiểu 64 bit, khác với group size/count kiểu int. Khi so giá trị unsigned của kế hoạch dispatch với giới hạn signed, ta mở rộng về int64 thay vì ép một số lớn xuống int và có nguy cơ đổi dấu.

Ở checkpoint 2, workload vẫn là 256 phần tử và một group. Bài 5 sẽ thêm `DispatchPlan` để preflight từng N lớn trước allocation. Việc tách hai bước giữ cho lần kiểm đầu chưa phụ thuộc phép chia group mà ta chưa viết.

### 3. Bàn giao context cho worker

Trước khi gọi worker lần đầu, main thread phải nhả current context:

```cpp title="include/compute_application.hpp — nhả current context"
if (!SDL_GL_MakeCurrent(computeWindow_, nullptr)) {
    throw std::runtime_error(std::string("Detach compute context: ") + SDL_GetError());
}
```

Sau đó `ComputeWorker::run` gọi `SDL_GL_MakeCurrent(window_, context_)` trên chính thread của nó rồi mới nạp entry point. Worker dọn resource và nhả context khi kết thúc. Application đợi worker join xong mới hủy context/window; thứ tự này quan trọng hơn việc chỉ có một con trỏ context khác null.

## Chạy checkpoint

Chạy `project_37_checkpoint_2`. Dashboard phải hiện renderer và OpenGL version thật. Nếu tạo context thất bại, đọc thông báo terminal; nếu preflight thất bại, worker báo trạng thái lỗi thay vì tiếp tục dispatch.

Worker hiện chỉ tính CPU. Việc tạo được context không biến dòng CPU thành output GPU. Đây cũng là lúc kiểm Escape và resize: chúng vẫn hoạt động vì UI không chờ worker trong event loop.

## Thử làm sai để hiểu đúng

1. Trong CPU fixture, đặt `maximumInvocations=128` trong khi local size cần 256. Preflight phải fail tại điều kiện local size/invocations, trước allocation.
2. Thử riêng cấu hình chỉ có hai storage bindings, rồi cấu hình có block quá nhỏ. Mỗi lần phải chỉ ra điều kiện không đạt tương ứng; đừng gom tất cả thành thông báo “GPU yếu”.

## Tự kiểm tra kết quả

- Đọc version thật sau khi tạo context và kiểm đầy đủ giới hạn cần dùng.
- Context chỉ current trên một thread; worker dọn GPU resource trước khi bỏ context.
- Cấu hình không hợp lệ dừng trước allocation/dispatch, có thông báo đọc được.
- Chưa dùng số liệu Canvas làm capability của máy thật.
