# Hoàn thiện máy tính vector GPU

## Bài toán của chúng ta

Từng phần đã chạy đúng riêng lẻ; bài cuối sẽ ghép chúng thành một ứng dụng hoàn chỉnh. Khi `count` thay đổi, ta tạo lại và upload bộ dữ liệu. Khi `operation` hoặc `scalar` thay đổi, ta chỉ tính lại kết quả CPU và chạy lại compute shader. Nếu người dùng không thay đổi gì, chương trình chỉ vẽ output hiện có thay vì xử lý lại hơn một triệu vector ở mọi frame.

Bài này thêm ba operation vào shader, controls, benchmark nút B, output bars, named validation và cleanup đảo ngược lifetime. Cuối bài, phần mã nguồn bên dưới và ZIP là cùng một snapshot final có thể build.

## Theo dõi dữ liệu từ CPU sang GPU

Luồng final có hai nhánh:

```text
Count đổi ───────> generate A/B ─> upload SSBO ─┐
Operation đổi ──────────────────────────────────┤
Scalar đổi ─────────────────────────────────────┤
                                                v
Bản CPU → GPU dispatch → barrier → đọc kết quả → kiểm tra → vẽ một số mẫu
```

Một expose/resize frame không đi qua nhánh compute; nó chỉ gọi `drawOutputBars` bằng readback gần nhất.

## Bắt tay vào code

### Bước 1 — Thêm uniform để chọn phép toán

```glsl title="shaders/vector_ops.comp — final arithmetic"
uniform int uElementCount;
uniform int uOperation;
uniform float uScalar;

void main() {
    uint index = gl_GlobalInvocationID.x;

    if (index >= uint(uElementCount)) {
        return;
    }

    if (uOperation == 1) {
        outputData[index] = inputA[index] * uScalar + inputB[index];
    } else if (uOperation == 2) {
        outputData[index] = inputA[index] - inputB[index];
    } else {
        outputData[index] = inputA[index] + inputB[index];
    }
}
```

Enum phía CPU có giá trị Add=0, AXPY=1, Difference=2; shader phải dùng đúng ba giá trị này. Trước khi thay program đang chạy, ta còn kiểm tra `uOperation` và `uScalar` có thật sự tồn tại trong shader đã link hay không.

### Bước 2 — Tách việc tạo lại dữ liệu khỏi phép tính

```cpp title="src/main.cpp — hai loại thay đổi"
auto rebuildDataset = [&]() -> bool {
    inputs = lab::makeVectorInputs(elementCount);
    cpuOutput = lab::computeCpu(inputs, operation, scalar);
    visibleOutput = cpuOutput;

    if (!engine.uploadInputs(gl, inputs, diagnostics)) {
        std::cerr << diagnostics << '\n';
        return false;
    }

    return true;
};

auto runCalculation = [&]() -> bool {
    cpuOutput = lab::computeCpu(inputs, operation, scalar);
    visibleOutput = cpuOutput;
    const std::size_t dispatchCount = elementCount;

    if (!engine.execute(
            gl,
            dispatchCount,
            operation,
            scalar,
            gpuOutput,
            gpuMilliseconds,
            diagnostics
        )) {
        std::cerr << diagnostics << '\n';
        return false;
    }

    visibleOutput = gpuOutput;
    validation = lab::validateOutput(cpuOutput, gpuOutput);
    return true;
};
```

Source thật còn diagnostics và checkpoint guards, nhưng ranh giới trách nhiệm vẫn như trên. `[`/`]` gọi cả hai; `1/2/3` và `-/=` chỉ gọi calculation.

### Bước 3 — Vẽ một phần kết quả nhưng kiểm tra toàn bộ buffer

```cpp title="src/main.cpp — chọn index đều nhau"
const std::size_t index = std::min(
    output.size() - 1U,
    (std::size_t(bar) * output.size()) / std::size_t(barCount)
);

const float value = output[index].x;
```

64 cột giúp đọc dấu/độ lớn của component `x`. `validateOutput` đã chạy trên đủ `gpuOutput`, cả bốn components, trước khi title báo PASS.

### Bước 4 — Dọn tài nguyên OpenGL trước khi hủy context

```cpp title="src/main.cpp — shutdown"
engine.destroy(gl);
destroyWindowAndContext(window, context);
```

`engine.destroy` xóa timer query, ba buffers rồi program. Mọi lệnh `glDelete*` chạy khi context còn current. Sau đó mới destroy context, window và SDL.

## Chạy checkpoint

Bản hoàn chỉnh khởi tạo theo một đường duy nhất: tạo context và đọc giới hạn, compile program, sinh rồi tải dữ liệu, chạy bản CPU cùng lần dispatch đầu tiên, sau đó mới vào event loop. Trong loop, event quyết định cần tạo lại dữ liệu hay chỉ tính lại kết quả; phần render luôn dùng `visibleOutput` mới nhất. Nhờ vậy code không giấu thêm một vòng compute thứ hai trong hàm vẽ.

Khi một bước trả `false`, diagnostics được in và vòng lặp kết thúc có kiểm soát. Shutdown vẫn đi qua `engine.destroy(gl)` trước context; app không gọi `std::exit` giữa chừng sau khi GPU resources đã được tạo.

## Điều khiển bản final

- `1`: Add, `2`: AXPY, `3`: Difference.
- `[` / `]`: 256 → 65.537 → 1.000.003 phần tử.
- `-` / `=`: đổi scalar theo bước 0,25 trong `[-4,4]`.
- `B`: một warm-up và chín timing samples, lấy median.
- `R`: về Add, scalar 1,25 và 1.000.003 phần tử.
- `Escape`: thoát.

Title báo operation, N, groups, scalar, sample GPU time, median, maximum error và PASS/FAIL. Không có một con số “FPS” vô nghĩa với calculator event-driven.

## Mã hoàn chỉnh và cách build

Phần **Mã chạy được ở cuối bài 9** phía dưới được sinh trực tiếp từ final checkpoint, gồm:

- `vector_compute_math.hpp`: dữ liệu đầu vào, bản tính CPU, kế hoạch dispatch, sai số cho phép và median;
- `gl_api.hpp`: OpenGL function pointers được nạp qua SDL;
- `vector_compute_engine.hpp`: shader, SSBO, dispatch, barrier, readback và timer query;
- `vector_ops.comp`: compute shader hoàn chỉnh;
- `main.cpp`: lifecycle, controls, visualization và diagnostics;
- `tests.cpp`: CTest thuần CPU, không mở window.

```bash title="Terminal — Debug"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON -DBUILD_TESTING=ON
cmake --build build --config Debug --target project_37_final project_37_tests
ctest --test-dir build -C Debug --output-on-failure --timeout 20
```

```bash title="Terminal — Release"
cmake --build build --config Release --target project_37_final project_37_tests
ctest --test-dir build -C Release --output-on-failure --timeout 20
```

Timeout giữ test automation hữu hạn. App có window được chạy thủ công và tự thoát bằng Escape; không đưa event loop vào CTest.

## Thử phá chương trình

1. Gọi `runCalculation` vô điều kiện ở mọi frame. GPU, readback và bản CPU đều chạy lại dù đầu vào không đổi.
2. Khi operation đổi, sinh/upload A/B lại. Kết quả vẫn đúng nhưng bạn tạo transfer vô ích và làm khó hiểu benchmark.
3. Đổi local size phía C++ thành 128 nhưng giữ shader ở 256. Số workgroup được tính theo một kích thước, còn GPU lại chạy theo kích thước khác.
4. Vẽ cột từ `cpuOutput` để hình luôn đẹp khi GPU fail. UI che mất lỗi cần quan sát.
5. Destroy context trước `engine.destroy`. GPU object cleanup mất context cần thiết.
