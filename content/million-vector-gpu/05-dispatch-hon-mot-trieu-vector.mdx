# Mở rộng tới 1.000.003 phần tử

## Bài toán của chúng ta

Một group chỉ xử lý 256 phần tử. Muốn xử lý mảng lớn, ta tăng số group, không sửa local size tùy tiện từ C++. Đồng thời, N không nhất thiết chia hết 256: một số invocation cuối sẽ không có phần tử tương ứng.

Bài này chuyển preset mặc định lên 1.000.003 phần tử thật. Bản 256 phần tử vẫn có ích để debug, nhưng không được dùng làm final rồi gọi đó là chương trình một triệu phần tử.

## Hiểu ý tưởng trước khi viết code

Với L invocation mỗi group, số group là $G=\lceil N/L\rceil$. Số lane được tạo là GL, và số lane dư là GL−N. Với N=1.000.003, L=256: G=3.907, tổng lane=1.000.192, dư 189.

Global index kết hợp group ID với local ID: `groupId * localSize + localId`. Shader dùng `gl_GlobalInvocationID.x` đã có đúng giá trị này. Không dùng `gl_LocalInvocationID.x` làm index chung cho toàn mảng: mỗi group sẽ ghi đè lên 256 phần tử đầu.

## Bắt tay vào code

### 1. Tính số group mà không mất phần đuôi

`ceilDiv` dùng phép chia nguyên mà không cộng N+L−1 trước, tránh một kiểu overflow khi tổng quá lớn:

```cpp title="include/vector_compute_math.hpp — số workgroup"
if (divisor == 0) {
    throw std::invalid_argument("Local size must be greater than zero.");
}
if (value == 0) {
    return 0;
}
const std::size_t result = 1U + (value - 1U) / divisor;
if (result > std::numeric_limits<std::uint32_t>::max()) {
    throw std::overflow_error("Workgroup count does not fit GLuint.");
}
return static_cast<std::uint32_t>(result);
```

`makeDispatchPlan` kiểm budget N trước khi tạo kế hoạch; `validateCapabilities` kiểm local/group/block/binding cho chính kế hoạch đó. Đổi N phải preflight lại, không tái sử dụng kết luận của preset trước.

### 2. Gửi đúng N và group count cho chương trình đã link

Phía engine, gán N trước dispatch:

```cpp title="include/vector_compute_engine.hpp — gửi N và group count"
const DispatchPlan plan = makeDispatchPlan(elementCount_, computeLocalSize);
api.Uniform1i(elementCountLocation_, static_cast<GLint>(elementCount_));
const GLuint workgroupCount = plan.workgroupCount;
```

### 3. Loại lane dư trước mọi truy cập

Shader thêm `uniform int uElementCount` và dừng ngay sau khi tính index:

```glsl title="shaders/vector_ops.comp — guard trước mọi truy cập"
uint index = gl_GlobalInvocationID.x;
if (index >= uint(uElementCount)) {
    return;
}
```

Đặt guard trước cả `inputA[index]` và `inputB[index]`, không chỉ trước câu ghi output. Bộ đệm padding phục vụ kiểm thử không phải lý do để cho invocation ngoài N tự do tính tiếp.

## Thử làm sai để hiểu đúng

1. Tính thử N/256 bằng chia làm tròn xuống: mảng sẽ thiếu ba phần tử cuối ở preset này. Nếu chỉ nhìn các mẫu đầu mảng, lỗi có thể không lộ; sentinel/validator đủ N ở bài sau phải bắt được phần thiếu.
2. Trong fixture shader, thử chuyển guard xuống sau lần đọc input. Dù câu ghi cuối được chặn, lần đọc trước đó vẫn ngoài N. Khôi phục guard về ngay sau index; không dùng một lần chạy tình cờ đúng để hợp thức hóa truy cập sai.

## Tự kiểm tra kết quả

- 1.000.003 phần tử tạo đúng 3.907 group và 189 lane dư.
- N=1/255/256/257 đều cho số group đúng; divisor 0 bị từ chối.
- Guard nằm trước mọi lần đọc/ghi, không chỉ bảo vệ output.
- N mới được kiểm budget/capability trước allocation.
