# Compute shader đầu tiên: một workgroup

## Bài toán của chúng ta

Ba SSBO đã có dữ liệu. Bây giờ ta viết chương trình GPU đọc một cặp A[i]/B[i] rồi ghi C[i]. Chưa cần bắt đầu bằng một triệu phần tử: đúng 256 phần tử và một workgroup giúp ta nhìn rõ quan hệ giữa một invocation và một index.

Compute shader không có vertex position hay fragment color. Nó chạy vì C++ gọi dispatch, và sản phẩm của nó ở đây là dữ liệu trong output buffer, không phải pixel được vẽ lên cửa sổ.

## Hiểu ý tưởng trước khi viết code

`layout(local_size_x = 256)` cố định 256 invocation trong một group. Với `glDispatchCompute(1, 1, 1)`, global ID theo X chạy từ 0 đến 255. Khi chỉ có một group, local ID và global ID trùng nhau; từ bài sau, điều này không còn đúng cho group thứ hai trở đi.

Ba operation đã được chọn từ CPU, nên uniform `uOperation` và `uScalar` cũng xuất hiện ở kernel đầu tiên. Không để CPU tính AXPY còn shader vẫn âm thầm cộng A+B.

## Bắt tay vào code

### 1. Viết kernel cho một invocation

Sau ba SSBO block của bài trước, khai báo uniform và viết `main`:

```glsl title="shaders/vector_ops.comp — tính một phần tử"
uniform int uOperation;
uniform float uScalar;

void main() {
    uint index = gl_GlobalInvocationID.x;
    if (uOperation == 1) {
        outputData[index] = inputA[index] * uScalar + inputB[index];
    } else if (uOperation == 2) {
        outputData[index] = inputA[index] - inputB[index];
    } else {
        outputData[index] = inputA[index] + inputB[index];
    }
}
```

Enum C++ dùng Add=0, AXPY=1, Difference=2. Ở checkpoint này N đúng 256 nên mọi invocation đều hợp lệ; đừng đổi N lẻ trước khi thêm guard ở bài 5.

### 2. Compile source trước khi link program

`compute_program.hpp` đọc file có budget 256 KiB, tạo `GL_COMPUTE_SHADER` rồi chuyển source vào shader:

```cpp title="include/compute_program.hpp — compile compute source"
const GLchar* sourcePointer = shaderSource.c_str();
const GLint sourceLength = static_cast<GLint>(shaderSource.size());
api.ShaderSource(shader, 1, &sourcePointer, &sourceLength);
api.CompileShader(shader);
GLint compiled = GL_FALSE;
api.GetShaderiv(shader, GL_COMPILE_STATUS, &compiled);
if (compiled != GL_TRUE) {
    throw std::runtime_error("Compute compile failed: " + computeInfoLog(api, shader, true));
}
```

Chỉ source đã compile mới được attach/link vào candidate program. Compile và link là hai bước riêng, mỗi bước có diagnostics và cleanup khi lỗi; đừng đọc link log để thay cho compile log của shader.

### 3. Kiểm interface rồi mới dispatch

Program link được chưa đủ: reflection còn kiểm local size `(256,1,1)`, type/size của uniform, binding, type, offset và array stride của các SSBO.

```cpp title="include/compute_program.hpp — kiểm local size đã link"
std::array<GLint, 3> localSize{};
api.GetProgramiv(candidate, GL_COMPUTE_WORK_GROUP_SIZE, localSize.data());
if (localSize != std::array<GLint, 3>{256, 1, 1}) {
    throw std::runtime_error("Compute program must use local_size = (256, 1, 1).");
}
```

Chỉ sau khi toàn bộ interface hợp lệ, engine mới thay program hiện tại. Một shader link được nhưng dùng binding sai không được phép trở thành program last-good mới.

`VectorComputeEngine::execute` upload input, bind program, gán uniform rồi dispatch một group. Fence cho worker biết command đã hoàn tất, có kiểm hủy/deadline. Bài này chưa readback; fence không tự mang output về CPU và cũng không thay barrier visibility sẽ học ở bài 6.

## Thử làm sai để hiểu đúng

1. Đổi `local_size_x` thành 128 trong shader fixture. Compile/link có thể thành công nhưng reflection phải từ chối vì hợp đồng dispatch còn là 256.
2. Đổi type `uScalar` thành int hoặc binding Output thành 3. Interface sai phải bị từ chối; program đúng trước đó không bị thay bằng candidate lỗi. Khôi phục shader đúng trước khi đi tiếp.

## Tự kiểm tra kết quả

- Shader là compute thật, không dùng fragment shader thay phép tính.
- Chỉ dispatch một group với N=256; CPU/GPU chọn cùng operation và scalar.
- Compile/link/interface lỗi có diagnostics và candidate bị dọn.
- Chưa tuyên bố output đúng khi chưa readback/validate.
