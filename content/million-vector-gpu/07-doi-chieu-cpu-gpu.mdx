# Hai kết quả giống nhau đến mức nào thì được chấp nhận?

## Bài toán của chúng ta

Inspector chỉ giúp đọc một phần tử, không kiểm thay toàn mảng. Một lỗi ở index cuối hay channel w rất dễ bị bỏ qua nếu chỉ nhìn vài cột. Ta cần validator duyệt đủ N phần tử, cả bốn thành phần và báo vị trí sai đầu tiên.

Không dùng `expected == actual` cho mọi phép tính float. Nhưng cũng không được tăng tolerance tùy ý tới khi bảng chuyển xanh. Ta phải công bố rõ ngưỡng và kiểm cả chính ngưỡng đó.

## Hiểu ý tưởng trước khi viết code

Một thành phần được chấp nhận khi:

$$|e-a| \le \epsilon_{abs} + \epsilon_{rel}\max(|e|,|a|).$$

Bản này chọn cả absTol và relTol bằng 2×10⁻⁶. Phần tuyệt đối hữu ích quanh zero; phần tương đối scale theo độ lớn. AXPY có thể được GPU thực hiện bằng fused multiply-add trong khi CPU làm tròn khác, nên phải dùng tolerance thay vì buộc mọi bit giống nhau.

Trước công thức trên, expected, actual và tolerance phải hợp lệ. NaN khiến nhiều phép so sánh trả false; nếu code chỉ viết “error lớn hơn ngưỡng thì fail”, một NaN có thể lách qua nhánh báo lỗi.

## Bắt tay vào code

### 1. Kiểm chính tham số tolerance

`validateOutput` không được bắt đầu so dữ liệu khi tolerance đã sai:

```cpp title="include/vector_compute_math.hpp — từ chối tolerance không hợp lệ"
OutputValidationReport report{};
report.tolerancesValid = std::isfinite(absoluteTolerance) && absoluteTolerance >= 0.0F &&
    std::isfinite(relativeTolerance) && relativeTolerance >= 0.0F;
report.sameSize = expected.size() == actual.size();
report.allFinite = true;
if (!report.tolerancesValid) {
    return report;
}
```

Report vẫn giữ `tolerancesValid=false`, nên `allPassed()` không thể chấp nhận nó dù chưa đếm được mismatch nào. Đây là lỗi cấu hình phép kiểm, không phải bằng chứng dữ liệu đúng.

### 2. Loại NaN/Inf trước phép tính sai số

Trong vòng component, đặt finite guard trước phép trừ:

```cpp title="include/vector_compute_math.hpp — chặn giá trị không hữu hạn"
if (!std::isfinite(expectedValue) || !std::isfinite(actualValue)) {
    report.allFinite = false;
    if (report.firstNonFinite == std::numeric_limits<std::size_t>::max()) {
        report.firstNonFinite = index;
    }
    if (elementMatches && report.firstMismatch == std::numeric_limits<std::size_t>::max()) {
        report.firstMismatchComponent = component;
    }
    elementMatches = false;
    continue;
}
```

`continue` bỏ phép tính sai số của channel không hữu hạn nhưng không bỏ lỗi: `elementMatches=false` sẽ làm phần tử này được tính mismatch ở cuối vòng.

### 3. So sai số và lưu vị trí có ích để debug

`validateOutput` kiểm tolerance hữu hạn/không âm và hai mảng cùng size trước khi kết luận. Trong mỗi phần tử, ta tạo hai mảng bốn component rồi xét lần lượt:

```cpp title="include/vector_compute_math.hpp — sai số của một component"
const float error = std::abs(expectedValue - actualValue);
report.maximumAbsoluteError = std::max(report.maximumAbsoluteError, error);
const float scale = std::max(std::abs(expectedValue), std::abs(actualValue));
if (error > absoluteTolerance + relativeTolerance * scale) {
    if (elementMatches && report.firstMismatch == std::numeric_limits<std::size_t>::max()) {
        report.firstMismatchComponent = component;
    }
    elementMatches = false;
}
```

Đoạn này chạy sau finite guard. `mismatchCount` đếm phần tử sai, không phải tổng channel sai; `firstMismatchComponent` cho biết channel đầu tiên ở phần tử lỗi đầu tiên. `firstNonFinite` được lưu riêng để phân biệt NaN/Inf với sai số hữu hạn.

Nếu hai size khác nhau, phần thiếu/thừa cũng được tính lỗi. So phần chung rồi thấy tất cả đúng không có nghĩa toàn workload đúng. Tương tự, `allPassed()` còn cần tolerance hợp lệ và tất cả giá trị hữu hạn, không chỉ `mismatchCount == 0`.

Worker chạy validator sau readback, ngoài vùng timing. Chỉ khi validation và canary cùng đạt mới công bố một lượt chạy thành công. Checksum giúp ghi nhận output đã được sử dụng, nhưng checksum không thay phép kiểm từng phần tử: hai mảng sai vẫn có thể cùng checksum.

## Thử làm sai để hiểu đúng

1. Trong CPU fixture, thay riêng x, rồi y, z, w của một phần tử bằng giá trị lệch 0,1. Validator phải bắt từng trường hợp và chỉ đúng component.
2. Thử NaN, Infinity, output thiếu, tolerance NaN và tolerance âm. Lỗi dữ liệu phải làm fail finite/size; lỗi tolerance phải làm `tolerancesValid=false`, không trở thành một lần kiểm thành công rỗng.

## Tự kiểm tra kết quả

- So đủ N×4 component, dùng abs/rel tolerance công bố.
- NaN/Inf không được xem là roundoff; size mismatch không bị bỏ qua.
- Báo được first mismatch/component, first non-finite và maximum error.
- Fixture có đáp án nhỏ độc lập, không lấy expected từ chính hàm đang kiểm.
