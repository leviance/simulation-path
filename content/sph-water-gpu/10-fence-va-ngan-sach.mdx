# Giữ ứng dụng phản hồi khi GPU đang tính

## Vấn đề cần giải quyết

Một dispatch lớn có thể kéo dài. Nếu CPU chờ GPU xong trong event loop, người dùng không pause hay đóng window được. Ta cần một batch pending, poll không chặn và giới hạn rõ ràng cho benchmark.

## Hiểu ý tưởng trước khi viết code

Memory barrier phục vụ visibility giữa GPU consumers; fence cho CPU biết các lệnh trước nó đã hoàn tất. Hai việc khác nhau. ClientWaitSync với timeout 0 là phép hỏi trạng thái, không phải đợi tới khi hoàn thành. Xem [Khronos reference](https://registry.khronos.org/OpenGL-Refpages/gl4/html/glClientWaitSync.xhtml).

Pause ngăn tick tiếp theo. Nó không thu hồi compute đã gửi. Timeout 5 s báo lỗi và dừng submit, cũng không phải cơ chế preempt driver. Vì thế safety bắt đầu từ workload nhỏ và xác nhận N, không chỉ từ một nút Stop.

## Viết code từng bước

### Bước 1 — Poll mà không khóa event loop

Trong `Queue::poll`, ta hỏi fence đúng một lần mỗi lượt event loop. Đọc cả hàm để thấy đường chưa xong, lỗi và hoàn tất là ba trường hợp riêng:

{/* snippet include/queue.hpp#fence-poll */}
```cpp title="include/queue.hpp — hỏi fence với timeout0"
bool poll(lab::GlApi& gl) {
    if (!pending()) {
        return true;
    }
    const auto result = gl.ClientWaitSync(fence_, 0, 0);
    if (result == GL_WAIT_FAILED || std::chrono::steady_clock::now() - started_ > std::chrono::seconds(5)) {
        throw GpuBatchError("GPU failed or exceeded 5s; no further batches will be sent");
    }
    if (result == GL_TIMEOUT_EXPIRED) {
        return false;
    }
    // Chỉ đọc kết quả khi tất cả timestamp đã sẵn sàng; không chờ bận.
    for (std::size_t i = 0; i < stampCount_; ++i) {
        GLint available = GL_FALSE;
        gl.GetQueryObjectiv(queries_[i], GL_QUERY_RESULT_AVAILABLE, &available);
        if (available != GL_TRUE)
            return false;
    }
    std::array<GLuint64, 16> ns{};
    for (std::size_t i = 0; i < stampCount_; ++i) {
        gl.GetQueryObjectui64v(queries_[i], GL_QUERY_RESULT, &ns[i]);
    }
    passCount = stampCount_ - 1;
    for (std::size_t i = 0; i < passCount; ++i) {
        timings[i].milliseconds = static_cast<double>(ns[i + 1] - ns[i]) / 1e6;
    }
    milliseconds = static_cast<double>(ns[stampCount_ - 1] - ns[0]) / 1e6;
    gl.DeleteSync(fence_);
    fence_ = nullptr;
    return true;
}
```

WAIT_FAILED là lỗi, TIMEOUT_EXPIRED trả false cho main tiếp tục xử lý input. Sau 5 s chưa xong, throw và không gửi thêm work; tuyệt đối không loop ClientWaitSync tới khi thành công.

Lỗi GPU phải đi được tới `main`, không chỉ được in ra rồi bỏ qua. Ta đặt tên riêng cho nhóm lỗi fence/deadline bằng lớp sau trong `gpu-error.hpp` và include nó từ `queue.hpp`:

{/* snippet include/gpu-error.hpp#fatal-gpu-error */}
```cpp title="include/gpu-error.hpp — lỗi GPU không được phục hồi qua UI"
class GpuBatchError : public std::runtime_error {
    public:
    explicit GpuBatchError(const char* message)
        : std::runtime_error(message) {}
};
```

Lớp này giữ thông báo của `std::runtime_error`, nhưng cho caller nhận biết lỗi nghiêm trọng. Trong `Controls::command` và `ReferenceJob::service`, nhánh `catch (const GpuBatchError&)` phải ném tiếp bằng `throw;` **trước** nhánh bắt `std::exception`. Nhờ vậy timeout của oracle phụ cũng đi ra vòng lặp chính, dừng submit và đóng ứng dụng với mã thất bại; người dùng không thể vô tình chạy tiếp scene chính trên GPU vừa báo lỗi. Chỉ lỗi kiểm chứng dữ liệu đã hoàn tất mới được báo trong panel. Không cố gây treo GPU để thử nhánh này; CTest dùng lỗi tổng hợp, còn kiểm source giữ đúng thứ tự bắt/ném tiếp.

### Bước 2 — Không xếp render đằng sau batch dài

`main.cpp` poll completion trước khi xử lý input để hitbox/nút không dùng trạng thái busy cũ. Sau input và các yêu cầu reset/oracle, main bỏ render/swap nếu còn compute pending:

{/* snippet src/main.cpp#pending-gate */}
```cpp title="src/main.cpp — trả quyền xử lý input"
if (engine.queue.pending() || controls.referencePending()) {
    if (expired)
        throw std::runtime_error("Finite run expired with GPU work pending");
    SDL_Delay(1);
    continue;
}
```

Nếu vẫn gửi một draw mỗi frame khi GPU đang bận, queue có thể đầy và SwapWindow lại chặn CPU. Khi batch hoàn tất, host kiểm diagnostics/commit bank, vẽ frame mới rồi mới gửi tick tiếp nếu đang playing. Phần gửi cuối vòng lặp rất ngắn, nhưng điều kiện quyết định quan trọng: đang chạy, không ở CLI verify và không còn batch cũ.

{/* snippet src/main.cpp#submit-loop */}
```cpp title="src/main.cpp — gửi nhiều nhất một tick tiếp theo"
if (running && controls.wantsStep() && !options.verify && !engine.queue.pending())
    engine.submit(gl);
```

### Bước 3 — Đặt timestamp ở ranh giới từng pass

`Queue::begin` đặt timestamp đầu. Sau mỗi pass, `Engine::submit/buildGrid` gọi `mark` với tên interval vừa hoàn thành:

{/* snippet include/queue.hpp#gpu-timestamp */}
```cpp title="include/queue.hpp — timestamp trong command stream GPU"
void mark(lab::GlApi& gl, const char* label) {
    if (stampCount_ >= queries_.size()) {
        throw std::runtime_error("Too many GPU profiler intervals");
    }
    timings[stampCount_ - 1].label = label;
    gl.QueryCounter(queries_[stampCount_], GL_TIMESTAMP);
    ++stampCount_;
}
```

`poll` kiểm query availability rồi mới đọc nanosecond. Hiệu hai timestamp liền nhau là GPU time của interval, không phải thời gian CPU gọi `DispatchCompute`. Cả batch, CPU enqueue và submit→commit đều có số đo riêng. Submit→commit còn chứa nhịp poll/event loop; không gắn nhãn nó là thời gian tính GPU.

### Bước 4 — Warm-up, lấy mẫu rồi dừng

B bắt đầu khi idle: reset lattice ở N hiện tại, bật CSR, đưa camera/mode về cố định. `Benchmark::completedStep` bỏ 30 warm-up tick, lấy 8 tick compute tiếp theo rồi đóng băng state để đo 8 frame render. Nó chỉ ghi một completion một lần:

{/* snippet include/benchmark.hpp#benchmark-completion */}
```cpp title="include/benchmark.hpp — thu mẫu có điểm dừng"
void completedStep(const Engine& engine, const View& view, bool completed) {
    if (!active())
        return;
    if (std::chrono::steady_clock::now() - started_ > std::chrono::seconds(20)) {
        cancel();
        message = "BENCH DEADLINE - RESULT INCOMPLETE";
        return;
    }
    if (!completed || engine.steps == 0 || engine.steps == lastStep_)
        return;
    lastStep_ = engine.steps;
    if (phase == BenchmarkPhase::Warmup) {
        ++warmups;
        if (warmups == 30)
            phase = BenchmarkPhase::Compute;
        return;
    }
    if (phase != BenchmarkPhase::Compute)
        return;
    passCount = engine.queue.passCount;
    total.push_back(engine.queue.milliseconds);
    enqueue.push_back(engine.enqueueMilliseconds);
    commit.push_back(engine.commitMilliseconds);
    for (std::size_t i = 0; i < passCount; ++i) {
        labels[i] = engine.queue.timings[i].label;
        pass[i].push_back(engine.queue.timings[i].milliseconds);
    }
    if (total.size() == 8) {
        phase = BenchmarkPhase::Render;
        // Loại timestamp của frame trước khi state cuối được đóng băng.
        renderBaseline_ = view.timer.sequence;
        if (view.timer.pending())
            ++renderBaseline_;
    }
}
```

Các mẫu compute là tám tick liên tiếp của cùng trajectory sau warm-up, **không phải** tám lần chạy từ cùng state. Render samples lại dùng state cuối cố định và bỏ kết quả frame đang in-flight lúc chuyển phase. `completedRender` chốt sau tám mẫu; kết quả là median và [min,max] cho từng pass, cả batch, CPU enqueue, submit→commit và scene render. Render timer không gồm UI hoặc swap. Không suy FPS ứng dụng từ nghịch đảo một pass.

Benchmark có deadline nội bộ 20 s; C hoặc blur hủy work chưa gửi. Nếu chưa đủ mẫu, kết quả là incomplete, không phải PASS. Các script nghiệm thu còn có timeout process để dọn cả cây tiến trình khi job lỗi.

## Ghép các phần lại

Checkpoint 10 mới bật Space chạy. N pause rồi gửi một tick nếu idle; C dừng/hủy tick tương lai. R dừng và ghi nhận yêu cầu reset, đợi batch hiện tại xong rồi reset cùng N/tham số. Blur/minimize dừng playing và thả pointer capture. Không có accumulator bù thời gian đã mất sau khi window quay lại.

## Thử làm sai để hiểu đúng

1. Dùng glFinish mỗi frame. Event loop phải chờ hết queue; khôi phục fence/poll.
2. Tính thời gian quanh `DispatchCompute` bằng CPU rồi gọi đó là GPU ms. So nó với timestamp để thấy enqueue và execution khác nhau. Giữ nhãn riêng và khôi phục timer GPU.

## Tự kiểm tra kết quả

Chỉ một batch pending; bank/readback không đổi trước fence. Pause/blur không tạo tick mới. Benchmark có 30 warm-up, 8 compute samples và 8 frozen-render samples, hoặc báo incomplete. Debug panel cuộn được bằng wheel/PgUp/PgDn, F1 trở về hình sạch. Cancel không hứa dừng GPU command đang chạy.
