# Nhìn khối hạt từ nhiều hướng trước khi viết solver

## Vấn đề cần giải quyết

Trong Project 50, hạt chỉ cần x và y. Lần này, nước phải có chiều sâu thật: một hạt nằm sau hạt khác, có thể bị che và đổi kích thước biểu kiến khi camera tới gần. Ta chưa vội viết solver. Trước hết, cần một khối hạt đứng yên để biết rằng hệ tọa độ và góc nhìn đã đúng.

Starter cung cấp cửa sổ SDL3 với OpenGL 4.3 core, bộ nạp hàm GL và vòng `SDL_PollEvent`. Khác Project 50, ở đây **không tạo SDL_Renderer** trong cửa sổ OpenGL. Phần khung được kế thừa từ Project 33–38 và có sẵn trong ZIP; bạn không cần ghép mã từ các ZIP khác. Bài này thêm 4×4×4 = 64 điểm CPU. Bài 02 mới đưa state 512 hạt lên GPU.

## Hiểu ý tưởng trước khi viết code

Hãy tưởng tượng khối hạt gồm nhiều lớp: x thay đổi trong một hàng, y chọn hàng, z chọn lớp. Với chỉ số `i`, ba tọa độ nguyên lần lượt là `i % side`, `(i / side) % side`, `i / (side * side)`. Thêm 0,5 để đặt hạt ở tâm ô rồi nhân với spacing. Khối ban đầu rộng 0,4 m, nằm trong hộp [0,1]³, y hướng lên.

Camera không làm các hạt quay trong bể. Nó chỉ đổi từ tọa độ world sang tọa độ của người quan sát: dịch điểm nhìn về quanh (0,5; 0,4; 0,5), quay theo yaw/pitch rồi lùi camera ra. Trong hệ camera, các điểm phía trước có z âm. Phép chiếu perspective chia x và y cho `-z`; vì thế cùng một vật ở xa trông nhỏ hơn. Zoom thay khoảng cách camera, không thay spacing hoặc mass.

Trước khi kéo, hãy chọn một góc nhìn khiến vài hạt chồng lên nhau. Sau đó kéo để thấy chúng thuộc các lớp z khác nhau. Canvas dùng hệ nhỏ để quan sát; nó không chạy compute shader hoặc đo tốc độ GPU.

## Viết code từng bước

### 1. Tạo các lớp hạt trong world space

`Plan` đã giữ side và spacing. Thêm hàm tạo vị trí trong `include/model.hpp`; hàm này không biết kích thước cửa sổ:

{/* snippet include/model.hpp#initial-position */}

```cpp title="include/model.hpp — vị trí lattice"
inline Vec3 initialPosition(const Plan& plan, std::uint32_t i) {
    return {0.08 + (i % plan.side + 0.5) * plan.spacing, ((i / plan.side) % plan.side + 0.5) * plan.spacing, 0.3 + (i / (plan.side * plan.side) + 0.5) * plan.spacing};
}
```

Sau mỗi `side` hạt, ta sang hàng mới; sau `side * side` hạt, ta sang lớp mới. X lệch 0,08 m và z lệch 0,3 m để chừa khoảng trống cho dòng chảy. Hàng dưới cách sàn đúng spacing/2. Khi có gravity ở Bài 07, đáy khối bắt đầu bị nén rồi nước lan ra, không cần chờ cả khối rơi từ trên cao.

### 2. Giữ camera tách khỏi hạt

Camera nằm trong header riêng; thay các giá trị dưới đây không ghi vào state SPH:

{/* snippet include/camera.hpp#camera-state */}

```cpp title="include/camera.hpp — state của camera"
struct Camera {
    float yaw = 0.65F;
    float pitch = 0.45F;
    float zoom = 1;
};
```

Đổi world sang eye space theo đúng thứ tự dịch → yaw → pitch → lùi camera:

{/* snippet include/camera.hpp#camera-point */}

```cpp title="include/camera.hpp — world sang eye space"
inline Vec3 cameraPoint(Vec3 position, const Camera& camera) {
    const auto p = subtract(position, {0.5, 0.4, 0.5});
    const double x = std::cos(camera.yaw) * p.x + std::sin(camera.yaw) * p.z;
    const double depth = -std::sin(camera.yaw) * p.x + std::cos(camera.yaw) * p.z;
    const double y = std::cos(camera.pitch) * p.y - std::sin(camera.pitch) * depth;
    const double z = std::sin(camera.pitch) * p.y + std::cos(camera.pitch) * depth;
    return {x, y, z - 1.75 / camera.zoom};
}
```

Hai góc đều đo bằng radian. `1.75 / camera.zoom` là khoảng cách nhìn tới điểm ngắm; dấu trừ đặt khối trước camera theo hướng -Z. Đây là scaffold camera dùng lại kiến thức projection trước đó, không phải một phần của phương trình chất lưu.

### 3. Chiếu và vẽ preview

Preview chỉ dùng `gl.Scissor`/`gl.Clear` để vẽ các ô nhỏ. Bài 03 sẽ thay đường vẽ này bằng vertex/fragment shader; hiện tại chưa có buffer hạt trên GPU:

{/* snippet include/view.hpp#preview */}

```cpp title="include/view.hpp — vẽ preview CPU"
inline void drawPreview(lab::GlApi& gl, const Camera& camera, int width, int height, int viewportX = 0, int viewportY = 0) {
    // Bài đầu chỉ vẽ 64 hạt CPU bằng scaffold; chưa chạy solver GPU.
    gl.Enable(GL_SCISSOR_TEST);
    gl.ClearColor(0.25F, 0.7F, 0.95F, 1);
    const auto plan = makePlan(4);
    for (std::uint32_t i = 0; i < std::min(plan.count, 64U); ++i) {
        const auto p = cameraPoint(initialPosition(plan, i), camera);
        if (p.z >= -nearPlane) {
            continue;
        }
        const double scale = height * 0.5 * focalLength / -p.z;
        const int x = static_cast<int>(width / 2 + scale * p.x);
        const int y = static_cast<int>(height / 2 + scale * p.y);
        gl.Scissor(viewportX + x - 2, viewportY + y - 2, 4, 4);
        gl.Clear(GL_COLOR_BUFFER_BIT);
    }
    gl.Disable(GL_SCISSOR_TEST);
}
```

`focalLength = 1 / tan(25°)` tương ứng FOV dọc 50°. Scale phụ thuộc chiều cao framebuffer và `-p.z`, không nhân zoom thêm lần nữa. Điểm ở sau near plane bị bỏ trước khi chia. Scissor dùng gốc dưới-trái nên y được cộng; Canvas dùng gốc trên-trái nên đường vẽ web trừ y.

## Ghép các phần lại

Trong vòng lặp của `main.cpp`, lấy kích thước bằng `SDL_GetWindowSizeInPixels`, clear color/depth rồi gọi preview trước `SDL_GL_SwapWindow`. Ở checkpoint 1, nhánh render thực sự chạy là:

{/* snippet src/main.cpp#render-call */}

```cpp title="src/main.cpp — gọi preview trong frame"
view.drawn = 64;
drawPreview(gl, view.camera, width, height, sceneX, sceneY);
```

Main đã nối drag với yaw/pitch, wheel với zoom, Home để đặt lại và release capture khi thả chuột/mất focus. Build target `project_51_checkpoint_1`; `starter` vẫn là cửa sổ nền trống. Mã hoàn chỉnh bên dưới chứa cả khung và vị trí gọi, không chỉ các helper trong bài.

## Thử làm sai để hiểu đúng

1. Đổi lớp z thành `i / side`. Dự đoán khối sẽ kéo dài theo hướng nào rồi chạy và khôi phục `side * side`.
2. Thay mẫu số `-p.z` bằng một hằng số. Hình vẫn quay được nhưng hạt xa/gần không còn đổi kích thước biểu kiến: bạn vừa trở lại phép chiếu trực giao.
3. Thay đổi position trong state mỗi lần kéo. Sau vài vòng quay, so tọa độ hạt với lúc đầu; khôi phục việc xoay chỉ trong camera.

## Tự kiểm tra kết quả

- Có 64 vị trí khác nhau theo cả ba trục; đổi góc nhìn giúp tách các hạt đang chồng hình.
- Kéo/zoom không đổi vị trí world của hạt, spacing hoặc số hạt. Home khôi phục góc nhìn.
- Resize không kéo dẹt khối. Không có gravity, density hoặc tick tự tiến trong bài này.
