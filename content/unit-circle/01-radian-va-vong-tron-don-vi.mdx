# Từ một đường tròn có sẵn đến góc radian

## Vấn đề cần giải quyết

Project 06 kết thúc với một bảng vector kéo được. Bây giờ ta xây một mô phỏng khác: một chiếc kim quay quanh tâm đường tròn, kèm hình chiếu và hai đồ thị sin/cos. Để đến đó, trước hết hãy mở được đường tròn trên màn hình và thống nhất cách đo góc.

Bài này chưa cho kim chạy. Checkpoint 01 thêm góc radian, các mốc thử và cung màu cam lên bộ khung đã chạy được.

## Hiểu ý tưởng trước khi viết code

Một radian là góc chắn một cung có độ dài đúng bằng bán kính. Nếu bán kính là r và cung dài s, góc θ = s/r. Đường tròn có chu vi 2πr, nên đi hết một vòng tương ứng 2π radian — không phải 360 radian.

| Góc quen thuộc | Radian | Hướng từ gốc |
|---|---|---|
| 0° | 0 | Sang phải |
| 90° | π/2 | Lên trên |
| 180° | π | Sang trái |
| 270° | 3π/2 | Xuống dưới |
| 360° | 2π | Trở lại bên phải |

Một góc có thể chứa nhiều vòng quay, nhưng vị trí sau cùng chỉ cần phần còn lại trong một vòng. Ta giữ `angle` trong khoảng [0,2π): lấy 0, không lấy 2π.

<InteractiveLab demo="angle" mode="angle-radians" />

Chọn **1 rad** và hình dung cung dài bằng bán kính của chính nó. Sau đó chọn 360° hoặc nhập góc âm: ô “góc vừa nhập / s/r” giữ giá trị bạn đưa vào; ô `angle` cho biết góc sau normalize. Cung minh họa chỉ vẽ tối đa một vòng. Chưa có đầu kim ở bài này; ta sẽ tính vị trí của nó trong bài 2.

## Viết code từng bước

### Bước 1 — Chạy đường tròn trước khi sửa code

Tải ZIP Project 07 ở đầu học phần, giải nén rồi mở terminal tại thư mục chứa CMakeLists.txt:

```bash title="Terminal — build và chạy starter"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_7_starter --parallel 2
.\build\Debug\project_7_starter.exe
```

Starter SDL3 đã có window, renderer, streaming texture, framebuffer và primitive từ Project 04. Hàm sau trong include/view.hpp ghép chúng thành bảng học toán:

```cpp title="include/view.hpp — đường tròn và trục đã có trong bộ khung"
inline void drawBoard(Framebuffer& image) {
    image.clear(kBackground);
    drawLine(image, 55, 390, 495, 390, kGuide);
    drawLine(image, 275, 170, 275, 610, kGuide);
    drawCircle(image, 275, 390, 185, kGuide);
    for (int sign : {-1, 1}) {
        drawLine(image, 275 + sign * 185, 385, 275 + sign * 185, 395, kWhite);
        drawLine(image, 270, 390 + sign * 185, 280, 390 + sign * 185, kWhite);
    }
}
```

Bạn phải thấy một đường tròn, trục X/Y và các vạch ±1. Một world unit được biểu diễn bằng 185 pixel của bảng logic. Resize không biến đường tròn thành ellipse: SDL letterbox toàn bảng 1100×760, không thay đổi dữ liệu toán học.

### Bước 2 — Đổi đơn vị ở ranh giới nhập và hiển thị

Thêm vào namespace lab trong include/lab.hpp:

```cpp title="include/lab.hpp — degree sang radian"
inline double degreesToRadians(double degrees) {
    return degrees * (kPi / 180.0);
}
```

```cpp title="include/lab.hpp — radian sang degree"
inline double radiansToDegrees(double radians) {
    return radians * (180.0 / kPi);
}
```

Nhân 90 với π/180 cho π/2. Ta chỉ dùng degree để người dùng nhập hoặc đọc cho quen; các phép lượng giác ở bài sau nhận radian. Hai hằng kPi/kTau đã được khai báo trong cùng header.

### Bước 3 — Giữ góc trong một vòng

Vẫn trong include/lab.hpp:

```cpp title="include/lab.hpp — chuẩn hóa góc, kể cả góc âm"
inline double normalizeAngle(double angle) {
    if (!std::isfinite(angle)) {
        return 0.0;
    }
    double normalized = std::fmod(angle, kTau);
    if (normalized < 0.0) {
        normalized += kTau;
    }
    // Cộng một số âm rất nhỏ vào 2π có thể bị làm tròn thành đúng 2π.
    if (normalized >= kTau || normalized == 0.0) {
        return 0.0;
    }
    return normalized;
}
```

`fmod(-π/2,2π)` trả phần dư âm, nên phải cộng thêm một vòng. Nhánh cuối xử lý cả −0 và trường hợp một số âm cực nhỏ làm phép cộng bị làm tròn thành đúng 2π. Giá trị NaN/infinity không phải một góc hợp lệ; ở đây ta chủ động dùng 0 làm fallback, không coi nó là kết quả lượng giác đúng.

### Bước 4 — Đưa giá trị nhập vào scene

include/scene.hpp giữ góc qua các frame. Thay Scene rỗng của starter bằng:


```cpp title="include/scene.hpp — state của checkpoint đầu tiên"
struct Scene {
    double angle{};
};
```

Ngay dưới Scene, thêm đường vào duy nhất khi đổi góc bằng tay:

```cpp title="include/scene.hpp — gán góc đã normalize"
inline void setManualAngle(Scene& scene, double angle) {
    scene.angle = normalizeAngle(angle);
}
```

Trong event loop của checkpoint 01, ←/→ thêm/bớt 5° rồi gọi hàm này. F1–F4 thử bốn góc chính; F5 thử 1 radian. include/view.hpp dùng drawAngleArc vẽ cung màu cam. Phần rasterize cung đã được ghép sẵn; bài này tập trung vào đơn vị và dữ liệu góc.

## Ghép các phần lại

Build project_7_checkpoint_1 và chạy nó, không chạy lại starter rồi chờ thấy chức năng mới. Luồng hiện tại là phím → setManualAngle → Scene.angle → renderScene. Bạn chưa lưu một điểm cuối hay một vận tốc nào.

Trên Windows với Visual Studio, executable nằm trong build/Debug. Với generator một cấu hình trên Linux/macOS, đặt CMAKE_BUILD_TYPE=Debug rồi chạy executable ngay trong build. Cuối bài có toàn bộ mã chạy được của checkpoint để đối chiếu.

## Thử làm sai để hiểu đúng

1. Bỏ phép chia 180 trong degreesToRadians, rồi thử góc 90°. Cung không còn tương ứng một phần tư vòng; ghi lại sai số trước khi sửa.
2. Bỏ nhánh cộng kTau khi phần dư âm. Nhấn ← từ 0 và kiểm tra angle: bạn đã phá cam kết [0,2π).
3. Thay fmod bằng vòng lặp trừ từng vòng. Đừng thử góc khổng lồ trong ứng dụng; hãy giải thích vì sao cách này có thể làm chương trình đứng rất lâu.

## Tự kiểm tra kết quả

- Starter và checkpoint 01 đều build/run độc lập.
- 180° đổi ra π; 2π đổi ra 360°.
- normalizeAngle(2π) trả 0; normalizeAngle(−π/2) gần 3π/2.
- 0≤angle và angle nhỏ hơn 2π, kể cả với số âm rất nhỏ.
- Đường tròn, trục và cung không méo sau resize; chưa có kim quay là đúng phạm vi bài.
