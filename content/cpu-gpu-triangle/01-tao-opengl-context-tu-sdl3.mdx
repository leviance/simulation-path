# Tạo OpenGL context từ SDL3

## Vấn đề cần giải quyết

Ở Project 16, bạn đã tự quyết định pixel nào nằm trong tam giác và tính màu cho pixel ấy. Sang đây, ta giao phần việc đó cho GPU, nhưng vẫn giữ renderer CPU để đối chiếu. Đích đến là một cửa sổ có hai tam giác nhận cùng dữ liệu; khi sửa một đỉnh, cả hai phía phải thay đổi cùng lúc.

Bài đầu chưa vội vẽ tam giác. Hãy mở ZIP và chạy `project_33_starter` trước: cửa sổ phải mở, resize và đóng bình thường. Ta giữ vòng lặp SDL ấy, thay phần hiển thị bằng OpenGL 3.3 Core. Cuối bài, bạn sẽ thấy hai vùng nền khác màu — đủ để kiểm tra đường đi từ window tới framebuffer trước khi thêm shader.

## Hiểu ý tưởng trước khi viết code

Window là cửa sổ của hệ điều hành; context giữ trạng thái và tài nguyên OpenGL. Context phải được tạo, gắn với thread hiện tại bằng `SDL_GL_MakeCurrent`, rồi mới load function pointers qua `SDL_GL_GetProcAddress`. Sau khi vẽ, `SDL_GL_SwapWindow` đưa back buffer ra màn hình.

Ta lấy kích thước bằng `SDL_GetWindowSizeInPixels`, vì viewport và scissor nhận pixel thật. Tọa độ chuột SDL vẫn là logical coordinates; bài cuối mới nối hai hệ đó khi kéo đỉnh.

## Viết code từng bước

### Bước 1 — Yêu cầu OpenGL 3.3 Core trước khi tạo window

Trước tiên, tải ZIP của project, giải nén và mở terminal tại thư mục có CMakeLists.txt. Build target project_33_starter rồi chạy nó: bạn phải mở, đóng và thay đổi kích thước cửa sổ được trước khi thêm OpenGL. Starter đã có SDL_Init, SDL_CreateWindow, SDL_PollEvent và cleanup; ta thay phần hiển thị, không viết thêm một vòng lặp thứ hai.

Trong src/main.cpp, đặt hàm dưới đây vào namespace ẩn ở đầu file. Gọi nó sau SDL_Init và trước SDL_CreateWindow. Nếu trả về false, in SDL_GetError rồi SDL_Quit và kết thúc chương trình; đừng tiếp tục tạo window với cấu hình chưa thiết lập thành công.

```cpp title="src/main.cpp — requestOpenGl33Core"
bool requestOpenGl33Core() {
    return SDL_GL_SetAttribute(SDL_GL_CONTEXT_MAJOR_VERSION, 3) &&
        SDL_GL_SetAttribute(SDL_GL_CONTEXT_MINOR_VERSION, 3) &&
        SDL_GL_SetAttribute(SDL_GL_CONTEXT_PROFILE_MASK, SDL_GL_CONTEXT_PROFILE_CORE) &&
        SDL_GL_SetAttribute(SDL_GL_DOUBLEBUFFER, 1);
}
```

Ta chọn Core Profile để không vô tình dựa vào `glBegin/glEnd`, matrix stack hay API fixed-function cũ. Project này sẽ dùng shader, VBO và VAO ngay từ đầu.

### Bước 2 — Tạo window rồi mới tạo context

```cpp title="src/main.cpp — window flags và context"
SDL_WindowFlags windowFlags = SDL_WINDOW_RESIZABLE;
windowFlags |= SDL_WINDOW_OPENGL;
windowFlags |= SDL_WINDOW_HIGH_PIXEL_DENSITY;
```

Sau khi `SDL_CreateWindow` thành công, ta gọi `SDL_GL_CreateContext(window)` rồi `SDL_GL_MakeCurrent(window, context)`. Mỗi lời gọi đều được kiểm tra riêng; nếu context bằng null, không có lệnh OpenGL nào được phép chạy.

Đây là phần cần thêm ngay sau nhánh kiểm tra window. Window là cửa sổ của hệ điều hành; context mới là nơi OpenGL giữ trạng thái vẽ và tài nguyên. Vì vậy tạo được window chưa chứng minh OpenGL đã sẵn sàng.

```cpp title="src/main.cpp — tạo context và gắn với thread hiện tại"
SDL_GLContext context = SDL_GL_CreateContext(window);
if (!context) {
    std::cerr << "SDL_GL_CreateContext failed: " << SDL_GetError() << '\n';
    SDL_DestroyWindow(window);
    SDL_Quit();
    return EXIT_FAILURE;
}
if (!SDL_GL_MakeCurrent(window, context)) {
    std::cerr << "SDL_GL_MakeCurrent failed: " << SDL_GetError() << '\n';
    destroyWindowAndContext(window, context);
    return EXIT_FAILURE;
}
```

Helper destroyWindowAndContext ở đầu file hủy context trước, rồi window và SDL. Nó dùng chung cho đường lỗi và lúc thoát bình thường; source đầy đủ của checkpoint nằm cuối trang để bạn kiểm lại cả khai báo lẫn thứ tự gọi.

### Bước 3 — Load function qua context hiện tại

```cpp title="include/gl_api.hpp — loadOne"
template <typename Function>
bool loadOne(Function& destination, const char* name) {
    destination = reinterpret_cast<Function>(SDL_GL_GetProcAddress(name));
    if (destination) {
        return true;
    }
    missingFunction = name;
    return false;
}
```

Loader giữ tên function đầu tiên bị thiếu. Vì vậy lỗi startup sẽ nói rõ `glCreateShader` hay `glGenVertexArrays` không load được, thay vì crash ở một con trỏ null không có ngữ cảnh.

loadOne là phương thức của GlApi trong include/gl_api.hpp, không phải một hàm cần chép vào main. Sau khi context current, tạo đối tượng và gọi loader như sau:

```cpp title="src/main.cpp — kiểm loader trước lần vẽ đầu tiên"
lab::GlApi gl{};
if (!gl.load()) {
    std::cerr << "SDL_GL_GetProcAddress failed for " << gl.missingFunction << '\n';
    destroyWindowAndContext(window, context);
    return EXIT_FAILURE;
}
```

### Bước 4 — Chia framebuffer theo pixel thật

```cpp title="src/main.cpp — framebuffer pixels và hai panel"
const int leftWidth = framebufferWidth / 2;
const int rightWidth = framebufferWidth - leftWidth;
```

`framebufferWidth` và `framebufferHeight` đến từ `SDL_GetWindowSizeInPixels`, không phải `SDL_GetWindowSize`. Nếu width lẻ, panel phải nhận phần dư nên hai vùng vẫn phủ đủ framebuffer.

## Ghép các phần lại

Giữ SDL_PollEvent ở đầu vòng lặp. Đọc framebuffer size, tính leftWidth/rightWidth, clear bằng scissor, rồi swap. Không tạo SDL_Renderer và không gọi SDL_RenderPresent trong nhánh OpenGL.

Nếu cửa sổ thu nhỏ tới mức không có vùng vẽ, bỏ qua frame đó. Ứng dụng vẫn phải xử lý event, không cấp một framebuffer giả rồi tiếp tục như thể kích thước hợp lệ. Hãy chạy checkpoint 01 trước khi chuyển sang compile shader.

```bash title="Terminal — build và chạy checkpoint 01"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_33_checkpoint_1 --parallel 2
./build/Debug/project_33_checkpoint_1.exe
```

Đường chạy trên dành cho Visual Studio trên Windows. Với Ninja, chọn CMAKE_BUILD_TYPE khi configure và chạy executable ngay trong build, không có thư mục Debug/Release trung gian. Mọi checkpoint và final đều nằm trong cùng ZIP; bạn không cần Node.js để build C++.

## Thử làm sai để hiểu đúng

Chỉ thay một chi tiết mỗi lần trên bản thử nghiệm. Ghi dự đoán trước, chạy để quan sát rồi phục hồi mã đúng trước khi đi tiếp.

1. Đổi màu clear bên trái rồi chạy lại. Dự đoán trước vùng nào đổi; sau đó kiểm vùng phải vẫn giữ màu cũ.
2. Tạm bỏ bật scissor, vẫn giữ hai lần clear. Quan sát lần clear cuối phủ toàn cửa sổ, rồi khôi phục trước khi sang shader.

## Bài tập mở rộng

1. In cả logical window size và framebuffer pixel size, rồi so trên display scale khác 100%.
2. Tạm yêu cầu OpenGL 9.9 để quan sát đường lỗi context creation, sau đó phục hồi 3.3.
3. Đổi màu hai scissor regions nhưng giữ alpha bằng 1 để xác nhận clear state độc lập với shader.

Bài tiếp theo sẽ compile vertex shader và fragment shader đầu tiên, nhưng vẫn chưa draw tam giác. Ta sẽ giữ shader diagnostics sạch trước khi thêm vertex data.
