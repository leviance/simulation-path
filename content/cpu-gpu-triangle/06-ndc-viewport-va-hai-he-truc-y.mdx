# NDC, viewport và hai hệ trục Y

## Vấn đề cần giải quyết

Hai tam giác cùng xoay đúng chưa có nghĩa ta có thể dùng chung một hàm đổi tọa độ pixel. Mảng ảnh CPU bắt đầu từ góc trên-trái; OpenGL window coordinates bắt đầu từ góc dưới-trái. Nhầm hai quy ước này thường làm ảnh lật dọc hoặc đọc nhầm pixel dù hình tam giác vẫn có vẻ đúng.

Bài này nối NDC với tọa độ thật trong từng panel và xử lý resize/high-DPI. Ta cũng chốt một giới hạn quan trọng: đây là thí nghiệm tam giác 2D trong NDC, không phải camera perspective. Đổi tỉ lệ cửa sổ có thể làm tam giác trông rộng hoặc cao hơn; hai phía phải biến đổi giống nhau, không được sửa một phía bằng hệ số aspect giấu trong shader.

## Hiểu ý tưởng trước khi viết code

NDC x/y chạy từ −1 tới +1. CPU top-left mapping đảo Y; GPU bottom-left mapping cộng origin viewport nhưng không đảo Y. Hai cặp forward/inverse phải round-trip trong sai số đã công bố.

Nếu framebuffer rộng 803 pixel, nửa trái rộng 401 và nửa phải 402. Cùng một NDC có thể rơi ở tâm mẫu khác nhau giữa hai panel. Phép kiểm ảnh GPU vì thế tạo CPU reference đúng bằng kích thước panel phải, không so mù hai mảng trái/phải theo cùng index.

## Viết code từng bước

### Bước 1 — NDC sang CPU top-left screen

```cpp title="include/pipeline.hpp — ndcToCpuScreen"
inline Vec2 ndcToCpuScreen(Vec2 position, int width, int height) {
    return {
        (position.x * 0.5F + 0.5F) * float(width),
        (1.0F - (position.y * 0.5F + 0.5F)) * float(height),
    };
}
```

Số `1 -` đảo Y. NDC `(+0,+1)` đi lên hàng đầu, còn NDC `(+0,-1)` đi xuống đáy framebuffer.

### Bước 2 — NDC sang GPU bottom-left window

```cpp title="include/pipeline.hpp — ndcToGpuWindow"
inline Vec2 ndcToGpuWindow(Vec2 position, const Viewport& viewport) {
    return {
        float(viewport.x) + (position.x * 0.5F + 0.5F) * float(viewport.width),
        float(viewport.y) + (position.y * 0.5F + 0.5F) * float(viewport.height),
    };
}
```

Ở đây không đảo Y. `viewport.x = leftWidth` dịch panel GPU sang nửa phải của framebuffer thật.

### Bước 3 — Giữ inverse để test round-trip

```cpp title="include/pipeline.hpp — gpuWindowToNdc"
inline Vec2 gpuWindowToNdc(Vec2 position, const Viewport& viewport) {
    return {
        (position.x - float(viewport.x)) / float(viewport.width) * 2.0F - 1.0F,
        (position.y - float(viewport.y)) / float(viewport.height) * 2.0F - 1.0F,
    };
}
```

CTest kiểm công thức này mà không cần GPU: đưa điểm NDC qua phép đổi viewport rồi đổi ngược, sau đó so với điểm ban đầu trong sai số nhỏ. Việc này kiểm công thức CPU; đến bài readback ta mới có bằng chứng từ ảnh GPU thật.

### Bước 4 — Resize mọi storage từ pixel size thật

Khi `leftWidth` hoặc height đổi, CPU framebuffer resize và texture gọi lại `glTexImage2D`. Mỗi frame, hai `glViewport` nhận left/right width mới. Không dùng CSS size hay logical window size cho các bước này.

## Ghép các phần lại

Đọc size mỗi frame bằng SDL_GetWindowSizeInPixels. Khi size đổi, resize framebuffer CPU và texture trước upload; glViewport nhận kích thước mới ở cả hai phía. Input chuột sẽ dùng SDL_GetWindowSize để quy đổi logical → pixel, không thay thế pixel size của viewport.

Kích thước bằng 0 được bỏ qua; kích thước vượt budget được báo rõ và vẫn giữ event loop. Như vậy resize không vô tình trở thành một phép cấp phát hàng trăm megabyte hay phép chia cho 0.

## Thử làm sai để hiểu đúng

Chỉ thay một chi tiết mỗi lần trên bản thử nghiệm. Ghi dự đoán trước, chạy để quan sát rồi phục hồi mã đúng trước khi đi tiếp.

1. Resize sang chiều rộng lẻ. Ghi hai chiều rộng và kiểm tổng bằng framebuffer width; quan sát panel phải nhận pixel dư.
2. Đổi công thức readback sang Y top-left trên bản thử nghiệm ở bài 08. Dự đoán pixel sẽ bị phản chiếu theo chiều dọc; quay lại đây để chỉ đúng chỗ cần đổi hệ, không rải dấu trừ trong nhiều hàm.

## Tự kiểm tra kết quả

- [ ] CPU mapping có đảo Y; GPU mapping không đảo Y.
- [ ] Cả hai mapping đều có inverse và round-trip test.
- [ ] `leftWidth + rightWidth == framebufferWidth`.
- [ ] CPU framebuffer, texture storage và viewports cùng resize.
- [ ] Hai panel không overlap hoặc để cột trống.
- [ ] Title bar dùng pixel size từ `SDL_GetWindowSizeInPixels`.

## Bài tập mở rộng

1. Kéo Canvas probe tới bốn góc NDC và ghi lại hai hệ tọa độ pixel.
2. Thêm divider một pixel; cập nhật công thức panel widths để tổng vẫn đúng.
3. Viết test round-trip cho viewport có origin khác 0 ở cả X lẫn Y.

Bài sau sẽ bật vertex colors để so barycentric interpolation CPU với varying interpolation của GPU.
