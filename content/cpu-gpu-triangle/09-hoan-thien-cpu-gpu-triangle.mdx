# Hoàn thiện CPU/GPU Triangle

## Vấn đề cần giải quyết

Mỗi stage riêng đã chạy, nhưng một project hoàn chỉnh còn phải giữ đúng lifecycle khi reset, resize, shader lỗi hoặc người dùng thoát. Bài cuối không thêm thuật toán đồ họa mới; nó biến các checkpoint thành một ứng dụng có thể kiểm chứng và một bộ source có thể build độc lập.

## Hiểu ý tưởng trước khi viết code

Bản final không ghép code bằng cách dồn mọi thứ vào `main`. Nó giữ state mô phỏng, tài nguyên GPU, framebuffer CPU và validation ở đúng vai trò để từng phần vẫn có thể kiểm tra riêng.

## Viết code từng bước

### Bước 1 — Ghép update và render mà không trộn state

Input chỉ sửa `Transform2D`, `paused`, `smoothColor` hoặc đặt `probeRequested`. Update tiến angle. Render dùng cùng snapshot transform cho CPU framebuffer và GPU uniforms trong một frame.

```cpp title="src/main.cpp — fixed angle step"
if (!paused) {
    transform.angleRadians += deltaSeconds * 0.5F;
}
if (singleStep) {
    transform.angleRadians += kFixedAngleStep;
}
```

Không có CPU angle và GPU angle riêng. Nếu tách hai biến, pause/step có thể làm chúng lệch dù công thức transform đúng.

### Bước 2 — Giữ từng validation có tên

```cpp title="include/pipeline.hpp — PipelineValidationReport"
struct PipelineValidationReport {
    bool vertexLayout{};
    bool transformOrder{};
    bool cpuRoundTrip{};
    bool gpuRoundTrip{};
    bool centroidWeights{};
    bool deterministicRaster{};
    bool rgba8Tolerance{};
};
```

Các check này chạy bằng code CPU thuần nên CTest không mở window. Runtime `P` bổ sung bằng chứng từ GPU thật nhưng không thay thế unit tests.

### Bước 3 — Cleanup theo dependency

```cpp title="src/main.cpp — cleanup đúng thứ tự"
cpuPresenter.destroy(gl);
gpuTriangle.destroy(gl);
destroyWindowAndContext(window, context);
```

Texture, VAO, VBO và program phải được xóa khi context còn sống. `destroyWindowAndContext` mới destroy context, window rồi `SDL_Quit`.

## Ghép các phần lại

Khi ba khối trên đứng đúng chỗ, `main` chỉ còn điều phối lifecycle: nhận input, cập nhật state, render CPU/GPU từ cùng snapshot, đo khi được yêu cầu rồi cleanup theo thứ tự ngược lúc tạo.

### Build và chạy bản hoàn chỉnh

```bash title="Terminal — nghiệm thu Debug"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure --timeout 20
```

```bash title="Terminal — nghiệm thu Release"
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure --timeout 20
```

Chạy `project_33_final` rồi thử đủ `Space`, `N`, arrows, `Q/E`, `C`, `P`, `R`, resize và `Esc`. App pause mặc định; scale bị giới hạn để triangle không biến mất ngoài ý muốn.

## Source hoàn chỉnh gồm những gì?

- `include/pipeline.hpp`: contract CPU có thể test—vertex layout, transform, viewport mapping, barycentric raster và validation.
- `include/gl_api.hpp`: tập OpenGL function pointers tối thiểu, load sau context.
- `include/gpu_renderer.hpp`: shader diagnostics, VBO/VAO, texture presenter và readback.
- `src/main.cpp`: lifecycle SDL/OpenGL cùng render hai panel.
- `tests/tests.cpp`: test code thuần, không phụ thuộc GPU hoặc window.

Phần “Mã hoàn chỉnh” bên dưới bài lấy trực tiếp từ final checkpoint. Đây chính là source trong ZIP, không phải bản rút gọn viết lại cho tài liệu.

## Thử làm sai để hiểu đúng

1. Destroy context trước `gpuTriangle.destroy`. Function pointers/resources không còn context hợp lệ.
2. Giữ `probeRequested=true` sau readback. App vô tình đồng bộ CPU/GPU mỗi frame.
3. Resize viewport nhưng không resize CPU texture. Panel trái méo hoặc upload lỗi.
4. Chỉ chạy Release vì “GPU code không cần Debug”. Shader/runtime lifecycle vẫn cần cả hai cấu hình.
5. Assert GPU pixel đúng trên edge. Test trở nên phụ thuộc coverage convention thay vì contract cần học.
