# Hoàn thiện ứng dụng đối chiếu CPU và GPU

## Vấn đề cần giải quyết

Mỗi stage riêng đã chạy, nhưng một project hoàn chỉnh còn phải giữ đúng lifecycle khi reset, resize, shader lỗi hoặc người dùng thoát. Bài cuối không thêm thuật toán đồ họa mới; nó biến các checkpoint thành một ứng dụng có thể kiểm chứng và một bộ source có thể build độc lập.

## Hiểu ý tưởng trước khi viết code

Bản final không ghép code bằng cách dồn mọi thứ vào `main`. Nó giữ state mô phỏng, tài nguyên GPU, framebuffer CPU và validation ở đúng vai trò để từng phần vẫn có thể kiểm tra riêng.

## Viết code từng bước

### Bước 1 — Ghép update và render mà không trộn state

Input sửa Transform2D hoặc mảng triangle dùng chung; không có một bản tam giác riêng cho GPU. Update tiến angle. Render dùng cùng snapshot transform cho CPU framebuffer và GPU uniforms trong một frame.

```cpp title="src/main.cpp — fixed angle step"
if (!paused) {
    transform.angleRadians += deltaSeconds * 0.5F;
    probeStatus = "ANIMATING - PAUSE THEN P TO MEASURE";
}
if (singleStep) {
    transform.angleRadians += kFixedAngleStep;
}
```

Không có CPU angle và GPU angle riêng. Nếu tách hai biến, pause/step có thể làm chúng lệch dù công thức transform đúng.

### Bước 2 — Sửa input chung, không sửa riêng ảnh bên trái

Khai báo `std::array<lab::GpuVertex, 3> triangle = lab::kSourceTriangle;` trong phần state của main. Khi kéo đỉnh, tọa độ con trỏ đang ở NDC sau transform; muốn sửa position trong VBO, phải đảo transform trước. Thêm helper trong include/editor.hpp:

```cpp title="include/editor.hpp — đưa vị trí kéo về tọa độ của vertex"
inline Vec2 inverseTransformPosition(Vec2 ndc, const Transform2D& transform) {
    const float x = (ndc.x - transform.translation.x) / transform.scale;
    const float y = (ndc.y - transform.translation.y) / transform.scale;
    const float cosine = std::cos(transform.angleRadians);
    const float sine = std::sin(transform.angleRadians);
    return {x * cosine + y * sine, -x * sine + y * cosine};
}
```

Ta trừ translation, chia scale rồi xoay góc ngược lại. Thứ tự đảo phải ngược với thứ tự tạo transform. Scale của ứng dụng luôn dương và không nhỏ hơn 0,25 nên phép chia hợp lệ.

pointerToPanel đổi tọa độ SDL theo logical size sang pixel size thật, rồi xác định panel và NDC. pickVertex chọn đỉnh gần con trỏ trong bán kính 20 framebuffer pixel. Khi bắt đầu kéo, lưu vertex cũ, pause chuyển động và capture mouse. Kéo ra panel khác không được nhảy sang một hệ tọa độ mới; thả chuột kết thúc, Escape hoàn tác vertex, mất focus nhả capture và giữ pause. Các nhánh event đầy đủ có trong src/main.cpp của checkpoint.

Sau khi cập nhật position hoặc color của triangle, đặt verticesDirty. Chỉ khi cờ này bật mới gửi lại ba vertex; không tạo VAO/VBO mới mỗi frame:

```cpp title="include/gpu_renderer.hpp — cập nhật đúng VBO đang dùng"
void uploadVertices(GlApi& api, const std::array<GpuVertex, 3>& triangle) const {
    api.BindBuffer(GL_ARRAY_BUFFER, vertexBuffer);
    api.BufferData(GL_ARRAY_BUFFER, GLsizeiptr(sizeof(triangle)), triangle.data(), GL_DYNAMIC_DRAW);
    api.BindBuffer(GL_ARRAY_BUFFER, 0U);
}
```

CPU rasterizer nhận chính triangle ấy; GPU nhận cùng byte qua VBO. readGpuProbe cũng nhận triangle hiện tại, không dùng tam giác mặc định sau khi người học đã kéo đỉnh. Phím 1/2/3 chọn A/B/C, I/J/K/L sửa position bằng bàn phím và V đổi màu vertex được chọn. V đồng thời bật smooth để màu sửa được nhìn thấy.

### Bước 3 — Đọc probe trước, vẽ nhãn sau

include/overlay.hpp vẽ nhãn CPU/GPU, A/B/C, tọa độ NDC và hướng dẫn bằng một font bitmap nhỏ dùng scissored clear. Đây chỉ là lớp chú thích, không rasterize thay tam giác. Bảng bên GPU ghi **NDC expected**: các tọa độ đó là đầu ra dự kiến tính từ contract C++, không phải kết quả đọc trực tiếp từ vertex shader. Bằng chứng GPU thật vẫn đến từ pixel readback.

Gọi drawPipelineOverlay **sau** readGpuProbe và trước swap. Nếu đọc sau khi vẽ nhãn, probe có thể gặp chữ hoặc marker thay vì fragment của tam giác. Khi input đổi, báo cáo cũ được đánh dấu cần đo lại; không để một con số từ trạng thái cũ trông như kết quả hiện tại.

### Bước 4 — Giữ từng validation có tên

```cpp title="include/pipeline.hpp — PipelineValidationReport"
struct PipelineValidationReport {
    bool vertexLayout{};
    bool transformOrder{};
    bool cpuRoundTrip{};
    bool gpuRoundTrip{};
    bool centroidWeights{};
    bool deterministicRaster{};
    bool rgba8Tolerance{};
};
```

Các check này chạy bằng code CPU thuần nên CTest không mở window. Runtime `P` bổ sung bằng chứng từ GPU thật nhưng không thay thế unit tests.

Chạy final với --verify để kiểm driver thật trong cửa sổ ẩn. Sáu frame hữu hạn lần lượt kiểm solid, smooth, transform, winding đảo, vertex/màu đã sửa và resize width lẻ. Mỗi frame so ba điểm nội thất và một điểm nền; tolerance là 2/255 cho mỗi channel sau RGBA8. Fixture trả exit code khác 0 nếu lệch màu, sai coverage nội thất hoặc có lỗi OpenGL. Đây không phải benchmark hiệu năng và không thay kiểm thao tác bằng tay.

Chế độ này còn đọc toàn bộ panel GPU rồi so với framebuffer CPU có **cùng kích thước panel phải**. Hàng GPU được đảo về top-left trước khi so. Pixel có sai khác lớn hơn 2 mức màu chỉ được nằm cách một cạnh tam giác tối đa 1,5 pixel; sai khác sâu trong nội thất hoặc ở nền xa tam giác làm fixture thất bại. Dải cạnh này là giới hạn kiểm chứng công bố rõ, không phải lời khẳng định hai rasterizer có fill rule giống hệt nhau. Với width lẻ, không so hai panel có chiều rộng khác nhau bằng cùng index.

### Bước 5 — Cleanup theo dependency

```cpp title="src/main.cpp — cleanup đúng thứ tự"
cpuPresenter.destroy(gl);
gpuTriangle.destroy(gl);
destroyWindowAndContext(window, context);
```

Texture, VAO, VBO và program phải được xóa khi context còn sống. `destroyWindowAndContext` mới destroy context, window rồi `SDL_Quit`.

## Source hoàn chỉnh gồm những gì?

- `include/pipeline.hpp`: contract CPU có thể test—vertex layout, transform, viewport mapping, barycentric raster và validation.
- `include/gl_api.hpp`: tập OpenGL function pointers tối thiểu, load sau context.
- `include/gpu_renderer.hpp`: shader diagnostics, VBO/VAO, texture presenter và readback.
- `include/editor.hpp`: mapping con trỏ high-DPI, chọn vertex và inverse transform.
- `include/overlay.hpp`: nhãn, tọa độ và controls trực tiếp trong cửa sổ.
- `include/verification.hpp`: fixture đọc màu từ OpenGL thật trong chế độ --verify.
- `src/main.cpp`: lifecycle SDL/OpenGL cùng render hai panel.
- `tests/tests.cpp`: test code thuần, không phụ thuộc GPU hoặc window.

Phần “Mã hoàn chỉnh” bên dưới bài lấy trực tiếp từ final checkpoint. Đây chính là source trong ZIP, không phải bản rút gọn viết lại cho tài liệu.

## Thử làm sai để hiểu đúng

1. Destroy context trước `gpuTriangle.destroy`. Function pointers/resources không còn context hợp lệ.
2. Giữ `probeRequested=true` sau readback. App vô tình đồng bộ CPU/GPU mỗi frame.
3. Resize viewport nhưng không resize CPU texture. Panel trái méo hoặc upload lỗi.
4. Chỉ chạy Release vì “GPU code không cần Debug”. Shader/runtime lifecycle vẫn cần cả hai cấu hình.
5. Assert GPU pixel đúng trên edge. Test trở nên phụ thuộc coverage convention thay vì contract cần học.
