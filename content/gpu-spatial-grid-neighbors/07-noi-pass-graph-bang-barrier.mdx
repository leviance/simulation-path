# Nối các compute pass bằng barrier

## Bài toán cần giải quyết

Các compute pass đã có đủ, nhưng gửi đúng thứ tự vẫn chưa đảm bảo pass sau nhìn thấy dữ liệu pass trước vừa ghi. Giữa count, scan, scatter và tìm hàng xóm, bước đọc tiếp theo đều là compute shader; trước readback, CPU lại là bên đọc. Ta sẽ ghi rõ từng cặp ghi–đọc và chọn barrier bit phù hợp. Trong tài liệu OpenGL, bên đọc tiếp theo thường được gọi là **consumer**.

Ta sẽ ngừng nói “thêm barrier cho chắc”. Thay vào đó, với mỗi pass, hãy ghi rõ buffer nào vừa được sửa và bước tiếp theo sẽ đọc nó bằng compute shader hay CPU readback.

## Theo dõi một particle đi qua grid

Pass graph final:

```text
clear counts
  → count cells
  → scan counts / recursive sums / uniform add
  → prepare cursors
  → scatter indices
  → find neighbors
  → readback validation/heatmap
```

Các cạnh compute→compute dùng `GL_SHADER_STORAGE_BARRIER_BIT`. Chỉ cạnh cuối compute→`glGetBufferSubData` dùng `GL_BUFFER_UPDATE_BARRIER_BIT`. `barrier()` trong scan shader chỉ đồng bộ lanes **trong một workgroup**; nó không nối hai dispatch.

## Xây từng phần

### Bước 1 — Nhật ký phải ghi cả buffer vừa được sửa

```cpp title="include/gpu_grid_engine.hpp — PassRecord"
struct PassRecord {
    std::string label{};
    std::string writes{};
    std::size_t itemCount{};
    GLenum barrierBit{};
};
```

Tên pass một mình chưa đủ. `writes` cho biết cạnh đang bảo vệ `cellCounts`, `cellOffsets`, `cellCursors`, `sortedIndices` hay `NeighborSummary`.

### Bước 2 — Đặt barrier ngay sau pass ghi dữ liệu

```cpp title="include/gpu_grid_engine.hpp — memoryBarrier"
void memoryBarrier(
    GlApi& gl,
    const char* label,
    const char* writes,
    std::size_t itemCount,
    GLenum barrierBit
) {
    gl.MemoryBarrier(barrierBit);
```

Ở checkpoint 7, hàm còn push `PassRecord`. Một helper duy nhất giữ việc dispatch và việc mô tả synchronization cạnh nhau trong source.

### Bước 3 — Ghi rõ bước nào sẽ đọc dữ liệu tiếp theo

```cpp title="include/gpu_grid_engine.hpp — barrierName"
inline const char* barrierName(GLenum barrierBit) {
    if (barrierBit == GL_SHADER_STORAGE_BARRIER_BIT) {
        return "SHADER_STORAGE -> compute consumer";
    }
    if (barrierBit == GL_BUFFER_UPDATE_BARRIER_BIT) {
        return "BUFFER_UPDATE -> readback consumer";
    }
    return "unexpected barrier";
}
```

Nhật ký không in một số hex khó đọc. Mỗi dòng nói thẳng bước nào sắp đọc dữ liệu.

### Bước 4 — Nối bước ghi index với bước tìm hàng xóm

```cpp title="include/gpu_grid_engine.hpp — scatter to neighbors edge"
dispatchScatter(gl);
memoryBarrier(gl, "scatter", "sortedIndices", positions_.size(), GL_SHADER_STORAGE_BARRIER_BIT);
dispatchNeighbors(gl);
memoryBarrier(gl, "neighbors", "NeighborSummary", positions_.size(), GL_BUFFER_UPDATE_BARRIER_BIT);
```

Neighbor shader đọc `sortedIndices`, nên shader-storage là bit của cạnh đầu. CPU validation/readout đọc summary sau cạnh thứ hai, nên buffer-update mới xuất hiện ở cuối.

## Cố tình làm hỏng grid

1. Bỏ barrier count→scan. Offset có thể được tính từ occupancy cũ hoặc chưa hoàn tất.
2. Dùng `GL_BUFFER_UPDATE_BARRIER_BIT` giữa scatter và neighbor. Bit này không dành cho compute shader đọc SSBO ở bước tiếp theo.
3. Chỉ gọi GLSL `barrier()` trong count shader rồi bỏ `glMemoryBarrier`. Workgroups/dispatches không được nối với nhau.
4. Dùng `GL_ALL_BARRIER_BITS` ở mọi chỗ. Chương trình có thể chạy, nhưng code không còn cho thấy dữ liệu sắp được đọc bằng cách nào và có thể đồng bộ thừa.
