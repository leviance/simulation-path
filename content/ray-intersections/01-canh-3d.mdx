# Dựng cảnh để nhìn thấy thứ mình sắp chọn

## Vấn đề cần giải quyết

Bạn nhìn thấy một quả cầu trên màn hình và nhấp vào nó. Chương trình nhận được hai con số — vị trí chuột theo pixel — nhưng điểm bạn muốn chọn lại nằm trong không gian ba chiều. Làm thế nào nối hai việc ấy với nhau?

Đó là câu hỏi xuyên suốt Project 52. Trước khi tìm giao điểm, ta cần một cảnh đủ rõ để tự nhìn ra kết quả đúng hay sai: mặt phẳng làm sàn, sphere màu xanh, AABB màu vàng và triangle màu tím. Bài đầu chỉ dựng cảnh và cho phép đổi góc nhìn, di chuyển các hình; **chưa có phép bắn tia**.

Tải ZIP ở trang tổng quan và giải nén. Thư mục gốc có `CMakeLists.txt`, `README.md`, `starter/`, `checkpoints/01..08/`, `final/` và `tests/`. Bạn chỉ cần compiler C++20, CMake 3.24 trở lên; không cần Node.js hoặc source của những project trước. Nếu muốn tự thử trước, hãy làm thử thách ở trang tổng quan rồi quay lại đây.

## Hiểu ý tưởng trước khi viết code

Trong world của ứng dụng, y hướng lên. Tọa độ SDL lại tăng y xuống dưới màn hình. Không trộn hai hệ ấy vào dữ liệu hình học: sphere lưu tâm và bán kính trong world, không lưu vị trí pixel hay kích thước trên cửa sổ.

Camera quan sát có `origin`, `target` và vertical FOV 55°. Từ đó dựng ba hướng vuông góc `forward`, `right`, `up`. Với một điểm world, lấy vector từ camera tới điểm rồi dot với ba hướng ấy. Thành phần theo `forward` là độ sâu; chia thành phần ngang/dọc cho độ sâu tạo ra phối cảnh.

$$
forward=normalize(target-origin),\qquad
right=normalize(upWorld\times forward),\qquad up=forward\times right
$$

Source có nhánh dự phòng khi camera nhìn gần thẳng đứng: lúc ấy `upWorld` gần song song `forward`, nên phải chọn một hướng tham chiếu khác để phép cross không thành vector zero.

**Phần được cung cấp:** `raster.hpp`, `mesh-drawing.hpp` và phần vẽ chữ/nút là bộ khung trình bày dựa trên renderer CPU ở Project 16–19. Nó chiếu, cắt near plane, rasterize triangle và kiểm depth; không gọi bất kỳ hàm ray intersection nào. Bạn không phải học OpenGL hay tự viết lại renderer để bắt đầu bài này. Phần tự xây của Project 52 là ray, các phép giao, lựa chọn giao gần nhất và cách kiểm chứng chúng.

## Viết code từng bước

### 1. Chạy bộ khung trước khi thêm hình

Build và mở `project_52_starter` trước. Nền tối xuất hiện, resize được và Esc thoát là đủ cho bước này. Nếu chưa chạy được, xử lý việc cài compiler/SDL theo Getting Started trước khi thêm công thức.

Phần đầu `src/main.cpp` tạo từng tài nguyên và kiểm lỗi ngay sau khi tạo:

{/* snippet src/main.cpp#sdl-window */}
```cpp title="src/main.cpp — tạo SDL window và renderer"
if (!SDL_Init(SDL_INIT_VIDEO)) {
    std::cerr << SDL_GetError() << '\n';
    return EXIT_FAILURE;
}
SDL_Window* window = SDL_CreateWindow("Project 52 - Ray geometry workshop", picking::viewWidth, picking::viewHeight, SDL_WINDOW_RESIZABLE | SDL_WINDOW_HIGH_PIXEL_DENSITY);
if (window == nullptr) {
    std::cerr << SDL_GetError() << '\n';
    SDL_Quit();
    return EXIT_FAILURE;
}
SDL_Renderer* renderer = SDL_CreateRenderer(window, nullptr);
if (renderer == nullptr) {
    std::cerr << SDL_GetError() << '\n';
    SDL_DestroyWindow(window);
    SDL_Quit();
    return EXIT_FAILURE;
}
```

Nếu renderer thất bại, window đã tạo vẫn phải được hủy. Cuối chương trình, texture được hủy trước renderer, renderer trước window, rồi mới `SDL_Quit`. Hãy giữ cách xử lý này khi thử sửa source; đừng gộp việc tạo nhiều tài nguyên vào một biểu thức khó kiểm tra.

### 2. Đặt hình trong world, không đặt bằng pixel

Đọc `include/shapes.hpp`: `Plane` có một điểm và normal; `Sphere` có tâm/bán kính; `Box` có minimum/maximum; `Triangle` có ba đỉnh. `Scene` giữ bốn hình ấy.

Sphere ở (−1.5,0,0), bán kính 0.85. AABB có min=(0.3,−0.9,0), max=(1.7,0.7,1.4). Tam giác được đặt cao hơn một chút để không bị hộp che hết ở góc nhìn ban đầu. Plane y=−1 là mặt phẳng vô hạn; chỉ miếng sàn minh họa được vẽ hữu hạn.

`Workshop` trong `workshop.hpp` giữ `scene`, camera `observer`, đối tượng đang chọn và trạng thái debug. Các phím 1–4 chọn hình; A/D dịch x, Q/E dịch y, S/W dịch z. Nút X−/X+/Y−/Y+/Z−/Z+ trên bảng gọi cùng hàm `translateObject` với bàn phím. Dịch một AABB nghĩa là cộng **cùng một delta** cho cả min và max, không làm méo kích thước hộp.

### 3. Theo dõi đường đi từ world tới pixel

Hàm `project` dùng để đặt nhãn world lên cảnh và để kiểm lại ray ở bài sau:

{/* snippet include/camera.hpp#projection */}
```cpp title="include/camera.hpp — chiếu một điểm world"
inline std::optional<Pixel> project(Vec3 point, const Camera& camera, double width, double height) {
    const Basis basis = cameraBasis(camera);
    const Vec3 relative = subtract(point, camera.origin);
    const double depth = dot(relative, basis.forward);
    if (depth <= 0.05 || width <= 0 || height <= 0) {
        return std::nullopt;
    }
    const double scale = height / (2 * camera.tanHalfFov * depth);
    return Pixel{width / 2 + scale * dot(relative, basis.right), height / 2 - scale * dot(relative, basis.up)};
}
```

Dấu trừ ở pixel y đổi world-up sang screen-down. Điểm sau near plane không được đem chia. Bộ rasterizer còn cắt các triangle/đoạn thẳng đi qua near plane trước khi chiếu; chỉ bỏ cả triangle có một đỉnh sau camera sẽ khiến bề mặt biến mất đột ngột khi tiến gần.

Trong `scene-drawing.hpp`, ta dùng bộ khung ấy để vẽ chính dữ liệu `Scene`:

{/* snippet include/scene-drawing.hpp#draw-scene */}
```cpp title="include/scene-drawing.hpp — dựng cảnh từ dữ liệu hình học"
inline void drawScene(Raster& raster, const Scene& scene, int selected, bool debug) {
    // Finite display patch; the plane intersection itself is infinite.
    const Vec3 p = scene.plane.point;
    const Vec3 a = add(p, {-6, 0, -5});
    const Vec3 b = add(p, {6, 0, -5});
    const Vec3 c = add(p, {6, 0, 7});
    const Vec3 d = add(p, {-6, 0, 7});
    raster.triangle(a, b, c, objectColor(0, selected));
    raster.triangle(a, c, d, objectColor(0, selected));
    // Meshes provide presentation only. No intersection routine is used here.
    drawSphereMesh(raster, scene.sphere, objectColor(1, selected));
    drawBoxMesh(raster, scene.box, objectColor(2, selected));
    raster.triangle(scene.triangle.a, scene.triangle.b, scene.triangle.c, objectColor(3, selected));

    if (debug) {
        for (int i = -5; i <= 5; ++i) {
            const double value = static_cast<double>(i);
            raster.line(add(p, {value, 0.002, -5}), add(p, {value, 0.002, 7}), {68, 102, 128});
            raster.line(add(p, {-6, 0.002, value}), add(p, {6, 0.002, value}), {68, 102, 128});
        }
        raster.line({0, 0, 0}, {1, 0, 0}, {248, 100, 103}, true, 1);
        raster.line({0, 0, 0}, {0, 1, 0}, {110, 234, 151}, true, 1);
        raster.line({0, 0, 0}, {0, 0, 1}, {103, 170, 250}, true, 1);
    }
}
```

`drawSphereMesh` chỉ chia mặt cầu thành triangle để **vẽ**. Bài 04 sẽ tìm giao với phương trình sphere giải tích, không dò giao với các triangle minh họa. Màu mặt phụ thuộc hướng normal và một nguồn sáng cố định; đó là scaffold trình bày, không phải thuật toán picking đang học.

## Ghép các phần lại

Sau khi đọc input, main gọi `drawWorkshop`. Hàm này lấy `state.observer.camera()`, xóa framebuffer/depth, rồi gọi `drawScene`. Framebuffer được đưa vào SDL texture để hiển thị:

{/* snippet src/main.cpp#frame-presentation */}
```cpp title="src/main.cpp — đưa cảnh CPU lên cửa sổ"
picking::drawWorkshop(sceneRaster, state);
const SDL_FRect viewport{0, 0, picking::sceneWidth, picking::viewHeight};
if (!picking::presentRaster(renderer, sceneTexture, sceneRaster, viewport)) {
    failed = true;
    break;
}
```

Bảng điều khiển được vẽ sau cảnh, trước `SDL_RenderPresent`. Logical presentation là **1200×760**, trong đó viewport quan sát rộng 880; resize dùng letterbox nên không làm sphere thành ellipse. Đây là kích thước bố cục, không phải kích thước world.

```bash title="Terminal — build starter và bài đầu"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_52_starter project_52_checkpoint_1 --parallel 1
```

Với Visual Studio, chạy `build/Debug/project_52_checkpoint_1.exe`. Generator single-config dùng `-DCMAKE_BUILD_TYPE=Debug` khi configure và đặt executable trực tiếp trong build directory.

## Thử làm sai để hiểu đúng

1. Trong `project`, đổi dấu trừ y thành cộng. Dự đoán nhãn sẽ lệch khỏi hình theo hướng nào rồi chạy thử. Bề mặt vẫn do rasterizer vẽ, nên bạn sẽ thấy rõ hai đường chiếu không còn thống nhất. Khôi phục dấu trước khi tiếp tục.
2. Khi dịch AABB, thử chỉ cộng delta vào minimum. Hộp sẽ đổi kích thước thay vì tịnh tiến. Khôi phục việc dịch cả hai bound, rồi kiểm khoảng `maximum−minimum` không đổi.

## Tự kiểm tra kết quả

Bạn nhìn rõ cả bốn loại hình, xoay/pan/zoom được và có thể dịch từng hình bằng nút hoặc phím. Tắt debug bỏ lưới/trục phụ nhưng bề mặt vẫn còn. Resize không làm biến dạng hình; Esc và nút đóng hoạt động. Checkpoint 1 **chưa có ray hoặc hit** — đó là phần sẽ thêm ở bài tiếp theo.

Đọc khoảng 25–35 phút, tự nối/sửa code 35–50 phút, thử các trường hợp trên 15–20 phút. Thời gian cài dependency và lần build đầu không tính vào khoảng này. Source đầy đủ, chạy độc lập của checkpoint nằm ở phần mã cuối bài.
