# Từ cosine đến góc sai lệch

## Vấn đề cần giải quyết

Normalized dot đã cho biết mức độ cùng hướng. Có lúc ta cần trả lời cụ thể hơn: nòng đang lệch mục tiêu bao nhiêu độ? Bài này đổi cosine thành góc, nhưng chưa quyết định quay trái hay phải.

## Hiểu ý tưởng trước khi viết code

Với hai hướng hợp lệ, cosine bằng dot của hai vector đơn vị. Hàm acos làm chiều ngược lại: cosine → góc trong [0,π]. Cùng hướng cho 0, vuông góc cho π/2, ngược hướng cho π.

Góc này **không có dấu**. Mục tiêu ở 45° bên trái và 45° bên phải đều cho π/4. Không thể dùng riêng acos để quyết định chiều quay.

Một điểm khác cần giữ rõ: góc giữa vector zero với một hướng không được xác định. Helper có thể trả 0 để không sinh NaN, nhưng UI không được biến quy ước đó thành kết luận “góc lệch bằng 0”.

## Viết code từng bước

### Bước 1 — Giữ cosine trong miền của acos

Trong include/lab.hpp:

```cpp title="include/lab.hpp — bảo vệ đầu vào hàm lượng giác ngược"
inline double clampCosine(double value) {
    if (!std::isfinite(value)) {
        return 0.0;
    }
    return std::clamp(value, -1.0, 1.0);
}
```

Trong số thực lý tưởng, cosine nằm trong [−1,1]. Trong floating point, một phép tính hợp lệ có thể trả 1+1e−16. acos của số đó không còn là một góc thực. Clamp xử lý sai số ở biên; nó không phải cách hợp thức hóa một raw dot chưa normalize.

### Bước 2 — Viết angleBetween và kiểm hướng trước

```cpp title="include/lab.hpp — góc không dấu chỉ có nghĩa khi cả hai hướng tồn tại"
inline double angleBetween(Vec2 a, Vec2 b) {
    if (!hasDirection(a) || !hasDirection(b)) {
        return 0.0;
    }
    return std::acos(clampCosine(cosineBetween(a, b)));
}
```

Hàm nhận vector bất kỳ có hướng, không yêu cầu caller đã normalize. Khi thiếu hướng, nó trả 0 theo chính sách kỹ thuật. Comment và UI phải nói rõ trường hợp ấy.

### Bước 3 — Giữ cùng một cách tính cosine

```cpp title="include/lab.hpp — normalize riêng trước khi tính cosine"
inline double cosineBetween(Vec2 a, Vec2 b) {
    if (!hasDirection(a) || !hasDirection(b)) {
        return 0.0;
    }
    return std::clamp(dot(normalize(a), normalize(b)), -1.0, 1.0);
}
```

cosineBetween đã clamp một lần vì đó cũng là giá trị được hiển thị trực tiếp ở bài 2. angleBetween vẫn dùng clampCosine ở ranh acos để thể hiện rõ miền hợp lệ của hàm. Không lấy độ dài hai mũi tên debug trên ảnh để tính góc.

### Bước 4 — Chỉ hiển thị một góc khi scene có hướng thao tác

Trước khi đọc kết quả, presentation kiểm chính sách vùng tâm:

```cpp title="include/scene.hpp — điều kiện hiển thị góc trong mô phỏng"
inline bool targetHasDirection(const Scene& scene) {
    return length(scene.targetOffset) >= 8.0 / kPixelsPerUnit;
}
```

Native dùng bool valid trong presentFramebuffer; Canvas dùng result.valid. Nếu false, chỉ ghi thông báo chưa có hướng, không hiển thị 0° hay 90° như một phép đo. Muốn đổi radian sang degree để đọc, nhân 180/π ở phần trình bày; phần toán vẫn làm việc bằng radian.

## Ghép các phần lại

Build project_8_checkpoint_3. Khi target=(4,3), forward=(1,0), cosine≈0.8 và angle≈0.643501 rad≈36.8699°. Kiểm cả bộ số thay vì chỉ so một con số sau cùng.

Đổi góc nòng bằng A/D hoặc slider, rồi đối chiếu lại các hướng mẫu. Checkpoint này chưa tự quay; như vậy bạn có thể giữ một câu hỏi đứng yên cho tới khi hiểu nó.

## Thử làm sai để hiểu đúng

1. Gọi acos(rawDot) thay vì acos(normalizedDot). Target ở (5,0) cho rawDot=5, ngoài miền của acos.
2. Bỏ clamp rồi thử riêng clampCosine với 1+1e−12 và −1−1e−12. Không cần chờ lỗi ngẫu nhiên trong UI mới kiểm được chính sách biên.
3. Khi target trùng tâm, in angleBetween=0 rồi ghi “đúng hướng”. Đây là lỗi diễn giải, dù executable không crash.

## Tự kiểm tra kết quả

- Các mốc 0/90/180° đúng trong sai số 1e-9 radian.
- Hai hướng lệch trái/phải cùng độ lớn tạo cùng unsigned angle.
- Target=(4,3) cho khoảng 36.8699° với nòng hướng X dương.
- Clamp đầu vào hơi vượt hai biên không sinh NaN.
- Vùng tâm hiển thị chưa có hướng, không coi fallback là góc đo.
