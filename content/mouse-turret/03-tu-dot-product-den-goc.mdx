# Từ dot product đến góc sai lệch

## Vấn đề cần giải quyết

Normalized dot cho biết hai hướng giống nhau tới mức nào, nhưng người dùng thường nghĩ bằng góc: nòng súng còn lệch mục tiêu 12°, 45° hay 90°? Ta cần đảo phép cosine để lấy `θ`.

Có hai bẫy cần xử lý trước. Thứ nhất, zero vector không có hướng nên góc với nó không được định nghĩa. Thứ hai, phép tính số thực có thể cho `1.0000000000000002` dù kết quả toán học là 1; truyền số đó vào `acos` sẽ trả `NaN`.

## Hiểu ý tưởng trước khi viết code

Từ công thức của bài trước:

$$
a\cdot b=|a||b|\cos(\theta)
$$

chia cho hai độ dài rồi lấy `acos`:

$$
\theta=\arccos\left(\frac{a\cdot b}{|a||b|}\right)
$$

`acos` trả một góc trong `[0,π]`, tương đương `[0°,180°]`. Đây là **góc không dấu**: nó nói lệch bao nhiêu, chưa nói mục tiêu nằm bên trái hay bên phải nòng súng.

Chọn các preset 0°, 90° và 180° rồi đối chiếu `normalized dot` với `angle error`. Sau đó kéo mục tiêu thật gần tâm; góc chỉ có ý nghĩa cho tới khi vector vẫn còn một hướng đủ lớn.

## Viết code từng bước

### Bước 1 — Nhận biết vector có hướng hay không

Đừng kiểm tra `x == 0 && y == 0` ở nhiều nơi. Đặt một tiêu chuẩn chung dựa trên độ dài:

```cpp title="include/lab.hpp — kiểm tra hướng hợp lệ"
inline constexpr double kDirectionEpsilon = 1e-12;

inline bool hasDirection(Vec2 vector) {
    const double magnitude = length(vector);
    return std::isfinite(magnitude) && magnitude > kDirectionEpsilon;
}
```

Ngưỡng rất nhỏ tránh chia cho một số gần zero. Kiểm tra `isfinite` cũng loại `NaN` và vô cực trước khi chúng lan sang phần còn lại của mô phỏng.

### Bước 2 — Bảo vệ miền của acos

```cpp title="include/lab.hpp — clampCosine"
inline double clampCosine(double value) {
    if (!std::isfinite(value)) {
        return 0.0;
    }
    if (value < -1.0) {
        return -1.0;
    }
    if (value > 1.0) {
        return 1.0;
    }
    return value;
}
```

Đây không phải “sửa” một kết quả sai lớn. Nó chỉ chặn phần sai số cực nhỏ ở biên của miền cosine. Nếu phép tính cho 1.2, bạn vẫn nên tìm lỗi ở dữ liệu thay vì trông chờ `clamp` che nó đi.

### Bước 3 — Tách cosine và góc thành hai hàm

```cpp title="include/lab.hpp — cosineBetween và angleBetween"
inline double cosineBetween(Vec2 left, Vec2 right) {
    if (!hasDirection(left) || !hasDirection(right)) {
        return 0.0;
    }
    return clampCosine(dot(left, right) / (length(left) * length(right)));
}

inline double angleBetween(Vec2 left, Vec2 right) {
    if (!hasDirection(left) || !hasDirection(right)) {
        return 0.0;
    }
    return std::acos(cosineBetween(left, right));
}
```

`cosineBetween` dùng được ở những nơi chỉ cần so ngưỡng; `angleBetween` dành cho lúc thật sự cần một góc để hiển thị hoặc đo đạc.

### Bước 4 — Hiển thị góc bằng degree, giữ tính toán bằng radian

```cpp title="src/main.cpp — góc sai lệch trên thanh tiêu đề"
const double angleError = lab::angleBetween(forward, targetOffset);

std::snprintf(
    title,
    sizeof(title),
    "normalized dot %.3f | unsigned angle %.1f deg",
    alignment,
    angleError * 180.0 / lab::kPi
);
```

`angleError` vẫn là radian. Phép nhân `180/π` chỉ xảy ra tại ranh giới hiển thị; các bài sau tiếp tục dùng radian.

## Ghép các phần lại

Build `project_8_checkpoint_3`. Di chuyển mục tiêu một vòng quanh tháp pháo. Góc tăng từ 0° tới 180° khi đi về phía sau, rồi giảm đối xứng ở nửa còn lại. Đó là hành vi đúng của góc không dấu.

Nếu muốn biết nên quay trái hay phải, chỉ `angleBetween` là chưa đủ: mục tiêu trên và dưới trục X đều có thể lệch 45°. Ta sẽ bổ sung dấu ở bài 5; trước đó, bài 4 dùng chính hướng nòng để tách vector mục tiêu thành hai phần có ý nghĩa hình học.

## Thử làm sai để hiểu đúng

1. Bỏ `clampCosine`, rồi gọi trực tiếp `acos(1.0 + 1e-12)` trong một phép thử. Kết quả không còn là số hữu hạn.
2. Dùng `acos(dot(forward,targetOffset))` mà không chia độ dài. Chỉ cần mục tiêu cách tâm hơn một pixel, đối số đã dễ vượt ngoài `[-1,1]`.
3. Trả 90° cho zero vector vì `cosineBetween` đang trả 0. Trong project, ta chủ động cho `angleBetween` trả 0 trước; zero vector được xem là “không có lệnh quay”, không phải một hướng vuông góc.

## Tự kiểm tra kết quả

- Hai hướng cùng chiều cho góc gần 0.
- Hai hướng vuông góc cho góc gần `π/2`.
- Hai hướng ngược chiều cho góc gần `π`.
- `clampCosine(1 + 10⁻¹²)` trả 1 và `clampCosine(-1 - 10⁻¹²)` trả -1.
- Mục tiêu đúng tâm không làm xuất hiện `NaN` trên thanh tiêu đề.

## Bài tập mở rộng

Vẽ một cung nhỏ biểu diễn `angleError` và ghi số degree cạnh cung. Sau đó thử phân loại “gần thẳng hướng” bằng `angleError < 10°`; nhớ đổi 10° sang radian trước khi so sánh.

Bài tiếp theo không chỉ đo góc. Ta sẽ trả lời hai câu hỏi cụ thể hơn: mục tiêu nằm bao xa dọc theo đường ngắm và lệch khỏi đường ngắm bao nhiêu pixel.
