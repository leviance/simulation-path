# Vẽ 100.000 hạt từ một bộ dữ liệu có thể tạo lại

## Vấn đề cần giải quyết

Hãy tưởng tượng bạn đang nhìn một tấm ảnh chụp bầu trời đầy sao. Khi rê một vòng tròn qua ảnh, bạn muốn chọn **mọi điểm nằm trong vòng tròn**, không chỉ một điểm gần chuột. Trước khi viết phép tìm kiếm đó, ta cần một bộ dữ liệu đủ lớn và một cách vẽ để nhìn được nó.

Project này bắt đầu bằng cửa sổ SDL3 đã quen từ Project 01. Starter có event loop, framebuffer và đường đưa ảnh lên màn hình, nhưng **chưa sinh hạt hay truy vấn**. Bạn có thể build `project_27_starter` ngay để thấy khung ứng dụng trống. Không cần chép vòng lặp SDL từ một project khác.

Đích của bài là 100.000 hạt thật trong một vector. Cùng một `seed` phải tạo lại đúng dữ liệu; ta gọi tính chất ấy là **deterministic**. Nó giúp bạn biết một thay đổi đến từ thuật toán hay chỉ do lần này chương trình sinh một đám điểm khác.

## Hiểu ý tưởng trước khi viết code

Ta quy ước thế giới là hình vuông $[0,1]^2$, gốc ở góc dưới bên trái, trục Y hướng lên. Mỗi hạt chỉ có vị trí. Index trong vector là định danh: hạt số 123 vẫn là hạt số 123 khi ta đổi bán kính hoặc resize cửa sổ.

Với số $u$ trong $[0,1]$, công thức $x=x_{min}+u(x_{max}-x_{min})$ đưa nó vào đoạn mong muốn. Làm tương tự với một số khác cho Y. `XorShift32` cung cấp chuỗi số có thể lặp lại; đây không phải bộ sinh dành cho mật mã hay một mô hình vật lý. Các hạt của project **đứng yên**. Chuyển động về sau là chuyển động của vòng tròn truy vấn.

## Viết code từng bước

### Bước 1 — Đọc các kiểu dữ liệu có sẵn trong Starter

Mở `include/lab.hpp`. Các kiểu nhỏ dưới đây đã được cung cấp để khung ứng dụng biên dịch được. Chưa thêm vận tốc, khối lượng hoặc cờ selected: chúng không phục vụ bài toán chọn điểm.

```cpp title="include/lab.hpp — mỗi hạt chỉ lưu vị trí"
struct Particle {
    Vec2 position{};
};
```

`Vec2` có hai trường `double x, y`; `Bounds2D` có `minimum, maximum`. Bạn sẽ dùng nguyên các kiểu này trong hàm sinh và hàm truy vấn. Màu của hạt nằm ở renderer, không nằm trong `Particle`.

### Bước 2 — Thêm bộ sinh số có trạng thái rõ ràng

Trong namespace `lab`, sau `Bounds2D`, thêm `validBounds` và lớp `XorShift32` sau. Các include chuẩn đã nằm ở đầu file. Hãy chép cả constructor: nếu bỏ phần xử lý seed 0, bộ sinh có thể kẹt ở 0 mãi mãi.

```cpp title="include/lab.hpp — kiểm vùng sinh hợp lệ"
inline bool validBounds(const Bounds2D& bounds) {
    return std::isfinite(bounds.minimum.x) && std::isfinite(bounds.minimum.y) && std::isfinite(bounds.maximum.x) && std::isfinite(bounds.maximum.y) && bounds.minimum.x < bounds.maximum.x && bounds.minimum.y < bounds.maximum.y;
}
```

```cpp title="include/lab.hpp — bộ sinh lặp lại được theo seed"
class XorShift32 {
    public:
    explicit XorShift32(std::uint32_t seed)
        : state_(seed) {
        if (state_ == 0U) {
            state_ = 0x6d2b79f5U;
        }
    }

    std::uint32_t nextU32() {
        state_ ^= state_ << 13U;
        state_ ^= state_ >> 17U;
        state_ ^= state_ << 5U;
        return state_;
    }

    double nextUnit() {
        return double(nextU32()) / double(std::numeric_limits<std::uint32_t>::max());
    }

    private:
    std::uint32_t state_{};
};
```

Mỗi lần gọi `nextU32()` cập nhật `state_`; `nextUnit()` chia cho số nguyên 32-bit lớn nhất để được số trong $[0,1]$. Hai lần gọi liên tiếp cung cấp X và Y. Đặt lại cùng seed là quay lại đầu cùng chuỗi, chứ không phải lấy một số ngẫu nhiên mới từ đồng hồ.

### Bước 3 — Thêm hàm sinh đủ số hạt

Đặt hàm này sau lớp `XorShift32`, vẫn trong namespace `lab`.

```cpp title="include/lab.hpp — sinh toàn bộ dữ liệu trước khi render"
inline std::vector<Particle> makeParticleCloud(std::size_t count, const Bounds2D& bounds, std::uint32_t seed) {
    std::vector<Particle> particles{};
    if (!validBounds(bounds)) {
        return particles;
    }

    particles.reserve(count);
    XorShift32 random{seed};
    const double width = bounds.maximum.x - bounds.minimum.x;
    const double height = bounds.maximum.y - bounds.minimum.y;
    for (std::size_t index = 0; index < count; ++index) {
        const double x = bounds.minimum.x + random.nextUnit() * width;
        const double y = bounds.minimum.y + random.nextUnit() * height;
        particles.push_back({{x, y}});
    }
    return particles;
}
```

`reserve(count)` chỉ chuẩn bị sức chứa, không tạo phần tử. `push_back` mới tăng `size()`. Khi hàm trả về, vector có đúng `count` phần tử. Seed được truyền vào thay vì giấu trong biến global để test có thể chủ động tạo lại cùng bộ dữ liệu.

### Bước 4 — Nối dữ liệu vào scene rồi vẽ từng hạt

Mở `include/scene.hpp`, thay `resetScene` bằng phiên bản sau. Đây là chỗ tạo dữ liệu khi bắt đầu hoặc reset, **không phải** mỗi lần vẽ.

```cpp title="include/scene.hpp — reset tạo lại cùng bộ dữ liệu"
inline void resetScene(Scene& scene) {
    const bool debug = scene.debug;
    scene = {};
    scene.debug = debug;
    scene.particles = makeParticleCloud(100'000, Scene::bounds, scene.seed);
}
```

Mở `include/view.hpp`. Hàm biến đổi dưới đây ánh xạ tọa độ thế giới vào khung nhìn. Starter đã có `makeWorldView` chọn vị trí viewport cho debug/chế độ sạch. Dấu `1.0 - point.y` đảo Y vì pixel màn hình tăng từ trên xuống.

```cpp title="include/view.hpp — đổi world position sang pixel"
inline Vec2 worldToScreen(Vec2 point, const WorldView& view) {
    return {view.left + point.x * view.size, view.top + (1.0 - point.y) * view.size};
}
```

Thay `drawScene` bằng hàm đầy đủ này. `Framebuffer::putPixel` đã có kiểm tra biên; các nét khung và màu cũng được cung cấp trong Starter.

```cpp title="include/view.hpp — không lấy mẫu hay bỏ qua hạt"
inline void drawScene(Framebuffer& image, const Scene& scene) {
    image.clear();
    const WorldView view = makeWorldView(scene.debug);
    rectangle(image, static_cast<int>(view.left) - 1, 109, static_cast<int>(view.left + view.size) + 1, 731, kGrid, false);
    for (std::size_t index = 0; index < scene.count; ++index) {
        const Vec2 point = worldToScreen(scene.particles[index].position, view);
        image.putPixel(static_cast<int>(std::lround(point.x)), static_cast<int>(std::lround(point.y)), kCloud);
    }
}
```

Sau cùng, xem lại đoạn có sẵn trong `src/main.cpp`. Nó đưa ảnh CPU lên texture, vẽ nhãn rồi present. Không có `SDL_UpdateTexture` thì bạn mới chỉ sửa vector trong RAM; cửa sổ sẽ chưa thấy bức ảnh mới.

```cpp title="src/main.cpp — đường đi từ framebuffer tới cửa sổ"
        if (dirty) {
            lab::drawScene(image, scene);
            if (!SDL_UpdateTexture(texture, nullptr, image.pixels.data(), lab::Framebuffer::width * static_cast<int>(sizeof(std::uint32_t))) ||

                failed = true;
                running = false;
            }
            dirty = false;
        }
```

Nhấn 1/2/3 để đổi N, P đổi seed, R quay về mặc định. Resize chỉ thay cách SDL trình bày logical board 1100×820; dữ liệu trong world không đổi.

## Thử làm sai để hiểu đúng

1. Bỏ `push_back`, chỉ giữ `reserve`. Vector vẫn rỗng dù đã có sức chứa. Khôi phục vòng lặp sau khi kiểm `size()`.
2. Đưa generation vào mỗi frame nhưng giữ nguyên seed. CPU tốn thêm công, **ảnh không thay đổi** vì cùng chuỗi được tạo lại. Đây là lãng phí, không phải chuyển động.
3. Đổi seed theo thời gian rồi reset. Bạn không còn đối chiếu được cùng hạt theo index. Quay về seed cố định trước khi đo hiệu năng.

## Tự kiểm tra kết quả

- Mặc định có đúng 100.000 hạt; 1/2/3 cho đúng 1.000 / 10.000 / 100.000.
- Mọi tọa độ đều thuộc bounds; cùng seed tái tạo đúng **từng vị trí**, không chỉ vài điểm đầu/cuối.
- Renderer duyệt đủ `scene.count`; resize không gọi generation.
- Cửa sổ hiển thị được đám hạt và chú giải, không chỉ log N ra terminal.
