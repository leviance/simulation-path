# Đọc chi phí khi tăng từ 1.000 lên 100.000 hạt

## Vấn đề cần giải quyết

Một con số “0,2 ms/query” chưa cho biết thuật toán sẽ phản ứng thế nào khi dữ liệu lớn gấp mười lần. Ta cần thay **một biến mỗi lần**: giữ nguyên query set, bán kính, seed và số lần lặp; chỉ tăng N.

Tiếp tục `project_27_starter` từ Bài 5. Chúng ta không sinh ba đám điểm độc lập. Một cloud 100.000 hạt đã đủ: lấy prefix 1.000, 10.000 và 100.000 để ba mức có chung phần dữ liệu đầu.

## Hiểu ý tưởng trước khi viết code

Với Q=48 query được đo, số lần kiểm lần lượt là:

| N | Q | Total scans |
| --- | --- | --- |
| 1.000 | 48 | 48.000 |
| 10.000 | 48 | 480.000 |
| 100.000 | 48 | 4.800.000 |

Đó là tỉ lệ work **1:10:100**, xác định từ vòng lặp, không cần đo đồng hồ mới biết. Ta gọi chi phí một query là $O(N)$. Điều này không hứa rằng thời gian cũng tăng đúng tỉ lệ 1:10:100: cache, branch, số hit cần ghi, timer, hệ điều hành và JIT của trình duyệt đều có ảnh hưởng.

Chạy scaling rồi đọc bảng ba dòng ngay dưới Canvas. Thử lại cùng seed/R để so checksum. Sau đó tăng R và đo lại: hit count thường tăng, nhưng full query vẫn kiểm đủ N. Một thuật toán không trở thành “dưới tuyến tính” chỉ vì vòng tròn nhỏ.

## Viết code từng bước

### Bước 1 — Gắn mỗi số đo với đúng N

Trong `include/lab.hpp`, thêm struct sau sau các hàm benchmark.

```cpp title="include/lab.hpp — mỗi dòng mang theo kích thước dữ liệu"
struct ScalingRow {
    std::size_t particleCount{};
    BatchMetrics metrics{};
};
```

Nếu không lưu N ngay cùng số đo, người dùng có thể đổi dropdown rồi nhìn nhầm một kết quả cũ thành kết quả của N mới. UI của ta cũng xóa số đo khi đổi cấu hình để tránh nhầm lẫn này.

### Bước 2 — Viết phép thử đồng bộ trên các prefix

Thêm hàm sau. Hàm nhận toàn cloud và cùng span query; không được tạo query mới trong từng dòng.

```cpp title="include/lab.hpp — chỉ N thay đổi giữa ba phép đo"
inline std::vector<ScalingRow> makeScalingStudy(std::span<const Particle> particles, std::span<const CircleQuery> queries, std::span<const std::size_t> requestedCounts, int repetitions) {
    std::vector<ScalingRow> rows{};
    rows.reserve(requestedCounts.size());
    QueryWorkspace workspace{};
    for (const std::size_t requestedCount : requestedCounts) {
        const std::size_t particleCount = std::min(requestedCount, particles.size());
        const std::span<const Particle> prefix = particles.first(particleCount);
        rows.push_back({particleCount, benchmarkBruteForce(prefix, queries, repetitions, workspace)});
    }
    return rows;
}
```

`particles.first(particleCount)` tạo một view, không copy dữ liệu. `min` chặn yêu cầu vượt số hạt thực có; kết quả phải báo đúng số thực dùng, không được gắn nhãn 100.000 cho một cloud chỉ có 1.000. Ứng dụng cuối luôn giữ sẵn đủ 100.000 để ba dòng bắt buộc đều có dữ liệu.

### Bước 3 — Mở rộng job UI qua ba dòng

Trong `include/scene.hpp`, `kStudyCounts` là mảng 1.000 / 10.000 / 100.000. `Scene` thêm `std::vector<ScalingRow> rows{};`. Thay `requestBenchmark` và `advanceJob` bằng hai hàm đầy đủ dưới đây.

```cpp title="include/scene.hpp — lựa chọn benchmark một N hoặc scaling"
inline void requestBenchmark(Scene& scene, bool scaling) {
    invalidateMeasurement(scene);
    scene.job = {};
    scene.job.active = true;
    scene.job.scaling = scaling;
    scene.job.probes = makeProbeQueries(kProbeCount, Scene::bounds, scene.query.radius, scene.seed ^ 0x9e3779b9U);
    reserveQueryWorkspace(scene.job.workspace, scene.particles.size());
}
```

```cpp title="include/scene.hpp — mỗi dòng có warm-up riêng và đúng 48 query"
inline void advanceJob(Scene& scene) {
    if (!scene.job.active) {
        return;
    }
    auto& job = scene.job;
    std::size_t count = scene.count;
    if (job.scaling) {
        count = kStudyCounts[job.row];
    }
    const auto active = std::span<const Particle>(scene.particles).first(count);
    // Tối đa một query mỗi frame. SDL vẫn xử lý input giữa hai lần gọi.
    if (job.warmup < job.probes.size()) {
        queryBruteForceSquared(active, job.probes[job.warmup], job.workspace);
        ++job.warmup;
        return;
    }
    const auto started = std::chrono::steady_clock::now();
    queryBruteForceSquared(active, job.probes[job.cursor % job.probes.size()], job.workspace);
    const auto finished = std::chrono::steady_clock::now();
    job.metrics.elapsedMicroseconds += std::chrono::duration<double, std::micro>(finished - started).count();
    ++job.metrics.queryCount;
    job.metrics.totalScanned += job.workspace.scanned;
    job.metrics.totalHits += job.workspace.hitIndices.size();
    job.metrics.checksum = updateChecksum(job.metrics.checksum, job.workspace);
    ++job.cursor;
    if (job.cursor != job.probes.size() * kRepetitions) {
        return;
    }
    if (job.scaling) {
        scene.rows.push_back({count, job.metrics});
        ++job.row;
        if (job.row < kStudyCounts.size()) {
            job.cursor = 0;
            job.warmup = 0;
            job.metrics = {};
            return;
        }
    } else {
        scene.benchmark = job.metrics;
    }
    job.active = false;
}
```

Điểm mới nằm ở lúc hoàn thành một dòng. Nếu đang scaling, lưu số đo rồi chuyển sang N tiếp theo; cursor, warm-up và metrics về 0 nhưng **probes vẫn giữ nguyên**. Không dùng số đo cộng dồn của dòng trước cho dòng sau.

Một study hoàn chỉnh cần $(24+48)\times3=216$ lần gọi job. Mỗi lần gọi làm tối đa một query benchmark rồi trả quyền cho event loop. Nếu bị hủy sau một dòng, bảng chỉ chứa dòng đã hoàn thành; chưa được kết luận toàn study đã xong.

### Bước 4 — Hiển thị bảng trong cửa sổ SDL

Phần `drawLabels` của `include/presentation.hpp` hiển thị N, Q, scans và us/query ngay trong viewport UI. Đây là toàn bộ hàm trình bày sau bài, để bạn không phải đoán cách ghép số liệu vào renderer.

```cpp title="include/presentation.hpp — bảng là một phần của sản phẩm, không chỉ console"
inline bool drawLabels(SDL_Renderer* renderer, const Scene& scene) {
    bool okay = SDL_SetRenderDrawColor(renderer, 210, 223, 242, 255);
    const auto line = [&](float x, float y, const char* text) {
        okay = SDL_RenderDebugText(renderer, x, y, text) && okay;
    };
    char text[250]{};
    line(32, 25, "100,000 PARTICLES / BRUTE-FORCE LENS");
    std::snprintf(text, sizeof(text), "N = %zu | seed = %08x | every particle is drawn (overlap is possible)", scene.count, static_cast<unsigned>(scene.seed));
    line(32, 48, text);
    line(32, 765, "Gray: all points. Gold: all hits. Blue: query. Red: nearest (even outside radius).");
    line(32, 785, "No grid/tree/index. The particles are static; only the query moves.");
    if (!scene.debug) {
        line(32, 70, "F: show debug | Space: auto lens | R: reset | close window to exit");
        return okay;
    }
    line(690, 110, "R: reset | F: clean/debug | Esc: stop");
    line(690, 136, "1/2/3: N=1k/10k/100k | P: seed");
    std::snprintf(text, sizeof(text), "center=(%.3f, %.3f) R=%.3f", scene.query.center.x, scene.query.center.y, scene.query.radius);
    line(690, 170, text);
    line(690, 192, "Move mouse / drag: move query");
    line(690, 214, "W/A/D/J: center | Up/Down: radius");
    const auto& result = scene.workspace;
    std::snprintf(text, sizeof(text), "scanned=%zu | hits=%zu", result.scanned, result.hitIndices.size());
    line(690, 250, text);
    std::snprintf(text, sizeof(text), "query = %.3f us (render excluded)", scene.queryMicroseconds);
    line(690, 272, text);
    if (scene.debug) {
        if (result.nearestIndex == kNoParticle) {
            std::snprintf(text, sizeof(text), "nearest: none (empty scan)");
        } else {
            std::snprintf(text, sizeof(text), "nearest index = %zu", result.nearestIndex);
        }
        line(690, 294, text);
    }
    line(690, 360, "B: benchmark | Esc: cancel job");
    if (scene.job.active) {
        std::snprintf(text, sizeof(text), "job row=%zu warm-up=%zu/24 run=%zu/48", scene.job.row + 1, scene.job.warmup, scene.job.cursor);
        line(690, 384, text);
    }
    if (scene.benchmark.queryCount > 0) {
        const auto& batch = scene.benchmark;
        std::snprintf(text, sizeof(text), "N=%zu Q=%zu scans=%zu", scene.count, batch.queryCount, batch.totalScanned);
        line(690, 410, text);
        std::snprintf(text, sizeof(text), "%.3f us/query | checksum=%08x", batch.elapsedMicroseconds / static_cast<double>(batch.queryCount), static_cast<unsigned>(batch.checksum));
        line(690, 432, text);
    }
    line(690, 470, "S: scaling / same 24 queries x 2");
    line(690, 494, "N       Q       scans       us/query");
    for (std::size_t index = 0; index < scene.rows.size(); ++index) {
        const auto& row = scene.rows[index];
        std::snprintf(text, sizeof(text), "%-7zu %-7zu %-11zu %.3f", row.particleCount, row.metrics.queryCount, row.metrics.totalScanned, row.metrics.elapsedMicroseconds / static_cast<double>(row.metrics.queryCount));
        line(690, 518 + static_cast<float>(index) * 28, text);
    }
    line(690, 616, "Timing is measured, not forced linear.");
    line(690, 638, "Exact work = N x Q, whatever radius.");
    return okay;
}
```

`SDL_RenderDebugText` ở đây chỉ trình bày nhãn ASCII, không thay renderer CPU của đám hạt. Timing đã được chốt trước khi vẽ bảng. Trình duyệt dùng bảng HTML cùng các cột, thuận tiện đọc và dùng bàn phím; JavaScript báo ms/query, C++ báo us/query.

C++ dùng S để bắt đầu scaling, nên từ bài này phím đi xuống của tâm đổi từ S sang J; W/A/D giữ nguyên. Đừng nhầm việc đổi N của query hiện tại với N của study: study luôn chạy ba prefix chuẩn, dù dropdown hiện tại đang là 1.000.

Bấm S, quan sát dòng xuất hiện lần lượt rồi tự dừng. Bấm Esc giữa chừng phải dừng tiến độ; bấm S lần nữa phải bắt đầu một study mới, không nối nhầm số đo cũ.

## Thử làm sai để hiểu đúng

1. Sinh probes lại bằng seed khác cho từng N. Bạn đang đổi cả dữ liệu câu hỏi. Khôi phục cùng probes trước khi so thời gian.
2. Vẽ cột timing bằng giá trị N nhân một hằng số. Hình có vẻ tuyến tính nhưng không còn là benchmark. Chỉ hiển thị số đo thật.
3. Cộng warm-up vào Q của một dòng. Bảng exact scans không khớp N×48; sửa trước khi diễn giải độ phức tạp.

## Tự kiểm tra kết quả

- Bảng có đúng ba N bắt buộc, Q=48 ở mỗi dòng.
- Total scans là 48.000 / 480.000 / 4.800.000, không phụ thuộc R.
- Hai study cùng cấu hình cho cùng checksum từng dòng.
- Job tự ngừng sau 216 tick; UI vẫn nhận Esc giữa các tick.
- Không đòi test thời gian tăng chính xác 10 lần: correctness kiểm work và kết quả, không kiểm một chiếc máy luôn rảnh.

## Bài tập mở rộng

Tăng R từ 0,02 lên 0,3 rồi đo lại. Viết hai câu riêng: một câu về số lần kiểm, một câu về thời gian và lượng ghi output. Đây là bước chuẩn bị để hiểu vì sao lọc ít candidate có thể hữu ích ở Project 28.
