# Tìm mọi hạt trong vòng tròn bằng brute force

## Vấn đề cần giải quyết

Ta đã kiểm được một hạt. Để tìm **mọi hạt** trong vòng tròn, cách thẳng thắn nhất là hỏi lần lượt từng hạt từ đầu tới cuối mảng. Đây là brute force. Nó chậm khi N lớn nhưng dễ kiểm chứng, và sẽ là mốc đối chiếu khi học cấu trúc không gian.

Tiếp tục `project_27_starter` từ Bài 2. Không đổi dữ liệu hay event loop. Bài này thêm kết quả truy vấn, một vòng lặp, và cách tô màu chính những index được tìm thấy.

## Hiểu ý tưởng trước khi viết code

Ba con số dễ nhầm cần tách riêng: **scanned** là số hạt đã kiểm, **hits** là số hạt thuộc vòng tròn, **nearest** là hạt gần tâm nhất trong phần đã kiểm. Ta tìm nearest trên toàn prefix, nên nó có thể ở **ngoài** R khi query không chứa hạt nào.

Mỗi hạt phải được kiểm vì mảng không được sắp theo khoảng cách và chưa có index không gian. R nhỏ làm ít hit hơn nhưng không cho biết các hạt còn lại ở đâu. Một full query luôn có scanned=N, kể cả hits=0.

Giảm số hạt đã quét về 0 rồi tiến từng bước. Đây là phần đầu của **mảng**, không phải một phần hình chữ nhật trên màn hình. Vì thứ tự sinh rải khắp world, các hit cũng xuất hiện rải khắp vòng tròn. Chỉ khi scanned=N mới được gọi danh sách đó là đầy đủ.

## Viết code từng bước

### Bước 1 — Định nghĩa kết quả có cả trường hợp rỗng

Thêm `kNoParticle` và struct sau vào `include/lab.hpp`, sau phần kiểm vòng tròn. Giá trị sentinel giúp phân biệt “không có hạt” với index 0.

```cpp title="include/lab.hpp — kết quả giữ index thay vì sao chép Particle"
struct BruteForceResult {
    std::vector<std::size_t> hitIndices{};
    std::size_t nearestIndex{kNoParticle};
    double nearestDistanceSquared{std::numeric_limits<double>::infinity()};
    std::size_t scanned{};
};
```

Khai báo `inline constexpr std::size_t kNoParticle = std::numeric_limits<std::size_t>::max();` ngay trước struct, đúng như file đầy đủ cuối bài. Khoảng cách gần nhất bắt đầu từ infinity: mọi khoảng cách hữu hạn của hạt đầu tiên đều nhỏ hơn nó.

### Bước 2 — Thêm hàm truy vấn đầy đủ

Đặt hàm này sau `BruteForceResult`. `std::span<const Particle>` chỉ nhìn vào một dãy hạt có sẵn, không sao chép vector.

```cpp title="include/lab.hpp — không dừng ở hit đầu tiên"
inline BruteForceResult queryBruteForce(std::span<const Particle> particles, const CircleQuery& query) {
    BruteForceResult result{};
    if (!validQuery(query)) {
        return result;
    }

    for (std::size_t index = 0; index < particles.size(); ++index) {
        const double candidateDistanceSquared = distanceSquared(particles[index].position, query.center);
        ++result.scanned;
        if (candidateDistanceSquared < result.nearestDistanceSquared) {
            result.nearestDistanceSquared = candidateDistanceSquared;
            result.nearestIndex = index;
        }
        if (insideCircleWithDistance(particles[index].position, query)) {
            result.hitIndices.push_back(index);
        }
    }
    return result;
}
```

Vòng lặp luôn tăng `scanned`, không chỉ khi trúng. Khi khoảng cách nhỏ hơn kỷ lục trước, ta thay nearest. Dùng dấu `<` ở đây giữ index đầu tiên khi hai hạt cách đều tâm. Ngược lại, phép kiểm membership vẫn dùng `<=` để nhận cả biên.

Đừng thêm `break` sau `push_back`: nó biến câu hỏi “mọi hạt nào?” thành “hạt đầu tiên nào?”. Đầu ra giữ thứ tự index tăng dần vì ta duyệt theo đúng thứ tự đó.

### Bước 3 — Chạy query ở nơi state thay đổi

Trong `Scene`, thêm `readable`, `scanLimit` và `queryMicroseconds` như source đầy đủ. Thêm hàm sau vào `include/scene.hpp`.

```cpp title="include/scene.hpp — đo riêng query rồi giữ kết quả để vẽ"
inline void refreshQuery(Scene& scene) {
    const auto active = std::span<const Particle>(scene.particles).first(std::min(scene.count, scene.scanLimit));
    const auto started = std::chrono::steady_clock::now();
    scene.readable = queryBruteForce(active, scene.query);
    const auto finished = std::chrono::steady_clock::now();
    scene.queryMicroseconds = std::chrono::duration<double, std::micro>(finished - started).count();
}
```

`first(min(count, scanLimit))` là phần mảng được kiểm trong thí nghiệm bước đơn. Ở chế độ full, `scanLimit=count`. Timer bao quanh hàm query, không bao quanh rendering. Phiên bản này còn tạo vector kết quả mỗi lần; Bài 4 sẽ sửa chi phí cấp phát đó.

Trong `main.cpp`, khi `queryDirty` là true, gọi `refreshQuery(scene)` trước `drawScene`. Mã nối có sẵn ở cuối bài. Nhờ vậy giữ chuột đứng yên không quét đi quét lại vô ích trong mọi vòng lặp.

### Bước 4 — Tô màu theo danh sách index vừa tìm

Thay `drawScene` bằng hàm sau. Màu vàng ghi đè đúng các hit; vòng đỏ chỉ nearest và chỉ hiện trong debug.

```cpp title="include/view.hpp — renderer không tự chạy một phép tìm kiếm khác"
inline void drawScene(Framebuffer& image, const Scene& scene) {
    image.clear();
    const WorldView view = makeWorldView(scene.debug);
    rectangle(image, static_cast<int>(view.left) - 1, 109, static_cast<int>(view.left + view.size) + 1, 731, kGrid, false);
    for (std::size_t index = 0; index < scene.count; ++index) {
        const Vec2 point = worldToScreen(scene.particles[index].position, view);
        image.putPixel(static_cast<int>(std::lround(point.x)), static_cast<int>(std::lround(point.y)), kCloud);
    }
    const auto& result = scene.readable;
    for (const std::size_t index : result.hitIndices) {
        const Vec2 point = worldToScreen(scene.particles[index].position, view);
        image.putPixel(static_cast<int>(std::lround(point.x)), static_cast<int>(std::lround(point.y)), kHit);
    }
    if (scene.debug && result.nearestIndex < scene.count) {
        circle(image, worldToScreen(scene.particles[result.nearestIndex].position, view), 6, kColors[0]);
    }
    const Vec2 center = worldToScreen(scene.query.center, view);
    circle(image, center, scene.query.radius * view.size, kLens);
    drawLine(image, center.x - 5, center.y, center.x + 5, center.y, kLens);
    drawLine(image, center.x, center.y - 5, center.x, center.y + 5, kLens);
}
```

Renderer đọc đúng output của query. Nó không kiểm thêm khoảng cách để quyết định màu, cũng không lấy mẫu hit list. Vì vậy nếu vòng lặp query bỏ sót, hình vẽ cũng lộ chỗ thiếu thay vì vô tình che lỗi.

## Thử làm sai để hiểu đúng

1. Đưa `++scanned` vào nhánh hit. Con số bây giờ là hits, không còn là lượng công việc. Đưa nó ra ngoài điều kiện.
2. Đổi so nearest từ `<` sang `<=`. Hai hạt cách đều sẽ chọn index cuối; test tie phải phát hiện.
3. Dừng sau hit đầu tiên rồi rê vòng tròn qua vùng đông hạt. Màu vàng chỉ còn một chấm. Bỏ `break` và so danh sách đầy đủ.

## Tự kiểm tra kết quả

- Fixture tâm (0,0), R=1 với (1,0), (-1,0), (0,1), (0,-1), (1,01;0) cho hits [0,1,2,3], nearest=0, scanned=5.
- R=0 mà không có hạt trùng tâm cho hits rỗng nhưng vẫn có nearest và vẫn quét đủ.
- Vector rỗng cho scanned=0 và sentinel nearest.
- Prefix một phần chỉ trả hit trong prefix; full query luôn scanned=N.
- Số hit đổi khi R đổi, số lần kiểm của full query không đổi.

## Bài tập mở rộng

Tạo hai mảng có cùng vị trí nhưng đảo thứ tự. Hit set hình học giữ nguyên, còn index và quy tắc tie thay đổi theo thứ tự mới. Giải thích vì sao “stable index” không đồng nghĩa với một ID sống qua mọi lần sắp xếp.
