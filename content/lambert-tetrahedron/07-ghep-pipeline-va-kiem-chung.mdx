# Hoàn thiện renderer và kiểm chứng độc lập

## Vấn đề cần giải quyết

Cube đổi sáng nhìn hợp lý chưa đủ chứng minh renderer đúng. Nếu normal bị đảo hoặc culling và depth cùng sai theo một cách, ảnh mặc định vẫn có thể “đẹp”. Bài cuối chốt đường đi của dữ liệu và kiểm ảnh bằng một phương pháp không dùng triangle rasterizer.

Ta cũng dọn chế độ trình diễn: tắt bảng số và vectors nhưng giữ perspective, grid và cube được chiếu sáng. Canvas giúp thử công thức; **sản phẩm chính vẫn là executable C++/SDL3 tải về và chạy độc lập**.

## Hiểu ý tưởng trước khi viết code

Một triangle đi qua pipeline:

$$
\text{local}\to\text{world}\to
\{\text{normal, lighting, culling}\}\to
\text{view}\to\text{near clip}\to\text{project}\to\text{raster}\to\text{depth}
$$

Flat color thuộc face gốc. Clipper có thể tạo thêm vertex, nhưng không tạo thêm một mặt vật liệu mới hoặc một normal mới. Hai triangle sau fan tiếp tục dùng cùng shadedColor.

Để đối chiếu, ta bắn một ray qua tâm từng pixel. Đưa ray về local space rồi giao với cube [−1,1]³ bằng slab method. Mặt AABB bị chạm cho normal là một vector trục; từ đó tính màu Lambert dự kiến. Cách này không gọi clipNear, orient2D, rasterizeTriangle hoặc sampleFace.

## Viết code từng bước

### Bước 1 — Giữ một màu từ face gốc tới fragment

Trong include/render.hpp, đoạn cuối mỗi face là:

```cpp title="include/render.hpp — clip và fan không tính lại lighting"
const auto polygon = clipNear(viewVertices, 0.5);
// Mọi triangle sinh ra từ face đều dùng lại một shadedColor.
for (std::size_t i = 1; i + 1 < polygon.size(); ++i) {
    const auto a = projectVertex(polygon[0], image.width, viewHeight);
    const auto b = projectVertex(polygon[i], image.width, viewHeight);
    const auto c = projectVertex(polygon[i + 1], image.width, viewHeight);
    if (!a || !b || !c) {
        continue;
    }
    ++stats.clippedTriangles;
    rasterizeTriangle({*a, *b, *c}, image.width, viewHeight, [&](int x, int y, double inverseZ) {
        ++stats.covered;
        const std::size_t pixel = std::size_t(y) * std::size_t(image.width) + std::size_t(x);
        if (inverseZ <= image.inverseDepth[pixel]) {
            return;
        }
        image.inverseDepth[pixel] = inverseZ;
        image.owner[pixel] = int(index);
        image.pixels[pixel] = packColor(sample.lighting.shadedColor);
        ++stats.passed;
    });
}
```

Color được lấy từ sample của face, không từ ID pixel, depth hoặc thứ tự triangle. Callback chỉ làm depth test rồi ghi màu. Clear inverseDepth về 0 đầu frame; nếu quên, frame cũ sẽ chặn mặt mới.

### Bước 2 — Dựng một reference không dùng rasterizer

Trong tests/tests.cpp, rayCube chỉ dùng origin/direction local và ba cặp slab:

```cpp title="tests/tests.cpp — reference ray với cube local"
std::optional<RayHit> rayCube(lab::Vec3 origin, lab::Vec3 direction) {
    double enter = -1e30, leave = 1e30;
    lab::Vec3 enterNormal;
    const std::array<double, 3> o = {origin.x, origin.y, origin.z};
    const std::array<double, 3> d = {direction.x, direction.y, direction.z};
    for (std::size_t axis = 0; axis < 3; ++axis) {
        if (std::abs(d[axis]) < 1e-12) {
            if (o[axis] < -1 || o[axis] > 1) {
                return std::nullopt;
            }
            continue;
        }
        double near = (-1 - o[axis]) / d[axis], far = (1 - o[axis]) / d[axis];
        double sign = -1;
        if (near > far) {
            std::swap(near, far);
            sign = 1;
        }
        if (near > enter) {
            enter = near;
            enterNormal = {};
            if (axis == 0) {
                enterNormal.x = sign;
            }
            if (axis == 1) {
                enterNormal.y = sign;
            }
            if (axis == 2) {
                enterNormal.z = sign;
            }
        }
        leave = std::min(leave, far);
    }
    if (enter > leave || leave <= 0 || enter <= 0) {
        return std::nullopt;
    }
    return RayHit{enter, enterNormal};
}
```

Mỗi axis tạo một khoảng t của đoạn ray nằm trong slab. Giao ba khoảng cho enter/leave. Normal lưu lại trục đã tạo enter lớn nhất: đó là mặt đầu tiên ray chạm.

Đây là reference dành riêng cho cube lồi của project, không phải một OBJ ray tracer. Nó đủ độc lập để bắt sai coverage, depth hoặc màu mà các test dot riêng lẻ không thấy.

### Bước 3 — So cả ảnh, không chỉ một pixel thuận lợi

Test chạy bốn tư thế model/camera và bốn hướng đèn. Với mỗi pixel:

- Nếu ray không chạm cube, owner phải là −1.
- Nếu ray chạm, pixel phải có owner và inverse depth gần bằng 1/t.
- Quay normal trục từ local sang world, tự tính dot với L rồi tính RGB dự kiến.
- Mọi pixel được cube phủ phải khớp màu, không chỉ checksum tổng.

```cpp title="tests/tests.cpp — RGB dự đoán từ normal mặt AABB"
const auto normalWorld = lab::rotateY(lab::rotateX(hit->localNormal, scene.pitch), scene.yaw);
const double cosine = normalWorld.x * light.surfaceToLight.x + normalWorld.y * light.surfaceToLight.y + normalWorld.z * light.surfaceToLight.z;
const double intensity = std::min(1.0, scene.ambient + scene.diffuseStrength * std::max(0.0, cosine));
const auto byte = [&](double base) {
    return std::uint32_t(std::lround(base * intensity));
};
const auto expected = (byte(100) << 24U) | (byte(180) << 16U) | (byte(240) << 8U) | 255U;
if (image.pixels[p] != expected || !close(image.inverseDepth[p], 1.0 / hit->distance, 1e-8)) {
    ++errors;
}
```

Ngoài oracle, test còn đảo draw order, tắt culling và tắt lighting. Hai phép đầu không được đổi ảnh; phép cuối được đổi màu nhưng không được đổi owner hoặc depth. Một lỗi geometry không được che bằng việc đổi đèn.

### Bước 4 — Dọn chế độ trình diễn và đường thoát lỗi

Checkpoint 7 mặc định tắt debug. F bật lại bảng số; N bật vectors, T chọn triangle. Khi tắt debug, grid và ký hiệu đèn vẫn giúp người xem hiểu scene 3D. Đèn không tạo shadow; grid không phải một mặt đang nhận ánh sáng.

main kiểm mọi bước tạo tài nguyên/upload/present và giải phóng mouse capture trước khi hủy window. Nhánh --smoke mở window ẩn, đổi preset, resize, đổi debug rồi tự kết thúc sau tám frame; không dùng vòng chạy vô hạn để test.

## Ghép các phần lại

Tại thư mục gốc của ZIP:

```bash title="Terminal — build và test toàn bộ Project 19"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON -DBUILD_TESTING=ON
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure --timeout 30
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure --timeout 30
```

Chạy project_19_final rồi kiểm: 1–4 đổi đèn; Space chạy/dừng; dấu chấm tiến một bước; L/P đổi lighting/material; M chuyển model/camera; WASD/kéo điều khiển mode đó; Q/E và [/] chỉnh đèn; N/T xem vector; C đối chiếu culling; F chuyển trình diễn/debug; R reset.

Phần **Toàn bộ mã nguồn của dự án** dưới bài cung cấp CMakeLists, mọi header, main và tests; ZIP chứa cả starter, từng checkpoint và final. Build final mặc định, chỉ bật BUILD_CHECKPOINTS khi cần đối chiếu các bài. Trên Linux/macOS, executable thường nằm trực tiếp trong build thay vì build/Debug.

## Thử làm sai để hiểu đúng

1. Trong callback raster, đổi shadedColor sang baseColor. Oracle phải báo sai RGB dù coverage và depth vẫn đúng. Khôi phục màu đã chiếu sáng.
2. Quên clear depth trước frame. Xoay cube làm xuất hiện vùng giữ ảnh cũ; test frame độc lập có thể không bắt lỗi lifecycle, nên renderScene phải chịu trách nhiệm clear.
3. Đổi L nhưng cũng vô tình đổi scene.yaw trong handler. Test “lighting changes color only” hoặc thao tác giữ cube đứng yên sẽ phát hiện geometry thay đổi. Tách hai state.

## Tự kiểm tra kết quả

- Cube tám vertex, mười hai triangle; normal/winding nhất quán.
- Diffuse không dương ở mặt quay lưng đèn, ambient giữ đúng phần nền.
- Đèn orbit, model rotation và camera orbit điều khiển riêng.
- Flat color được giữ sau near clip; perspective/depth không phụ thuộc draw order.
- Reference ray/AABB khớp coverage, inverse depth và RGB ở nhiều tư thế.
- Starter, cả bảy checkpoint, final và tests build ở Debug lẫn Release.
- Mã đầy đủ có comment, thụt 4 spaces, có cách chạy và kiểm tra.
- Resize/HiDPI, pointer cancel, Tab và reduced motion không làm mất điều khiển.

## Bài tập mở rộng

Thay cube bằng một mesh lồi khác, giữ lighting pipeline nhưng thay reference AABB bằng một cách kiểm phù hợp. Đừng tự động dùng test cube để tuyên bố mesh mới đúng. Với non-uniform scale, cần giải thích normal matrix hoặc tính lại normal từ vertex đã transform như ta đang làm.
