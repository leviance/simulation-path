# Cho điểm bay, dừng và bước từng nhịp

## Vấn đề cần giải quyết

Điều khiển tay đủ để kiểm công thức, nhưng khó lặp lại cùng một thí nghiệm. Ta thêm quỹ đạo tự động để điểm đi qua nhiều depth và có thể dừng ở đúng thời điểm. Quan trọng là không để input tay và quỹ đạo cùng sửa point trong một frame.

## Hiểu ý tưởng trước khi viết code

Quỹ đạo là một hàm vị trí tuyệt đối của elapsed time:

$$
x(t)=2.2\sin(0.9t),\quad y(t)=1.3\cos(1.3t),\quad
z(t)=6+4\sin(0.55t).
$$

Z đi từ 2 đến 10 world, nên bạn thấy rõ điểm tiến gần/rời xa, ngay cả khi không đổi size marker. Cùng t phải cho cùng point, bất kể t được tích lũy bằng 20 hay 60 frame.

Có hai kiểu thao tác khác nhau: WASD/QE dịch point hiện tại, còn Chạy quỹ đạo đặt point theo công thức trên. Vì vậy khi bật chạy hoặc nhấn N lần đầu sau chỉnh tay, điểm chuyển đến vị trí của quỹ đạo tại elapsed tương ứng; đây không phải lệnh “bay tiếp theo hướng vừa bấm”. Pause giữ elapsed, R/preset đặt elapsed=0. Input tay tạm dừng quỹ đạo.

Clamp dt tối đa 0.1s ngăn một frame bị treo làm nhảy quá xa. Nó không cố bù toàn bộ wall-clock time đã mất khi debugger dừng; hãy gọi đúng đây là simulation elapsed time.

## Viết code từng bước

Tiếp tục sửa **starter/include** và **starter/src**, giữ lại mã đã hoàn thành ở bài trước. Tiêu đề code block ghi đường dẫn tính từ thư mục Starter. Nếu bài yêu cầu thay một hàm, hãy thay hàm cũ, không dán thêm một bản trùng tên.

Build và chạy đúng mã bạn vừa viết:

```powershell title="Chạy mã đang học trong Starter"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_11_starter --parallel 2
.\build\Debug\project_11_starter.exe
```

**Checkpoint 06 là bản tham khảo sau bài này**, không phải nơi tự nhận thay đổi từ Starter. Khi cần đối chiếu, mở checkpoints/06 hoặc build riêng target project_11_checkpoint_6; lệnh đó chạy mã mẫu, không kiểm chứng phần bạn vừa sửa.

### Bước 1 — Viết quỹ đạo thành hàm thuần

```cpp title="include/lab.hpp — một thời điểm xác định một vị trí"
inline Vec3 flightPoint(double timeSeconds) {
    return {std::sin(0.9 * timeSeconds) * 2.2, std::cos(1.3 * timeSeconds) * 1.3, 6.0 + std::sin(0.55 * timeSeconds) * 4.0};
}
```

Tại t=0, point=(0,1.3,6). Không thêm điểm cũ vào kết quả này; nếu cộng dồn, bạn đang tích phân một hàm vị trí như vận tốc.

### Bước 2 — Tích lũy thời gian an toàn

```cpp title="include/lab.hpp — bỏ dt không hợp lệ và giới hạn frame bị trễ"
inline double advanceFlightTime(double current, double deltaTime) {
    if (!std::isfinite(current) || !std::isfinite(deltaTime) || deltaTime <= 0.0) {
        return current;
    }
    return current + std::min(deltaTime, 0.1);
}
```

```cpp title="include/scene.hpp — cập nhật đúng một nguồn point"
inline void advanceScene(Scene& scene, double deltaTime) {
    if (!std::isfinite(deltaTime) || deltaTime <= 0.0) {
        return;
    }
    scene.elapsed = advanceFlightTime(scene.elapsed, deltaTime);
    scene.point = flightPoint(scene.elapsed);
}
```

Thêm flightPoint và advanceFlightTime vào cuối namespace lab trong lab.hpp. Thêm advanceScene vào namespace lab trong scene.hpp, sau movePoint/applyPreset. Hàm advanceScene chủ động cập nhật một bước; chính main.cpp quyết định có gọi nó liên tục hay không bằng !paused. Khối WASD/QE gọi movePoint trước và đặt paused=true, vì vậy quỹ đạo không ghi đè thao tác tay ở cuối frame.

### Bước 3 — Pause và step không phụ thuộc key-repeat

```cpp title="src/main.cpp — Space đổi mode, N tiến một bước"
if (event.key.key == SDLK_SPACE && !event.key.repeat) {
    scene.paused = !scene.paused;
}
if (event.key.key == SDLK_N && !event.key.repeat && scene.paused) {
    lab::advanceScene(scene, 0.1);
}
```

Mỗi lần nhấn Space chỉ toggle một lần nhờ !event.key.repeat. N chỉ chạy khi paused. Trong Canvas có hai button tương đương; reduced-motion tắt chạy tự động nhưng vẫn cho step và các slider.

## Ghép các phần lại

Trong main.cpp, đặt khối dưới **sau phần đọc WASD/QE và trước if (dirty)**. Nếu bạn chỉ thêm hàm advanceScene mà quên gọi ở vòng lặp, Space sẽ đổi paused nhưng điểm vẫn đứng yên.

```cpp title="src/main.cpp — chạy quỹ đạo sau khi xử lý input tay"
if (!scene.paused) {
    lab::advanceScene(scene, deltaTime);
    dirty = true;
}
```

Trong presentFramebuffer, sau dòng lens và trước SDL_RenderPresent, thêm trạng thái và thời gian:

```cpp title="include/presentation.hpp — đọc simulation elapsed và pause"
const char* state = "PAUSED";
if (!scene.paused) {
    state = "FLYING";
}
std::snprintf(value, sizeof(value), "t %.3f s | %s | Space pause, N step 0.1s, mouse drag from lesson 7, F debug from lesson 8", scene.elapsed, state);
if (!text(renderer, 16, 768, value)) {
    return false;
}
```

Bộ khung đã xử lý focus lost, hidden/minimize và resize: đặt paused=true và dirty=true. Khi cửa sổ được hiện lại hoặc bị yêu cầu vẽ lại, nó đặt dirty=true để ảnh không bị trống. Giữ các nhánh đó; đừng thay bằng việc chạy quỹ đạo trong mọi frame.

Build lại project_11_starter. Thử Chạy/Pause, tiến 0.1s và reset. So quỹ đạo tại elapsed=1s khi chia thành nhiều dt nhỏ: vị trí phải trùng. FOV và camera không làm đổi công thức world, chỉ đổi cách nhìn.

Chuyển tab, mất focus hoặc resize sẽ pause. Khi quay lại, ứng dụng không tự bay tiếp. Đây là lựa chọn để người học không mất vị trí đang quan sát và không gặp một dt khổng lồ sau thời gian tab ẩn.

## Thử làm sai để hiểu đúng

1. Thay scene.point=flightPoint(t) bằng phép cộng kết quả đó vào point. Quỹ đạo trôi rất nhanh; giải thích vì sao vị trí không thể được cộng như vận tốc, rồi khôi phục.

2. Bỏ !repeat ở Space. Giữ phím sẽ bật/tắt liên tục theo OS key-repeat. Khôi phục và kiểm giữ Space chỉ đổi một lần.

3. Dùng 60 bước 1/60s và 20 bước 0.05s. Tổng đều là 1s, nên point bằng nhau trong sai số. Đừng dùng một bước 1s để so vì dt bị cap thành 0.1s.

## Tự kiểm tra kết quả

- Tại t=0 công thức cho (0,1.3,6), depth nằm trong [2,10].
- Cùng simulation elapsed cho cùng point ở nhiều phân hoạch dt hợp lệ.
- Negative/NaN/Inf dt không làm state nhiễm lỗi; dt lớn chỉ tăng 0.1s.
- Input tay dừng tự động, pause giữ elapsed, reset/preset đặt elapsed về 0.
- Hidden/blur/resize pause; reduced-motion vẫn dùng step được.
