# Chặn điểm không thể nhìn thấy

## Vấn đề cần giải quyết

Ta sắp dựng bốn cổng giống hệt nhau trên một đoạn đường. Chỉ cần nhìn kích thước của chúng, bạn sẽ đoán được cổng nào ở gần. Nhưng có một cái bẫy: nếu một đầu vạch sàn lọt ra sau camera, có nên xóa luôn cả vạch không? Làm vậy, sàn sẽ biến mất ngay dưới chân người xem.

Các nhánh kiểm tra ở bài 3 đã ngăn trường hợp đó. Bài này ta sẽ kiểm chứng từng nhánh, rồi giải quyết một bài toán mới: **một đoạn thẳng có đầu nằm ngoài vùng nhìn thì có phải bỏ cả đoạn không?** Từ cách cắt đoạn đó, ta mới dựng thêm lưới sàn và bốn khung 3D để điểm sáng có cảnh nền đối chiếu.

## Hiểu ý tưởng trước khi viết code

Trình tự xử lý quan trọng hơn tên các nhánh:

- invalid: dữ liệu nonfinite, FOV/viewport không hợp lệ hoặc near/far sai.
- behind: camera-space Z≤0.
- before-near: Z dương nhưng nhỏ hơn near.
- beyond-far: Z>far.
- outside: depth hợp lệ, nhưng ít nhất một NDC nằm ngoài [-1,1].
- visible: depth hợp lệ và cả hai NDC nằm trong khung.

Near và far ở đây đều nhận điểm đúng trên plane. Guard kiểm Z **trước** cameraToNdc. Chặn sau phép chia vẫn để Inf/NaN lọt vào những bước trung gian.

Với behind/near/far/invalid, screen và NDC chưa tồn tại. Với outside, phép chiếu vẫn cho số hữu hạn, nhưng renderer không vẽ marker. Không clamp số outside về cạnh viewport rồi gọi nó là visible.

### Bước 2 — Kiểm tra vì sao điểm bị loại

Trong projectPerspective, ba nhánh dưới nằm **trước** lời gọi cameraToNdc. Giữ nguyên thứ tự này; đây là đoạn cần đọc lại, không phải một hàm mới để dán thêm:

```cpp title="include/lab.hpp — kiểm depth rồi mới gọi cameraToNdc"
if (cameraPoint.z <= 0.0) {
    result.status = ProjectionStatus::BehindCamera;
    return result;
}
if (cameraPoint.z < lens.nearPlane) {
    result.status = ProjectionStatus::BeforeNearPlane;
    return result;
}
if (cameraPoint.z > lens.farPlane) {
    result.status = ProjectionStatus::BeyondFarPlane;
    return result;
}
```

Behind khác before-near: Z âm nghĩa là điểm nằm sau camera; Z dương nhưng nhỏ hơn near nghĩa là điểm vẫn ở phía trước, chỉ là quá gần. Tương tự, vượt far khác ra ngoài cạnh trái/phải của ảnh. Hai loại lỗi cần hai phép kiểm khác nhau.

inline bool isInsideNdc(Vec2 ndc) {
    return std::abs(ndc.x) <= 1.0 && std::abs(ndc.y) <= 1.0;

### Bước 3 — Cắt đoạn lưới thay vì xóa cả đoạn

Một điểm không nhìn thấy thì có thể bỏ. Nhưng đoạn từ A=(−1,0,0) đến B=(1,0,2) vẫn đi xuyên qua near=0.5. Nếu bỏ cả đoạn chỉ vì A không hợp lệ, đường lưới sẽ biến mất quá sớm.

Viết đoạn theo tham số P(t)=A+t(B−A). Riêng trục Z cho 0+t×2=0.5, nên t=0.25. Thế lại X được −1+0.25×2=−0.5. Phần còn lại phải bắt đầu ở (−0.5,0,0.5).

Để dùng cùng cách tính cho cả near và far, ta quy ước a/b là khoảng cách có dấu: không âm ở phía được giữ lại. Khi đó t=a/(a−b). Với near, lấy Z−near; với far, lấy far−Z. Thêm clipDepth vào lab.hpp, sau projectPerspective:

```cpp title="include/lab.hpp — near/far clipping trước perspective divide"
inline bool clipDepth(Vec3& start, Vec3& end, const PerspectiveLens& lens) {
    if (!finite(start) || !finite(end) || !std::isfinite(lens.nearPlane) || !std::isfinite(lens.farPlane) || lens.nearPlane <= 0.0 || lens.farPlane <= lens.nearPlane) {
        return false;
    }

    struct DepthPlane {
        double depth;
        double direction;
    };

    for (const auto& plane : {DepthPlane{lens.nearPlane, 1.0}, DepthPlane{lens.farPlane, -1.0}}) {
        const double a = (start.z - plane.depth) * plane.direction;
        const double b = (end.z - plane.depth) * plane.direction;
        if (!std::isfinite(a) || !std::isfinite(b)) {
            return false;
        }
        if (a < 0.0 && b < 0.0) {
            return false;
        }
        if (a < 0.0 || b < 0.0) {
            const double denominator = a - b;
            if (!std::isfinite(denominator)) {
                return false;
            }
            const double t = a / denominator;
            Vec3 hit{start.x + t * (end.x - start.x), start.y + t * (end.y - start.y), plane.depth};
            if (!finite(hit)) {
                return false;
            }
            if (a < 0.0) {
                start = hit;
            } else {
                end = hit;
            }
        }
    }
    return true;
}
```

DepthPlane ghi rõ hai thông tin: vị trí mặt phẳng và chiều được giữ lại. Near dùng direction=+1, far dùng direction=−1. Cả hai đầu mút nằm ngoài cùng một phía thì bỏ. Nếu chỉ một đầu mút nằm ngoài, thay nó bằng giao điểm. Gán Z của giao điểm đúng bằng plane.depth để tránh sai số rất nhỏ khiến guard loại nhầm điểm vừa cắt.

Ngay đầu hàm phải kiểm cả hai giới hạn `near` và `far`. Nếu một giới hạn là NaN, phép so sánh `<` sẽ không phát hiện được nó. Khi hàm trả `false`, bỏ qua đoạn này và vẽ tiếp đoạn kế bên.

### Bước 4 — Chiếu một đoạn thẳng, rồi ghép thành cảnh nền

Bạn đã có `clipScreen` và `drawLine` trong khung ban đầu. Trong `work/include/view.hpp`, viết `drawScreenSegment` để hai hàm đó làm việc với nhau. Hàm nhận tọa độ **đã chiếu**: nó cắt ở mép khung trước, rồi mới làm tròn về chỉ số pixel. Ở khung rộng 800 px, cạnh hình học có thể là x=800, nhưng chỉ số cuối chỉ là 799.

```cpp title="include/view.hpp — từ đoạn trên ảnh tới pixel hợp lệ"
inline void drawScreenSegment(Framebuffer& image, Vec2 from, Vec2 to, const Viewport& viewport, std::uint32_t color) {
    if (!clipScreen(from, to, viewport)) {
        return;
    }
    // Biên phải và biên dưới là tọa độ hình học, không phải chỉ số pixel cuối.
    const double left = std::max(0.0, std::ceil(viewport.x));
    const double top = std::max(0.0, std::ceil(viewport.y));
    const double right = std::min(static_cast<double>(Framebuffer::width - 1), std::ceil(viewport.x + viewport.width) - 1.0);
    const double bottom = std::min(static_cast<double>(Framebuffer::height - 1), std::ceil(viewport.y + viewport.height) - 1.0);
    if (right < left || bottom < top) {
        return;
    }
    const int x0 = static_cast<int>(std::lround(std::clamp(from.x, left, right)));
    const int y0 = static_cast<int>(std::lround(std::clamp(from.y, top, bottom)));
    const int x1 = static_cast<int>(std::lround(std::clamp(to.x, left, right)));
    const int y1 = static_cast<int>(std::lround(std::clamp(to.y, top, bottom)));
    drawLine(image, x0, y0, x1, y1, color);
}
```

Bây giờ đặt `line3D` trước `renderScene`. Hai đầu **đầu vào** vẫn ở trong không gian 3D. Đổi chúng về hệ camera, cắt phần nằm ngoài khoảng độ sâu, rồi chiếu phần còn lại. Vì đã trừ vị trí camera một lần, bước chiếu ở đây dùng camera tại gốc:

```cpp title="include/view.hpp — giữ phần đoạn nhìn thấy được"
inline void line3D(Framebuffer& image, Vec3 start, Vec3 end, const Scene& scene, std::uint32_t color) {
    start = worldToCamera(start, scene.camera);
    end = worldToCamera(end, scene.camera);
    if (!clipDepth(start, end, scene.lens)) {
        return;
    }
    const Camera3D origin{};
    const Viewport viewport = viewportFor(scene);
    const auto a = projectPerspective(start, origin, scene.lens, viewport);
    const auto b = projectPerspective(end, origin, scene.lens, viewport);
    if (!a.screen || !b.screen) {
        return;
    }
    drawScreenSegment(image, *a.screen, *b.screen, viewport, color);
}
```

Vì start/end đã ở camera space, hai lời gọi projectPerspective dùng camera tại gốc. Nếu truyền scene.camera lần nữa, ta sẽ trừ vị trí camera hai lần. Sau phép chiếu, clipScreen cắt theo bốn cạnh viewport để Bresenham không phải duyệt một đoạn dài nằm ngoài màn hình. Đầu mút nằm ngoài NDC vẫn có thể thuộc một đoạn cắt qua ảnh, nên ở đây ta kiểm screen có giá trị, không yêu cầu cả hai status đều Visible.

```cpp title="include/view.hpp — lưới sàn và bốn khung cùng kích thước"
inline void drawDepthScene(Framebuffer& image, const Scene& scene) {
    constexpr std::uint32_t rail = 0x426474FFu;
    constexpr std::uint32_t reflector = 0x75C9D1FFu;

    // Mỗi ô sàn rộng một đơn vị. Cả vạch giữa lẫn hai mép đường đều nằm trên sàn.
    for (int x = -4; x <= 4; ++x) {
        const double position = static_cast<double>(x);
        line3D(image, {position, kRunwayFloor, 1.0}, {position, kRunwayFloor, 16.0}, scene, kGrid);
    }
    for (int z = 1; z <= 16; ++z) {
        const double depth = static_cast<double>(z);
        line3D(image, {-4.0, kRunwayFloor, depth}, {4.0, kRunwayFloor, depth}, scene, kGrid);
        if (z < 16) {
            line3D(image, {0.0, kRunwayFloor, depth}, {0.0, kRunwayFloor, depth + 0.45}, scene, kGhost);
        }
    }
    for (double side : {-1.0, 1.0}) {
        const double edge = side * 1.90;
        line3D(image, {edge, kRunwayFloor, 1.0}, {edge, kRunwayFloor, 16.0}, scene, rail);
    }

    // Dựng cùng một cổng bốn lần: chỉ thay Z, không tự thu nhỏ cổng ở xa.
    for (double z : {2.0, 4.0, 8.0, 12.0}) {
        line3D(image, {-1.55, 1.10, z}, {1.55, 1.10, z}, scene, kGhost);
        for (double side : {-1.0, 1.0}) {
            const double post = side * 1.90;
            const double shoulder = side * 1.55;
            line3D(image, {post, kRunwayFloor, z}, {post, 0.75, z}, scene, kGhost);
            line3D(image, {post, 0.75, z}, {shoulder, 1.10, z}, scene, reflector);
            line3D(image, {post, kRunwayFloor, z}, {side * 1.63, kRunwayFloor, z}, scene, reflector);
        }
    }

    // Đặt bộ trục ở chân cổng thứ hai: nhìn được cả trục Z vì nó lệch trục nhìn.
    if (scene.debug) {
        const Vec3 foot{-1.90, kRunwayFloor, 4.0};
        line3D(image, foot, {-1.35, kRunwayFloor, 4.0}, scene, kAxisX);
        line3D(image, foot, {-1.90, kRunwayFloor + 0.55, 4.0}, scene, kAxisY);
        line3D(image, foot, {-1.90, kRunwayFloor, 4.55}, scene, kAxisZ);
    }
}
```

Vòng lặp đầu vẽ đường dọc sàn, vòng thứ hai vẽ đường ngang. Các chân cổng, vai vát và thanh ngang giữ nguyên tọa độ X/Y ở cả bốn cổng; chỉ Z thay đổi. Chúng thu nhỏ dần vì cùng đi qua phép chia cho Z, không phải vì ta vẽ sẵn bốn hình chữ nhật có kích thước pixel khác nhau.

## Thử làm sai để hiểu đúng

1. Cho point Z chạy lần lượt −1,0,10⁻¹²,near,far,far+0.01. Dự đoán từng status trước khi nhìn HUD; near/far chính xác phải visible nếu X=Y=0.

2. Với near=0.5, đoạn từ (−1,0,0) đến (1,0,2) phải bị cắt tại (−0.5,0,0.5). Tự tính t=0.25, rồi đối chiếu clipDepth; đây là expected độc lập.

3. Thay outside bằng clamp NDC về [-1,1]. Marker sẽ bám cạnh dù point không nhìn thấy. Khôi phục phân loại, không dùng clamp để giấu lỗi projection.

## Tự kiểm tra kết quả

- Các guard chạy trước phép chia; không cast số không hữu hạn sang int.
- Before-near khác behind, beyond-far khác outside.
- Near/far đúng trên plane được nhận; invalid lens trả Invalid.
- Đoạn cắt plane còn phần nhìn thấy được; screen clipping giữ rasterizer hữu hạn.
- Marker ngoài khung không bị đẩy giả lên cạnh.
