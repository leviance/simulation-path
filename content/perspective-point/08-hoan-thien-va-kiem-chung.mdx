# Hoàn thiện demo và kiểm chứng

## Vấn đề cần giải quyết

Bạn sẽ mang hàm chiếu sang bài tam giác xoay. Trước khi dùng nó ba lần cho ba đỉnh, hãy thử chứng minh nó đúng với **một** điểm. Đừng vội nhìn các con số: chọn nơi đốm sáng sẽ xuất hiện nếu đưa nó ra xa gấp đôi, rồi mới bật thước để kiểm tra dự đoán.

Bài cuối sẽ thêm chế độ ẩn thông tin debug để quan sát cảnh, sau đó kiểm công thức bằng một ví dụ tính tay. Cuối bài có toàn bộ mã nguồn chạy độc lập; bạn cũng sẽ biết cách chạy tests trên chính những file mình vừa viết trong `work/`, thay vì chỉ kiểm bản mẫu.

## Hiểu ý tưởng trước khi viết code

Round-trip rất hữu ích nhưng không phải bằng chứng duy nhất. Nếu chiều xuôi và chiều ngược cùng sai một quy ước, chúng vẫn có thể trả về điểm cũ.

Vì vậy cần một đáp án được tính độc lập, còn gọi là oracle. Chọn FOV 90°, viewport có gốc (10,20), rộng 800 và cao 600 pixel. Khi đó focalPixels=600/2=300. Với P=(1,0.5,4) và camera tại gốc:

$$
s_x=10+400+300\frac{1}{4}=485,\quad
s_y=20+300-300\frac{0.5}{4}=282.5.
$$

Đổi riêng Z=8 cho (447.5,301.25). Ví dụ này đồng thời kiểm perspective, Y flip và viewport origin.

Lỗi round-trip chỉ có nghĩa khi point visible và inverse có kết quả. Điểm sau camera trả “không xác định”, không phải 0 rồi được tính là một test thành công.

### Bước 2 — Viết test với đáp án độc lập

```cpp title="tests/tests.cpp — pixel biết trước, không lấy expected từ inverse"
void knownProjection() {
    const lab::Camera3D camera{};
    lab::PerspectiveLens lens;
    lens.verticalFovRadians = lab::kPi * 0.5;
    const lab::Viewport viewport{10.0, 20.0, 800.0, 600.0};
    // Tính tay bằng focalPixels = 300, không gọi inverse để tạo expected.
    const auto point = lab::projectPerspective({1.0, 0.5, 4.0}, camera, lens, viewport);
    check(point.status == lab::ProjectionStatus::Visible && point.screen.has_value(), "analytic point visible");
    check(point.screen && close(point.screen->x, 485.0) && close(point.screen->y, 282.5), "independent analytic pixel");
    const auto farther = lab::projectPerspective({1.0, 0.5, 8.0}, camera, lens, viewport);
    check(farther.screen && close(farther.screen->x, 447.5) && close(farther.screen->y, 301.25), "double depth halves displacement");
    const auto centered = lab::projectPerspective({0.0, 0.0, 4.0}, camera, lens, viewport);
    check(centered.screen && close(centered.screen->x, 410.0) && close(centered.screen->y, 320.0), "viewport origin included");
    const auto translated = lab::worldToCamera({3.0, 2.0, 8.0}, {{1.0, -1.0, 2.0}});
    check(close(translated.x, 2.0) && close(translated.y, 3.0) && close(translated.z, 6.0), "world minus camera");
}
```

tests/tests.cpp trong ZIP đã có hàm check, close, các case và main gọi chúng. Giữ nguyên file này; không tạo thêm một main trùng tên. check chỉ ghi nhận lỗi và tăng biến failures, nó không dừng chương trình ngay. Vì vậy mọi lần đọc optional đều nằm sau điều kiện point.screen && ...; nếu quên guard, chính test có thể đọc dữ liệu không tồn tại thay vì báo lỗi projection.

Tests còn kiểm near/far chính xác, invalid FOV/viewport/NaN, giao điểm clipping tính tay, ảnh CPU có lưới/marker ở clean mode và không vẽ marker behind. check ghi failure và trả EXIT_FAILURE; không dùng assert bị tắt ở Release.

### Bước 3 — Bổ sung round-trip, không lạm dụng nó

{/* snippet include/lab.hpp#round-trip */}
```cpp title="include/lab.hpp — không báo lỗi bằng zero khi phép đo chưa xác định"
inline std::optional<double> projectionRoundTripError(Vec3 point, const Camera3D& camera, const PerspectiveLens& lens, const Viewport& viewport) {
    const ProjectionResult projected = projectPerspective(point, camera, lens, viewport);
    if (projected.status != ProjectionStatus::Visible || !projected.screen) {
        return std::nullopt;
    }
    const auto restored = screenToCameraAtDepth(*projected.screen, projected.cameraPoint.z, lens, viewport);
    if (!restored) {
        return std::nullopt;
    }
    return std::hypot(restored->x - projected.cameraPoint.x, restored->y - projected.cameraPoint.y, restored->z - projected.cameraPoint.z);
}
```

Chạy trên nhiều FOV, aspect và depth hợp lệ. Mục tiêu error nhỏ hơn 10⁻⁹ world; nó bổ sung cho numeric oracle, không thay thế oracle.

### Bước 4 — Hai lần chiếu, một phép đo

Lấy A từ kết quả chiếu hiện tại. Tạo B bằng cách nhân đôi **Z tính từ camera**, giữ X và Y, rồi đưa B qua đúng hàm chiếu đã dùng cho A. Vì tâm ảnh không nhất thiết là (0,0), phải trừ tâm trước khi đo. Không cần tính tỉ số: khi đèn nằm trên trục nhìn thì cả hai khoảng cách đều bằng 0.

{/* snippet include/lab.hpp#depth-ruler */}
```cpp title="include/lab.hpp — đo khoảng cách từ tâm tới hai ảnh"
inline std::optional<DepthMeasurement> measureDoubleDepth(Vec3 point, const Camera3D& camera, const PerspectiveLens& lens, const Viewport& viewport) {
    const auto first = projectPerspective(point, camera, lens, viewport);
    if (first.status != ProjectionStatus::Visible || !first.screen) {
        return std::nullopt;
    }

    Vec3 deeper = first.cameraPoint;
    deeper.z *= 2.0;
    const auto second = projectPerspective(cameraToWorld(deeper, camera), camera, lens, viewport);
    if (second.status != ProjectionStatus::Visible || !second.screen) {
        return std::nullopt;
    }

    const Vec2 center{viewport.x + viewport.width * 0.5, viewport.y + viewport.height * 0.5};
    const double firstOffset = std::hypot(first.screen->x - center.x, first.screen->y - center.y);
    const double secondOffset = std::hypot(second.screen->x - center.x, second.screen->y - center.y);
    return DepthMeasurement{*first.screen, *second.screen, firstOffset, secondOffset};
}
```

Trong bài kiểm số ở trên, tâm là (410,320). Đo lần lượt hai đoạn (75,−37.5) và (37.5,−18.75): độ dài xấp xỉ 83.85 và 41.93 px. Nếu B đã vượt mặt phẳng xa, hãy trả về `std::nullopt`; một kết quả không đo được khác với một khoảng cách bằng 0.

### Chạy bản bạn vừa viết

Bấm F1 rồi M (Canvas: **Đo ở hai độ sâu**). Đốm màu hổ phách là A; nhìn dọc đường thước từ tâm ảnh đến A, bạn sẽ gặp vòng B ở giữa. Kéo đèn ra sát trục nhìn: cả hai dấu dồn về tâm. Tăng Z cho tới khi B vượt `far`: vòng phải biến mất, không được nhảy về góc cửa sổ.

```powershell title="Kiểm chính work/ ở cả hai cấu hình"
cmake -S . -B build-work -DCOURSE_WORKBOOK=ON
cmake --build build-work --config Debug --target project_11_work project_11_tests --parallel 1
ctest --test-dir build-work -C Debug --output-on-failure --timeout 30
cmake --build build-work --config Release --target project_11_work project_11_tests --parallel 1
ctest --test-dir build-work -C Release --output-on-failure --timeout 30
```

Không cần đổi đường dẫn include trong CMake. Với `COURSE_WORKBOOK=ON`, CTest biên dịch bằng `work/include`. Bộ test đầy đủ dùng các hàm của bài 8, nên chỉ chạy nó khi đã hoàn tất bước này.

## Thử làm sai để hiểu đúng

1. Cho projectPerspective luôn trả tâm màn hình, đồng thời sửa inverse để luôn trả point đầu vào. Một round-trip được dựng sai có thể vẫn xanh, nhưng test pixel (485,282.5) sẽ đỏ. Khôi phục và giữ oracle độc lập.

2. Tắt debug bằng F rồi thử FOV, depth, pause/step. Cảnh nền và point vẫn phải có chiều sâu. Nếu chúng biến mất, hãy tách debug overlay khỏi geometry.

3. Cố đưa test thất bại rồi chạy Release. CTest phải trả failure; sau đó khôi phục test. Không chấp nhận suite chỉ hoạt động ở Debug.

## Tự kiểm tra kết quả

- Với FOV 90° và viewport lệch gốc, A nằm ở (485, 282.5), B ở (447.5, 301.25). B nằm giữa tâm và A, không phải giữa góc cửa sổ và A.
- Đặt đèn đúng trên mặt phẳng gần hoặc xa: vẫn thấy nó nếu X/Y nằm trong khung. Đặt sau camera: không vẽ nó.
- Chiếu rồi dựng ngược điểm ở nhiều góc nhìn. Một điểm bị loại phải báo “không xác định”, không được báo sai số bằng 0.
- Tắt debug vẫn thấy đèn và mặt đường. Khi chỉnh đèn bằng tay, đồng hồ phải dừng.
- Starter, tám checkpoint, final và tests build Debug/Release; CTest chạy không cần window.
- Chọn điểm trên trục: A và B đều cách tâm 0 px. Chọn điểm mà B vượt `far`: phải thấy “không đo được”.
- Thử kéo rồi thả ngoài cửa sổ; khi quay lại, đốm sáng không còn đi theo chuột.
