# Ghép X/Y/Z và thử hai thứ tự

## Vấn đề cần giải quyết

Xoay quanh X đã đúng. Muốn tam giác đổi orientation theo mọi hướng, ta thêm Y và Z. Nhưng ở 3D, gọi X rồi Y không giống gọi Y rồi X. Bài này sẽ viết thứ tự thành các bước dễ đọc và kiểm bằng số, không giấu nó trong matrix.

## Hiểu ý tưởng trước khi viết code

Giữ nguyên quy tắc bàn tay phải:

$$
R_Y(x,y,z)=(x\cos\theta+z\sin\theta,\ y,\ -x\sin\theta+z\cos\theta),
$$
$$
R_Z(x,y,z)=(x\cos\theta-y\sin\theta,\ x\sin\theta+y\cos\theta,\ z).
$$

Ta gọi góc quanh X là pitch, quanh Y là yaw, quanh Z là roll. Tên này chỉ đặt vai trò cho ba con số; không tự biến chúng thành camera FPS hay một mô hình máy bay.

**Quy ước của project:** mọi phép quay đều theo các trục world cố định. XYZ nghĩa là áp dụng X trước, lấy kết quả quay Y, rồi quay Z. Không đọc ngược thứ tự từ tên và không gọi nó là ba phép quanh trục local đang quay. Ví dụ (1,2,3), X=Y=90°, Z=0:

- XYZ: X90 cho (1,-3,2), Y90 cho (2,-3,-1).
- ZYX: Y90 cho (3,2,-1), X90 cho (3,1,2).

Hai kết quả khác nhau dù cả hai đều giữ độ dài. Đây là sự không giao hoán, không phải lỗi rounding.

### Bước 1 — Viết hai phép quay còn lại

```cpp title="include/lab.hpp — quay quanh Y, giữ Y"
inline Vec3 rotateY(Vec3 point, double angle) {
    const double cosine = std::cos(angle);
    const double sine = std::sin(angle);
    return {cosine * point.x + sine * point.z, point.y, -sine * point.x + cosine * point.z};
}
```

```cpp title="include/lab.hpp — quay quanh Z, giữ Z"
inline Vec3 rotateZ(Vec3 point, double angle) {
    const double cosine = std::cos(angle);
    const double sine = std::sin(angle);
    return {cosine * point.x - sine * point.y, sine * point.x + cosine * point.y, point.z};
}
```

Với point (1,2,3), Y90 phải ra (3,2,-1); Z90 phải ra (-2,1,3). Hai ví dụ khóa dấu sin trước khi ghép công thức.

### Bước 2 — Đặt tên cho dữ liệu góc

```cpp title="include/lab.hpp — radian nằm trong struct có ý nghĩa"
struct EulerAngles {
    double pitch{};
    double yaw{};
    double roll{};
};
```

Scene giữ thêm RotationOrder::Xyz hoặc ::Zyx. Không truyền ba double không rõ góc nào và không đổi chúng sang degree ở giữa hàm toán.

### Bước 3 — Ghép tuần tự bằng biến trung gian

```cpp title="include/lab.hpp — thứ tự code chính là thứ tự thao tác"
inline Vec3 rotateEuler(Vec3 point, EulerAngles angles, RotationOrder order) {
    if (order == RotationOrder::Zyx) {
        Vec3 rotated = rotateZ(point, angles.roll);
        rotated = rotateY(rotated, angles.yaw);
        return rotateX(rotated, angles.pitch);
    }
    Vec3 rotated = rotateX(point, angles.pitch);
    rotated = rotateY(rotated, angles.yaw);
    return rotateZ(rotated, angles.roll);
}
```

```cpp title="include/lab.hpp — cùng một order cho cả ba đỉnh"
inline Triangle3 rotateTriangleX(const Triangle3& triangle, double angle) {
    return {rotateX(triangle.a, angle), rotateX(triangle.b, angle), rotateX(triangle.c, angle)};
}
```

Nhánh Zyx thực hiện Z→Y→X; nhánh còn lại X→Y→Z. Mỗi hàm vẫn quay quanh trục cố định của hệ tọa độ đang biểu diễn vector. Không rotate local axes rồi truyền chúng làm trục mới.

## Ghép các phần lại

worldTriangle thay rotateTriangleX bằng rotateTriangle(localTriangle,scene.angles,scene.order), sau đó vẫn translate như trước. W/S sửa pitch, A/D sửa yaw, Q/E sửa roll; O đổi order và pause tự động để so hình không bị trôi.

Chọn preset Hai góc 90°, đổi XYZ/ZYX. Với default triangle, hai orientation khác nhau; readout order difference đo độ lệch local A giữa hai cách. Nếu một hoặc hai góc bằng zero, đôi khi hai order trùng nhau; điều đó không chứng minh phép quay luôn giao hoán.

## Thử làm sai để hiểu đúng

1. Viết cùng một chuỗi X→Y→Z trong cả hai nhánh. Nhãn order vẫn đổi nhưng hình không đổi; oracle (2,-3,-1) so (3,1,2) sẽ bắt lỗi. Khôi phục hai chuỗi khác nhau.

2. Đưa 90 trực tiếp vào std::sin/std::cos thay vì π/2. Quay sẽ không phải 90°. Chỉ đổi degree→radian ở input/hiển thị.

3. Chỉ thử ba góc đều zero rồi kết luận order đúng. Thêm hai góc 90° hoặc góc tổng quát để test thật sự phân biệt được các nhánh.

## Tự kiểm tra kết quả

- Y90 và Z90 đúng các đáp án số trong bài.
- XYZ và ZYX cho kết quả khác với hai góc 90°.
- Ba edge lengths vẫn giữ nguyên ở cả hai order.
- Code, dropdown và mô tả cùng nói một quy ước trục world cố định.
- Model position không đổi khi đổi order; không rotate dồn hình của frame trước.
