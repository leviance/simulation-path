# Tái hiện lỗi che khuất do thứ tự vẽ

## Vấn đề cần giải quyết

Ảnh hiện tại mô tả thứ tự ghi pixel: fragment đến sau luôn ghi đè fragment trước. Ta giữ nguyên khối và camera, chỉ đảo thứ tự gửi triangle để nhìn rõ lỗi.

## Hiểu ý tưởng trước khi viết code

Đảo draw order không phải đảo winding. Winding đổi thứ tự ba đỉnh của một triangle; draw order đổi triangle nào được gửi trước.

Với cube lồi, sắp mặt xa trước có thể chữa một số ảnh. Nhưng các bề mặt giao nhau có thể gần ở vùng này và xa ở vùng khác, không có một thứ tự toàn triangle giải quyết được mọi pixel. Project này sẽ kiểm khoảng cách theo fragment, không dùng Painter sorting làm thay Z-buffer.

## Viết code từng bước

Viết tiếp trong **starter/include** và **starter/src** của ZIP đã giải nén. Đường dẫn trên code block tính từ Starter. Phần nào ghi “đã có” thì chỉ đọc lại; khi thay hàm hoặc struct, thay bản cũ thay vì tạo thêm định nghĩa trùng tên.

```powershell title="Build mã đang học"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_17_starter --parallel 2
.\build\Debug\project_17_starter.exe
```

Checkpoint 02 là **bản tham khảo sau bài**, chạy độc lập bằng target project_17_checkpoint_2. Nó không nhận các thay đổi bạn vừa viết trong Starter.

### Bước 1 — Viết ánh xạ thứ tự

Thêm triangleIndexAt trước renderCube trong render.hpp:

```cpp title="include/render.hpp — xuôi hoặc ngược trên cùng draw list"
inline std::size_t triangleIndexAt(std::size_t position, std::size_t count, bool reverseOrder) {
    if (position >= count) {
        return count;
    }
    if (reverseOrder) {
        return count - 1 - position;
    }
    return position;
}
```



### Bước 2 — Dùng index vừa tính trong vòng vẽ

Trong renderCube, giữ dòng std::size_t index=position, rồi thêm dòng dưới ngay sau nó và trước const auto& indexed:

```cpp title="include/render.hpp — chỉ đổi draw order"
index = triangleIndexAt(position, mesh.triangles.size(), reverseOrder);
```


Không đổi CubeMesh hoặc góc quay. Thí nghiệm này chỉ thay một biến.

### Bước 3 — Nối phím O và quan sát

Trong handleKey của controls.hpp, thêm nhánh sau trước ba dòng (void):

```cpp title="include/controls.hpp — bỏ qua key repeat"
if (!repeat && key == SDLK_O) {
    scene.reverseOrder = !scene.reverseOrder;
}
```



## Ghép các phần lại

Chạy Starter, chọn preset 3 rồi nhấn O nhiều lần. Màu thay đổi dù góc không đổi. HUD có reversed=0/1; đây là dữ liệu state thật, không phải một preset đổi cả hình học.

Canvas chưa bật depth test trong bài này. Một ảnh nhìn có vẻ hợp lý không chứng minh cơ chế che khuất đã đúng.

## Thử làm sai để hiểu đúng

1. Đảo cả B/C cùng với draw list: bạn đã thay hai yếu tố. Chỉ dùng triangleIndexAt.

2. Ghi count-position thay vì count-1-position: lượt đầu truy cập ngoài mesh. Giữ kiểm position>=count.

3. Chữa riêng preset 1 bằng một thứ tự mặt cố định rồi xoay sang góc khác để thấy giới hạn.

## Tự kiểm tra kết quả

- O không thay đổi mesh, camera hoặc góc.
- Hai thứ tự cho ảnh khác nhau khi chưa có depth test.
- Mọi triangle vẫn được gửi đúng một lần, không có index bằng count.
