# So sánh rồi ghi depth đúng thứ tự

## Vấn đề cần giải quyết

Ta đã có nơi lưu depth và cách tính depth mới. Bước quyết định còn lại rất ngắn: chỉ cho fragment gần hơn cập nhật pixel. Điều quan trọng là thứ tự compare, depth write và color write.

## Hiểu ý tưởng trước khi viết code

Với quy ước nhỏ hơn là gần hơn:

$$pass=(0\le d<1)\land(d<storedDepth).$$

Nếu pass, ghi depth và color cho cùng một pixel. Nếu fail, giữ nguyên cả hai. Dùng `<` thay vì `<=` nên fragment bằng depth sẽ không ghi đè. Các mặt đồng phẳng chồng nhau có màu khác có thể cần một tie-break riêng; project này tránh tình huống đó bằng topology và top-left rule.

Ở đây, tắt Depth test sẽ tắt cả compare và depth write; color vẫn được ghi theo draw order. Đây là hành vi được chọn rõ ràng, không dùng depth buffer còn sót để làm như vẫn có kiểm tra.

### Bước 1 — Viết compare và depth write

Thêm depthTestAndWrite sau DepthTestResult trong depth.hpp. Kiểu kết quả đã có trong Starter:

```cpp title="include/depth.hpp — reject dữ liệu sai trước khi truy cập mảng"
inline DepthTestResult depthTestAndWrite(DepthBuffer& depthBuffer, int x, int y, double newDepth, bool depthEnabled = true) {
    DepthTestResult result{1.0, newDepth, false};
    if (x < 0 || y < 0 || x >= depthBuffer.width() || y >= depthBuffer.height() || !std::isfinite(newDepth) || newDepth < 0.0 || newDepth >= 1.0) {
        return result;
    }
    result.storedDepth = depthBuffer.at(x, y);
    result.passed = !depthEnabled || newDepth < result.storedDepth;
    // Khi tắt depth test, color vẫn được ghi nhưng depth giữ giá trị clear.
    if (result.passed && depthEnabled) {
        depthBuffer.at(x, y) = newDepth;
    }
    return result;
}
```


Hàm từ chối NaN, tọa độ ngoài buffer và d ngoài [0,1), kể cả khi depth test đang tắt.

### Bước 2 — Thay quyết định luôn pass

Trong callback của renderCube, sau `DepthTestResult test{1.0,depth,true}`, thêm dòng dưới. Nhánh if(!test.passed) và lệnh ghi color đã có từ bài 1; giữ nguyên chúng:

```cpp title="include/render.hpp — compare xảy ra trước color write"
test = depthTestAndWrite(depthBuffer, x, y, depth, depthEnabled);
```


Trong Scene của scene.hpp, đổi giá trị mặc định từ false sang true:

```cpp title="include/scene.hpp — bản mới khởi đầu có depth test"
bool depthEnabled{true};
```

## Ghép các phần lại

Build Starter, chọn preset 3. Khi depth bật, O không còn làm mặt xa che mặt gần. Nhấn D rồi O để thấy lỗi quay lại. Click một pixel trên cube: fragment gần pass, fragment xa tới sau fail và không đổi màu đã lưu.

Bộ đếm pass/reject có thể đổi khi đảo order, vì fragment xa có thể pass trước khi bị fragment gần thay thế. Hãy so kết quả color/depth cuối, không yêu cầu hai bộ đếm trung gian bằng nhau.

## Thử làm sai để hiểu đúng

1. Đổi `<` thành `>` với clear=1: hầu hết fragment thua; khôi phục quy tắc nhỏ hơn thắng.

2. Ghi color trước compare: depth đúng nhưng hình vẫn phụ thuộc order. Đưa color write về sau nhánh fail.

3. Ghi depth cho cả fragment fail: fragment xa phá thông tin gần đã lưu. Chỉ ghi khi pass và depthEnabled.

## Tự kiểm tra kết quả

- 0.25 pass từ clear=1; 0.75 đến sau fail; 0.25 bằng nhau fail.
- Fail giữ nguyên color/depth; dữ liệu không hợp lệ không truy cập ngoài mảng.
- Tắt depth test: color theo draw order, depth vẫn clear.
- Depth mặc định của Scene đã chuyển sang true.

## Bài tập mở rộng

Thử chuỗi depth 0.8 → 0.3 → 0.5 ở cùng pixel, ghi stored/new/pass sau từng lượt. Kết quả cuối phải là 0.3.
