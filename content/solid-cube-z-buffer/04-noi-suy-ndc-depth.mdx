# Nội suy NDC depth cho từng fragment

## Vấn đề cần giải quyết

Một mặt nghiêng không có cùng depth ở mọi pixel. Lấy Z của tâm mặt hoặc một vertex cho cả triangle có thể khiến che khuất sai. Ta cần tính depth tại đúng sample mà rasterizer đã chọn.

## Hiểu ý tưởng trước khi viết code

projectVertex đã giữ ndcDepth từ bộ khung. Với camera nhìn +Z và near n, far f:

$$z_{ndc}=\frac{f}{f-n}-\frac{nf}{(f-n)z_{view}},\qquad d=w_Az_A+w_Bz_B+w_Cz_C.$$

NDC depth đã qua perspective divide nên được nội suy tuyến tính theo barycentric screen-space. Không áp dụng công thức này trực tiếp cho camera-space Z. Với n=1, f=10: z_view=1 cho 0; z_view=10 cho 1; z_view=4 cho 5/6.

Callback của raster.hpp nhận **triangle đã chuẩn hóa cùng weights của triangle đó**. Phải lấy cả ba ndcDepth từ normalized, không lấy B/C của input cũ rồi ghép với weights mới.

### Bước 1 — Đọc lại depth sau phép chiếu

projectVertex đã có trong geometry.hpp. Đọc lại hàm dưới, không dán trùng định nghĩa:

```cpp title="include/geometry.hpp — near và far được kiểm trước chia"
inline ScreenVertex projectVertex(Vec3 point, int width, int height, double nearPlane = 1.0, double farPlane = 10.0) {
    if (width <= 0 || height <= 0 || !std::isfinite(point.x) || !std::isfinite(point.y) || !std::isfinite(point.z) || !std::isfinite(nearPlane) || !std::isfinite(farPlane) || nearPlane <= 0.0 || farPlane <= nearPlane || point.z < nearPlane || point.z > farPlane) {
        return {0.0, 0.0, 0.0, false};
    }
    const double focalPixels = height * 0.5 / std::tan(3.14159265358979323846 / 6.0);
    const double depthRange = farPlane - nearPlane;
    const double ndcDepth = farPlane / depthRange - nearPlane * farPlane / (depthRange * point.z);
    return {width * 0.5 + focalPixels * point.x / point.z, height * 0.5 - focalPixels * point.y / point.z, ndcDepth, true};
}
```


Cả triangle bị bỏ qua nếu có vertex không hợp lệ. Đây chưa phải thuật toán cắt tam giác qua near plane; Project 18 sẽ làm phần đó.

### Bước 2 — Nội suy tại tâm pixel

Thêm interpolateNdcDepth sau DepthBuffer trong depth.hpp:

```cpp title="include/depth.hpp — một depth riêng cho mỗi fragment"
inline double interpolateNdcDepth(const ScreenTriangle& triangle, Barycentric weights) {
    return weights.a * triangle.a.ndcDepth + weights.b * triangle.b.ndcDepth + weights.c * triangle.c.ndcDepth;
}
```


Trong callback của renderCube, giữ double depth=0.0 rồi thêm dòng sau ngay trước DepthTestResult test:

```cpp title="include/render.hpp — weights và depth cùng thứ tự vertex"
depth = interpolateNdcDepth(normalized, weights);
```



### Bước 3 — Hiện kết quả thật trên HUD

Trong presentFramebuffer của presentation.hpp, trước (void)probe và return cuối hàm, thêm khối dưới. Pixel được chọn khi mouse-down ở bài 1; probe.traces đã được callback ghi lại:

```cpp title="include/presentation.hpp — weights và depth tại pixel đã chọn"
if (!probe.traces.empty()) {
    const auto& fragment = probe.traces.back();
    std::snprintf(line, sizeof(line), "pixel (%d %d) | triangle %zu | weights %.3f %.3f %.3f | depth %.6f", probe.x, probe.y, fragment.triangleIndex, fragment.weights.a, fragment.weights.b, fragment.weights.c, fragment.newDepth);
    if (!SDL_RenderDebugText(renderer, 16, 694, line)) {
        return false;
    }
}
```


Nếu click nền không có fragment thì không hiện một depth giả. Vẫn chưa ghi depth vào buffer ở bài này.

## Ghép các phần lại

Build Starter, click trên một mặt nghiêng rồi xem weights và depth trong HUD. Đổi góc nhìn: độ sâu tại các pixel khác nhau phải thay đổi. Canvas cho nhập Pixel X/Y để chọn chính xác sample; các phép toán không phụ thuộc số pixel được phóng to trên trang.

## Thử làm sai để hiểu đúng

1. Dùng camera-space Z với clear=1.0: cube ở Z≈4 sẽ không cùng thang đo. Giữ ndcDepth từ projectVertex.

2. Dùng depth của vertex A cho mọi fragment: vùng mặt nghiêng bị phẳng về depth. Trả tổ hợp barycentric.

3. Normalize triangle nhưng nội suy theo B/C cũ: tổng weights vẫn bằng 1 mà depth sai. Dùng normalized trong callback.

## Tự kiểm tra kết quả

- near=1 → 0, far=10 → 1, Z=4 → 5/6 là oracle tính tay.
- Weights tổng gần 1; d hữu hạn trong [0,1] cho scene hợp lệ.
- Pixel khác nhau trên mặt nghiêng có depth khác nhau.
- Đang tính depth, chưa compare/write; ảnh chưa hết lỗi che khuất.

## Bài tập mở rộng

Với depth ba vertex 0.2, 0.5, 0.8 và weights (0.25,0.5,0.25), tính tay d. Đáp án phải là 0.5.
