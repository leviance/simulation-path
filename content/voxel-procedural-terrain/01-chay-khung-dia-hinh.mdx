# Chạy world phẳng và tìm đúng chỗ tạo địa hình

## Vấn đề cần giải quyết

Ở Project 62, nhân vật đã đi được giữa các chunk nhưng mặt đất chỉ là một tấm phẳng. Trước khi làm đồi núi, ta cần biết chính xác đoạn nào tạo Block ID, đoạn nào dựng mesh và đoạn nào chỉ vẽ ảnh. Nếu sửa nhầm rasterizer, bạn có thể làm hình trông gồ ghề mà dữ liệu voxel vẫn phẳng.

## Hiểu ý tưởng trước khi viết code

Tạm coi mỗi cột X/Z như một chồng gạch. `heightAt(x,z)` trả về số viên trong chồng, chưa phải tọa độ viên trên cùng. Với H=4, ta đặt block tại y=0,1,2,3; y=4 là Air. Starter đã mang theo toàn bộ camera, greedy mesher và scheduler của Project 62. Trong bài này ta giữ mặt đất cao 4 để kiểm luồng chương trình trước.

## Viết code từng bước

### Bước 1 — Chạy lại cửa sổ và ảnh CPU

Mở starter trước, không chép một chương trình SDL trống mới. Window, renderer và streaming texture đã sẵn sàng; ảnh CPU vẫn có Z-buffer. Nếu chương trình không mở được, kiểm compiler và SDL trước khi viết hàm terrain.

```cpp title="src/main.cpp"
    SDL_Window* window = SDL_CreateWindow("Procedural terrain - global coordinates", 960, 600, flags);
    SDL_Renderer* renderer = nullptr;
    if (window != nullptr) {
        renderer = SDL_CreateRenderer(window, nullptr);
    }
    SDL_Texture* texture = nullptr;
    if (renderer != nullptr) {
        texture = SDL_CreateTexture(renderer, SDL_PIXELFORMAT_RGBA32, SDL_TEXTUREACCESS_STREAMING, voxel::imageWidth, voxel::imageHeight);
    }
```

### Bước 2 — Tìm nơi Entry nhận dữ liệu

Theo lời gọi từ createWorld tới loadChunk. Entry nhận buffer từ generateTerrain bằng đúng config của World, rồi mới được đưa vào map. Rebuild là bước sau, không được gọi generateTerrain trong lúc đọc neighbor hoặc xoay camera.

```cpp title="include/world.hpp"
inline bool loadChunk(World& world, Key key) {
    if (world.chunks.contains(key) || world.chunks.size() >= maxResident) {
        return false;
    }
    Entry entry;
    entry.blocks = generateTerrain(key, world.config);
    world.chunks.emplace(key, std::move(entry));
    ++world.loads;
    return true;
}
```

### Bước 3 — Đọc độ cao đơn giản nhất

heightAt kiểm đầu vào thông qua terrainSignal rồi hiện trả 4. Bài 01 thêm H vào bảng thông tin native. Đặt breakpoint ở generateTerrain: local x,z được cộng Key*16 trước khi hỏi heightAt; vòng y chỉ lấp đến H−1. Đây là điểm ta sẽ thay ở bài tiếp.

```cpp title="include/terrain.hpp"
inline int heightAt(double x, double z, const TerrainConfig& config) {
    const double signal = terrainSignal(x, z, config);
    (void)signal;
    return 4;
}
```

## Ghép các phần lại

Configure với BUILD_CHECKPOINTS=ON, build checkpoint_1 rồi chạy. Ban đầu có một resident và tám job chờ; N xử lý tối đa hai job, Space tải dần. WASD là bước 4 đơn vị, không phải controller có vận tốc. Cả chunk mới lẫn chunk cũ đều phải cao 4. Việc lặp lại phần này giúp tách lỗi pipeline khỏi lỗi noise.

```bash title="Terminal — checkpoint 01"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_63_checkpoint_1 --parallel 2
./build/Debug/project_63_checkpoint_1.exe
```

Lệnh trên dùng Visual Studio 2022 trên Windows. Với Ninja/Make single-config, đặt `-DCMAKE_BUILD_TYPE=Debug` khi configure và chạy executable trong `build/`. Tên target có trong CMakeLists.txt của ZIP. Mục **Mã chạy được sau bài** dưới đây có toàn bộ file của checkpoint, không chỉ các đoạn vừa thay.

## Thử làm sai để hiểu đúng

1. Đổi điều kiện lấp cột từ `y < height` sang `y <= height`. Dữ liệu thành 5 lớp dù inspector vẫn ghi H=4; hãy đọc block y=4 để chứng minh lệch một.
2. Thử gọi generateTerrain từ hàm sceneMesh rồi đếm lời gọi khi chỉ xoay camera. Nếu số lần sinh tăng, dữ liệu đã bị trộn vào bước vẽ; khôi phục cách cache trong Entry.

Thực hiện trên bản thử riêng rồi hoàn tác trước khi sang bài tiếp theo.

## Tự kiểm tra kết quả

Có đất nhìn thấy ngay từ starter, không cần tải hết mới thấy ảnh. H=4, block trên cùng y=3; N không vượt budget. Camera chỉ raster lại ảnh, không thay checksum Block ID. Bạn chỉ ra được chuỗi generateTerrain → Entry.blocks → rebuild → Entry.mesh → render.

## Bài tập mở rộng

Thêm một bộ đếm cột đã sinh, đặt ở generateTerrain chứ không ở draw. Với một chunk, bạn dự đoán được con số 16×16=256 trước khi chạy. Bài tiếp theo thay đúng một hàm để mặt đất bắt đầu nhấp nhô.
