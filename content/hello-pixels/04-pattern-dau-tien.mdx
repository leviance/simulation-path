# Tạo bốn chế độ: solid, gradient, checkerboard và noise

## Vấn đề cần giải quyết

Dấu cộng chứng minh một số pixel đã đi từ CPU lên cửa sổ. Nhưng để kiểm cả ảnh, ta cần chạm đến mọi hàng và mọi cột. Spec yêu cầu bốn chế độ; mỗi chế độ cũng giúp nhận ra một loại lỗi:

- Solid kiểm toàn ảnh được ghi đúng một màu.
- Gradient kiểm hai trục và hai đầu dải 0–255.
- Checkerboard kiểm chia ô, chẵn/lẻ và thứ tự x/y.
- Noise kiểm thứ tự duyệt cùng khả năng tái lập từ seed.

Ta viết và chạy từng mẫu, sau đó mới nối với phím 1–4. Không cần thay texture mỗi khi đổi scene vì kích thước và định dạng ảnh vẫn giống nhau.

## Hiểu ý tưởng trước khi viết code

Solid chỉ gán cùng số màu cho mọi phần tử, chính là clear ở bài 03.

Gradient cần biết vị trí tương đối của một pixel. Với width=3, ba cột có x=0,1,2; chia cho width−1 cho các tỉ lệ 0, 0,5 và 1:

$$
R(x)=\left\lfloor255\frac{x}{\max(1,width-1)}\right\rfloor,\qquad
G(y)=\left\lfloor255\frac{y}{\max(1,height-1)}\right\rfloor
$$

Mẫu số bằng 1 khi ảnh chỉ có một cột/hàng để không chia cho 0. Kênh ấy nhận 0 vì tọa độ duy nhất là 0. Với ảnh 3×3, pixel giữa có R=G=127 sau khi cắt phần thập phân.

Checkerboard nhóm mỗi cell pixel thành một ô. `x/cell` và `y/cell` là tọa độ ô; tổng chẵn chọn màu A, tổng lẻ chọn màu B.

Noise dùng một chuỗi số giả ngẫu nhiên. Chuỗi của bài này là LCG 32 bit:

$$state_{n+1}=(1664525\,state_n+1013904223)\bmod 2^{32}$$

“Ngẫu nhiên” không có nghĩa mỗi lần vẽ phải đổi ảnh. Cùng seed, cùng số phần tử và cùng thứ tự duyệt phải cho đúng cùng chuỗi.

## Viết code từng bước

### Bước 1 — Giữ solid là trường hợp đơn giản nhất

Trong main, scene 1 gọi đúng hàm clear đã học. Khi chọn Solid, mọi phần tử trở thành màu xanh `rgba(83,240,174)`. Không cần viết lại vòng fill hay tạo một lớp scene phức tạp cho project đầu tiên.

Nếu Solid không phủ kín hoặc sai màu, dừng ở đây để kiểm framebuffer/pitch trước khi viết gradient. Một mẫu đơn giản là cách khoanh vùng lỗi tốt hơn việc thêm công thức mới liên tục.

### Bước 2 — Thêm gradient vào Framebuffer

```cpp title="include/lab.hpp — gradient hai trục"
void gradient() {
    const int denominatorX = std::max(1, width - 1);
    const int denominatorY = std::max(1, height - 1);

    for (int y = 0; y < height; ++y) {
        for (int x = 0; x < width; ++x) {
            const auto red = static_cast<std::uint8_t>(255.0 * x / denominatorX);
            const auto green = static_cast<std::uint8_t>(255.0 * y / denominatorY);
            putPixel(x, y, rgba(red, green, 180));
        }
    }
}
```

`255.0` khiến phép tính dùng số thực trước khi chuyển về uint8_t. Nếu chia nguyên x/denominatorX trước rồi mới nhân 255, hầu hết pixel sẽ nhận 0.

Vòng ngoài đi theo y, vòng trong theo x, cùng thứ tự row-major. Tự đối chiếu ảnh 3×3: bốn góc có (R,G) lần lượt (0,0), (255,0), (0,255), (255,255).

### Bước 3 — Thêm checkerboard

```cpp title="include/lab.hpp — checkerboard"
void checker(int cell = 32) {
    cell = std::max(1, cell);

    for (int y = 0; y < height; ++y) {
        for (int x = 0; x < width; ++x) {
            const int cellX = x / cell;
            const int cellY = y / cell;
            const bool odd = (cellX + cellY) % 2 != 0;
            std::uint32_t color = rgba(83, 240, 174);
            if (odd) {
                color = rgba(31, 43, 68);
            }
            putPixel(x, y, color);
        }
    }
}
```

Với cell=32, x từ 0 đến 31 thuộc ô 0; x=32 bắt đầu ô 1. Sang một ô ngang/dọc đổi chẵn lẻ, còn sang chéo một ô theo cả hai trục thì cộng thêm 2, giữ màu.

Clamp cell về ít nhất 1 là quy tắc của hàm checker, không phải thay kích thước framebuffer. Hai loại đầu vào có trách nhiệm khác nhau: ảnh sai kích thước bị từ chối, còn cell≤0 được hiểu là ô một pixel.

### Bước 4 — Thêm noise, chỉ duyệt vector một lần

```cpp title="include/lab.hpp — noise có seed"
void noise(std::uint32_t seed = 17) {
    std::uint32_t state = seed;

    for (std::uint32_t& pixel : pixels) {
        state = state * 1664525u + 1013904223u;
        const auto value = static_cast<std::uint8_t>(state >> 24);
        pixel = rgba(value, static_cast<std::uint8_t>(value / 2), static_cast<std::uint8_t>(255 - value));
    }
}
```

Tính toán trên uint32_t tự quay vòng theo modulo 2³²; đây là phép toán có chủ đích, không phải signed overflow. Hai hằng số là tham số của LCG, không cần chứng minh tính chất thống kê của bộ sinh ở bài framebuffer.

`state >> 24` lấy 8 bit cao. Với seed 17, sáu giá trị đầu là 62, 210, 117, 76, 182, 85. Chúng tạo màu theo ba kênh `(value, value/2, 255-value)`. Fixture này giúp phát hiện việc đổi thuật toán, chứ không chỉ chứng minh cùng một hàm giống chính nó.

Range-for đi qua những phần tử chắc chắn tồn tại nên không cần đổi về x/y rồi kiểm biên lần nữa. Không tạo lại chuỗi từ seed cho từng pixel: cách đó làm lượng công việc tăng không cần thiết.

### Bước 5 — Cho bàn phím chọn công thức

Trước vòng lặp runPixels, thêm:

```cpp title="src/main.cpp — thông số ảnh"
int pattern = 2;
int cell = 32;
std::uint32_t seed = 17;
```

Trong nhánh KEY_DOWN, sau khi đã kiểm `!event.key.repeat`, thêm:

```cpp title="src/main.cpp — chuyển scene và đổi tham số"
if (event.key.key >= SDLK_1 && event.key.key <= SDLK_4) {
    pattern = static_cast<int>(event.key.key - SDLK_1) + 1;
    dirty = true;
}
if (event.key.key == SDLK_N) {
    ++seed;
    dirty = true;
}
if (event.key.key == SDLK_MINUS) {
    cell = std::max(1, cell - 1);
    dirty = true;
}
if (event.key.key == SDLK_EQUALS) {
    cell = std::min(128, cell + 1);
    dirty = true;
}
```

Mã phím 1–4 liên tiếp; trừ SDLK_1 rồi cộng 1 cho số scene 1–4. KEY_DOWN chỉ sửa state và đánh dấu dirty; nó không tạo texture hay chạy vòng lặp pixel.

N tăng seed một lần cho mỗi lần nhấn. −/= đổi cell trong 1–128. Bỏ key repeat giúp giữ phím không vô tình đổi hàng trăm lần trước khi người dùng nhận ra.

### Bước 6 — Tạo lại ảnh khi dirty

Trong `if (dirty)`, thay phần vẽ dấu cộng bằng:

```cpp title="src/main.cpp — chọn thuật toán tạo ảnh"
if (pattern == 1) {
    framebuffer.clear(lab::rgba(83, 240, 174));
    SDL_SetWindowTitle(window, "Hello Pixels | 1 Solid | 2 Gradient | 3 Checker | 4 Noise");
} else if (pattern == 2) {
    framebuffer.gradient();
    SDL_SetWindowTitle(window, "Hello Pixels | Gradient | 1-4: scene | Esc: quit");
} else if (pattern == 3) {
    framebuffer.checker(cell);
    SDL_SetWindowTitle(window, "Hello Pixels | Checker | -/=: cell size | 1-4: scene");
} else {
    framebuffer.noise(seed);
    SDL_SetWindowTitle(window, "Hello Pixels | Noise | N: next seed | 1-4: scene");
}
```

Phần upload và `dirty=false` giữ nguyên bên dưới. Phần present vẫn ở ngoài if dirty. Nhờ đó ảnh được hiển thị lại mà không phải tính và upload hàng triệu pixel khi không có thay đổi.

Mỗi scene ghi kín ảnh nên không cần clear thêm trước gradient/checker/noise. Khi quay lại Noise mà không đổi seed/kích thước, bạn phải thấy đúng ảnh trước đó.

## Ghép các phần lại

Input đổi `pattern/cell/seed`; vòng lặp nhìn dirty để chạy công thức; framebuffer đổi rồi được upload; texture được copy ra cửa sổ. Chỉ một phần công thức khác nhau giữa bốn scene, không có bốn event loop hoặc bốn bộ tài nguyên.

Build `project_1_checkpoint_4` và thử cả phím 1–4 trước khi sang resize. Ở bước này texture vẫn có kích thước lúc mở cửa sổ; kéo window sẽ co giãn ảnh cũ. Đây là hạn chế còn lại được xử lý ở bài tiếp theo.
