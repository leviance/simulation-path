# Mở cửa sổ đầu tiên và giữ chương trình phản hồi

## Vấn đề cần giải quyết

Mục tiêu cuối project là tạo ảnh từ một mảng pixel của riêng mình. Nhưng trước khi có ảnh, ta cần một chương trình mở được cửa sổ, nhận được yêu cầu đóng và báo lỗi đúng lúc. Nếu phần này chưa chạy ổn, rất khó biết một màn hình đen là do công thức màu hay do ứng dụng chưa vẽ gì.

Bài này bắt đầu từ starter chỉ in một dòng ra terminal. Chúng ta sẽ tự thêm SDL, cửa sổ và vòng lặp. Kết quả cuối bài là cửa sổ nền xanh đen, chưa có framebuffer. Đây là bước chuẩn bị, không phải sản phẩm hoàn chỉnh của Project 01.

Nếu chưa build được starter, hãy hoàn thành [Getting Started](/getting-started) trước. Không cần cài lại compiler hoặc chép SDL vào thư mục project nếu đã làm xong phần đó.

## Hiểu ý tưởng trước khi viết code

Ứng dụng console thường làm xong công việc rồi kết thúc. Ứng dụng có cửa sổ thì khác: nó phải tiếp tục chờ chuột, bàn phím và hệ điều hành cho đến khi người dùng muốn thoát.

Một lần đi qua vòng lặp gồm ba việc: lấy những sự kiện đang chờ, quyết định có tiếp tục không, rồi hiển thị ảnh. Phần vẽ không được nằm trong vòng lấy sự kiện; không có thao tác mới cũng không có nghĩa cửa sổ được phép ngừng phản hồi.

Ta tạo tài nguyên theo thứ tự `SDL_Init → Window → Renderer`. Renderer gắn với window, nên khi thoát phải hủy renderer trước window, rồi mới `SDL_Quit`. Ở các bài sau, texture sẽ được hủy trước renderer.

## Viết code từng bước

### Bước 1 — Build và chạy đúng mốc bài học

Giải nén ZIP vào một thư mục riêng. Trong terminal tại thư mục chứa `CMakeLists.txt`, chạy:

```bash title="Terminal — chuẩn bị starter và checkpoint"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_1_starter --parallel 2
```

Trên Windows với Visual Studio, chạy `.\build\Debug\project_1_starter.exe`. Bạn phải thấy dòng xác nhận toolchain. Starter chưa mở cửa sổ; đừng lấy final rồi xóa bớt tùy ý vì rất dễ giữ lại code của các bài chưa học.

CMake dùng C++20 và FetchContent để tải đúng SDL 3.4.8 có checksum. Executable link qua `SDL3::SDL3`. Cấu hình đầy đủ nằm trong gói source và phần mã chạy được cuối trang; bạn không phải tự đoán các include/library path.

### Bước 2 — Khởi tạo SDL và tạo window

Mở `src/main.cpp` của bài làm. Các header dùng trong bài là `SDL3/SDL.h`, `cstdlib` và `iostream`. Trong `main`, bắt đầu bằng:

```cpp title="src/main.cpp — đầu hàm main"
if (!SDL_Init(SDL_INIT_VIDEO)) {
    std::cerr << "SDL_Init failed: " << SDL_GetError() << '\n';
    return EXIT_FAILURE;
}
```

SDL3 trả `bool`: thành công là `true`. Ta đọc `SDL_GetError()` ngay khi thất bại, không tiếp tục tạo tài nguyên từ một bước khởi tạo lỗi.

Đặt `kInitialWidth = 960`, `kInitialHeight = 540` trong namespace không tên ở đầu file. Đây là các hằng số dùng trong chính file này. Tiếp theo, tạo window:

```cpp title="src/main.cpp — tạo window sau SDL_Init"
SDL_WindowFlags flags = SDL_WINDOW_RESIZABLE | SDL_WINDOW_HIGH_PIXEL_DENSITY;
SDL_Window* window = SDL_CreateWindow("Project 01 - Hello Pixels", kInitialWidth, kInitialHeight, flags);
if (!window) {
    std::cerr << "SDL_CreateWindow failed: " << SDL_GetError() << '\n';
    SDL_Quit();
    return EXIT_FAILURE;
}
```

`RESIZABLE` cho phép kéo thay đổi kích thước. `HIGH_PIXEL_DENSITY` cho phép vùng vẽ dùng mật độ pixel của màn hình. Kích thước 960×540 là kích thước window được yêu cầu, không phải lời khẳng định rằng mọi màn hình đều có đúng 518.400 pixel đầu ra.

### Bước 3 — Tạo renderer

Đặt ngay sau phần tạo window:

```cpp title="src/main.cpp — tạo renderer"
SDL_Renderer* renderer = SDL_CreateRenderer(window, nullptr);
if (!renderer) {
    std::cerr << "SDL_CreateRenderer failed: " << SDL_GetError() << '\n';
    SDL_DestroyWindow(window);
    SDL_Quit();
    return EXIT_FAILURE;
}
```

`nullptr` để SDL chọn driver phù hợp. Nếu bước này lỗi thì window đã tồn tại, nhưng renderer chưa tồn tại; vì vậy nhánh lỗi chỉ hủy window rồi đóng SDL.

Ở bài này renderer tô nền tạm để xác nhận cửa sổ chạy được. Từ bài 03, ảnh sẽ do CPU tạo; renderer chỉ copy texture chứa ảnh đó ra cửa sổ, không vẽ primitive thay cho chúng ta.

### Bước 4 — Viết vòng lặp, không bỏ sót đường thoát

Thêm `runWindowCheckpoint` vào namespace không tên, phía trên `main`:

```cpp title="src/main.cpp — vòng lặp của bài 01"
bool runWindowCheckpoint(SDL_Renderer* renderer) {
    bool running = true;
    while (running) {
        SDL_Event event{};
        while (SDL_PollEvent(&event)) {
            if (event.type == SDL_EVENT_QUIT) {
                running = false;
            }
            if (event.type == SDL_EVENT_KEY_DOWN && event.key.key == SDLK_ESCAPE) {
                running = false;
            }
        }
        if (!running) {
            break;
        }

        if (!SDL_SetRenderDrawColor(renderer, 11, 16, 32, 255)) {
            return false;
        }
        if (!SDL_RenderClear(renderer)) {
            return false;
        }
        if (!SDL_RenderPresent(renderer)) {
            return false;
        }

        SDL_Delay(10);
    }
    return true;
}
```

`PollEvent` trả từng sự kiện; ta lấy hết những sự kiện đang chờ trước khi vẽ. Chỉ đọc `event.key` khi `event.type` là sự kiện bàn phím. Close và Escape đều đổi cùng biến `running`; kiểm biến này trước phần vẽ để không tạo thêm ảnh sau yêu cầu thoát.

`SetRenderDrawColor` chọn màu, `RenderClear` xóa nền, `RenderPresent` đưa kết quả lên cửa sổ. Mọi lời gọi đều được kiểm tra. Hàm trả `false` khi vẽ lỗi, không đánh đồng lỗi render với việc người dùng đóng bình thường.

`SDL_Delay(10)` nhường CPU trong lúc chờ. Nó không bảo đảm 60 FPS: thời gian làm việc và độ chính xác của bộ lập lịch chưa được tính. Chúng ta sẽ giải quyết timing ở Project 02.

### Bước 5 — Gọi vòng lặp rồi dọn tài nguyên

Sau khi có renderer, khai báo `bool success = false;` rồi gọi:

```cpp title="src/main.cpp — chạy và dọn dẹp"
success = runWindowCheckpoint(renderer);
if (!success) {
    std::cerr << "Application failed: " << SDL_GetError() << '\n';
}

SDL_DestroyRenderer(renderer);
SDL_DestroyWindow(window);
SDL_Quit();
if (!success) {
    return EXIT_FAILURE;
}
return EXIT_SUCCESS;
```

Đoạn này là phần cuối `main`. Dọn tài nguyên ở một chỗ giúp cả đường thoát bình thường lẫn lỗi trong vòng lặp đều được xử lý. Mã đầy đủ cuối trang ghép chính xác các phần trên; không cần tự thêm lời gọi chưa được giải thích.

## Ghép các phần lại

Chạy target `project_1_checkpoint_1`. Đặt breakpoint ở `SDL_Init`, đầu `runWindowCheckpoint` và `SDL_DestroyRenderer`. Mở cửa sổ rồi đóng: debugger phải đi theo thứ tự khởi tạo, chờ sự kiện, dọn dẹp.

Chương trình chưa có ảnh CPU. Nếu cửa sổ đã hiện đúng, hãy giữ nguyên nền này làm mốc kiểm tra. Bài sau chỉ thêm bộ nhớ framebuffer; đến bài 03 mới đưa dữ liệu ấy lên màn hình.

## Thử làm sai để hiểu đúng

1. Đưa phần vẽ vào trong `while (SDL_PollEvent)`. Dự đoán điều gì xảy ra khi không có sự kiện rồi thử một lát và hoàn tác.
2. Bỏ nhánh Escape, giữ Close. Xác nhận hai cách thoát không phải cùng một sự kiện.
3. Đổi màu nền thành đỏ và chạy lại. Nếu không đổi, kiểm tra xem bạn có đang chạy đúng executable vừa build hay không.

Không cần cố tình bỏ toàn bộ event loop để làm ứng dụng treo. Ta có thể hiểu vai trò của nó bằng breakpoint và các thay đổi nhỏ an toàn.

## Bài tập mở rộng

1. Thêm phím R đổi nền giữa hai màu bằng một biến state, không tạo renderer mới.
2. In tên driver đang dùng nếu muốn tìm hiểu thêm SDL; đây không phải yêu cầu để sang bài.
3. Vẽ lại sơ đồ thứ tự tạo/hủy bằng lời của bạn.
