# Ghi màu và đưa những pixel đầu tiên lên cửa sổ

## Vấn đề cần giải quyết

Ta đã có vùng nhớ ảnh, nhưng một phần tử bằng 1 hay 255 chưa tự nói lên nó là màu gì. Và dù đổi vector trong debugger, cửa sổ vẫn chưa thay đổi: dữ liệu chưa được gửi sang SDL.

Bài này giải quyết trọn hai việc ấy. Đầu tiên quy định cách lưu màu và ghi pixel an toàn. Sau đó tạo texture, giải thích pitch và copy ảnh CPU lên cửa sổ. Cuối bài bạn phải nhìn thấy một dấu cộng do `putPixel` tạo ra, không phải một hình do API primitive của SDL vẽ hộ.

Bắt đầu từ checkpoint 2. Phần toán nằm trong `lab.hpp`; phần chuyển ảnh sang SDL được tách vào `presentation.hpp` để sau này test framebuffer không phải mở cửa sổ.

## Hiểu ý tưởng trước khi viết code

Mỗi màu có bốn kênh R, G, B, A, mỗi kênh 8 bit từ 0 đến 255. Ta chọn quy ước số nguyên `0xRRGGBBAA`:

```text title="Vị trí bit trong một giá trị uint32_t"
31........24 23........16 15.........8 7..........0
    Red          Green        Blue        Alpha
```

Ví dụ `rgba(1,2,3,4)` cho số `0x01020304`. Trên CPU little-endian, memory viewer hiện bốn byte `04 03 02 01` vì byte thấp nằm trước. Hai cách nhìn không mâu thuẫn: một bên là giá trị số, một bên là thứ tự byte trong RAM.

SDL có cả packed format và byte-array format. Ta dùng `SDL_PIXELFORMAT_RGBA8888` cho mảng uint32_t theo quy ước trên; không tự đổi sang `RGBA32` chỉ vì tên trông gần giống. [Tài liệu pixel format của SDL](https://wiki.libsdl.org/SDL3/SDL_PixelFormat) phân biệt hai loại này.

Một texture có thể hình dung là bản sao của ảnh mà renderer biết cách hiển thị. CPU tạo ảnh; `SDL_UpdateTexture` chuyển dữ liệu; `SDL_RenderTexture` copy texture; `SDL_RenderPresent` đưa kết quả lên cửa sổ.

Đổi RGBA rồi bấm “Thử putPixel”. Chọn tọa độ âm hoặc đúng bằng width để thử bị bỏ qua. Alpha vẫn được lưu trong số màu; bài này chọn chế độ copy RGB trực tiếp, chưa pha màu trong suốt.

## Viết code từng bước

### Bước 1 — Viết hàm đóng gói màu

Trong namespace `lab`, phía trên struct Framebuffer, thêm:

```cpp title="include/lab.hpp — rgba"
constexpr std::uint32_t rgba(std::uint8_t red, std::uint8_t green, std::uint8_t blue, std::uint8_t alpha = 255) {
    const std::uint32_t redBits = static_cast<std::uint32_t>(red) << 24;
    const std::uint32_t greenBits = static_cast<std::uint32_t>(green) << 16;
    const std::uint32_t blueBits = static_cast<std::uint32_t>(blue) << 8;
    return redBits | greenBits | blueBits | static_cast<std::uint32_t>(alpha);
}
```

Ta chuyển mỗi kênh sang 32 bit trước khi dịch. R nằm ở bit cao nhất, A ở thấp nhất; OR ghép những nhóm bit không chồng nhau. Viết thành các biến có tên để bạn đọc được từng phần, không cần nhẩm cả biểu thức dài.

Alpha mặc định là 255, nên ba đối số đủ tạo một màu đục. `constexpr` cho phép kiểm hàm lúc biên dịch; bài 06 sẽ dùng static_assert với các kết quả biết trước.

### Bước 2 — Bảo vệ mọi lần ghi theo tọa độ

Thêm vào Framebuffer:

```cpp title="include/lab.hpp — putPixel và clear"
void putPixel(int x, int y, std::uint32_t color) {
    if (x < 0 || y < 0 || x >= width || y >= height) {
        return;
    }

    pixels[index(x, y)] = color;
}

void clear(std::uint32_t color) {
    std::fill(pixels.begin(), pixels.end(), color);
}
```

Ảnh rộng 4 chỉ có x từ 0 đến 3. Điều kiện phải là `x >= width`, không phải `x > width`. Bốn phía đều được kiểm trước khi gọi index, lúc x/y vẫn có dấu.

`clear` không có tọa độ từ bên ngoài: std::fill đi qua đúng các phần tử vector đang có. Nó không xóa vector; nó gán cùng màu cho tất cả pixel. Nhờ đó `pixels.size()` vẫn giữ nguyên.

### Bước 3 — Tạo texture có định dạng khớp CPU

Tạo `include/presentation.hpp`, include `lab.hpp` và `SDL3/SDL.h`, đặt các helper trong namespace lab:

```cpp title="include/presentation.hpp — tạo texture"
inline SDL_Texture* createFramebufferTexture(SDL_Renderer* renderer, int width, int height) {
    SDL_Texture* texture = SDL_CreateTexture(renderer, SDL_PIXELFORMAT_RGBA8888, SDL_TEXTUREACCESS_STREAMING, width, height);
    if (!texture) {
        return nullptr;
    }

    if (!SDL_SetTextureBlendMode(texture, SDL_BLENDMODE_NONE)) {
        SDL_DestroyTexture(texture);
        return nullptr;
    }
    return texture;
}
```

Streaming texture nhận dữ liệu từ CPU. `BLENDMODE_NONE` làm phép copy không pha RGB với nền; vì vậy thay A chưa khiến dấu cộng mờ đi. Ta vẫn lưu đúng A trong framebuffer để hiểu cấu trúc màu.

`inline` ở đây cho phép định nghĩa helper trong header mà không gây trùng định nghĩa khi sau này có nhiều file cpp include nó. Bạn chưa cần xây class quản lý renderer.

Nếu tạo texture hoặc đặt blend mode lỗi, helper trả nullptr. Texture vừa tạo được hủy ngay nếu không dùng được.

### Bước 4 — Đọc pixel output rồi tạo cả ảnh và texture

Trong main.cpp, include presentation.hpp và thay hàm vòng lặp cũ bằng `bool runPixels(SDL_Window* window, SDL_Renderer* renderer)`. Phần khởi tạo của hàm:

```cpp title="src/main.cpp — đầu runPixels"
int width = 0;
int height = 0;
if (!SDL_GetRenderOutputSize(renderer, &width, &height)) {
    return false;
}

lab::Framebuffer framebuffer;
if (!framebuffer.resize(width, height)) {
    SDL_SetError("Cannot allocate initial framebuffer");
    return false;
}
SDL_Texture* texture = lab::createFramebufferTexture(renderer, width, height);
if (!texture) {
    return false;
}
```

`GetRenderOutputSize` lấy kích thước renderer theo pixel, thay vì mặc định 960×540 là mọi thứ. Framebuffer và texture phải dùng cùng hai số ấy.

Sau đó giữ event loop Close/Escape của bài trước. Khai báo `dirty`, `running` và `failed` trước vòng lặp:

```cpp title="src/main.cpp — trạng thái vòng lặp pixel"
bool dirty = true;
bool running = true;
bool failed = false;
```

`dirty` nghĩa là ảnh CPU vừa thay đổi và cần upload. Hiện chỉ có một ảnh tĩnh nên bắt đầu bằng true; tính ảnh xong sẽ đặt false. Bài 04 mới có phím đổi mẫu.

### Bước 5 — Vẽ dấu cộng bằng CPU

Sau phần lấy event và kiểm running, đặt đoạn sau trong `if (dirty)`:

```cpp title="src/main.cpp — tạo ảnh dấu cộng"
framebuffer.clear(lab::rgba(11, 16, 32));
const int centerX = framebuffer.width / 2;
const int centerY = framebuffer.height / 2;
for (int offset = -20; offset <= 20; ++offset) {
    framebuffer.putPixel(centerX + offset, centerY, lab::rgba(83, 240, 174));
    framebuffer.putPixel(centerX, centerY + offset, lab::rgba(83, 240, 174));
}
```

Mỗi offset tạo một pixel trên nét ngang và một pixel trên nét dọc. Hai nét giao ở tâm. Không có SDL_RenderLine nào ở đây: chính vector đã chứa dấu cộng trước khi SDL nhận dữ liệu.

### Bước 6 — Hiểu pitch ngay tại lần upload đầu tiên

Thêm helper:

```cpp title="include/presentation.hpp — upload ảnh"
inline bool uploadFramebuffer(SDL_Texture* texture, const Framebuffer& framebuffer) {
    const int pitch = framebuffer.width * static_cast<int>(sizeof(std::uint32_t));
    return SDL_UpdateTexture(texture, nullptr, framebuffer.pixels.data(), pitch);
}
```

Với ảnh rộng 4, mỗi hàng có 4 số 32 bit, nên pitch là `4 × 4 = 16 byte`. Đối số cuối của [SDL_UpdateTexture](https://wiki.libsdl.org/SDL3/SDL_UpdateTexture) là khoảng cách byte giữa hai hàng. Truyền 4 thay vì 16 khiến SDL đọc hàng tiếp theo sai vị trí.

`pixels.data()` là địa chỉ phần tử đầu. `nullptr` ở đối số vùng cập nhật nghĩa là gửi toàn bộ ảnh. Ta dùng UpdateTexture để dễ đối chiếu ảnh CPU; với ảnh thay đổi liên tục, SDL còn có LockTexture/UnlockTexture để tối ưu, chưa cần thêm vào bài này.

Ngay sau phần vẽ dấu cộng, vẫn trong if dirty:

```cpp title="src/main.cpp — upload một lần sau khi ảnh đổi"
if (!lab::uploadFramebuffer(texture, framebuffer)) {
    failed = true;
    break;
}
dirty = false;
```

### Bước 7 — Copy/present và giải phóng texture

Thêm helper cuối:

```cpp title="include/presentation.hpp — đưa texture ra cửa sổ"
inline bool presentFramebuffer(SDL_Renderer* renderer, SDL_Texture* texture) {
    if (!SDL_RenderClear(renderer)) {
        return false;
    }
    if (!SDL_RenderTexture(renderer, texture, nullptr, nullptr)) {
        return false;
    }
    return SDL_RenderPresent(renderer);
}
```

Hai nullptr trong RenderTexture chọn toàn bộ ảnh nguồn và toàn bộ vùng đích. Clear chỉ chuẩn bị output; pixel của dấu cộng vẫn đến từ framebuffer.

Bên ngoài if dirty, gọi:

```cpp title="src/main.cpp — cuối mỗi vòng lặp pixel"
if (!lab::presentFramebuffer(renderer, texture)) {
    failed = true;
    break;
}
SDL_Delay(10);
```

Cuối runPixels, hủy texture rồi trả `!failed`. Trong main, gọi runPixels thay cho runWindowCheckpoint; main vẫn phụ trách hủy renderer/window và SDL_Quit.

Bản đầy đủ cuối trang có toàn bộ runPixels ở đúng thứ tự. Texture thuộc phần chạy pixel nên được hủy trước khi quay về main; không được để main hủy renderer trong khi texture còn sống.

## Ghép các phần lại

Theo dõi một điểm trên dấu cộng:

`rgba → putPixel → index → pixels[index] → uploadFramebuffer → texture → presentFramebuffer`.

Các helper tách trách nhiệm, không làm mất bước. Bạn có thể dừng ở putPixel để xem số màu, rồi dừng ở upload để xem pitch. Nếu vector đúng nhưng ảnh sai màu, kiểm format; nếu từng hàng bị xô, kiểm pitch.

Ở checkpoint 3, resize mới chỉ co giãn texture cũ. Ta chưa tuyên bố đây là resize đúng số pixel; bài 05 sẽ tạo lại cả cặp tài nguyên.

## Thử làm sai để hiểu đúng

1. Trong Lab, thử x bằng width hoặc y bằng height. Quan sát thông báo bỏ qua và kiểm pixel đang chọn còn nguyên.
2. Tính pitch sai bằng width trên giấy cho ảnh 4×3: hàng 1 sẽ bắt đầu ở byte 4 thay vì byte 16. Không cần đọc quá vùng nhớ để thấy vì sao sai.
3. Đổi màu dấu cộng thành đỏ bằng rgba; nếu thành xanh dương, kiểm quy ước R/B và định dạng texture.
4. Đổi A trong Lab và xem số packed thay đổi dù RGB vẫn được copy trực tiếp. Không kết luận alpha “không hoạt động” khi blending đã tắt.
