# Nối clipper vào renderer đang chạy

## Vấn đề cần giải quyết

Đến đây debug đã có polygon và fan đúng, nhưng bề mặt vẫn biến mất theo cách discard cũ. Bài này thay đúng đường dữ liệu của renderer: chỉ những tam giác sau clip mới được project và tô pixel.

## Hiểu ý tưởng trước khi viết code

Pipeline hoàn chỉnh là classify → clip polygon → triangulate → project → rasterize. ClipForRender gom kết quả cho một frame; HUD đọc lại kết quả đó, không clip thêm một lần riêng cho bảng số.

Projection vẫn giữ guard z≥near trước phép chia. Đây là hàng rào bảo vệ dữ liệu sai, không phải thuật toán clipping. Nếu có một đỉnh outside, ta phải sinh giao điểm đúng trên cạnh; không thể chỉ trả nullopt cho cả tam giác và xem như đã xử lý xong.

Màu tại giao điểm được nội suy trong camera space. Sau projection, rasterizer ở project này dùng barycentric tuyến tính trên màn hình; chưa có perspective-correct interpolation. Khi cắt làm thay topology, màu có thể khác cách phối màu của tam giác chưa cắt. Ta kiểm đúng giao điểm và geometry, không hứa màu xuyên perspective chính xác như texture renderer.

### Bước 1 — Gom một kết quả clipping duy nhất

Trong clip.hpp, thêm clipForRender sau triangulateFan:

```cpp title="include/clip.hpp — một input, một polygon, một batch"
inline ClipResult clipForRender(const Triangle3& triangle, double nearPlane) {
    ClipResult result{};
    result.inputCounts = classifyTriangle(triangle, nearPlane);
    result.polygon = clipTriangleToNearPlane(triangle, nearPlane);
    result.batch = triangulateFan(result.polygon);
    return result;
}
```

Trong Scene ở scene.hpp, thay dòng khởi tạo clipping=false thành dòng dưới. Không thêm một field thứ hai:

```cpp title="include/scene.hpp — mặc định dùng phần sau clip"
bool clipping{true};
```



### Bước 2 — Thay renderScene để dùng batch mới

Thay toàn bộ renderScene trong view.hpp bằng bản dưới, không giữ các lời gọi phân loại/clip/fan rời của bài 2–5 ở ngoài hàm:

```cpp title="include/view.hpp — clip trước projection rồi tô pixel thật"
inline FrameStats renderScene(Framebuffer& image, const Scene& scene) {
    image.clear(kBackground);
    FrameStats stats{};
    stats.source = cameraTriangle(scene);
    stats.clip = clipForRender(stats.source, scene.nearPlane);
    TriangleBatch renderBatch{};
    if (scene.clipping) {
        renderBatch = stats.clip.batch;
    }
    if (!scene.clipping) {
        const auto& t = stats.source;
        if (t.a.position.z >= scene.nearPlane && t.b.position.z >= scene.nearPlane && t.c.position.z >= scene.nearPlane) {
            renderBatch.triangles[0] = t;
            renderBatch.count = 1;
        } else {
            stats.discarded = true;
        }
    }
    const Viewport viewport{0, 0, Framebuffer::width, viewportHeight(scene)};
    for (std::size_t i = 0; i < renderBatch.count; ++i) {
        const auto projected = projectTriangle(renderBatch.triangles[i], 1.0471975511965976, viewport, scene.nearPlane);
        if (!projected) {
            continue;
        }
        ++stats.renderedTriangles;
        const auto raster = rasterizeScreenTriangle(*projected, viewport.width, viewport.height, [&](int x, int y, Color color) {
            image.putPixel(x, y, packColor(color));
        });
        stats.candidates += raster.candidateCount;
        stats.covered += raster.coveredCount;
    }
    if (scene.debug) {
        drawProfile(image, stats, scene);
    }
    (void)scene;
    return stats;
}
```

scene.clipping chọn batch đã cắt; discard vẫn là một đối chứng có thể bật riêng. projectTriangle trả optional, rasterizer giới hạn bounding box theo viewport trước vòng pixel. Color double chỉ đổi thành RGBA8888 tại packColor. Các hàm này đã có trong Starter và được liệt kê đầy đủ ở phần mã nguồn cuối bài.

### Bước 3 — So hai cách xử lý mà không đổi đầu vào

Trong handleKey của controls.hpp, trước `(void)scene`, thêm:

```cpp title="include/controls.hpp — đổi policy bằng V"
if (!repeat && key == SDLK_V) {
    scene.clipping = !scene.clipping;
    scene.paused = true;
}
```

Đọc lại projectVertex đã có trong raster.hpp. Guard chạy trước phép chia, không sau khi đã tạo infinity:

```cpp title="include/raster.hpp — hàng rào trước phép chia"
inline std::optional<ScreenVertex> projectVertex(
    const ClipVertex& vertex,
    double verticalFovRadians,
    const Viewport& viewport,
    double nearPlane
) {
    if (!isFinite(vertex) || !std::isfinite(nearPlane) || nearPlane <= 0.0 || !std::isfinite(verticalFovRadians) || verticalFovRadians <= 0.0 || verticalFovRadians >= 3.141592653589793 || vertex.position.z < nearPlane || viewport.width <= 0 || viewport.height <= 0) {
        return std::nullopt;
    }

    const double aspectRatio = double(viewport.width) / double(viewport.height);
    const double focalScale = 1.0 / std::tan(verticalFovRadians * 0.5);
    const double ndcX = vertex.position.x * focalScale / (aspectRatio * vertex.position.z);
    const double ndcY = vertex.position.y * focalScale / vertex.position.z;

    if (!std::isfinite(ndcX) || !std::isfinite(ndcY)) {
        return std::nullopt;
    }
    return ScreenVertex{
        {
            double(viewport.left) + (ndcX + 1.0) * 0.5 * double(viewport.width),
            double(viewport.top) + (1.0 - ndcY) * 0.5 * double(viewport.height),
        },
        vertex.color,
    };
}
```

Main đã nhả capture và held input trước lệnh thay state. Nhấn V vì vậy không mang theo thao tác kéo cũ để ghi đè scene.

## Ghép các phần lại

Build Starter, chọn preset 2. Lần đầu tiên bề mặt RGB vẫn hiện dù A ở trước near. Nhấn V: cùng geometry đó biến mất ở discard; nhấn lại thì phần còn hợp lệ trở lại. Đừng thay near/offset giữa hai lần so sánh.

Nội dung Canvas trước bài này chỉ cho xem kết quả trung gian trong mặt cắt. Từ bài 6, viewport chính mới thực sự rasterize các tam giác đầu ra. Một pixel thuộc đường chéo fan không được tô hai lần.

## Thử làm sai để hiểu đúng

1. Đưa projectTriangle trước clipForRender: một đỉnh outside làm optional rỗng và hình vẫn biến mất. Đổi lại thứ tự.

2. Bỏ guard z≥near để thử preset có điểm sau camera: phép chia có thể đảo dấu/phóng lớn hình. Không dùng đường này trong bản cuối.

3. Nối batch vào HUD nhưng vẫn rasterize stats.source: bảng đếm có vẻ đúng mà ảnh vẫn sai. renderBatch mới là dữ liệu cần đi vào vòng vẽ.

## Tự kiểm tra kết quả

- Preset 2 tạo hai output triangle và có pixel thật trên viewport.
- V chỉ đổi policy; source/camera/near/offset không đổi.
- Mọi output vertex có z≥near; input chưa clip bị projection từ chối.
- Raster loop có giới hạn theo viewport, top-left không tô đè đường chéo fan.
