# Quét qua camera và kiểm bằng oracle độc lập

## Vấn đề cần giải quyết

Một ảnh đúng ở preset mặc định chưa chứng minh clipper hoạt động khi đi qua camera. Ta cần quét liên tục qua các topology, dừng ở vị trí khó và so kết quả với một cách tính khác thuật toán vừa viết.

## Hiểu ý tưởng trước khi viết code

Sweep chỉ đổi depthOffset trong [−4,3]. Ở đầu gần nhất, cả ba đỉnh có thể ở sau camera; không còn bề mặt là kết quả đúng, không phải lỗi. Điều phải giữ là các điểm **đầu ra** đều ở phía z≥near, không có NaN, không tạo spike khi chỉ một phần tam giác còn nhìn thấy.

Dùng ba lớp kiểm chứng: đáp án scalar/giao điểm tính tay; diện tích và winding trong 3D; mặt nạ pixel so với ray gặp tam giác nguồn. Oracle cuối không gọi clipper để tạo expected. Quét 1001 vị trí chỉ chạy toán clipping nhỏ, không render framebuffer 1100×800 hàng nghìn lần.

### Bước 1 — Cho sweep tiến theo thời gian, có thể dừng

Trong scene.hpp, thêm stepSweep trước advanceScene, rồi thay advanceScene bằng bản mới:

```cpp title="include/scene.hpp — đổi chiều tại hai giới hạn"
inline bool stepSweep(Scene& scene, double distance) {
    if (!std::isfinite(distance) || distance < 0.0) {
        return false;
    }
    double next = scene.depthOffset + scene.direction * distance;
    if (next >= 3.0) {
        next = 3.0;
        scene.direction = -1.0;
    }
    if (next <= -4.0) {
        next = -4.0;
        scene.direction = 1.0;
    }
    return moveDepthOffset(scene, next);
}
```



```cpp title="include/scene.hpp — held input và sweep dùng chung offset"
inline bool advanceScene(Scene& scene, double deltaSeconds, int heldAxis) {
    if (!std::isfinite(deltaSeconds) || deltaSeconds <= 0.0) {
        return false;
    }
    const double dt = std::min(deltaSeconds, 0.05);
    if (heldAxis != 0) {
        return moveDepthOffset(scene, scene.depthOffset + heldAxis * dt);
    }
    if (!scene.paused) {
        return stepSweep(scene, 0.75 * dt);
    }
    return false;
}
```

Held axis ưu tiên thao tác người dùng. Dt giới hạn 0.05 s để một lần khựng không làm vật nhảy qua nhiều trạng thái. Đây là chính sách tránh bước quá lớn, không phải cam kết bù toàn bộ thời gian bị mất.

Thay handleKey trong controls.hpp bằng bản dưới để thêm Space và N, giữ các lệnh cũ:

```cpp title="include/controls.hpp — pause, single-step và policy"
inline void handleKey(Scene& scene, SDL_Keycode key, bool repeat) {
    if (!repeat && (key == SDLK_R || (key >= SDLK_1 && key <= SDLK_5))) {
        int preset = scene.preset;
        if (key != SDLK_R) {
            preset = static_cast<int>(key - SDLK_0);
        }
        resetScene(scene, preset);
    }
    if (key == SDLK_W) {
        scene.nearPlane = std::min(2.0, scene.nearPlane + 0.05);
        scene.paused = true;
    }
    if (key == SDLK_S) {
        scene.nearPlane = std::max(0.25, scene.nearPlane - 0.05);
        scene.paused = true;
    }
    if (!repeat && key == SDLK_V) {
        scene.clipping = !scene.clipping;
        scene.paused = true;
    }
    if (!repeat && key == SDLK_SPACE) {
        scene.paused = !scene.paused;
    }
    if (!repeat && key == SDLK_N && scene.paused) {
        stepSweep(scene, 0.08);
    }

    (void)scene;
    (void)key;
    (void)repeat;
}
```



### Bước 2 — Đo điều kiện biên từ chính output

Trong clip.hpp, sau clipForRender, thêm maximumNearPlaneViolation:

```cpp title="include/clip.hpp — invalid không được giả thành zero error"
inline double maximumNearPlaneViolation(const ClippedPolygon& polygon, double nearPlane) {
    if (!polygon.valid || polygon.count > 4 || !std::isfinite(nearPlane)) {
        return std::numeric_limits<double>::infinity();
    }
    double maximum = 0.0;
    for (std::size_t i = 0; i < polygon.count; ++i) {
        if (!isFinite(polygon.vertices[i])) {
            return std::numeric_limits<double>::infinity();
        }
        maximum = std::max(maximum, nearPlane - polygon.vertices[i].position.z);
    }
    return maximum;
}
```

Trong presentFramebuffer, sau HUD Y=694, thêm:

```cpp title="include/presentation.hpp — violation và số pixel ứng viên"
std::snprintf(line, sizeof(line), "max near violation %.3g | candidates %zu", maximumNearPlaneViolation(stats.clip.polygon, scene.nearPlane), stats.candidates);
if (!SDL_RenderDebugText(renderer, 16, 720, line)) {
    return false;
}
```

Với output hợp lệ, violation bằng zero chính xác vì giao điểm mới có z=near. Nếu polygon invalid, helper báo infinity. Polygon rỗng hợp lệ có violation=0 nhưng không có nghĩa vẫn còn hình để vẽ.

### Bước 3 — Kiểm bằng đáp án không đi qua clipper

tests/tests.cpp của ZIP đã có runner check/EXIT_FAILURE và các helper vector thuần. Đọc hai đáp án giao điểm sau; bạn có thể thêm chúng vào runner riêng sau khi viết xong các hàm tương ứng:

```cpp title="tests/tests.cpp — giao điểm và màu tính tay"
const auto hit = lab::intersectNearPlane(v(-2, 0, .5, 0), v(2, 0, 1.5, 100), 1);
check(hit && close(hit->position.x, 0) && hit->position.z == 1 && close(hit->color.red, 50), "midpoint intersection and RGB share t");
const auto reverse = lab::intersectNearPlane(v(2, 0, 1.5, 100), v(-2, 0, .5, 0), 1);
check(hit && reverse && close(hit->position.x, reverse->position.x) && close(hit->color.red, reverse->color.red), "edge reversal preserves intersection");
```

Trong test bốn topology, diện tích không suy ra từ số đỉnh output. Mặt phẳng đi qua giữa hai cạnh cắt bỏ tam giác nhỏ đồng dạng tỷ lệ cạnh 1/2, tức diện tích 1/4. Đọc phần kiểm tỷ lệ:

```cpp title="tests/tests.cpp — diện tích còn lại 3/4 và 1/4"
if (i == 1) {
    check(close(sumArea, .75 * area(cases[i])), "analytic three-quarter retained area");
}
if (i == 2) {
    check(close(sumArea, .25 * area(cases[i])), "analytic one-quarter retained area");
}
```

Kiểm raster mạnh hơn nữa: với mỗi tâm pixel, tạo ray camera rồi giải giao với tam giác **gốc**. Pixel expected chỉ khi ray ở trong tam giác và depth≥near. Cách này không dựa vào biên polygon do clipper trả về. Runner còn kiểm không tô hai lần cạnh fan, giao điểm rất nhỏ, mọi hoán vị input, tiếp xúc điểm/đoạn và input không hữu hạn.

Ở bài này chưa chạy toàn bộ CTest cho Starter: các test scene sạch ở cuối runner cần phần lưới/camera của bài 8. Có thể build/run bản tham khảo final để đọc đáp án; đừng gọi đó là kiểm chứng code Starter vừa viết.

## Ghép các phần lại

Build Starter, chọn preset 2 rồi nhấn Space. Tam giác đi qua near, qua camera và trở lại; Space dừng tại chỗ, N tiến 0.08 unit khi paused. Giữ A/D sẽ dừng tự chạy để bạn điều khiển. Chuyển preset/reset/resize hoặc mất focus phải bỏ input cũ.

Canvas cũng dùng giới hạn [−4,3], tốc độ sweep 0.75 unit/s và held input 1 unit/s. Reduced motion chỉ tắt chuyển động tự chạy; kéo, giữ phím và single-step vẫn dùng được. Bài 8 hoàn thiện lưới world, clean mode và kiểm toàn bộ source người học.

## Thử làm sai để hiểu đúng

1. Bật sweep rồi đổi near mà không pause: khó biết hình đổi do vật hay plane. Mọi lệnh chỉnh thông số trong bản này dừng tự chạy để kết quả quan sát rõ.

2. Trả violation=0 cho mọi input invalid: test có thể xanh vì lỗi bị giấu. Giữ infinity/valid flag.

3. Dùng chính clipper để tạo mask expected: cùng một lỗi có thể tồn tại ở cả actual và expected. Dùng ray trên tam giác nguồn.

## Tự kiểm tra kết quả

- Sweep đi qua đủ vùng trong/ngoài, kể cả hoàn toàn sau camera; không tạo NaN hoặc vòng raster vô hạn.
- N chỉ tiến khi paused; repeat của Space/N/V không lật trạng thái liên tục.
- Counts, polygon, batch và pixels lấy từ kết quả frame thật.
- Có đáp án midpoint/RGB, tỷ lệ diện tích, winding và ray mask độc lập; không chỉ test count.

## Bài tập mở rộng

Thay chiều duyệt ba đỉnh nguồn. So silhouette và diện tích, không chỉ số triangle. Khi dùng top-left rule đúng, đường chéo nội bộ không được để lại khe hở hoặc pixel bị tô hai lần.
