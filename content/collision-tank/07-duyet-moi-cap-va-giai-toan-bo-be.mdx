# Cho 256 bóng thật sự va vào nhau

## Vấn đề cần giải quyết

Ta đã hiểu phản ứng của một cặp. Bây giờ trở lại mục tiêu chính: **256 bóng thật sự va vào nhau**, không chỉ nảy vào tường. Thêm một vòng lặp thứ hai không khó; điều dễ sai là giải lặp cùng cặp hai lần, tích phân nhiều dt trong một bước hoặc đo nhầm phần xuyên trước/sau solver.

## Hiểu ý tưởng trước khi viết code

Với N vật, số cặp không có thứ tự là N(N−1)/2. Với 256 bóng, một lượt có 32.640 cặp; ba lượt có **97.920 pair checks** mỗi physics step.

Một bước gồm: tích phân **một lần**, rồi lặp tường/các cặp I lần, cuối cùng khóa tường lại. Cặp gần tường có thể đẩy tâm ra ngoài khi sửa position, nên chỉ kiểm tường ở đầu lượt chưa đủ.

Contact visits có thể gặp lại một cặp qua nhiều iterations; nó không phải số cặp độc nhất. Pair checks chỉ tính công việc của solver, chưa bao gồm lượt đo độc lập ở bài 8.

### Bước 2 — Duyệt i&lt;j và giải một bước hoàn chỉnh

Thêm stepCollisionWorld:

```cpp title="include/lab.hpp — stepCollisionWorld"
inline CollisionStepStats stepCollisionWorld(std::vector<Ball>& balls, const TankBounds& bounds, const CollisionStepSettings& settings) {
    CollisionStepStats stats{};
    if (!validBounds(bounds) || balls.size() > 512 || !std::isfinite(settings.deltaSeconds) || settings.deltaSeconds <= 0.0 || settings.deltaSeconds > 1.0 / 30.0 || !std::isfinite(settings.restitution) || settings.restitution < 0.0 || settings.restitution > 1.0 || settings.solverIterations < 1 || settings.solverIterations > 8 || !std::isfinite(settings.correctionPercent) || settings.correctionPercent < 0.0 || settings.correctionPercent > 1.0 || !std::isfinite(settings.penetrationSlop) || settings.penetrationSlop < 0.0) {
        stats.valid = false;
        return stats;
    }
    for (const auto& ball : balls) {
        if (!finiteBall(ball) || 2.0 * ball.radius > std::min(bounds.maximumX - bounds.minimumX, bounds.maximumY - bounds.minimumY)) {
            stats.valid = false;
            return stats;
        }
    }
    for (Ball& ball : balls) {
        integrateBall(ball, settings.deltaSeconds);
    }

    const int iterations = std::clamp(settings.solverIterations, 1, 8);
    for (int iteration = 0; iteration < iterations; ++iteration) {
        for (Ball& ball : balls) {
            const WallCollisionResult wall = resolveWallCollision(ball, bounds, settings.restitution);
            stats.wallHits += std::size_t(wall.hitCount);
            stats.wallImpulse = add(stats.wallImpulse, wall.wallImpulse);
            stats.maximumPenetration = std::max(stats.maximumPenetration, wall.deepestPenetration);
        }
        for (std::size_t firstIndex = 0; firstIndex < balls.size(); ++firstIndex) {
            for (std::size_t secondIndex = firstIndex + 1; secondIndex < balls.size(); ++secondIndex) {
                ++stats.pairChecks;
                const PairResolutionResult pair = resolveBallPair(balls[firstIndex], balls[secondIndex], settings.restitution, settings.correctionPercent, settings.penetrationSlop);
                if (!pair.contact.colliding) {
                    continue;
                }
                ++stats.contacts;
                if (pair.impulseMagnitude > 0.0) {
                    ++stats.impulses;
                }
                if (iteration == 0 && stats.debugContacts.size() < 48) {
                    const Vec2 point = add(balls[firstIndex].position, scale(pair.contact.normal, balls[firstIndex].radius));
                    stats.debugContacts.push_back({point, pair.contact.normal, pair.contact.penetration, pair.impulseMagnitude});
                }
                stats.maximumPenetration = std::max(stats.maximumPenetration, pair.contact.penetration);
            }
        }
    }
    // Correction gần tường có thể đẩy tâm ra ngoài. Khóa lại bounds sau lượt cuối.
    for (auto& ball : balls) {
        const auto wall = resolveWallCollision(ball, bounds, settings.restitution);
        stats.wallHits += static_cast<std::size_t>(wall.hitCount);
        stats.wallImpulse = add(stats.wallImpulse, wall.wallImpulse);
    }
    return stats;
}
```


Guard kiểm toàn bộ state và setting trước khi vật đầu tiên được tích phân. Nếu body cuối chứa NaN, hàm không được để nửa đàn đã đi trước.

Chú ý vòng cuối resolveWallCollision sau tất cả iterations. Nó không thêm pair check; Jwall của lần đó vẫn phải được cộng.

### Bước 3 — Trở lại cảnh lớn và nối vào Scene

Trong Scene thêm một CollisionStepStats stats. Thay rebuildScene và stepScene bằng các phiên bản bài 7:

```cpp title="include/scene.hpp — rebuildScene"
inline void rebuildScene(Scene& scene) {
    scene.message.clear();
    scene.balls = makeTankBalls(kSceneSeed, scene.elastic);
    if (scene.count == 64)
        scene.balls.resize(64);
    beginMeasurement(scene);
}
```


`correctionFraction` là phần overlap cần sửa, không phải hệ số đàn hồi. Ta bắt đầu bằng 0 để tắt sửa vị trí; khi `scene.correction` bật, giá trị là 0,8. Đặt lựa chọn này trước lời gọi solver giúp nhìn rõ từng tham số và tránh nhầm rằng tắt correction cũng tắt impulse.

```cpp title="include/scene.hpp — stepScene"
inline bool stepScene(Scene& scene) {
    const double dt = scene.dt;
    if (!std::isfinite(dt) || dt < 1e-6 || dt > 1.0 / 30.0) {
        stopScene(scene);
        scene.message = "Invalid fixed dt rejected.";
        return false;
    }
    {
        auto candidate = scene.balls;
        double correctionFraction = 0.0;
        if (scene.correction) {
            correctionFraction = 0.8;
        }
        const auto stats = stepCollisionWorld(candidate, kTankBounds, {dt, scene.restitution, scene.iterations, correctionFraction, 0.001});
        if (!stats.valid) {
            scene.message = "Invalid 2D step rejected; state was not committed.";
            stopScene(scene);
            return false;
        }
        scene.stats = stats;
        scene.balls = std::move(candidate);
    }
    scene.elapsed += dt;
    ++scene.substeps;
    return true;
}
```


Thêm phím I để đổi số lượt và C để đối chiếu 64/256 bóng:

## Ghép các phần lại

Khôi phục 256 bóng rồi bấm N. Counter phải hiện 97.920 ở ba iterations. Vẽ lại khi pause không tăng counter. Khi chọn 64, ba iterations cho 6.048 checks; đây là số công việc thật trong vòng lặp, không phải giá trị được UI tự tính thay solver.

Thay drawTank2D trong view.hpp bằng bản đọc contact của toàn bể:

```cpp title="include/view.hpp — drawTank2D"
inline void drawTank2D(Framebuffer& image, const Scene& scene) {
    rectangle(image, 100, 95, 1000, 635, 0x7187b4ffU, false);
    if (scene.debug) {
        for (int x = -8; x <= 8; x += 2) {
            const Vec2 a = worldToScreen({static_cast<double>(x), -6});
            const Vec2 b = worldToScreen({static_cast<double>(x), 6});
            drawLine(image, a.x, a.y, b.x, b.y, kGrid);
        }
    }
    for (const auto& ball : scene.balls)
        drawBall(image, ball);
    if (scene.debug) {
        for (const auto& contact : scene.stats.debugContacts) {
            arrow2D(image, contact.point, contact.normal, 0.5, 0xffe26cffU);
            if (contact.impulse > 0.0)
                arrow2D(image, contact.point, contact.normal, std::min(2.0, contact.impulse * 0.2), 0xff7b72ffU);
        }
    }
}
```

Trong view.hpp, dùng stats.debugContacts khi debug để vẽ normal vàng và vector j đỏ. Phần vẽ mũi tên chỉ đổi dữ liệu sang screen; độ dài vector j được scale và chặn cho dễ nhìn, còn trị số vật lý giữ nguyên trong record. Tắt debug vẫn phải thấy toàn bộ đàn bóng.

## Thử làm sai để hiểu đúng

1. Cho j bắt đầu từ 0. Bạn vừa thêm self-pair và cặp đảo; counter không còn bằng I×N(N−1)/2.

2. Đặt integrateBall vào bên trong vòng iterations. I=3 lúc này làm vật tiến ba dt thay vì chỉ giải tốt hơn trong cùng dt.

3. Bỏ lần khóa tường cuối. Correction gần biên có thể để một phần bóng ở ngoài bể dù lần xử lý tường đầu đã đúng.

## Tự kiểm tra kết quả

- Cảnh chính có 256 bóng khác khối lượng/bán kính, không phải chỉ hai bóng mẫu.
- Ba lượt với N=256 cho 97.920 checks; N=64 cho 6.048.
- Mỗi physics step chỉ tích phân một lần; chỉ solver lặp I lần.
- Các vật vẫn nằm trong radius-aware bounds sau lượt cuối; debug có thể tắt.

## Bài tập mở rộng

Đo pair-check count với I=1, 3, 5 và N=64, 256. Viết bảng lượng công việc; đừng gọi các con số đếm đó là runtime. Dùng kết quả này làm baseline khi tới project tối ưu tìm láng giềng.
