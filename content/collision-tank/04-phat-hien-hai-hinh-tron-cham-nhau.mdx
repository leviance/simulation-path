# Phát hiện hai hình tròn chạm nhau

## Vấn đề cần giải quyết

Tường đã hoạt động, nhưng hai bóng vẫn xuyên nhau. Trước khi đổi velocity, ta cần trả lời đúng một câu hỏi hình học: chúng có chồng lấn không, và nếu có thì hướng tách là hướng nào? Detection không tự quyết định phản ứng va chạm.

## Hiểu ý tưởng trước khi viết code

Đặt delta = pB−pA và R=rA+rB. Nếu dot(delta,delta) lớn hơn hoặc bằng R², ta không tạo contact trong quy ước của project. Khi có chồng lấn:

$$
d=\|p_B-p_A\|,\qquad n=\frac{p_B-p_A}{d},\qquad penetration=r_A+r_B-d.
$$

Normal luôn đi từ A sang B. Bóng mẫu có tâm −0,6 và +0,6, radius mỗi quả 0,75: d=1,2, R=1,5, penetration=0,3 m, n=(1,0).

Nếu hai tâm trùng, normal hình học không xác định. Ta cần một quy ước hữu hạn, không gọi normalize cho vector zero. Dùng hướng ngược relative velocity; nếu relative velocity cũng zero, chọn trục X cố định. Quy ước này không biến một state suy biến thành một tiếp xúc vật lý chính xác.

### Bước 1 — Trả dữ liệu contact, chưa sửa Ball

Thêm kiểu:

```cpp title="include/lab.hpp — CircleContact"
struct CircleContact {
    bool colliding{};
    Vec2 normal{1.0, 0.0};
    double penetration{};
    double centerDistance{};
};
```


Normal mặc định chỉ là fallback; colliding=false thì không được dùng nó để áp impulse.

### Bước 2 — Loại sớm cặp ở xa

Thêm toàn bộ findCircleContact vào lab.hpp:

```cpp title="include/lab.hpp — findCircleContact"
inline CircleContact findCircleContact(const Ball& first, const Ball& second) {
    if (!finiteBall(first) || !finiteBall(second)) {
        return {};
    }
    const Vec2 centerDelta = subtract(second.position, first.position);
    const double radiusSum = first.radius + second.radius;
    const double distanceSquared = lengthSquared(centerDelta);
    if (!std::isfinite(distanceSquared) || !std::isfinite(radiusSum) || distanceSquared >= radiusSum * radiusSum) {
        return {};
    }
    if (distanceSquared <= kCollisionEpsilon * kCollisionEpsilon) {
        const Vec2 relativeVelocity = subtract(second.velocity, first.velocity);
        const Vec2 fallbackNormal = normalizedOr(scale(relativeVelocity, -1.0), {1.0, 0.0});
        return {true, fallbackNormal, radiusSum, 0.0};
    }
    const double centerDistance = std::sqrt(distanceSquared);
    const Vec2 normal = scale(centerDelta, 1.0 / centerDistance);
    return {true, normal, radiusSum - centerDistance, centerDistance};
}
```


So squared distance trước sqrt. Không lấy absolute của penetration để biến một cặp đang ở xa thành contact. Hàm nhận const Ball&, nên detection không vô tình dịch chuyển vật.

### Bước 3 — Giữ một ví dụ có thể đọc bằng mắt

Checkpoint 04 thay cảnh bằng hai bóng khác khối lượng. Cập nhật phần tạo ví dụ trong rebuildScene:

```cpp title="include/scene.hpp — hai vật để phân tích contact"
scene.balls = {{{-0.6, 0.0}, {1.5, 0.0}, 0.75, 1.0, 0xff7b72ffU, 1.0}, {{0.6, 0.0}, {-0.5, 0.0}, 0.75, 0.5, 0x53f0aeffU, 1.0}};
scene.lastContact = findCircleContact(scene.balls[0], scene.balls[1]);
scene.lastNormalSpeed = dot(subtract(scene.balls[1].velocity, scene.balls[0].velocity), scene.lastContact.normal);
scene.lastImpulse = 0.0;
scene.lastCorrection = 0.0;
```


Trong Scene thêm các member sau để lưu dữ liệu minh họa. lastImpulse và lastCorrection ban đầu bằng zero; các bài sau mới ghi kết quả vào chúng:

```cpp title="include/scene.hpp — dữ liệu đọc lại của một contact"
CircleContact lastContact{};
double lastNormalSpeed = 0.0;
double lastImpulse = 0.0;
double lastCorrection = 0.0;
```

Trong stepScene sau tích phân/tường, thêm đoạn ghi lại contact:

```cpp title="include/scene.hpp — lưu dữ liệu trước phản ứng"
const auto contact = findCircleContact(candidate[0], candidate[1]);
scene.lastContact = contact;
scene.lastNormalSpeed = dot(subtract(candidate[1].velocity, candidate[0].velocity), contact.normal);
```


lastNormalSpeed chỉ là số đo, chưa dùng để đổi velocity. Trong drawTank2D của view.hpp, thêm nhánh vẽ normal:

```cpp title="include/view.hpp — chỉ hiện normal khi debug"
if (scene.debug && scene.lastContact.colliding && scene.balls.size() == 2) {
    arrow2D(image, scene.balls[0].position, scene.lastContact.normal, 1.5, 0xffe26cffU);
}
```

Phần HUD trong presentation.hpp của checkpoint 04 chỉ đọc các số này; đối chiếu file đó để hiện n, penetration và normal speed ngay trong cửa sổ.

## Ghép các phần lại

Ở t=0, kiểm bốn số d, radius sum, penetration và normal. Bấm N: hai vật vẫn giữ vận tốc ban đầu và tiếp tục đi xuyên nhau vì bài này **mới có detection**. Đừng thêm teleport hoặc phản xạ tạm trong hàm tìm contact để hình trông đúng hơn.

Khối lượng không xuất hiện trong công thức tìm chồng lấn. Nó sẽ xuất hiện khi phân phối impulse ở bài 5.

## Thử làm sai để hiểu đúng

1. Quên cộng hai bán kính, chỉ so d với rA. Có khoảng chồng lấn mà detection vẫn nói không.

2. Đổi delta thành pA−pB nhưng giữ lời giải thích n từ A sang B. Mũi tên vàng đã đảo; bài impulse sẽ dùng dấu sai.

3. Cho hai tâm trùng nhau rồi bỏ nhánh fallback. Normal tạo NaN và lan sang toàn bộ state. Khôi phục guard, không thay NaN bằng zero velocity để giấu lỗi.

## Tự kiểm tra kết quả

- Ví dụ ban đầu cho d=1,2, penetration=0,3, normal=(1,0).
- Đổi thứ tự A/B đảo normal nhưng giữ penetration.
- Hai tâm trùng trả normal hữu hạn có độ dài một.
- Detection không đổi position hoặc velocity; cặp tách xa không có contact.

## Bài tập mở rộng

Tạo một cặp chạm đúng d=rA+rB. Giải thích vì sao quy ước colliding=false ở ranh giới này vẫn hợp lý cho solver chồng lấn rời rạc, nhưng không thay thế được truy tìm thời điểm va chạm.
