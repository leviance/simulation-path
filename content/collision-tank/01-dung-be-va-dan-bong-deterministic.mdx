# Dựng bể và tạo đàn bóng lặp lại được

## Vấn đề cần giải quyết

Ta muốn nhìn thấy hàng trăm quả bóng chuyển động, nảy vào tường rồi va vào nhau. Nếu bắt đầu bằng công thức impulse ngay, rất khó biết lỗi nằm ở dữ liệu, tọa độ hay phần vẽ. Vì vậy bài đầu chỉ dựng một cảnh **đủ 256 bóng**, không chồng lấn và có thể tạo lại y hệt.

Chưa có va chạm ở bài này. Các bài 2–8 đưa bể 2D tới mốc kiểm chứng; bài 9–11 mới mở rộng sang sphere 3D và ghép ứng dụng cuối. Hai quả bóng trong vài bài giữa là thí nghiệm để hiểu công thức, không phải sản phẩm cuối.

## Hiểu ý tưởng trước khi viết code

Khung Starter đã có SDL3 window, renderer, texture và event loop từ các project trước. Chạy nó sẽ thấy khung bể trống. Luồng dữ liệu vẫn là **Scene → renderScene → framebuffer → SDL_UpdateTexture → present**. Ta chỉ cần thêm dữ liệu vật lý vào đúng luồng ấy.

Bể dùng x từ −10 đến 10 m, y từ −6 đến 6 m; Y dương hướng lên. Chia 16 cột và 16 hàng cho khoảng cách 1,25 m theo X và 0,75 m theo Y. Đường kính lớn nhất chỉ 0,48 m, nên lưới ban đầu không chồng lấn. Đây là bảo đảm từ hình học, không phải hy vọng rằng vài lần random sẽ tìm được chỗ.

Mỗi Ball giữ position, velocity, radius, inverseMass và restitution. Với vật động, inverseMass bằng 1/m; khối lượng lớn thì cùng một impulse làm vận tốc đổi ít hơn. Màu chỉ giúp nhận ra vật, không tham gia công thức.

### Bước 2 — Tạo lưới trước, chọn vận tốc sau

SeededRandom đã được cung cấp trong Starter. Thêm makeBallLattice sau kiểu đó. Hàm kiểm số ô trước khi reserve để input sai không tạo một allocation khổng lồ:

```cpp title="include/lab.hpp — makeBallLattice"
inline std::vector<Ball> makeBallLattice(int columns, int rows, const TankBounds& bounds, double radius, double speed, std::uint32_t seed) {
    std::vector<Ball> balls{};
    if (columns <= 0 || rows <= 0 || columns > 512 || rows > 512 || columns * rows > 512 || !validBounds(bounds) || !std::isfinite(radius) || radius <= 0.0 || !std::isfinite(speed) || speed < 0.0) {
        return balls;
    }
    const double cellWidth = (bounds.maximumX - bounds.minimumX) / double(columns);
    const double cellHeight = (bounds.maximumY - bounds.minimumY) / double(rows);
    if (2.0 * radius > std::min(cellWidth, cellHeight)) {
        return balls;
    }

    constexpr std::uint32_t palette[] = {
        0x61afefffU,
        0x98c379ffU,
        0xe5c07bffU,
        0xc678ddffU,
        0xe06c75ffU,
        0x56b6c2ffU,
    };
    SeededRandom random(seed);
    balls.reserve(std::size_t(columns) * std::size_t(rows));
    for (int row = 0; row < rows; ++row) {
        for (int column = 0; column < columns; ++column) {
            const double positionX = bounds.minimumX + (double(column) + 0.5) * cellWidth;
            const double positionY = bounds.minimumY + (double(row) + 0.5) * cellHeight;
            const double angle = 2.0 * kPi * random.nextUnit();
            const double speedScale = 0.75 + 0.5 * random.nextUnit();
            const Vec2 velocity{speed * speedScale * std::cos(angle), speed * speedScale * std::sin(angle)};
            const std::size_t colorIndex = std::size_t(row * columns + column) % std::size(palette);
            balls.push_back({{positionX, positionY}, velocity, radius, 1.0, palette[colorIndex]});
        }
    }
    return balls;
}
```


Vị trí chỉ phụ thuộc hàng/cột. Hai lần gọi cùng seed cho cùng dãy góc và độ lớn vận tốc trong cùng implementation. Không dùng clock hay random_device; chúng khiến một lỗi khó tái hiện.

### Bước 3 — Tạo vật liệu khác nhau và đưa vào Scene

Thêm hàm sau ngay sau makeBallLattice:

```cpp title="include/lab.hpp — makeTankBalls"
inline std::vector<Ball> makeTankBalls(std::uint32_t seed, bool elastic = false) {
    const TankBounds bounds{-10.0, -6.0, 10.0, 6.0};
    auto balls = makeBallLattice(16, 16, bounds, 0.24, 2.2, seed);
    for (std::size_t index = 0; index < balls.size(); ++index) {
        balls[index].radius = 0.18 + 0.02 * static_cast<double>(index % 4);
        balls[index].inverseMass = 1.0 / (0.5 + 0.25 * static_cast<double>(index % 5));
        if (elastic) {
            balls[index].restitution = 1.0;
        } else {
            balls[index].restitution = 0.7 + 0.15 * static_cast<double>(index % 3);
        }
    }
    return balls;
}
```


Bán kính thay đổi từ 0,18 đến 0,24 m; mass từ 0,5 đến 1,5 kg; restitution là 0,7, 0,85 hoặc 1. Preset elastic sẽ đặt mọi vật liệu về 1 ở bài 8. Chưa cần dùng các tham số đó để phản ứng va chạm.

Thay rebuildScene trong scene.hpp bằng phiên bản của bài này:

```cpp title="include/scene.hpp — rebuildScene"
inline void rebuildScene(Scene& scene) {
    scene.message.clear();
    scene.balls = makeTankBalls(kSceneSeed, scene.elastic);
    if (scene.count == 64)
        scene.balls.resize(64);
    beginMeasurement(scene);
}
```


## Ghép các phần lại

Build Starter rồi chạy. renderScene đã duyệt scene.balls và gọi drawBall, nên không cần tạo một vector bóng khác trong renderer. Bạn phải thấy 256 hình tròn có kích thước và màu khác nhau. N chưa làm chúng chuyển động; đó là phần việc của bài 2.

Reset gọi lại hàm tạo cảnh với seed cố định. Đừng nhầm “có thể tái lập” với việc mọi compiler/CPU bắt buộc cho cùng byte số thực: các phép sin/cos có thể lệch rất nhỏ giữa môi trường. Tests so trong tolerance phù hợp.

## Thử làm sai để hiểu đúng

1. Đổi khoảng cách hàng xuống dưới 0,48 m. Quan sát các bóng chồng lấn ngay ở t=0, trước khi có solver; đừng đổ lỗi đó cho impulse.

2. Dùng vận tốc random từ đồng hồ mỗi lần reset. Bấm reset vài lần rồi thử tái hiện một va chạm: dữ liệu ban đầu đã khác.

3. Lưu worldToScreen vào position. Hình có thể còn hiện trong một cửa sổ, nhưng radius và velocity không còn cùng đơn vị. Hoàn tác trước khi đi tiếp.

## Tự kiểm tra kết quả

- Cảnh chính có đúng 256 bóng, mọi tâm cách mỗi mặt tường ít nhất một radius.
- Khoảng cách lưới lớn hơn tổng hai bán kính lớn nhất; không có overlap ban đầu.
- Cùng seed/reset tái tạo cùng vị trí, vận tốc và vật liệu.
- Không có thuật toán va chạm chạy sớm hoặc một đàn bóng khác được renderer tự sinh.

## Bài tập mở rộng

Chọn hai bóng nhẹ/nặng và ghi mass = 1/inverseMass của chúng. Dự đoán vật nào đổi vận tốc nhiều hơn nếu nhận cùng một impulse; giữ dự đoán đó tới bài 5.
