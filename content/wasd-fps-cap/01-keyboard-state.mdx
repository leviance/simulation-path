# Tự tô ô vuông rồi đọc WASD

## Vấn đề cần giải quyết

Trong Project 01, ta đã tạo ảnh trên CPU rồi đưa ảnh lên cửa sổ bằng texture. Bây giờ hãy dùng lại cách đó để vẽ một nhân vật đơn giản: ô vuông 34×34 pixel. Sau khi vẽ được hình, ta sẽ kiểm tra bàn phím bằng cách đổi màu khi giữ WASD. **Bài này chưa làm ô vuông di chuyển.**

Trước khi mở code hướng dẫn, thử tự làm hai việc: tô hình tại góc trái trên (120,220), rồi cho nó đổi từ xám sang xanh khi giữ D. Nếu làm được, thêm ba phím còn lại. Chưa cần nghĩ tới vận tốc hay FPS.

Starter đã có window, renderer, framebuffer và hàm upload/present từ Project 01. Chạy từ thư mục project sau khi giải nén ZIP:

```bash title="Terminal — build nền trống và checkpoint đầu"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_2_starter project_2_checkpoint_1 --parallel 2
```

Trên Windows, chạy `.\build\Debug\project_2_starter.exe`. Bạn phải thấy nền xanh đen. Với Ninja/Makefiles, đặt `-DCMAKE_BUILD_TYPE=Debug` khi configure; executable thường ở trực tiếp trong `build/`. **Checkpoint** là mã chạy được sau khi hoàn thành một bài, không phải phần đang viết dở. Phần mã đầy đủ cuối trang cho phép đối chiếu cả file, không chỉ các đoạn trích dưới đây.

## Hiểu ý tưởng trước khi viết code

Một hình chữ nhật không cần một công cụ vẽ mới: chỉ cần tô các pixel theo từng hàng. Hình có góc (120,220), rộng 34 và cao 34 gồm các cột 120…153, các hàng 220…253. Cột 154 và hàng 254 nằm ngoài hình. Quy ước **lấy cạnh trái/trên, không lấy cạnh phải/dưới** giúp ta tô đúng 34×34 = 1.156 pixel.

Project 01 thay số pixel theo kích thước đầu ra. Trong project này, ta chọn **ảnh logic cố định 960×540** để 180 pixel/giây luôn có cùng ý nghĩa khi resize. SDL co giãn cả ảnh theo cùng một tỉ lệ và chừa viền nếu cần. Không kéo giãn riêng chiều ngang khiến ô vuông thành hình chữ nhật. Pixel logic không nhất thiết bằng một pixel vật lý trên màn hình HiDPI.

Về bàn phím, hãy phân biệt hai câu hỏi:

- `SDL_EVENT_KEY_DOWN`: phím nào **vừa được nhấn**? Dùng cho Escape, hoặc bật/tắt một chế độ.
- `SDL_GetKeyboardState`: phím nào **đang được giữ**? Dùng cho di chuyển liên tục.

Ta xử lý hết event trước, rồi mới đọc keyboard state. SDL cập nhật trạng thái khi xử lý sự kiện; chỉ gọi hàm lấy mảng không làm hệ điều hành tự gửi thêm dữ liệu. Một lần nhấn và thả quá nhanh giữa hai lần lấy mẫu có thể không còn trong trạng thái đang giữ; các hành động cần bắt từng lần nhấn vẫn dùng event. [Tài liệu SDL](https://wiki.libsdl.org/SDL3/SDL_GetKeyboardState).

## Viết code từng bước

### Bước 1 — Nhận lại phần hiển thị đã biết

`include/framebuffer.hpp` giữ `pixels` theo hàng, có `clear` và `putPixel` như Project 01. `include/presentation.hpp` tạo texture `RGBA8888`, không pha alpha, upload với `pitch = width × sizeof(uint32_t)` rồi present. Hai file này có sẵn trong starter; đừng viết thêm một vòng lặp SDL thứ hai.

Điểm mới trong setup là chọn cách hiển thị ảnh cố định:


```cpp title="src/main.cpp — giữ tỉ lệ ảnh logic"
if (!SDL_SetRenderLogicalPresentation(renderer, lab::Framebuffer::width, lab::Framebuffer::height, SDL_LOGICAL_PRESENTATION_LETTERBOX)) {
        std::cerr << "Logical presentation failed: " << SDL_GetError() << '\n';
        SDL_DestroyRenderer(renderer);
        SDL_DestroyWindow(window);
        SDL_Quit();
        return EXIT_FAILURE;
    }
```


`LETTERBOX` giữ nguyên tỉ lệ 16:9. Việc này chỉ thay cách ảnh được hiển thị, không sửa vị trí hoặc số phần tử của framebuffer. [SDL giải thích logical presentation](https://wiki.libsdl.org/SDL3/SDL_SetRenderLogicalPresentation).

### Bước 2 — Tự tô hình bằng putPixel

Thêm hàm sau trong namespace `lab`, sau `rgba` của `include/framebuffer.hpp`:


```cpp title="include/framebuffer.hpp — tô các hàng bên trong hình"
inline void fillRectangle(Framebuffer& framebuffer, int left, int top, int width, int height, std::uint32_t color) {
    if (width <= 0 || height <= 0) {
        return;
    }

    // Dùng int64_t trước khi cộng để cả tọa độ cực trị cũng không tràn int.
    const auto right = std::clamp<std::int64_t>(std::int64_t(left) + width, 0, Framebuffer::width);
    const auto bottom = std::clamp<std::int64_t>(std::int64_t(top) + height, 0, Framebuffer::height);
    const int firstX = std::clamp(left, 0, Framebuffer::width);
    const int firstY = std::clamp(top, 0, Framebuffer::height);
    for (int y = firstY; y < bottom; ++y) {
        for (int x = firstX; x < right; ++x) {
            framebuffer.putPixel(x, y, color);
        }
    }
}
```


Hai vòng `for` là phần tạo ra ô vuông. Phần phía trước chỉ cắt hình theo biên ảnh để không duyệt hàng triệu tọa độ nằm ngoài cửa sổ. `firstX/firstY` là điểm bắt đầu sau khi cắt; `right/bottom` là điểm dừng không được lấy.

Vì `left + width` có thể tràn kiểu `int` trước khi kịp clamp, code đổi `left` sang `int64_t` **trước phép cộng**. Đây không phải công thức vẽ mới, chỉ là cách giữ phép tính biên an toàn. Width/height không dương thì không có pixel nào cần tô.

### Bước 3 — Lưu vị trí và vẽ trước khi đọc phím

Thêm `#include "lab.hpp"` ngay sau include phần hiển thị trong `main.cpp`:

```cpp title="src/main.cpp — include phần hiển thị và dữ liệu của bài"
#include "presentation.hpp"
#include "lab.hpp"
```

Tạo `include/lab.hpp` với phần đầu sau, rồi đặt các khai báo bên dưới bên trong namespace `lab`. Đóng namespace bằng `}` ở cuối file:

```cpp title="include/lab.hpp — header mới cho vị trí và bàn phím"
#pragma once
#include <cmath>
namespace lab {
```

Ta cần hai tọa độ, nên tạo kiểu dữ liệu nhỏ:


```cpp title="include/lab.hpp — hai tọa độ của vị trí hoặc hướng"
struct Vec2 {
    double x{};
    double y{};
};
```


`position` được khai báo **trước vòng lặp** và giữ giá trị từ frame này sang frame sau. Trong checkpoint này nó luôn là `{120.0, 220.0}`. Khi vẽ, `renderFrame` xóa ảnh cũ, chọn màu, tô hình và hiển thị:


```cpp title="src/main.cpp — toàn bộ hàm vẽ một frame"
bool renderFrame(SDL_Renderer* renderer, SDL_Texture* texture, lab::Framebuffer& framebuffer, lab::Vec2 position, bool isMoving) {
    framebuffer.clear(lab::rgba(11, 16, 32));
    std::uint32_t color = lab::rgba(126, 143, 177);
    if (isMoving) {
        color = lab::rgba(83, 240, 174);
    }

    // Chỉ làm tròn lúc vẽ; position vẫn giữ phần lẻ cho lần cập nhật sau.
    const int left = static_cast<int>(std::floor(position.x));
    const int top = static_cast<int>(std::floor(position.y));
    lab::fillRectangle(framebuffer, left, top, kPlayerSize, kPlayerSize, color);
    return lab::presentFramebuffer(renderer, texture, framebuffer);
}
```


`std::floor` lấy cột/hàng nguyên ở bước vẽ, không làm mất phần lẻ của `position`. Điều này chưa tạo khác biệt khi đứng yên, nhưng sẽ quan trọng khi mỗi lần cập nhật chỉ đi được 0,3 pixel. Để thử phần vẽ trước khi thêm WASD, truyền `false` cho đối số `isMoving` khi gọi hàm; hình phải có màu xám. Sau khi phần phím bên dưới hoàn thành, thay bằng giá trị `length(direction) > 0` của checkpoint. Kiểm tra hình xuất hiện đúng vị trí trước khi tiếp tục.

### Bước 4 — Cho từng phím đóng góp một hướng

Trong `include/lab.hpp`, thêm:


```cpp title="include/lab.hpp — bốn nhánh dễ đọc cho WASD"
inline Vec2 directionFromKeys(bool left, bool right, bool up, bool down) {
    Vec2 direction{};
    if (left) {
        direction.x -= 1.0;
    }
    if (right) {
        direction.x += 1.0;
    }
    if (up) {
        direction.y -= 1.0;
    }
    if (down) {
        direction.y += 1.0;
    }
    return direction;
}
```


A giảm X, D tăng X; W giảm Y vì gốc màn hình ở góc trên trái, S tăng Y. Các `if` độc lập để nhiều phím có thể cùng đóng góp. A+D cho `-1 + 1 = 0`. Nếu đổi sang `else if`, phím đầu tiên sẽ thắng thay vì triệt tiêu.

Hàm này không phụ thuộc SDL nên có thể kiểm thử riêng. Phần lấy phím của SDL chỉ làm nhiệm vụ truyền bốn giá trị `bool`:


```cpp title="src/main.cpp — đọc trạng thái sau SDL_PollEvent"
lab::Vec2 readDirection() {
    const bool* keyboard = SDL_GetKeyboardState(nullptr);
    return lab::directionFromKeys(
        keyboard[SDL_SCANCODE_A],
        keyboard[SDL_SCANCODE_D],
        keyboard[SDL_SCANCODE_W],
        keyboard[SDL_SCANCODE_S]
    );
}
```


Mảng dùng chỉ số `SDL_SCANCODE_*`, không dùng `SDLK_*`. Ta không cấp phát hay giải phóng mảng này: SDL sở hữu nó.

### Bước 5 — Dùng màu để xác nhận kết quả

Sau vòng xử lý event, gọi `readDirection`. `length` dùng `std::hypot` để tính độ dài; ở đây ta chỉ cần biết hướng có khác 0 không:


```cpp title="include/lab.hpp — độ dài của hướng"
inline double length(Vec2 vector) {
    return std::hypot(vector.x, vector.y);
}
```



```cpp title="src/main.cpp — đọc hướng mỗi vòng lặp"
lab::Vec2 direction = readDirection();
```



```cpp title="src/main.cpp — kiểm tra kết quả vẽ"
const bool isMoving = lab::length(direction) > 0.0;
        if (!renderFrame(renderer, texture, framebuffer, position, isMoving)) {
            std::cerr << "Render failed: " << SDL_GetError() << '\n';
            failed = true;
            break;
        }
```


Giữ D: hình chuyển xanh. Thả D: hình xám. Giữ A+D: hình xám vì hướng tổng bằng 0. Giữ W+D: hướng là (1,-1), hình vẫn đứng yên nhưng xanh. **Ta chưa chuẩn hóa hướng ở bài này**; bài sau mới cần sửa tốc độ chéo.

## Ghép các phần lại

Thứ tự trong vòng lặp là xử lý Close/Escape → đọc WASD → xóa framebuffer → tô hình → upload texture → present. Không đặt phần vẽ bên trong `while (SDL_PollEvent(...))`: khi hàng đợi trống, hình vẫn cần được vẽ.

Chạy `project_2_checkpoint_1`. Đối chiếu mã đầy đủ cuối trang nếu bạn chưa biết đặt một hàm ở đâu. Hàm vẽ ở phía trên `main`; biến `position` ở trước vòng lặp; lời gọi đọc phím và vẽ ở trong vòng lặp, sau xử lý event.

## Thử làm sai để hiểu đúng

1. Đổi `x < right` thành `x <= right`. Hình rộng thêm một cột; đếm pixel sẽ phát hiện lỗi dù nhìn bằng mắt khó thấy.
2. Bỏ `framebuffer.clear` rồi đổi vị trí khởi đầu bằng debugger. Hình cũ còn lại vì bạn chưa xóa ảnh CPU.
3. Đổi nhánh D thành `else if` sau A. Giữ A+D và so màu với bản đúng.
4. Đọc phím chỉ trong `SDL_EVENT_KEY_DOWN`. Khi thả phím, bạn phải tự quản thêm trạng thái; việc di chuyển liên tục không còn đơn giản như lấy keyboard state mỗi vòng.

## Tự kiểm tra kết quả

- Starter có nền trống; checkpoint 1 có ô vuông xám 34×34 ở (120,220).
- WASD làm hình xanh khi hướng khác 0; hai phím đối nghịch triệt tiêu.
- Hình chưa di chuyển. Close và Escape vẫn thoát sạch.
- Resize giữ tỉ lệ ô vuông; số pixel logic trong framebuffer không đổi.
- Phần tạo hình không dùng `SDL_RenderFillRect`; SDL chỉ hiển thị ảnh do CPU tạo.
