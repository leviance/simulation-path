# Kéo một slider trong cây để thay đổi đàn chim

## Vấn đề cần giải quyết

Bạn đã tìm được ID dưới con trỏ. Bây giờ kéo Radius ra khỏi Panel: chim phải tiếp tục nhận bán kính mới dù chuột đã đi sang viewport. Trả ID dưới con trỏ ở mỗi frame không giải được trường hợp này.

## Hiểu ý tưởng trước khi viết code

Ghi `active` khi nhấn và giao cả chuỗi move/up cho ID ấy. Với slider bị cắt, vẫn dùng bounds đủ để tính tỷ lệ; clip chỉ trả lời câu hỏi có được bắt đầu thao tác tại đây không.

## Viết code từng bước

### Sửa đúng tham số được gắn với node

`locate` tìm lại view còn hợp lệ. Một slider gắn Radius, slider kia gắn Separation. Đọc binding rồi gọi `assign`, không đoán loại tham số từ chữ ghi trên nhãn.

{/* snippet include/input.hpp#drag */}

```cpp title="include/input.hpp — Sửa đúng tham số được gắn với node"
inline void drag(const Tree& tree, Model& model, WidgetId id, double x) {
    const auto view = locate(tree, id);
    if (view && view->enabled && view->node->kind == Kind::Slider) {
        assign(model, view->node->binding, (x - view->bounds.x) / view->bounds.width);
    }
}
```

### Nhận mẫu cuối cùng trước khi nhả capture

Sự kiện up có thể đến ở một tọa độ mới dù không có move cuối. Ghi giá trị lần chót, xóa active, rồi chỉ kích hoạt button nếu nhấn và thả trên cùng một ID.

{/* snippet include/input.hpp#release */}

```cpp title="include/input.hpp — Nhận mẫu cuối cùng trước khi nhả capture"
inline void pointerUp(const Tree& tree, Model& model, Ui& ui, Point point) {
    reconcile(tree, ui);
    const WidgetId active = ui.active;
    drag(tree, model, active, point.x);
    ui.active = 0;
    ui.hot = hitTest(tree, point);
    if (active != 0 && active == ui.hot)
        activate(tree, model, active);
}
```

## Thử làm sai để hiểu đúng

Chia cho `clip.width` thay vì `bounds.width`. Sau khi Panel bị cắt, cùng một điểm trên thanh bỗng cho hai bán kính khác nhau.
