# Tab đi qua những control đang dùng được

## Vấn đề cần giải quyết

Một nhóm mới được thêm vào bảng. Nếu Tab vẫn dựa trên danh sách năm nút của Project 65, người dùng bàn phím không bao giờ tới được nhóm ấy.

## Hiểu ý tưởng trước khi viết code

Dùng danh sách các view còn nhìn thấy theo thứ tự vẽ; bỏ Panel, Label và node bị disable. Focus là ID của một control thuộc danh sách hiện tại, không phải số thứ tự của nó.

## Viết code từng bước

### Lấy những node có thể nhận focus

Khi toàn bộ nhóm mất khỏi clip, child cũng mất khỏi danh sách. Label còn nhìn thấy không có nghĩa là nó phải nhận Tab.

{/* snippet include/traversal.hpp#focus */}

```cpp title="include/traversal.hpp — Lấy những node có thể nhận focus"
inline std::vector<WidgetId> focusOrder(const Tree& tree) {
    std::vector<WidgetId> result;
    for (const WidgetView& view : paintList(tree)) {
        if (view.enabled && (view.node->kind == Kind::Button || view.node->kind == Kind::Slider))
            result.push_back(view.node->id);
    }
    return result;
}
```

### Đi vòng mà không tạo chỉ số âm

Xác định hướng và vị trí kế tiếp, cộng chiều dài trước phép modulo. Tab từ cuối về đầu; Shift+Tab từ đầu tới cuối, kể cả sau khi preset vừa đổi.

{/* snippet include/keyboard.hpp#keyboard-order */}

```cpp title="include/keyboard.hpp — Đi vòng mà không tạo chỉ số âm"
const int size = static_cast<int>(order.size());
ui.focus = order[static_cast<std::size_t>((next + size) % size)];
```

## Thử làm sai để hiểu đúng

Cho Tab duyệt toàn bộ cây kể cả node bị che. Viền focus có thể biến mất khỏi màn hình trong khi phím mũi tên vẫn tác động tới một slider.

## Tự kiểm tra kết quả

Tab và Shift+Tab đi ngược nhau; giữ Enter trên checkbox không đảo liên tục. Hai phím mũi tên trên slider chạm đúng binding của nó.
