# Đọc vertex và vẽ point cloud đầu tiên

## Vấn đề cần giải quyết

Đến đây, renderer của ta đã tô được các mặt 3D, nhưng geometry vẫn nằm sẵn trong mã C++. Muốn xem một model khác, ta phải sửa mảng vertex rồi biên dịch lại. Project này bỏ bước đó: ứng dụng đọc một file OBJ và đưa mesh vừa đọc qua chính software renderer của ta.

Đừng bắt đầu bằng toàn bộ model có hàng nghìn triangle. Bài đầu chỉ đọc position và vẽ các điểm rời. Khi thấy đúng 18 điểm của rocket, ta mới nối chúng thành mặt. Nhờ vậy, nếu hình sai, bạn biết nên kiểm parser hay kiểm renderer.

Tải ZIP ở trang project, giải nén rồi mở thư mục có `CMakeLists.txt`. Starter đã có window, SDL renderer, streaming texture và framebuffer 800×500. Chạy nó trước:

```powershell title="Terminal — chạy bộ khung trước khi thêm parser"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_21_starter --parallel 2
./build/Debug/project_21_starter.exe
```

Bạn sẽ thấy cửa sổ nền tối. Đây chưa phải lỗi thiếu mesh: starter chưa biết đọc OBJ. Trong `src/main.cpp`, vòng lặp gọi `renderViewer`, chuyển `frame.pixels` sang texture bằng `SDL_UpdateTexture`, rồi gọi `presentFramebuffer`. Toàn bộ phần học mới sẽ nối vào đường đi này, không tạo một ứng dụng SDL thứ hai.

## Hiểu ý tưởng trước khi viết code

OBJ là file văn bản. Với dòng `v 0.5 -0.8 0`, chữ `v` cho biết ba số tiếp theo là XYZ của một position trong model space. Dòng `f` nói các position nào tạo nên một mặt; ta chưa xử lý nó ở bài này. Dòng bắt đầu bằng `#` là comment.

```text title="assets/low-poly-rocket.obj — đọc thử bằng trình soạn thảo"
o LowPolyRocket
v 0.500000 -0.800000 0.000000
v 0.353553 -0.800000 0.353553
```

Giữ nguyên XYZ khi đọc file. Tọa độ màn hình chỉ được tính lúc vẽ:

$$
p_{camera}=R_xR_y p_{model}+(0,0,d)
$$

Camera ban đầu chưa orbit, nên phép view này chính là tịnh tiến model ra trước camera. Phép chiếu và framebuffer vẫn theo quy ước của Project 17: camera nhìn về +Z, +Y hướng lên trong 3D và xuống màn hình sau viewport mapping.

## Viết code từng bước

### Bước 1 — Giữ việc đọc text tách khỏi việc mở file

`parseObj` nhận `std::istream&`: ứng dụng truyền file stream, còn test truyền chuỗi. Với mỗi dòng, ta giữ số dòng, bỏ comment rồi dùng `std::istringstream` đọc record. Không đọc liên tục cả file bằng một chuỗi `>>`, vì lỗi ở một dòng sẽ khó truy ngược hơn.

Đây là nhánh xử lý `v` trong parser. Nó chỉ thêm position sau khi cả ba tọa độ hợp lệ:

```cpp title="include/obj-parser.hpp — đọc trọn một position trước khi lưu"
if (keyword == "v") {
    Vec3 position{};
    if (!(record >> position.x >> position.y >> position.z) ||
        !std::isfinite(position.x) ||
        !std::isfinite(position.y) ||
        !std::isfinite(position.z)) {
        addDiagnostic(result, lineNumber, "record v cần ba tọa độ hữu hạn");
        continue;
    }
    std::string extra{};
    if ((record >> extra) || std::max({std::abs(position.x), std::abs(position.y), std::abs(position.z)}) > 1000000.0) {
        addDiagnostic(result, lineNumber, "chỉ hỗ trợ v x y z, mỗi tọa độ trong [-1e6, 1e6]");
        continue;
    }
    result.mesh.positions.push_back(position);
    continue;
}
```

`Vec3 position{}` là biến tạm của dòng hiện tại. Nếu Y là `nope`, phép đọc thất bại và parser ghi diagnostic, không thêm một vertex giả có Y bằng 0. Kiểm `std::isfinite` chặn NaN/infinity; kiểm token thừa giúp `v 1 2 3oops` không lọt qua.

Bản tiny parser này chỉ nhận `v x y z`, chưa nhận vertex weight hay vertex color. Giới hạn tọa độ ±1e6 và giới hạn dung lượng có thông báo rõ; đây là lựa chọn của viewer, không phải giới hạn chung của định dạng OBJ.

### Bước 2 — Mở file và báo đúng lỗi I/O

```cpp title="include/obj-parser.hpp — mở đường dẫn UTF-8 và giới hạn kích thước"
inline ObjLoadResult loadObjFile(const std::string& path) {
    std::error_code error{};
    const auto nativePath = std::filesystem::path(std::u8string(path.begin(), path.end()));
    const auto size = std::filesystem::file_size(nativePath, error);
    if (!error && size > 8 * 1024 * 1024) {
        ObjLoadResult result{};
        addDiagnostic(result, 0, "file vượt giới hạn 8 MiB: " + path);
        return result;
    }
    std::ifstream input(nativePath);
    if (!input) {
        ObjLoadResult result{};
        result.opened = false;
        addDiagnostic(result, 0, "không mở được file: " + path);
        return result;
    }
    return parseObj(input);
}
```

`opened = false` chỉ ra lỗi mở file, khác với file mở được nhưng có dòng sai. Chuyển chuỗi UTF-8 thành `std::u8string` giúp đường dẫn có dấu trên Windows được xử lý bởi `std::filesystem`. Không thay một file mất bằng geometry hard-code: làm vậy sẽ khiến người dùng tưởng model của họ đã được đọc.

### Bước 3 — Đưa các position vừa đọc tới framebuffer

```cpp title="include/viewer.hpp — vẽ point cloud từ mesh đã nạp"
inline void drawPoints(Framebuffer& frame, const ObjMesh& mesh, const ViewerState& state) {
    for (const Vec3 position : mesh.positions) {
        const auto screen = projectVertex(modelToCamera(position, state), frame.width, frame.height);
        if (!screen) {
            continue;
        }
        for (int dy = -2; dy <= 2; ++dy) {
            for (int dx = -2; dx <= 2; ++dx) {
                putPixel(frame, int(std::lround(screen->x)) + dx, int(std::lround(screen->y)) + dy, 0xffd166ffU);
            }
        }
    }
}
```

`modelToCamera` áp dụng model transform và view transform. `projectVertex` trả về optional; điểm nằm ngoài miền depth không được đổi sang pixel. Marker 5×5 chỉ giúp dễ nhìn hơn, không làm thay đổi dữ liệu OBJ.

## Ghép các phần lại

`main.cpp → openModel → loadObjFile → parseObj` là đường nạp. `renderViewer → drawPoints → modelToCamera → projectVertex → putPixel` là đường vẽ. Đọc theo hai đường này trong checkpoint, thay vì cố hiểu mọi header cùng lúc.

```powershell title="Terminal — checkpoint 1"
cmake --build build --config Debug --target project_21_checkpoint_1 --parallel 2
./build/Debug/project_21_checkpoint_1.exe
```

Rocket có **18 position**. Kéo chuột để xem các điểm không nằm trên cùng một mặt phẳng. Cuối cửa sổ có số vertex và đường dẫn asset; grid/axes chỉ là mốc tham chiếu.

## Thử làm sai để hiểu đúng

1. Trong Canvas, chọn “Input có lỗi”. Dòng `v 1 nope 0` phải báo lỗi theo số dòng. Sửa `nope` thành số rồi nạp lại. Với bản C++, hãy sửa một bản sao asset: ứng dụng dừng nạp khi có diagnostic, không vẽ một point cloud đã bị mất vertex.

2. Đổi tên thư mục assets cạnh executable trong bản sao thử nghiệm rồi chạy từ một thư mục khác. Thông báo cần chứa đường dẫn không mở được; cửa sổ nền trống không được xem là đã load thành công.
