# Giải mã slash token và negative index

## Vấn đề cần giải quyết

Một file OBJ xuất từ phần mềm 3D thường không viết face đơn giản như `f 1 2 3`. Bạn có thể gặp `f 1/1/1 2/2/1 3/3/1` hoặc index âm. Nếu đưa cả chuỗi `1/1/1` vào parser integer, model hợp lệ sẽ không mở được.

Ta mở rộng đúng hàm resolver của bài trước. Renderer vẫn nhận ba position index 0-based; nó không cần biết face ban đầu có slash hay không.

## Hiểu ý tưởng trước khi viết code

Bốn dạng corner là `v`, `v/vt`, `v//vn`, `v/vt/vn`. Chữ `v` trong các ký hiệu này là **position index**, không phải keyword bắt đầu dòng. Phần sau slash lần lượt tham chiếu texture coordinate và normal của OBJ.

Project này tính face normal từ geometry và chưa đọc texture/material. Vì vậy ta kiểm **cú pháp** các suffix nhưng không sử dụng hay tra phạm vi vector vt/vn. Đây không phải parser Wavefront đầy đủ. Các record metadata được đếm là đã nhận diện nhưng chưa dùng.

Negative index tính theo số position đã đọc **tại dòng face**:

$$
i=\begin{cases}
r-1 & r>0\\
n+r & r<0
\end{cases}
$$

Nếu n = 5, `-1` chỉ position[4], `-5` chỉ position[0]. Thêm một dòng v ở sau face không được làm kết quả này thay đổi. Index 0 luôn không hợp lệ.

Preset đầu là triangle có slash. Đổi face thành `f -3//1 -2//1 -1//1`: geometry phải giữ nguyên. Đừng chọn quad để thử ở mốc này; polygon thuộc bài sau.

## Viết code từng bước

### Bước 1 — Tách suffix nhưng không bỏ qua cú pháp hỏng

Đây là nhánh có slash, nằm trước bước parse position integer:

```cpp title="include/obj-parser.hpp — nhận đúng bốn dạng token"
if (slash != std::string_view::npos) {
    const std::string_view suffix = token.substr(slash + 1);
    const std::size_t secondSlash = suffix.find('/');
    const auto validAttribute = [](std::string_view field) {
        int value = 0;
        const auto parsed = std::from_chars(field.data(), field.data() + field.size(), value);
        return parsed.ec == std::errc{} && parsed.ptr == field.data() + field.size() && value != 0;
    };
    if (secondSlash == std::string_view::npos) {
        if (!validAttribute(suffix)) {
            return std::nullopt;
        }
    } else {
        const auto texture = suffix.substr(0, secondSlash);
        const auto normal = suffix.substr(secondSlash + 1);
        if ((!texture.empty() && !validAttribute(texture)) || !validAttribute(normal)) {
            return std::nullopt;
        }
    }
    token = token.substr(0, slash);
}
```

Nếu chỉ có một slash, suffix phải là integer khác 0. Nếu có slash thứ hai, field texture có thể rỗng để biểu diễn `v//vn`, nhưng field normal phải tồn tại. Một slash thứ ba sẽ còn trong field normal và khiến `from_chars` không đọc trọn token.

Ta không chấp nhận `1/`, `1///2`, `1/foo` hay suffix index 0. “Chưa dùng thuộc tính” không có nghĩa là nên chấp nhận mọi chuỗi phía sau slash.

### Bước 2 — Giải index bằng kiểu có dấu

```cpp title="include/obj-parser.hpp — chọn công thức theo dấu của index"
long long resolved = 0;
if (rawIndex > 0) {
    resolved = static_cast<long long>(rawIndex) - 1;
} else {
    resolved = static_cast<long long>(positionCount) + rawIndex;
}
```

`resolved` được khai báo là `long long` ngay trước nhánh. Với negative index, không viết `positionCount + rawIndex` trực tiếp: positionCount là unsigned nên phép cộng có thể đổi rawIndex âm thành unsigned.

### Bước 3 — Giữ kiểm phạm vi sau cả hai nhánh

```cpp title="include/obj-parser.hpp — chặn cả hai phía trước khi cast"
if (resolved < 0 || resolved >= static_cast<long long>(positionCount)) {
    return std::nullopt;
}
```

Sau nhánh kiểm, hàm mới trả `static_cast<std::size_t>(resolved)`. Phần thêm face và phần vẽ wireframe không đổi. Đây là lợi ích của việc gom quy ước file vào một điểm ở parser.

## Thử làm sai để hiểu đúng

1. Với ba position, thử lần lượt `-1`, `-3`, `-4`. Hai trường hợp đầu hợp lệ; trường hợp cuối nằm ngoài mảng. Đặt một dòng v mới **sau face**: resolver không được quay lại đổi index đã lưu.

2. Thử `1//0` và `1/2/3/4`. Cả hai phải có diagnostic. Sau đó so `f 1 2 3` với `f 1/1/1 2/2/1 3/3/1`: cùng position index thì phải sinh cùng indexed geometry, dù ta chưa dùng vt/vn.

## Tự kiểm tra kết quả

- Bốn dạng token hợp lệ đều lấy đúng position field.
- Negative index gắn với số position tại dòng face, không phải tổng cuối file.
- Index 0, suffix rỗng/sai và position ngoài mảng đều bị chặn.
- Renderer không chứa thêm logic xử lý slash hay negative index.
