# Đưa model về tâm và scale vừa khung

## Vấn đề cần giải quyết

Một file dùng đơn vị mét, file khác dùng milimét. Model cũng có thể được lưu cách origin hàng nghìn đơn vị. Nếu giữ camera cố định mà nạp cả hai file, một model nằm gọn trong cửa sổ còn model kia biến mất hoặc lớn đến mức chỉ thấy một mảng màu.

Ta cần đưa model về một kích thước thuận tiện **mà không làm thay đổi hình dáng**. Bước này diễn ra sau parse và trước vòng render; đừng normalize lại mỗi frame.

## Hiểu ý tưởng trước khi viết code

AABB là hộp nhỏ nhất theo các trục X/Y/Z chứa mọi position. Từ hai góc min/max:

$$
c=\frac{min+max}{2},\qquad e=max-min,\qquad s=\frac{2}{\max(e_x,e_y,e_z)}
$$

Sau đó:

$$
p'=(p-c)s
$$

Trừ tâm hộp để model nằm quanh origin, rồi nhân **cùng một s** vào cả ba trục. Cạnh dài nhất của AABB mới bằng 2. Nếu model cao gấp đôi bề rộng, tỷ lệ ấy vẫn giữ nguyên.

Đây là tâm của bounds, không nhất thiết là trọng tâm vật thể. Với một model lệch hình học, hai điểm này khác nhau; ta đang chọn quy tắc fit đơn giản, dễ kiểm chứng cho viewer.

## Viết code từng bước

### Bước 1 — Lấy bounds từ dữ liệu thật

```cpp title="include/normalize.hpp — khởi tạo bằng position đầu tiên"
inline std::optional<Bounds3> meshBounds(const ObjMesh& mesh) {
    if (mesh.positions.empty()) {
        return std::nullopt;
    }
    Bounds3 bounds{mesh.positions.front(), mesh.positions.front()};
    for (const Vec3 position : mesh.positions) {
        bounds.minimum.x = std::min(bounds.minimum.x, position.x);
        bounds.minimum.y = std::min(bounds.minimum.y, position.y);
        bounds.minimum.z = std::min(bounds.minimum.z, position.z);
        bounds.maximum.x = std::max(bounds.maximum.x, position.x);
        bounds.maximum.y = std::max(bounds.maximum.y, position.y);
        bounds.maximum.z = std::max(bounds.maximum.z, position.z);
    }
    return bounds;
}
```

Không khởi tạo min/max bằng {0,0,0}. Nếu mọi vertex có X từ 100 tới 102, làm vậy sẽ tạo bounds giả từ 0 tới 102. Khi mesh rỗng, trả nullopt thay vì truy cập front().

### Bước 2 — Tính center và cạnh lớn nhất

```cpp title="include/normalize.hpp — tâm bounds"
inline Vec3 boundsCenter(const Bounds3& bounds) {
    return (bounds.minimum + bounds.maximum) * 0.5;
}
```

```cpp title="include/normalize.hpp — chọn một kích thước chung"
inline double boundsMaxExtent(const Bounds3& bounds) {
    const Vec3 extent = bounds.maximum - bounds.minimum;
    return std::max({extent.x, extent.y, extent.z});
}
```

`std::max` trả một số duy nhất. Nếu chia X cho extent.x, Y cho extent.y và Z cho extent.z riêng, bạn ép mọi model thành một khối có tỷ lệ 1:1:1. Một rocket dài sẽ bị kéo thành vật thể bè ngang.

### Bước 3 — Biến đổi position, giữ topology

```cpp title="include/normalize.hpp — center rồi uniform scale"
inline bool normalizeMesh(ObjMesh& mesh, double targetExtent = 2.0) {
    const std::optional<Bounds3> bounds = meshBounds(mesh);
    if (!bounds) {
        return false;
    }
    const double maxExtent = boundsMaxExtent(*bounds);
    if (!std::isfinite(maxExtent) || maxExtent <= 1e-9 || !std::isfinite(targetExtent) || targetExtent <= 0.0) {
        return false;
    }
    const Vec3 center = boundsCenter(*bounds);
    const double scale = targetExtent / maxExtent;
    for (Vec3& position : mesh.positions) {
        position = (position - center) * scale;
    }
    return true;
}
```

`triangles` không đổi vì vị trí trong vector không đổi. Normals tự tính sau này sẽ dùng geometry mới. Điều kiện maxExtent gần 0 chặn model co lại thành một điểm; còn mesh phẳng vẫn hợp lệ nếu ít nhất một extent khác 0.

## Ghép các phần lại

`openModel` gọi normalize trên mesh tạm ở checkpoint 5 trở đi. Khi thành công mới thay model đang hiển thị. Như vậy renderer không cần đoán file dùng đơn vị gì.

```powershell title="Terminal — checkpoint 5"
cmake --build build --config Debug --target project_21_checkpoint_5 --parallel 2
./build/Debug/project_21_checkpoint_5.exe assets/cube.obj
```

So với checkpoint 4, cube có thể đổi kích thước trên màn hình, nhưng vẫn là cube. Rocket vẫn có tỷ lệ thân/chóp cũ; việc normalize không phải kéo từng bộ phận cho vừa cửa sổ.

## Thử làm sai để hiểu đúng

1. Tạo một hộp có extent (4,2,1). Sau normalize, extent phải là (2,1,0.5), không phải (2,2,2). Dịch tất cả position bằng cùng một vector rồi nạp lại: bounds trước thay đổi nhưng model sau fit phải giống nhau.

2. Thử file chỉ có các position trùng nhau. Viewer phải báo bounds suy biến, không tạo NaN. Thử một quad nằm trên Z = 0: nó vẫn normalize được vì maxExtent không bằng 0.

## Tự kiểm tra kết quả

- Tâm AABB mới gần origin; cạnh lớn nhất gần 2.
- Tỷ lệ extent khác 0 và tỷ lệ chiều dài cạnh không đổi.
- Số position, index và source face không đổi.
- Mesh rỗng/co thành điểm bị từ chối; mesh phẳng không bị từ chối chỉ vì một extent bằng 0.
