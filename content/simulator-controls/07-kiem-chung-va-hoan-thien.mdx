# Nghiệm thu bàn quan sát bằng một đàn biết trước đáp án

## Vấn đề cần giải quyết

Đàn bay đẹp không chứng minh slider đang sửa đúng mô hình. Chẳng hạn, vòng tròn có thể to gấp đôi nhưng solver vẫn hỏi bán kính cũ. Bài cuối cần một cách phát hiện lỗi này mà không dựa vào cảm giác.

## Hiểu ý tưởng trước khi viết code

Cố định seed và tạm dừng để giữ nguyên bài toán. Cho lưới trả về danh sách hàng xóm, rồi duyệt lần lượt từng con theo khoảng cách tuần hoàn. Hai danh sách phải chứa cùng ID, không chỉ có cùng độ dài. Đổi lực tách lại cần một phép thử khác: so trạng thái sau một bước.

## Viết code từng bước

### So hai cách trả lời độc lập

Sắp xếp kết quả từ các bucket rồi đối chiếu với kết quả vét cạn. F1 ở bản hoàn chỉnh chạy audit chỉ đọc: thao tác kiểm không được chữa dữ liệu sai hay làm chim nhảy một bước.

{/* snippet include/audit.hpp#audit-grid */}

```cpp title="include/audit.hpp — So hai cách trả lời độc lập"
inline bool audit(const Model& model, const Ui& ui) {
    const auto& colony = model.colony;
    if (!validParams(colony.params) || colony.selected >= colony.birds.size()) return false;
    if (model.accumulator < 0 || model.accumulator >= fixedDt + 1e-12) return false;
    auto actual = colony.observe().neighbors;
    std::vector<std::size_t> expected;
    findNeighbors(colony.birds, colony.selected, colony.params, expected);
    std::sort(actual.begin(), actual.end());
    if (actual != expected) return false;
    for (Control c : {ui.active, ui.hot, ui.focus})
        if (c != Control::None && std::find(order.begin(), order.end(), c) == order.end()) return false;
    return true;
}
```

### Thử một thay đổi có tác dụng lên quỹ đạo

Hai model khởi đầu giống nhau; giữ nguyên bán kính, chỉ đổi Separation rồi tiến đúng một tick. Kiểm thêm hai lịch khung hình có cùng tổng thời gian. Đây là test của hành vi, không phải so hai ảnh đẹp.

{/* snippet tests/tests.cpp#oracle */}

```cpp title="tests/tests.cpp — Thử một thay đổi có tác dụng lên quỹ đạo"
void testBoids() {
    using namespace lab;
    Model a, b;
    Ui ui;
    for (double t : {0.0, 0.5, 1.0}) {
        setSlider(a, Control::Radius, t);
        check(audit(a, ui), "grid neighbor IDs equal independent brute force");
    }
    setSlider(b, Control::Radius, 1.0);
    setSlider(a, Control::Separation, 0);
    setSlider(b, Control::Separation, 1);
    stepPhysics(a); stepPhysics(b);
    check(!sameBirds(a.colony.birds, b.colony.birds), "separation changes trajectories");
    resetSimulation(a); resetSimulation(b);
    advance(a, fixedDt); advance(a, fixedDt);
    advance(b, 2 * fixedDt);
    check(a.ticks == 2 && sameBirds(a.colony.birds, b.colony.birds), "fixed step partition");
    check(advance(a, 9.0) == 6, "bounded catch-up");
}
```

## Ghép các phần lại

Giải nén ZIP vào thư mục mới, cấu hình và build bản final. Thử chuỗi Pause → tăng Radius → tắt rồi bật Neighbors → Reset. Trong phần mã hoàn chỉnh bên dưới có cả đầu vào CMake, solver được cung cấp, UI và tests.

```bash title="Terminal — chạy checkpoint của bài"
cmake --build build --config Release --target project_65_checkpoint_7 --parallel 2
.\build\Release\project_65_checkpoint_7.exe
```

## Thử làm sai để hiểu đúng

Tạm đổi `observe()` để luôn dùng bán kính 64. Ảnh ban đầu vẫn đúng; bài kiểm ở bán kính 20 hoặc 140 phải báo sai. Sửa lại trước khi chạy nghiệm thu lần cuối.

## Tự kiểm tra kết quả

Debug và Release đều qua CTest. Kéo ra ngoài panel, dùng bàn phím, resize và đổi focus không làm lẫn input giữa hai vùng. Có thể dừng cùng một đàn và đọc lại cùng kết quả ở cùng seed.

```bash title="Terminal — nghiệm thu bản ZIP độc lập"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --parallel 2
ctest --test-dir build -C Debug --output-on-failure --timeout 15
cmake --build build --config Release --parallel 2
ctest --test-dir build -C Release --output-on-failure --timeout 15
.\build\Release\project_65_final.exe
```
