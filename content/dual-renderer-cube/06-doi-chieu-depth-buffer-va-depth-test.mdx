# Clipping, depth và winding phải khớp

## Vấn đề cần giải quyết

Một mesh có vẻ đúng từ mặt trước vẫn có thể mất mặt khi nhìn từ sau, rách ở near plane hoặc phụ thuộc triangle order. Đây là lỗi visibility, không phải vấn đề cần chữa bằng cách thêm đèn hay chọn màu đẹp hơn.

CPU và OpenGL phải cùng hiểu vùng nhìn, mặt trước và fragment nào được quyền ghi lên ảnh.

## Hiểu ý tưởng trước khi viết code

Ba quyết định khác nhau:

- **Clipping:** phần nào của tam giác nằm trong clip volume?
- **Culling:** hướng winding của mặt có được phép vẽ không?
- **Depth test:** ở pixel đã được phủ, fragment này có gần hơn fragment đã ghi không?

Culling không thay thế depth. Tắt culling vẫn cần Z-buffer để mặt sau không đè mặt trước. Ngược lại, tắt depth có thể lộ draw order dù culling đúng, nhất là khi nhìn vào mô hình.

Depth lưu là $z_{window}=\tfrac12(z_{clip}/w_{clip})+\tfrac12$. Bản CPU và OpenGL cùng clear về 1 rồi dùng LESS, không so khoảng cách Euclid.

Tắt culling, tắt depth rồi đảo thứ tự tam giác. Sau đó bật depth và thử lại. Phần bị che phải ổn định khi depth hoạt động. Canvas vẫn là mô hình giảng dạy; bản --verify kiểm trên OpenGL thật.

## Viết code từng bước

### 1. Quyết định ghi pixel tại một nơi

```cpp title="include/viewer-cpu.hpp — bool writeViewerPixel"
inline bool writeViewerPixel(Framebuffer& frame, int x, int y, float depth, Rgb color, bool depthEnabled, float bias = 0) {
    if (x < 0 || y < 0 || x >= frame.width || y >= frame.height || !std::isfinite(depth) || depth < 0 || depth > 1)
        return false;
    const auto pixel = std::size_t(y) * std::size_t(frame.width) + std::size_t(x);
    if (depthEnabled && depth - bias >= frame.depth[pixel])
        return false;
    if (depthEnabled)
        frame.depth[pixel] = depth;
    const auto offset = pixel * 4;
    frame.rgba[offset] = color.red;
    frame.rgba[offset + 1] = color.green;
    frame.rgba[offset + 2] = color.blue;
    frame.rgba[offset + 3] = 255;
    return true;
}
```

Ba điều cần nhìn rõ: bounds trước khi truy cập mảng, depth hữu hạn trong [0,1], và fragment chỉ qua khi nhỏ hơn depth đang giữ. Nếu depth test tắt, source **không ghi depth**, giống OpenGL khi GL_DEPTH_TEST bị disable.

Màu chỉ được ghi sau các kiểm này. Nếu ghi màu trước rồi mới so depth, fragment bị loại vẫn làm ảnh đổi.

### 2. Culling trước khi đổi winding để rasterize

Screen CPU đảo Y so với NDC. Do đó tam giác CCW ở NDC có signed area âm trong screen top-left. CPU loại area dương khi `cullBackfaces` bật.

Rasterizer có thể đổi thứ tự b/c sau quyết định culling để làm edge tests bằng area dương. Đó là bước tính coverage, không phải thay source indices hoặc sửa winding riêng cho GPU.

### 3. Đặt state OpenGL theo đúng scene

```cpp title="include/viewer-gpu.hpp —         if "
if (scene.depthEnabled) {
    gl.Enable(GL_DEPTH_TEST);
    gl.DepthFunc(GL_LESS);
} else
    gl.Disable(GL_DEPTH_TEST);
if (scene.view.cullBackfaces) {
    gl.Enable(GL_CULL_FACE);
    gl.CullFace(GL_BACK);
    gl.FrontFace(GL_CCW);
} else
    gl.Disable(GL_CULL_FACE);
```

GL_DEPTH_TEST + GL_LESS tương ứng Z-buffer CPU. GL_CULL_FACE + GL_CCW + GL_BACK tương ứng quy ước mặt trước. D/C chỉ bật/tắt hai quyết định này; không thay index order.

Cả hai nhánh bắt đầu frame với clear depth 1. Việc presenter disable depth/culling khi vẽ quad không được ảnh hưởng draw model của frame kế tiếp; GPU renderer luôn đặt lại state cần dùng.

### 4. Kiểm bằng fixture, không chỉ một góc cube đẹp

```cpp title="include/viewer-fixtures.hpp — ViewerMesh viewerVisibilityFixture"
inline ViewerMesh viewerVisibilityFixture() {
    ViewerMesh mesh{};
    mesh.name = "front-CCW-and-back-CW";
    appendViewerFixtureTriangle(mesh, {-1, -0.7F, 0}, {-0.1F, -0.7F, 0}, {-0.55F, 0.7F, 0});
    appendViewerFixtureTriangle(mesh, {0.1F, -0.7F, 0}, {0.55F, 0.7F, 0}, {1, -0.7F, 0});
    return mesh;
}
```

Fixture có một tam giác CCW bên trái và một tam giác CW bên phải. Với pose chính diện và culling bật, chỉ bên trái hiện. Tắt culling, cả hai phải hiện. Nếu cùng mất hoặc cùng còn, kiểm dấu area/front face trước.

```cpp title="include/viewer-fixtures.hpp — ViewerMesh viewerNearFixture"
inline ViewerMesh viewerNearFixture() {
    ViewerMesh mesh{};
    mesh.name = "triangle-crossing-near-and-eye";
    appendViewerFixtureTriangle(mesh, {-1, -0.7F, 0}, {1, -0.7F, 0}, {0, 0.9F, 1.8F});
    return mesh;
}
```

Tam giác này vượt qua near plane và cả phía sau eye khi camera ở distance 1,2. Clipping phải giữ phần còn trong tầm nhìn; không bỏ nguyên tam giác và không divide đỉnh sau eye trước.

D đổi depth, C đổi culling, O đảo thứ tự **các tam giác**. Thử rocket/sphere từ phía trước và phía sau, sau đó F1/F2. Zoom sát để kích hoạt near clipping.

Các pixel sát cạnh có thể khác giữa software rasterizer và driver. Điều đó không cho phép bỏ qua cả một mặt mất hoặc hàng trăm pixel sâu trong tam giác. Bài 9 định nghĩa dải cạnh và dung sai số cụ thể trước khi chạy phép so.

## Thử làm sai để hiểu đúng

Thay GL_LESS bằng GL_GREATER mà vẫn clear depth 1. Dự đoán fragment nào còn được ghi; kiểm rồi khôi phục cặp clear/compare đúng.

Đổi GL_CCW thành GL_CW nhưng giữ nguyên source indices. Các mặt sẽ đảo. Khôi phục GL_CCW, không đảo riêng EBO GPU.

Cuối cùng bỏ mặt near khỏi clipping CPU. So cảnh zoom gần ở F1/F2, rồi trả lại đủ sáu mặt. Đừng cố dùng culling để che clipping sai.

## Tự kiểm tra kết quả

- [ ] Depth CPU/GPU cùng clear 1, LESS, range [0,1].
- [ ] Tắt depth không ghi depth buffer; đảo order chỉ là thí nghiệm, không phải test phải giống.
- [ ] Culling dùng một source winding CCW; không có index buffer “sửa hướng cho GPU”.
- [ ] Fixture trước/sau hiện đúng số mặt ở hai trạng thái culling.
- [ ] Near/eye crossing còn phần hình hợp lệ, không NaN hoặc kéo vô hạn.
- [ ] Khi depth bật, đổi triangle order không đổi ảnh solid ở các mesh kiểm.
