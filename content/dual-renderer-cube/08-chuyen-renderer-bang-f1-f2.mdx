# Chuyển renderer bằng F1 và F2

## Vấn đề cần giải quyết

Đến checkpoint 7, CPU và GPU đều chạy nhưng các checkpoint chọn backend cố định để tập trung debug. Bây giờ mới ghép F1/F2. Nếu ta xử lý input bên trong từng renderer hoặc init/destroy resource mỗi lần bấm phím, cube sẽ giật, mất state hoặc tạo lỗi lifetime.

Checkpoint 8 đặt event → update → render theo đúng một chiều. F1/F2 sửa đúng một enum; cả hai backend và resource của chúng được tạo từ startup, dùng lại đến cleanup.

## Hiểu ý tưởng trước khi viết code

Frame loop cần một snapshot duy nhất:

```text
Poll events
  ├─ F1/F2 → RendererKind
  ├─ drag/N/Space/R → CubeScene + paused
  └─ resize → framebuffer pixel size
Update angle một lần
Render CPU hoặc GPU từ cùng scene + aspect
Swap window
```

Không render CPU rồi update rồi mới render GPU. Dù chỉ một backend hiện trên màn hình, switching phải giữ continuity như đổi camera trong cùng chương trình.

## Ghép các phần lại

Chạy checkpoint 8, pause rồi tiến N vài lần. Bấm F1/F2 liên tục: orientation phải không đổi. Tiếp tục animation, drag, toggle D/C và resize; mọi state phải đi theo scene.

```bash title="Terminal — build checkpoint chuyển backend"
cmake --build build --config Debug --target project_34_checkpoint_8
```

Đừng so CPU timer quanh `glDrawElements` với thời gian CPU raster rồi kết luận tốc độ. GPU command có thể chỉ mới được submit; Project này kiểm correctness và architecture, không phải benchmark CPU/GPU.

## Thử làm sai để hiểu đúng

1. Trong F2, gán lại `scene = {}`. Cube nhảy về preset mỗi lần chuyển GPU.
2. Tạo/destroy `GpuCubeRenderer` trong nhánh F2. Nhấn phím nhanh làm allocation/resource churn và mở đường cho use-after-destroy.
3. Để tái hiện lỗi resize một cách có chủ đích, tạm chuyển khối chuẩn bị `cpuFramebuffer` và `cpuPresenter` vào riêng nhánh CPU. Sau đó resize khi đang ở GPU rồi bấm F1: texture cũ không khớp framebuffer mới. Đưa khối này trở lại trước nhánh chọn renderer ngay sau khi quan sát xong.

Hoàn tác lỗi, thực hiện lại chuỗi F1 → resize → F2 → drag → F1.
