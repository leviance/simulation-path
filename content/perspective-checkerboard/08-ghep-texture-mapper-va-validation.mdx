# Hoàn thiện ứng dụng và kiểm chứng cả ảnh

## Vấn đề cần giải quyết

Ta đã có đường đi đầy đủ từ một tấm bảng 3D đến từng texel bàn cờ. Bài cuối không thêm một công thức texture mới. Ta làm cho ứng dụng dễ thử, tách phần trình diễn khỏi phần debug và kiểm những lỗi mà một ảnh mặc định “trông ổn” có thể bỏ sót.

Sản phẩm bàn giao là **executable C++/SDL3 chạy độc lập**, cùng starter, tám checkpoint và final trong ZIP. Canvas giúp thử và đọc số liệu; nó không thay cho chương trình native.

## Hiểu ý tưởng trước khi viết code

Pipeline cuối là `quad → near clip → projection → coverage → affine/corrected UV → sampler → framebuffer`. Mỗi bước có một trách nhiệm rõ:

- Clipping giữ geometry và thuộc tính đi cùng nhau.
- Coverage quyết định pixel nào thuộc face nào.
- Interpolation tìm UV tại pixel; chỉ bước này thay khi bật A/B.
- Sampler đổi UV thành màu; nó không biết camera hoặc triangle.

Reference ray–plane đi theo một con đường khác. Nó tìm thẳng vị trí trên quad rồi đọc UV; vì vậy nó có thể phát hiện sai sót của đường nội suy, thay vì chỉ xác nhận hai bản sao cùng công thức trả cùng kết quả.

## Viết code từng bước

### Bước 1 — Mở mặc định ở chế độ trình diễn sạch

Trong constructor của `Scene`, bản final đặt:

```cpp title="include/scene.hpp — default final không phủ wireframe lên texture"
debug = false;
```

Khi debug tắt, vẫn giữ grid chiều sâu và nhãn AFFINE/PERSPECTIVE-CORRECT. F bật wireframe, marker và bảng số trở lại. Không được tắt cả depth cues rồi để người xem nhầm đây là một hình 2D bị kéo góc.

### Bước 2 — Cho single-step một ý nghĩa cố định

`advanceScene` dùng phase để xoay quad. Nhánh cập nhật:

```cpp title="include/scene.hpp — một bước có thời gian xác định"
double step = std::min(dt, 0.05);
if (singleStep) {
    step = 1.0 / 60.0;
}
const double nextPhase = std::fmod(scene.phase + step, 6.283185307179586);
scene.yaw = std::clamp(scene.yaw + 0.5 * (std::sin(nextPhase) - std::sin(scene.phase)), -1.25, 1.25);
scene.phase = nextPhase;
scene.preset = 0;
return true;
```

Ta cộng phần thay đổi góc, thay vì gán lại một góc mặc định, để bật chạy sau khi kéo chuột không làm quad nhảy tư thế. Đây là chuyển động trình diễn pose, không phải solver vật lý. Trong `handleKey`, dấu chấm chủ động dừng rồi tiến một bước:

```cpp title="include/controls.hpp — tiến đúng một bước dù ứng dụng vừa đứng yên lâu"
if (key == SDLK_PERIOD) {
    scene.paused = true;
    advanceScene(scene, 1.0 / 60.0, true);
}
```

Không lấy delta time ngẫu nhiên từ frame trước để định nghĩa “một bước”. Reset và đổi preset phải hủy drag cũ. Focus lost, resize và minimize dừng animation; input ở ngoài vùng letterbox không được xem là một pixel trong quad.

### Bước 3 — Kiểm cả coverage và UV bằng reference

Trong `tests/tests.cpp`, với mỗi preset, render ảnh corrected, affine, bản đổi diagonal và bản đảo winding. Với mỗi pixel, so owner count rồi bắn ray qua đúng tâm pixel:

```cpp title="tests/tests.cpp — coverage phải khớp đường kiểm hình học độc lập"
if (bool(rayUv) != (image.owners[pixel] == 1)) {
    ++errors;
}
```

Nếu có giao điểm hợp lệ và pixel được phủ, so UV của cả ba cách chia/vẽ:

```cpp title="tests/tests.cpp — đổi diagonal và winding không đổi UV corrected"
if (lab::uvDistance(image.uv[pixel], *rayUv) > 1e-9 || lab::uvDistance(alternative.uv[pixel], *rayUv) > 1e-9 || lab::uvDistance(reversed.uv[pixel], *rayUv) > 1e-9) {
    ++errors;
}
```

Test RGB tự tính ô cờ từ UV ray hit, không gọi lại sampler của renderer. Chỉ bỏ so màu tại ranh giới ô cờ trong tolerance rất nhỏ, nơi làm tròn floating point có thể chọn hai phía khác nhau; coverage và UV ở các pixel ấy vẫn được kiểm. Đừng nới tolerance màu cho cả ảnh để che một sampler sai.

### Bước 4 — Kiểm lifecycle, không chỉ công thức

`main.cpp` xử lý lỗi của tạo tài nguyên, upload, render và present; luôn nhả capture trước khi hủy window. Vòng lặp chỉ render lại khi state đổi và ngủ ngắn lúc rảnh, nên khi pause không cần vẽ texture liên tục.

Chạy `--smoke` tạo window ẩn, đổi preset, resize và tự thoát sau tám frame. Nó giúp phát hiện crash hoặc lỗi khởi tạo mà không để một event loop vô hạn giữ test suite. Smoke test **không thay thế** việc tự kiểm hình ảnh và input ở cửa sổ thật.

## Ghép các phần lại

```bash title="Terminal — build mọi phiên bản và kiểm cả hai cấu hình"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON -DBUILD_TESTING=ON
cmake --build build --config Debug --parallel 2
ctest --test-dir build -C Debug --output-on-failure --timeout 30
cmake --build build --config Release --parallel 2
ctest --test-dir build -C Release --output-on-failure --timeout 30
# Windows / Visual Studio
.\build\Release\project_20_final.exe
```

Linux/macOS với generator một cấu hình: chọn `-DCMAKE_BUILD_TYPE=Release` khi configure và chạy `./build/project_20_final`. Lần configure đầu cần mạng để tải đúng SDL 3.4.8; các thuật toán cốt lõi không cần thư viện graphics bổ sung.

Trong bản final: `1–4` đổi pose, kéo/WASD xoay, wheel đổi khoảng cách, `M` đổi affine/corrected, `C` bật so sánh, `F` bật debug, `Space` chạy/dừng, dấu chấm tiến một bước và `R` reset. `T` đổi addressing; với UV quad chỉ trong `[0,1]`, clamp/repeat gần như giống nhau ở lòng mặt phẳng — dùng bài 2 để thử UV ngoài miền thay vì mong toggle này sửa distortion.

Phần **Toàn bộ mã nguồn của dự án** bên dưới có CMake, mọi header, main và tests. ZIP còn có README mô tả cách chạy. Bạn không phải đi tìm hoặc ghép thêm code từ project khác.

## Thử làm sai để hiểu đúng

1. Trả affine UV trong nhánh corrected. Test constant-depth có thể vẫn qua; pose nghiêng và oracle toàn ảnh phải phát hiện.
2. Bỏ UV khi tạo intersection. Preset chính diện không phát hiện, nhưng near crossing phải sai ở cả UV lẫn màu.
3. Dùng thứ tự weights trước swap winding. Coverage vẫn khớp nhưng test UV của bản đảo winding phải thất bại.
4. Cho single-step dùng dt từ đồng hồ. Đợi vài giây rồi bấm lại: bước không còn tái lập. Khôi phục 1/60 giây.

## Tự kiểm tra kết quả

- Một quad 3D quay/tilt thật, không biến dạng kích thước local.
- Bàn cờ tự sinh, sampler nearest có clamp/repeat rõ ràng.
- A/B thể hiện affine méo ở góc nghiêng lớn; corrected giữ texture đúng trên mặt phẳng.
- Near clip giữ cùng t cho XYZ và UV, sau đó mới tạo reciprocal attributes.
- Đổi diagonal hoặc winding không tạo overlap/khe hoặc thay UV corrected.
- Oracle độc lập kiểm coverage, UV và RGB ở bốn pose; Debug/Release đều chạy điều kiện test.
- Showcase sạch, debug bật/tắt được; input, resize/HiDPI, pause/reset và Tab trên Canvas hoạt động.
- Starter, tám checkpoint và final build độc lập; mã hoàn chỉnh có comment và thụt 4 spaces.
