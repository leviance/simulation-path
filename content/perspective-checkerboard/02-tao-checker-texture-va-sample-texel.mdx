# Tạo checker texture và lấy mẫu texel

## Vấn đề cần giải quyết

Bài trước mới cho ta một tấm bảng trống. Bây giờ cần một ảnh để dán lên nó. Ta tự tạo bàn cờ thay vì tải PNG để nhìn được toàn bộ dữ liệu: ảnh rộng bao nhiêu, mỗi pixel nằm ở đâu và UV chọn màu thế nào.

Trong bài này, **chưa dán ảnh lên quad**. Ta xem ảnh nguồn riêng và viết một sampler có thể kiểm tra bằng vài giá trị cụ thể. Sau đó mới nối sampler vào rasterizer.

## Hiểu ý tưởng trước khi viết code

Một pixel trong texture gọi là **texel**, để phân biệt với pixel đầu ra của framebuffer. Ảnh nguồn 64 × 64 gồm 8 × 8 ô cờ; mỗi ô rộng 8 texel.

UV là tọa độ liên tục. Với cách lấy mẫu nearest của project này, texel thứ x sở hữu khoảng `[x/width, (x+1)/width)`. Vì vậy:

$$
x=\min(\lfloor u\,width\rfloor,width-1),\qquad
y=\min(\lfloor v\,height\rfloor,height-1)
$$

Ta xử lý UV ngoài miền **trước** khi chuyển sang integer. Clamp ép về `[0,1]`; repeat giữ phần lẻ `value−floor(value)`. Chẳng hạn `−0.1` repeat thành `0.9`, không phải một chỉ số âm.

## Viết code từng bước

### Bước 1 — Tạo bộ nhớ ảnh nguồn

Thêm `include/sampler.hpp`, giữ nó độc lập với SDL:

```cpp title="include/sampler.hpp — texture có kích thước và texel riêng"
struct Texture2D {
    int width{};
    int height{};
    std::vector<Color> texels;
};
```

Trong `makeCheckerTexture`, kiểm kích thước trước khi cấp phát, rồi resize `texels` thành `width × height`. Không dùng chung mảng này với framebuffer: xoay quad không được làm thay đổi ảnh nguồn.

### Bước 2 — Tô hai màu theo ô cờ

```cpp title="include/sampler.hpp — mỗi texel được ghi đúng một lần"
for (int y = 0; y < height; ++y) {
    for (int x = 0; x < width; ++x) {
        const int cellX = x * cells / width;
        const int cellY = y * cells / height;
        Color color{236, 240, 248};
        if ((cellX + cellY) % 2 != 0) {
            color = {38, 48, 72};
        }
        texture.texels[std::size_t(y) * std::size_t(width) + std::size_t(x)] = color;
    }
}
```

`cellX` và `cellY` là vị trí **ô cờ**, không phải texel. Chẵn thì sáng, lẻ thì tối. Dòng cuối vẫn là row-major quen thuộc từ Project 01. Hai màu cố định giúp kết quả không phụ thuộc light/dark theme của website.

### Bước 3 — Đưa UV về miền được phép

```cpp title="include/sampler.hpp — clamp và repeat có quy ước rõ ràng"
inline double addressCoordinate(double value, AddressMode mode) {
    if (!std::isfinite(value)) {
        return 0;
    }
    if (mode == AddressMode::clamp) {
        return std::clamp(value, 0.0, 1.0);
    }
    return value - std::floor(value);
}
```

Không dùng `%` với số nguyên sau khi nhân UV: bạn sẽ đánh mất phần lẻ và xử lý số âm sai. Sampler còn từ chối NaN/infinity trước khi đọc mảng; việc `addressCoordinate` trả 0 cho input không hữu hạn không có nghĩa đó là UV hợp lệ.

### Bước 4 — Tìm chỉ số rồi đọc texel

```cpp title="include/sampler.hpp — tọa độ texel sau addressing"
const double u = addressCoordinate(uv.x, mode);
const double v = addressCoordinate(uv.y, mode);
const int x = std::min(int(std::floor(u * texture.width)), texture.width - 1);
const int y = std::min(int(std::floor(v * texture.height)), texture.height - 1);
return {x, y};
```

Nhánh clamp tại U bằng 1 tạo `floor(1×64)=64`, nên cần `min(...,63)`. Repeat tại U bằng 1 đã trở thành 0 trước bước này.

`sampleNearest` kiểm kích thước/mảng/UV, gọi `nearestTexelIndex`, rồi đọc `texels[y×width+x]`. Nó trả `Color`, chưa ghi vào framebuffer; ở bài sau, rasterizer mới quyết định màu ấy đi vào pixel nào.

## Thử làm sai để hiểu đúng

1. Bỏ `min(..., width−1)` rồi thử UV `(1,1)` với clamp. Chỉ số 64 nằm ngoài ảnh; đừng chờ đến lúc đọc mảng mới sửa lỗi.
2. Thay `floor` bằng `round` mà vẫn giữ công thức `u×width`. Ranh giới texel thay đổi; test ở U gần `1/64` sẽ lộ lỗi quy ước.
3. Dùng UV `(-0.1,1.1)` với repeat. Ảnh 64 × 64 phải chọn texel `(57,6)`; nếu nhận số âm, addressing đang sai.

## Tự kiểm tra kết quả

- Mảng có đúng 4096 texel và hai màu bàn cờ khác nhau rõ ràng.
- Clamp `(1,1)` chọn `(63,63)`; repeat chọn `(0,0)`.
- Repeat xử lý được UV âm mà không đọc ngoài mảng.
- Marker/texel index đổi khi điều chỉnh UV; hình học quad không bị sửa.
- Không có bilinear filtering hay mipmap trong sampler này.
