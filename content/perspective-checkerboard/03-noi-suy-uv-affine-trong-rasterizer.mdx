# Nội suy UV affine trong rasterizer

## Vấn đề cần giải quyết

Ta đã có một mặt phẳng biết quay và một ảnh nguồn biết lấy mẫu. Việc còn thiếu là nối chúng: **pixel này trên mặt phẳng phải đọc UV nào?** Rasterizer của Project 16 đã trả barycentric weights; thử dùng chúng để trộn UV ở ba đỉnh.

Cách này hợp lý nếu chỉ nhìn màn hình, và cũng là cách dễ viết nhất. Ta cố ý giữ nó thành một phiên bản chạy được. Bạn cần thấy nó làm sai điều gì trước khi học công thức sửa.

## Hiểu ý tưởng trước khi viết code

Với một pixel thuộc triangle, ba weights thỏa tổng gần bằng 1. Nội suy affine là:

$$
uv_{affine}=\lambda_Auv_A+\lambda_Buv_B+\lambda_Cuv_C
$$

Weights này đo vị trí **trên triangle đã chiếu xuống màn hình**. Khi cả mặt phẳng có cùng Z, nó hoạt động đúng. Khi mặt phẳng nghiêng, perspective divide làm thay đổi tỉ lệ gần/xa; UV trên bề mặt không còn biến thiên đều theo khoảng cách màn hình.

Ta chưa sửa điều đó ở bài này. Geometry, coverage và sampler phải chạy đúng trước; chỉ phép nội suy UV còn là bản affine.

## Viết code từng bước

### Bước 1 — Lấy weights tại tâm pixel

`include/raster.hpp` dùng edge function dạng đường thẳng `Ax+By+C`. Giá trị trên ba cạnh cho biết pixel nằm trong triangle hay không:

```cpp title="include/raster.hpp — edge function trên screen space"
inline double edgeFunction(Vec2 a, Vec2 b, Vec2 p) {
    return (a.y - b.y) * p.x + (b.x - a.x) * p.y + (a.x * b.y - a.y * b.x);
}
```

Tại pixel `(x,y)`, dùng tâm `(x+0.5,y+0.5)`, không dùng góc trái trên. Rasterizer chia mỗi giá trị cạnh cho area để lấy λ. Top-left rule giải quyết trường hợp giá trị cạnh bằng 0: cạnh chung chỉ thuộc một triangle, không cộng thêm epsilon để cả hai cùng nhận.

### Bước 2 — Đổi winding thì đổi cả UV

Rasterizer chuẩn hóa area về dương:

```cpp title="include/raster.hpp — đổi cả ScreenVertex, không chỉ position"
if (area < 0) {
    std::swap(triangle[1], triangle[2]);
    area = -area;
}
```

`ScreenVertex` chứa cả position và UV. Nếu chỉ swap hai position rồi trộn UV theo thứ tự cũ, ảnh có thể bị lật dù coverage vẫn đúng. Vì thế callback nhận **cả triangle đã chuẩn hóa** lẫn weights:

```cpp title="include/raster.hpp — thứ tự weights khớp thứ tự thuộc tính"
shadePixel(triangle, RasterSample{x, y, {a / area, b / area, c / area}});
```

### Bước 3 — Viết hàm nội suy affine

Thêm `include/interpolation.hpp`:

```cpp title="include/interpolation.hpp — UV tuyến tính trên màn hình"
inline Vec2 interpolateAffineUv(const ScreenTriangle& triangle, Barycentric weights) {
    const double u = weights.a * triangle[0].uv.x + weights.b * triangle[1].uv.x + weights.c * triangle[2].uv.x;
    const double v = weights.a * triangle[0].uv.y + weights.b * triangle[1].uv.y + weights.c * triangle[2].uv.y;
    return {u, v};
}
```

Đừng clamp ở đây. Hàm này chỉ chịu trách nhiệm trộn thuộc tính; clamp/repeat vẫn do sampler xử lý.

### Bước 4 — Nối UV tới framebuffer

Trong `renderTexturedTriangle`, sau coverage, tạo `affineUv` rồi dùng nó làm `selectedUv`. Cuối callback:

```cpp title="include/render.hpp — sampler trả màu, callback ghi pixel"
write(sample, selectedUv, sampleNearest(texture, selectedUv, scene.address));
++stats.covered;
```

Hàm `write` được truyền từ `renderScene`; nó gọi `putPixel` cho `sample.x/sample.y`. Chương trình không dùng SDL để dán texture lên geometry: SDL chỉ trình bày framebuffer CPU cuối cùng.

## Ghép các phần lại

Build `project_20_checkpoint_3`. So phím `1` chính diện với phím `3` nghiêng mạnh. Hãy nhìn đường chia giữa hai triangle: đường biên quad vẫn đúng, nhưng kích thước/hướng các ô cờ có thể thay đổi thiếu tự nhiên qua diagonal.

Đường đi nay đã đủ: `quad → projectVertex → rasterizeTriangle → interpolateAffineUv → sampleNearest → putPixel`. Giữ đường đi này trong đầu; các bài sau chỉ thay đúng bước nội suy, không viết lại toàn bộ renderer.

## Thử làm sai để hiểu đúng

1. Dùng tọa độ `(x,y)` thay cho tâm pixel. Marker và coverage sẽ lệch nửa pixel; khôi phục `+0.5`.
2. Swap position nhưng giữ UV theo thứ tự cũ. Texture sai mà silhouette không đổi: coverage không đủ để chứng minh shading đúng.
3. Chia quad thành nhiều triangle nhỏ để ảnh trông bớt méo. Đây chỉ là cách che sai số affine; project yêu cầu sửa công thức trên hai triangle gốc.
