# Khôi phục UV perspective-correct tại pixel

## Vấn đề cần giải quyết

Projected vertex đã có đủ dữ liệu. Bây giờ ta thay đúng một mắt xích: pixel không dùng raw UV được trộn affine nữa, mà nội suy `u/z`, `v/z`, `1/z` rồi chia lại. Quad, coverage và sampler giữ nguyên.

Đừng xóa bản affine. Nó là đối chứng cho thấy phép sửa có tác dụng gì; nhìn một ảnh corrected đơn lẻ khó nhận ra bạn vừa giải quyết vấn đề nào.

## Hiểu ý tưởng trước khi viết code

Hai tử số và mẫu số phải dùng cùng barycentric weights:

$$
U'=\sum_i\lambda_i(u_i/z_i),\qquad
V'=\sum_i\lambda_i(v_i/z_i),\qquad
D=\sum_i\lambda_i/z_i
$$

Khôi phục:

$$
u=U'/D,\qquad v=V'/D
$$

Ở một vertex, công thức trở về đúng UV vertex. Khi mọi Z bằng nhau, các hệ số `1/z` triệt tiêu và công thức trở lại affine. Với mặt phẳng nghiêng, corrected UV phải khớp giao ray–plane trong khi affine có thể lệch rõ.

## Viết code từng bước

### Bước 1 — Tính UV corrected trong một hàm riêng

Thêm vào `include/interpolation.hpp`:

```cpp title="include/interpolation.hpp — chia sau khi đã cộng đủ tử và mẫu"
inline std::optional<Vec2> interpolatePerspectiveUv(const ScreenTriangle& triangle, Barycentric weights) {
    const double denominator = reciprocalDepthDenominator(triangle, weights);
    if (!std::isfinite(denominator) || denominator <= 0) {
        return std::nullopt;
    }
    const double uOverZ = weights.a * triangle[0].uOverZ + weights.b * triangle[1].uOverZ + weights.c * triangle[2].uOverZ;
    const double vOverZ = weights.a * triangle[0].vOverZ + weights.b * triangle[1].vOverZ + weights.c * triangle[2].vOverZ;
    const Vec2 uv{uOverZ / denominator, vOverZ / denominator};
    if (!isFinite(uv)) {
        return std::nullopt;
    }
    return uv;
}
```

`optional` buộc nơi gọi xử lý trường hợp dữ liệu không hợp lệ. Không đưa infinity tới sampler rồi clamp về một góc ảnh: cách ấy che lỗi upstream thay vì sửa nó.

### Bước 2 — Chọn UV, giữ nguyên sampler

Trong callback raster của `renderTexturedTriangle`, `selectedUv` ban đầu là affine. Thêm:

```cpp title="include/render.hpp — chỉ lựa chọn phương pháp nội suy"
const auto perspectiveUv = interpolatePerspectiveUv(triangle, sample.barycentric);
if (!perspectiveUv) {
    return;
}
if (corrected) {
    selectedUv = *perspectiveUv;
}
```

Dòng `sampleNearest(texture, selectedUv, scene.address)` vẫn như bài 3. Affine và corrected không được dùng hai texture, hai bộ geometry hoặc hai sampler khác nhau, nếu không A/B không còn là một phép so công bằng.

### Bước 3 — Cho hai viewport dùng cùng scene

Khi bật compare, `viewports` tạo hai panel có cùng width/height. Trong `renderScene`, mỗi panel xác định cách nội suy như sau:

```cpp title="include/render.hpp — trái affine, phải corrected"
bool corrected = scene.corrected;
if (scene.compare) {
    corrected = panel == 1;
}
```

Hai panel đều gọi `makeQuad` từ cùng `Scene`. Khi chỉ xem một ảnh, phím M đổi affine/corrected. Phím C bật/tắt so sánh. Inspector đọc cùng vị trí tương đối trong hai panel; ở chế độ compare, bảng texel đang vẽ thuộc panel corrected bên phải.

## Ghép các phần lại

Build `project_20_checkpoint_6`. Chọn preset 3, bật compare và nhìn các đường ô cờ đi qua diagonal: corrected phải thẳng và liên tục trên mặt phẳng. Chúng vẫn hội tụ/co nhỏ theo perspective; “đúng” không có nghĩa mọi ô hiện thành hình vuông trên màn hình.

Chọn preset 1 làm constant-depth test. Hai ảnh phải gần như giống hệt nhau; nếu corrected vẫn khác, đừng đổ cho perspective khi scene không có chênh lệch depth.

## Thử làm sai để hiểu đúng

1. Chia từng `uOverZ` cho `oneOverZ` trước khi nội suy. Bạn vừa quay về raw UV và tái tạo đúng lỗi affine.
2. Dùng D của một triangle khác. Thử vị trí sát diagonal để thấy UV nhảy dù mẫu số vẫn dương.
3. Nhân màu texture với D. D sửa tọa độ lấy mẫu, không phải độ sáng; project này không có lighting hoặc attenuation.

## Tự kiểm tra kết quả

- M/C đổi cách xem mà không đổi pose, texture hoặc coverage.
- Corrected UV khớp ray UV với sai số cỡ floating point.
- Constant-depth làm affine và corrected trùng nhau.
- Nghiêng mạnh có khác biệt A/B rõ ràng nhưng silhouette giống nhau.
- Đổi diagonal không làm thay ảnh corrected ngoài sai khác số học ở biên texel.
