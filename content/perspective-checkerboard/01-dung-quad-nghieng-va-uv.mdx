# Dựng mặt phẳng có thể xoay và gắn UV

## Vấn đề cần giải quyết

Đặt một tấm bàn cờ trước mặt: khi bạn nghiêng nó, các ô ở xa phải nhỏ lại. Ta sẽ tự vẽ tấm bàn cờ ấy bằng CPU, giữ một bản sai để so sánh rồi sửa cách dán ảnh. Nhưng trước khi có ảnh, ta cần một mặt phẳng **thật sự quay trong 3D**, không phải một hình thang được kéo góc trên màn hình.

Hãy tải ZIP ở trang tổng quan và build starter trước. Nó đã có window, renderer, streaming texture và framebuffer như các project trước. Trong `src/main.cpp`, việc tạo renderer vẫn rất bình thường, không có API vẽ 3D nào của SDL:

```cpp title="src/main.cpp — tạo renderer và xử lý khi thất bại"
SDL_Renderer* renderer = SDL_CreateRenderer(window, nullptr);
if (!renderer) {
    std::cerr << SDL_GetError() << '\n';
    SDL_DestroyWindow(window);
    SDL_Quit();
    return EXIT_FAILURE;
}
```

Starter mở một nền tối và dòng hướng dẫn. Ta giữ bộ khung đó, thêm dữ liệu quad trong `geometry.hpp`, rồi nối phép chiếu và vẽ cạnh trong `render.hpp`. Chưa cần sửa sampler hay nghĩ đến công thức `u/z`.

## Hiểu ý tưởng trước khi viết code

**Position nói đỉnh nằm ở đâu; UV nói đỉnh đó chạm vào đâu trên ảnh nguồn.** Quad rộng 3.2, cao 2, ban đầu nằm trên mặt phẳng local `z=0`. Bốn góc có UV lần lượt là `(0,1)`, `(1,1)`, `(1,0)`, `(0,0)`. U tăng sang phải; V tăng xuống dưới ảnh, nên góc trên có V bằng 0.

Hai triangle dùng index `{0,2,1}` và `{0,3,2}`. Chúng dùng chung hai đỉnh 0 và 2 trên đường chéo. Đừng tạo hai bản sao UV rồi hy vọng sau này chúng luôn được sửa giống nhau.

Camera đặt tại origin và nhìn theo `+Z`. Quay mặt phẳng quanh X, tiếp đến Y, rồi đưa nó ra trước camera:

$$
P_{view}=R_Y(yaw)R_X(pitch)P_{local}+(0,0,distance)
$$

Phép quay giữ nguyên chiều dài cạnh. Nếu chỉ tăng Z của cạnh phải mà giữ nguyên X/Y, cạnh ngang sẽ dài ra: đó là **biến dạng mặt phẳng**, không phải xoay.

## Viết code từng bước

### Bước 1 — Thêm vertex có cả position và UV

Trong `include/geometry.hpp`, thêm kiểu sau. `Vec2` và `Vec3` đã có trong starter:

```cpp title="include/geometry.hpp — thuộc tính đi cùng vị trí"
struct TexturedVertex {
    Vec3 position{};
    Vec2 uv{};
};

using TexturedTriangle = std::array<TexturedVertex, 3>;

struct TexturedQuad {
    std::array<TexturedVertex, 4> vertices{};
    std::array<std::array<std::size_t, 3>, 2> faces{{{0, 2, 1}, {0, 3, 2}}};
};
```

Ta dùng array vì số đỉnh và face ở đây cố định. `faces` chỉ chứa index; dữ liệu position và UV vẫn nằm ở bốn vertex gốc.

### Bước 2 — Tạo hình chữ nhật local rồi quay cả bốn đỉnh

```cpp title="include/geometry.hpp — tạo quad không làm thay đổi chiều dài cạnh"
inline TexturedQuad makeQuad(double yaw, double pitch, double distance) {
    TexturedQuad quad;
    quad.vertices[0] = {{-1.6, -1, 0}, {0, 1}};
    quad.vertices[1] = {{1.6, -1, 0}, {1, 1}};
    quad.vertices[2] = {{1.6, 1, 0}, {1, 0}};
    quad.vertices[3] = {{-1.6, 1, 0}, {0, 0}};
    for (auto& vertex : quad.vertices) {
        vertex.position = rotateY(rotateX(vertex.position, pitch), yaw);
        vertex.position.z += distance;
    }
    return quad;
}
```

`rotateX` và `rotateY` dùng sin/cos từ Project 12. UV không tham gia phép quay: một góc của tấm bàn cờ vẫn là góc ấy, dù tấm bàn quay đi đâu. Chỉ position thay đổi.

### Bước 3 — Chiếu đỉnh xuống viewport

`projectVertex` từ chối vertex có `z < 1`; near plane của project là 1. Sau các kiểm tra đầu hàm, phần tính screen position là:

```cpp title="include/geometry.hpp — dùng chiều cao viewport để tính focal length"
const double focalPixels = double(viewport.height) * 0.5 / std::tan(3.141592653589793 / 6.0);
ScreenVertex output;
output.position = {viewport.left + viewport.width * 0.5 + focalPixels * vertex.position.x / vertex.position.z, viewport.top + viewport.height * 0.5 - focalPixels * vertex.position.y / vertex.position.z};
output.uv = vertex.uv;
```

FOV theo chiều dọc là 60°. Cùng một `focalPixels` được dùng cho X và Y, nên một đơn vị ngang không bị kéo khác một đơn vị dọc. Dấu trừ ở screen Y đổi quy ước Y lên trên của 3D sang Y xuống dưới của framebuffer.

### Bước 4 — Nối cạnh bằng code CPU đã biết

Trong `renderScene`, sau khi lấy `quad` và `viewport`, duyệt index của từng face:

```cpp title="include/render.hpp — wireframe của hai triangle"
for (const auto& face : quad.faces) {
    for (std::size_t edge = 0; edge < face.size(); ++edge) {
        const auto a = projectVertex(quad.vertices[face[edge]], viewport);
        const auto b = projectVertex(quad.vertices[face[(edge + 1) % face.size()]], viewport);
        if (a && b) {
            drawLine(image, a->position, b->position, {60, 220, 170}, viewport);
        }
    }
}
```

`drawLine` là Bresenham trên framebuffer, không phải `SDL_RenderLine`. Cạnh chung được vẽ hai lần ở bước wireframe, chưa ảnh hưởng kết quả. Tới bài tô kín, ta sẽ giao pixel cạnh chung cho đúng một triangle.

## Ghép các phần lại

Đường đi của một frame là `makeQuad → projectVertex → drawLine → SDL_UpdateTexture → presentFramebuffer`. SDL chỉ nhận ảnh CPU đã vẽ xong. `SDL_SetRenderLogicalPresentation` giữ khung logic 960 × 640 và thêm letterbox khi resize; input được đổi về khung ấy bằng `SDL_ConvertEventToRenderCoordinates`.

```bash title="Terminal — chạy bản đầu tiên có quad"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_20_checkpoint_1
# Windows / Visual Studio
.\build\Debug\project_20_checkpoint_1.exe
# Linux/macOS với generator một cấu hình
./build/project_20_checkpoint_1
```

Thử phím `1` chính diện, `2` nghiêng vừa, `3` nghiêng mạnh; kéo chuột hoặc giữ WASD để quay. Wheel đổi khoảng cách. Các thao tác này chỉ sửa `Scene`; frame sau tạo lại quad từ hình chữ nhật local, nên không tích lũy biến dạng.

## Thử làm sai để hiểu đúng

1. Bỏ phép chia cho Z trong projection. Đỉnh gần/xa không còn tạo chiều sâu; bạn đang nhìn một bản gần orthographic.
2. Chuyển dòng cộng `distance` lên trước phép quay. Tấm bàn sẽ quay quanh camera thay vì quay quanh tâm của nó. Khôi phục thứ tự quay rồi tịnh tiến.
3. Đổi UV ở một góc nhưng không đổi position. Wireframe không đổi: đây là cách nhận ra geometry và thuộc tính ảnh là hai việc khác nhau. Khôi phục UV trước bài sau.
