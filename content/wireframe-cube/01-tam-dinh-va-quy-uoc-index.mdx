# Từ một điểm đến tám đỉnh của cube

## Vấn đề cần giải quyết

Ở Project 12, ba đỉnh đã đủ để vẽ và xoay một tam giác. Với cube, ta có tám đỉnh. Nếu đặt tên từng biến rồi viết riêng từng phép chiếu, rất dễ quên một góc hoặc dùng nhầm tọa độ.

Bài này chưa nối cạnh. Mục tiêu là có **tám vị trí 3D đúng**, đánh số từ 0 đến 7, rồi nhìn thấy ảnh chiếu của chúng. Những chấm này là dữ liệu đầu vào cho toàn bộ các bài sau, không phải một hình vuông 2D vẽ giả chiều sâu.

## Hiểu ý tưởng trước khi viết code

Chọn tâm cube tại local origin. Gọi nửa độ dài cạnh là $h$; mỗi tọa độ chỉ nhận một trong hai giá trị:

$$
x,y,z\in\{-h,+h\},\qquad 2^3=8.
$$

Ta chia tám góc thành hai vòng. Vòng 0–3 nằm ở $z=-h$, vòng 4–7 ở $z=+h$. Hai vòng phải đi cùng thứ tự X/Y để bài sau nối 0–4, 1–5, 2–6, 3–7 mà không bị xoắn.

```text title="Quy ước index — nhìn vào dữ liệu local"
index   X   Y   Z
0       −   −   −
1       +   −   −
2       +   +   −
3       −   +   −
4       −   −   +
5       +   −   +
6       +   +   +
7       −   +   +
```

Không có thứ tự index bắt buộc cho mọi renderer. Đây là quy ước riêng của chương trình, và edge list phải tuân theo nó.

Chọn **Vertex index** để đọc local/world của từng đỉnh. Cam là vòng 0–3, xanh là vòng 4–7. Hai màu giúp phân biệt lớp, không nói rằng lớp nào đang bị che.

## Viết code từng bước

### Bước 1 — Chạy bộ khung kế thừa từ P12

Tải ZIP của project, giải nén rồi mở terminal trong thư mục có `CMakeLists.txt`. Bộ khung đã có `framebuffer.hpp` (pixel/Bresenham), `projection.hpp` (camera nhìn +Z), `rotation.hpp` (sin/cos từ P12), SDL window/texture và vòng lặp. Chưa có cube trong Starter.

```bash title="Terminal — build và mở Starter trên Windows"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_13_starter
./build/Debug/project_13_starter.exe
```

Bạn phải thấy sàn lưới 3D trên bảng logic 1100×800. Resize chỉ letterbox bảng này: ảnh không bị kéo méo, tọa độ world không đổi. Trên generator một cấu hình, executable nằm trực tiếp trong `build/`, không có thư mục `Debug/`.

Các thay đổi dưới đây được thêm vào Starter theo đúng đường dẫn. Nếu muốn đối chiếu, mở `checkpoints/01/`; không cần tự tạo lại window hay event loop.

### Bước 2 — Tạo tám đỉnh, mỗi dòng một index

Trong `include/lab.hpp`, đặt `kCubeVertexCount=8` và alias `CubeVertices` ngay trong namespace `lab`, rồi thêm hàm:

```cpp title="include/lab.hpp — đoạn ghép"
constexpr std::size_t kCubeVertexCount = 8;
using CubeVertices = std::array<Vec3, kCubeVertexCount>;
```

```cpp title="include/lab.hpp — makeCubeVertices"
inline CubeVertices makeCubeVertices(double halfExtent) {
    const double h = std::abs(halfExtent);
    CubeVertices vertices{};
    vertices[0] = {-h, -h, -h};
    vertices[1] = {h, -h, -h};
    vertices[2] = {h, h, -h};
    vertices[3] = {-h, h, -h};
    vertices[4] = {-h, -h, h};
    vertices[5] = {h, -h, h};
    vertices[6] = {h, h, h};
    vertices[7] = {-h, h, h};
    return vertices;
}
```

Dùng `std::array<Vec3, 8>` vì số đỉnh đã biết. Viết từng index giúp nhìn ngay tổ hợp dấu, không cần giải mã bit hay một vòng lặp lồng nhau khi mới học.

Hàm chỉ tạo hình dạng quanh gốc. Nó không biết camera hoặc màn hình; đây là lý do ta có thể tái sử dụng cùng tám điểm để xoay về sau.

### Bước 3 — Đặt cube trước camera

Thêm phép tịnh tiến:

```cpp title="include/lab.hpp — translateCube"
inline CubeVertices translateCube(const CubeVertices& local, Vec3 position) {
    CubeVertices world{};
    for (std::size_t i = 0; i < local.size(); ++i) {
        world[i] = add(local[i], position);
    }
    return world;
}
```

Trong `scene.hpp`, `Scene::position` mặc định là `(0,0,6)`. Hàm `worldCube` lấy local từ `makeCubeVertices(scene.halfExtent)` rồi trả `translateCube(local, scene.position)`.

Với $h=1.2$, đỉnh 0 đi từ $(-1.2,-1.2,-1.2)$ đến $(-1.2,-1.2,4.8)$; đỉnh 6 thành $(1.2,1.2,7.2)$. Z của cả hai lớp đều nằm trong khoảng near=0.5, far=16.

### Bước 4 — Lưu đủ kết quả chiếu, rồi vẽ marker

`ProjectedCube` giữ một `ProjectionResult` cho mỗi index, không chỉ `Vec2`. Ta cần status để biết có thể đọc screen hay không.

```cpp title="include/scene.hpp — đoạn ghép"
struct ProjectedCube {
    std::array<ProjectionResult, kCubeVertexCount> vertices{};
```

```cpp title="include/scene.hpp — projectCube"
inline ProjectedCube projectCube(const CubeVertices& world, const Scene& scene) {
    ProjectedCube projected;
    for (std::size_t i = 0; i < world.size(); ++i) {
        projected.vertices[i] = projectVertex(world[i], scene);
        ++projected.projectionCount;
    }
    return projected;
}
```

Ở bài này, `projectVertex` gọi phép chiếu perspective từ P11. Trong `renderScene`, sau khi vẽ nền, lấy world cube và cache:

```cpp title="include/view.hpp — đoạn ghép"
const CubeVertices world = worldCube(scene);
const ProjectedCube projected = projectCube(world, scene);
stats.vertexProjections = projected.projectionCount;
```

Sau đó duyệt cache để vẽ các marker:

```cpp title="include/view.hpp — đoạn ghép"
for (const auto& vertex : projected.vertices) {
    if (vertex.status == ProjectionStatus::Visible && vertex.screen) {
        disc(image, static_cast<int>(std::lround(vertex.screen->x)), static_cast<int>(std::lround(vertex.screen->y)), 4, kWhite);
    }
}
```

Điều kiện `Visible` và `screen` có giá trị phải được kiểm tra trước khi làm tròn sang số nguyên. Điểm sau camera không biến thành một chấm sai tại góc (0,0).

## Ghép các phần lại

`main.cpp` gọi `renderScene`, dùng `SDL_UpdateTexture` upload `image.pixels` lên SDL texture rồi present. `RenderStats` chuyển số đếm sang HUD; HUD không chiếu tám đỉnh thêm lần nữa.

```bash title="Terminal — chạy checkpoint 1"
cmake --build build --config Debug --target project_13_checkpoint_1
./build/Debug/project_13_checkpoint_1.exe
```

Kết quả là hai lớp bốn chấm. Lớp Z=4.8 ở gần camera nên trải rộng hơn lớp Z=7.2. HUD báo cache bằng 8; native marker đều trắng, còn Canvas dùng màu và nhãn số để dễ đọc dữ liệu.

## Thử làm sai để hiểu đúng

1. Đổi đỉnh 6 thành cùng tọa độ với đỉnh 5. Mảng vẫn có tám phần tử nhưng chỉ còn bảy vị trí khác nhau. Đếm phần tử chưa đủ chứng minh hình học đúng.
2. Đổi `scene.position.z` thành 0. Bốn đỉnh ở sau camera phải bị loại an toàn; không xuất hiện đường hoặc chấm “bắn” vô hạn.
3. Đổi cả hai lớp sang cùng dấu Z. Ở góc nhìn chính diện, các marker chồng lên nhau: bạn đã làm phẳng dữ liệu chứ không phải lỗi SDL.

## Tự kiểm tra kết quả

- Index 0–7 khớp bảng dấu; mỗi tọa độ local có trị tuyệt đối bằng $h$.
- World vertex 0 và 6 khớp hai con số tính tay phía trên.
- Cache chứa tám kết quả; mặc định tám status đều visible.
- Resize giữ tỉ lệ hình; các giá trị local/world không thay đổi.
