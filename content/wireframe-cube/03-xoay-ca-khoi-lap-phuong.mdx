# Xoay hình dạng rồi mới đặt vào world

## Vấn đề cần giải quyết

Cube đã hiện đúng khi đứng yên. Bây giờ ta muốn xoay nó quanh tâm, không phải làm nó bay vòng quanh camera. Sai lầm thường gặp là xoay trực tiếp world vertices hoặc tiếp tục xoay kết quả của frame trước.

Ta dùng lại các hàm quay trực tiếp bằng sin/cos đã viết ở P12. Điểm mới là áp cùng một phép biến đổi lên cả mảng tám đỉnh, còn edge list giữ nguyên.

## Hiểu ý tưởng trước khi viết code

Mỗi frame bắt đầu từ local vertices gốc:

$$
p_{world}=R(p_{local})+t.
$$

$t$ là vị trí tâm cube. Với local origin $(0,0,0)$, phép quay không làm tâm đổi vị trí. Sau khi cộng $t$, tâm nằm đúng tại model position.

Ngược lại, $R(p_{local}+t)$ quay cả vector vị trí. Đó là xoay quanh world origin, không còn là hành vi của model viewer này.

## Viết code từng bước

### Bước 1 — Dùng lại rotation đã hiểu, không thêm thư viện

`rotation.hpp` trong Starter chứa các hàm quay X/Y/Z của P12. Chẳng hạn quay quanh Y:

```cpp title="include/rotation.hpp — rotateY"
inline Vec3 rotateY(Vec3 point, double angle) {
    const double cosine = std::cos(angle);
    const double sine = std::sin(angle);
    return {cosine * point.x + sine * point.z, point.y, -sine * point.x + cosine * point.z};
}
```

Nhìn vào hai dấu sin: +X quay 90° quanh +Y sẽ đi về −Z. Đây là quy ước bàn tay phải của ta, không suy dấu từ việc ảnh trên màn hình đang chạy sang trái hay phải.

`rotateEuler` gọi từng phép theo thứ tự. XYZ nghĩa là X trước, Y tiếp, Z cuối, theo các trục world cố định. Nó không có nghĩa các trục tự quay theo vật; Euler vẫn có tư thế mà hai hướng điều khiển trùng nhau.

### Bước 2 — Quay từng vertex từ local gốc

Thêm vào `lab.hpp`:

```cpp title="include/lab.hpp — rotateCube"
inline CubeVertices rotateCube(const CubeVertices& local, EulerAngles angles, RotationOrder order) {
    CubeVertices rotated{};
    for (std::size_t i = 0; i < local.size(); ++i) {
        rotated[i] = rotateEuler(local[i], angles, order);
    }
    return rotated;
}
```

Cả tám điểm dùng cùng angles/order. Mảng đầu vào là const; không có phép ghi đè world vertices frame trước.

Nếu chỉ quay một vài đỉnh, các cạnh sẽ dài ngắn thất thường. Nếu quay dồn nhiều lần với góc tổng hiện tại, vật quay ngày càng nhanh và sai số tích lũy không cần thiết.

### Bước 3 — Ghép rotation trước translation

Thay `worldCube` của bài trước bằng:

```cpp title="include/scene.hpp — worldCube"
inline CubeVertices worldCube(const Scene& scene) {
    const CubeVertices local = makeCubeVertices(scene.halfExtent);
    const CubeVertices rotated = rotateCube(local, scene.angles, scene.order);
    return translateCube(rotated, scene.position);
}
```

Các bước được tách biến để dễ lần theo: `local` là hình dạng, `rotated` là hình dạng sau quay nhưng vẫn quanh gốc, kết quả trả về mới nằm trong world.

Với local điểm $(1,0,0)$, yaw 90° và $t=(2,0,6)$, đáp án là $(2,0,5)$. Nếu bạn được $(6,0,-3)$ thì đã quay cả vị trí $t$.

### Bước 4 — Cho keyboard đổi tư thế

Trong nhánh `SDL_EVENT_KEY_DOWN`, phím mũi tên đổi góc theo nấc 5°. Đây chỉ là điều khiển góc rời rạc; di chuyển liên tục bằng WASD/QE sẽ được thêm ở bài 5.

```cpp title="src/main.cpp — đổi pitch theo nấc"
const double angleStep = 5.0 * lab::kPi / 180.0;
if (event.key.key == SDLK_UP) {
    scene.angles.pitch = lab::wrapAngle(scene.angles.pitch + angleStep);
    scene.paused = true;
}
```

Nhánh còn lại tương tự cho down/left/right và PageUp/PageDown. `wrapAngle` đưa góc về $[-\pi,\pi]$ chứ không khóa pitch ở ±89°: ta đang xoay object, chưa điều khiển camera FPS.

## Ghép các phần lại

```bash title="Terminal — chạy checkpoint 3"
cmake --build build --config Debug --target project_13_checkpoint_3
./build/Debug/project_13_checkpoint_3.exe
```

Mũi tên lên/xuống đổi pitch, trái/phải đổi yaw; PageUp/Down đổi roll. O chuyển XYZ/ZYX, R đặt lại. Chọn preset “Nhìn chính diện” để về ba góc 0, rồi quay từng trục riêng.

Pipeline sau bài: local → rotate → translate → world → camera → project → cache → edge clip → Bresenham. Topology không có tọa độ để xoay; nó chỉ trỏ vào những điểm đã đổi vị trí.

## Thử làm sai để hiểu đúng

1. Trong `worldCube`, translate trước rồi rotate kết quả. Đặt tâm lệch X: cube bắt đầu chạy vòng quanh gốc world.
2. Chỉ rotate vertex 0. Các cạnh nối với nó biến dạng, dù edge list vẫn đủ 12 phần tử.
3. Cho yaw=90°, pitch=90°, roll=0 rồi đổi O. XYZ và ZYX thường cho tư thế khác; điều này không phải lỗi làm tròn.

## Tự kiểm tra kết quả

- Các local vertex không đổi khi xoay.
- Tâm world vẫn bằng model position ở mọi góc.
- Chiều dài mỗi cạnh vẫn là $2h$; bài cuối sẽ khóa điều này bằng test.
- Cùng một edge list dùng được cho cả hai rotation order.
- Reset trả lại cả position lẫn angles, không chỉ làm cube trông gần giống ban đầu.
