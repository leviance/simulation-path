# Một viên đá nằm ở đâu trong 4.096 ô?

## Vấn đề cần giải quyết

Ở bài trước, vị trí viên đá nằm ngay trong lệnh dựng hình. Bây giờ hãy giữ nguyên hình trên màn hình nhưng thay nguồn dữ liệu: viên đá ở đó vì một ô trong mảng mang giá trị `Stone`. Đến lúc đó ta mới có thể hỏi “ở trên nó là cỏ hay không khí?” mà không cần đọc màu pixel.

## Hiểu ý tưởng trước khi viết code

Một section kích thước 16×16×16 dùng x chạy nhanh nhất, rồi z, rồi y. Nếu đang ở ô `(15,0,0)`, phần tử kế tiếp trong bộ nhớ là `(0,0,1)`, không phải `(16,0,0)`. Cạnh bên phải của ô thuộc về ô kế bên.

## Viết code từng bước

Viên đá đã hiện. Bây giờ ta muốn nó có địa chỉ để về sau hỏi được: “Ở ô này là đá hay không khí?”. Sau bài này hình gần như không đổi; cách kiểm phải nhìn vào dữ liệu.

### Đổi ba tọa độ thành một địa chỉ

Trong `blocks.hpp`, khai báo `Section` gồm 4.096 `Block`. Cho x chạy nhanh nhất: sang phải một ô tăng 1, sang hàng z kế tăng 16, sang tầng y kế tăng 256. Chặn tọa độ ngoài đoạn 0–15 trước khi nhân; nếu không, hai ô khác nhau có thể trỏ vào cùng vị trí.

{/* snippet include/trail/blocks.hpp#local-index */}

```cpp title="include/trail/blocks.hpp — Xoá nhập nhằng giữa địa chỉ world và local"
inline int localIndex(int x, int y, int z) {
    if (x < 0 || x >= side || y < 0 || y >= side || z < 0 || z >= side) {
        throw std::out_of_range("cell outside section");
    }
    return x + side * (z + side * y);
}
```

### Tách tọa độ world khi đi qua gốc

Cũng trong tệp này, lấy thương làm tròn xuống rồi tính local bằng phần còn lại. Thử nói bằng lời: ô ngay bên trái gốc là ô cuối của chunk bên trái. Nó phải ra chunk −1, local 15, không phải chunk 0, local −1.

{/* snippet include/trail/blocks.hpp#split-coordinate */}

```cpp title="include/trail/blocks.hpp — Đi sang phía âm của gốc"
struct Address {
    int chunk, local;
};
inline Address splitCoordinate(int world) {
    const int chunk = static_cast<int>(std::floor(static_cast<double>(world) / side));
    const int local = world - chunk * side;
    return {chunk, local};
}
```

### Cất viên đá rồi đọc nó ra

Thêm `Column` vào `bank.hpp`: `get` chọn section bằng `y / side`, còn `y % side` chọn tầng trong section. `singleStone()` tạo cột rỗng và `put` đúng một lần. Trong `Scene`, giữ cột làm dữ liệu; ở `generate` dùng `singleStone()`, xóa mesh tạm rồi gọi `appendCube` với vật liệu lấy từ `column.get(7, 7, 7)`. Không vẽ chồng viên thứ hai.

## Ghép các phần lại

Bạn vẫn thấy một viên đá, không phải hai. Tạm đổi vật liệu trong `singleStone()` sang `Block::Sand`: cùng chỗ ấy phải đổi sang màu cát. Trả lại `Stone`. Đây mới là bằng chứng hình trên màn hình thực sự đọc từ cột.

```bash title="Terminal — chạy bản bạn vừa viết"
cmake --build build-work --config Release --target project_58_work --parallel 1
.\build-work\Release\project_58_work.exe
```

## Thử làm sai để hiểu đúng

Bỏ kiểm biên rồi thử `localIndex(16,0,0)` và `localIndex(0,0,1)`. Hai ô khác tên nhưng cùng giá trị; thêm số phần tử vào mảng không sửa được lỗi này.

## Tự kiểm tra kết quả

4096 tọa độ khác nhau có 4096 index khác nhau. Kiểm thêm x = −17, −16, −1, 0, 15, 16. Kích thước hoặc góc nhìn cửa sổ không được đổi bất kỳ kết quả nào.
