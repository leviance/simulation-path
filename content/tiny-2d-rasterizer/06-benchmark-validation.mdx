# Kiểm chứng rồi mới đo tốc độ

## Vấn đề cần giải quyết

Ứng dụng đã có các hình, nhưng một ảnh đẹp chưa chứng minh thuật toán đúng. Một vài đường chéo dễ che lỗi ở hướng khác; đường tròn lớn dễ che một điểm chéo sai; benchmark có thể trông nhanh chỉ vì không thực sự dùng những pixel vừa tính.

Bài này hoàn thiện ba việc: có đáp án để kiểm hình học, có bảng hình mẫu để quan sát toàn bộ công cụ, và có một phép đo DDA/Bresenham đủ rõ để người khác lặp lại.

## Hiểu ý tưởng trước khi viết code

Một đường hợp lệ cần giữ hai đầu, đúng số pixel theo trục dài, liên thông và gần đường lý tưởng. Đó là những điều có thể kiểm độc lập mà không sao chép vòng lặp Bresenham vào test.

Khoảng cách vuông góc từ pixel P tới đường qua A/B:

$$
\delta =
\frac{|d_y(P_x-A_x)-d_x(P_y-A_y)|}
{\sqrt{d_x^2+d_y^2}}
$$

Đoạn dài 0 phải kiểm riêng trước phép chia. Những trường hợp đang xét dùng ngưỡng 0,500001 pixel để chừa một dung sai nhỏ cho tính toán double.

Không bắt buộc DDA và Bresenham, hoặc hai chiều của cùng một đoạn, cho cùng tập pixel khi đường nằm giữa hai lựa chọn. So sự khác nhau không đồng nghĩa đã tìm được lỗi.

## Viết code từng bước

### Bước 1 — Viết phép kiểm vẫn chạy ở Release

tests/tests.cpp include view.hpp và benchmark.hpp, nên nó gọi đúng các hàm mà app sử dụng. Hàm check không dựa vào assert:


```cpp title="tests/tests.cpp — ghi nhận lỗi mà không phụ thuộc NDEBUG"
void check(bool condition, std::string_view label) {
    if (condition) {
        return;
    }
    if (failures < 20) {
        std::cerr << "FAILED: " << label << '\n';
    }
    ++failures;
}
```

Cuối main, failures khác 0 trả EXIT_FAILURE; thành công trả EXIT_SUCCESS. CTest nhận được trạng thái thật ở cả Debug và Release. Giới hạn 20 dòng log chỉ để một lỗi lặp không tạo hàng nghìn dòng; bộ đếm vẫn ghi nhận tất cả lỗi.

Đây là phép kiểm đường thẳng:


```cpp title="tests/tests.cpp — đáp án hình học độc lập cho một đường"
void checkLine(const std::vector<lab::LineStep>& steps, lab::Point start, lab::Point end) {
    check(!steps.empty(), "valid line has pixels");
    if (steps.empty()) {
        return;
    }
    check(steps.front().point == start, "line keeps start");
    check(steps.back().point == end, "line keeps end");
    const int dx = end.x - start.x;
    const int dy = end.y - start.y;
    const int expectedCount = std::max(std::abs(dx), std::abs(dy)) + 1;
    check(steps.size() == static_cast<std::size_t>(expectedCount), "major axis determines count");
    const double length = std::hypot(static_cast<double>(dx), static_cast<double>(dy));
    for (std::size_t index = 0; index < steps.size(); ++index) {
        const lab::Point point = steps[index].point;
        if (length > 0.0) {
            const double cross = static_cast<double>(dy) * (point.x - start.x) - static_cast<double>(dx) * (point.y - start.y);
            check(std::abs(cross) / length <= 0.500001, "pixel stays close to ideal line");
        }
        if (index == 0) {
            continue;
        }
        const lab::Point previous = steps[index - 1].point;
        const int distanceX = std::abs(point.x - previous.x);
        const int distanceY = std::abs(point.y - previous.y);
        check(std::max(distanceX, distanceY) == 1, "neighbor pixels are connected and unique");
    }
}
```

testLines duyệt X/Y từ −24 tới 24 quanh một gốc dịch chuyển: **2.401 trường hợp**, mỗi trường hợp kiểm DDA/Bresenham ở cả hai chiều. Nó còn có đáp án error/e2 cụ thể, làm tròn số âm và các đầu vào bị từ chối.

Khoảng cách đúng không đủ nếu thiếu đầu mút; hai đầu đúng không đủ nếu có lỗ ở giữa. Vì vậy cần nhiều tiêu chí cùng lúc, không chọn một tiêu chí tiện nhất.

### Bước 2 — Kiểm các primitive còn lại và đường đi của input

Bộ test còn bao gồm:

- **544 kích thước rectangle**: 32 độ rộng × 17 độ cao. Đáp án độc lập xét pixel nằm trên bốn biên hoặc trong toàn vùng; kiểm cả đảo/cắt chéo thứ tự hai góc và không trùng pixel.
- **129 bán kính circle**, từ 0 tới 128 tại tâm dịch chuyển: bốn điểm ngoài cùng, đối xứng, độ lệch bán kính tối đa 0,55 và không trùng. Hình đặc chứa viền, mỗi hàng liên tục. Bán kính 1/2 có số đếm cụ thể để kiểm nhánh decision = 0.
- **Ảnh thật**: fillRect ghi 12 ô, fillCircle ở góc ảnh còn tám ô; putPixel không ghi ngoài biên; inspector đọc đúng màu CPU.
- **Trạng thái kéo thật**: vị trí chỉ có ở up vẫn được nhận; hover không kéo tiếp; lần kéo đang có không bị chiếm; ra ngoài ảnh kết thúc kéo; bán kính bị giới hạn đúng.
- **Giới hạn dữ liệu**: từ chối số rất lớn trước abs/phép đổi int/cấp phát, không thử bằng một vòng lặp vô hạn.

Đáp án rectangle không gọi lại Bresenham. Test dùng hai `std::set<Point>` là expectedFill và expectedOutline, duyệt mọi X/Y trong hình bao từ first tới second. Trong mỗi ô, phần quyết định là:


```cpp title="tests/tests.cpp — tạo đáp án viền độc lập"
expectedFill.insert({x, y});
if (x == first.x || x == second.x || y == first.y || y == second.y) {
    expectedOutline.insert({x, y});
}
```

Các hàm test đầy đủ nằm trong phần mã cuối trang và ZIP; không có một phiên bản mô hình rút gọn chỉ dùng để làm test xanh.

### Bước 3 — Chuẩn bị dữ liệu trước vùng đo

include/benchmark.hpp tạo 20.000 đoạn trong phạm vi ảnh bằng seed cố định:


```cpp title="include/benchmark.hpp — bộ dữ liệu đầu vào lặp lại được"
inline std::vector<Segment> benchmarkData(int count) {
    std::uint32_t seed = 0x2D04u;
    const auto next = [&seed]() {
        seed = seed * 1664525u + 1013904223u;
        return seed;
    };
    std::vector<Segment> segments;
    for (int index = 0; index < count; ++index) {
        const Point start{static_cast<int>(next() % 960u), static_cast<int>(next() % 540u)};
        const Point end{static_cast<int>(next() % 960u), static_cast<int>(next() % 540u)};
        segments.push_back({start, end});
    }
    return segments;
}
```

Cả hai thuật toán nhận cùng vector segments, không tự sinh dữ liệu riêng. Một bộ dữ liệu cố định không đại diện cho mọi ứng dụng; nó giúp tái hiện phép đo. Khi đổi phân bố độ dài/hướng, phải ghi rõ đó là một phép thử khác.

Trước bảy lượt chính, harness chạy tối đa 500 đoạn để làm nóng. Mỗi lượt đổi thuật toán chạy trước: DDA rồi Bresenham, lượt sau đảo lại. Làm vậy giảm một loại thiên lệch thứ tự, không loại hết ảnh hưởng của cache, CPU boost hoặc hệ điều hành.

### Bước 4 — Buộc kết quả pixel được sử dụng


```cpp title="include/benchmark.hpp — đọc cả tọa độ chứ không chỉ số phần tử"
inline std::uint64_t consumePixels(const std::vector<LineStep>& steps, std::uint64_t checksum) {
    for (const LineStep& step : steps) {
        checksum ^= static_cast<std::uint32_t>(step.point.x);
        checksum *= 1099511628211ull;
        checksum ^= static_cast<std::uint32_t>(step.point.y);
        checksum *= 1099511628211ull;
    }
    return checksum;
}
```

Nếu chỉ cộng vector.size(), ta chỉ quan sát độ dài. Ở đây mọi X/Y đi vào checksum được in cuối phép đo; các pixel giữa đoạn không thể trở thành dữ liệu vô dụng chỉ vì không đưa lên SDL.

Checksum không chứng minh hình học đúng và có thể có va chạm. Nó bảo đảm phép đo sử dụng tọa độ; correctness vẫn dựa vào các test riêng. Cũng **không bắt buộc checksum DDA bằng Bresenham**, vì quy tắc chọn pixel ở trường hợp hòa có thể khác.

Trong measureBatch, algorithm được chọn từ algorithmIndex (0 là DDA, 1 là Bresenham). checksum lấy từ kết quả đã lưu; benchmark.cursor và end xác định đợt đang chạy, tối đa 128 đoạn. Phần nằm giữa hai lần đọc đồng hồ là:


```cpp title="include/benchmark.hpp — đo rasterization và tiêu thụ kết quả"
const auto begin = std::chrono::steady_clock::now();
for (std::size_t index = benchmark.cursor; index < end; ++index) {
    const Segment& segment = benchmark.segments[index];
    const auto steps = lineSteps(segment.start, segment.end, algorithm);
    checksum = consumePixels(steps, checksum);
}
const auto elapsed = std::chrono::steady_clock::now() - begin;
```

Đồng hồ steady_clock bao quanh việc tạo vector LineStep, rasterize và hash. Sinh segments, thao tác SDL và thời gian giữa các đợt không nằm trong vùng này. Vì vậy đây không phải thời gian thuần của phép cộng/chia, cũng không phải FPS.

Sau đoạn này, hàm lưu checksum và cộng elapsed, đổi sang millisecond, vào ô milliseconds[algorithmIndex][round]. Đợt làm nóng chỉ cập nhật warmupChecksum, không cộng vào thời gian đo. Toàn bộ measureBatch ở phần mã cuối trang thể hiện cả phần chọn đầu vào và lưu kết quả này.

### Bước 5 — Trả quyền cho event loop sau mỗi đợt


```cpp title="include/benchmark.hpp — lập lịch phép đo hữu hạn"
inline void advanceBenchmark(Benchmark& benchmark) {
    if (!benchmark.active) {
        return;
    }
    const auto age = std::chrono::steady_clock::now() - benchmark.started;
    if (age > std::chrono::seconds(30)) {
        benchmark.active = false;
        return;
    }
    std::size_t limit = benchmark.segments.size();
    if (benchmark.warming) {
        limit = std::min(limit, std::size_t(500));
    }
    const std::size_t end = std::min(benchmark.cursor + 128, limit);
    int first = benchmark.round % 2;
    measureBatch(benchmark, first, end);
    measureBatch(benchmark, 1 - first, end);
    benchmark.cursor = end;
    if (benchmark.cursor < limit) {
        return;
    }
    benchmark.cursor = 0;
    if (benchmark.warming) {
        benchmark.warming = false;
        return;
    }
    ++benchmark.round;
    if (benchmark.round == Benchmark::rounds) {
        benchmark.active = false;
        benchmark.complete = true;
    }
}
```

Mỗi lần gọi xử lý tối đa 128 đoạn cho mỗi thuật toán rồi trả về main. Event loop tiếp tục nhận input và present giữa các đợt; T lần nữa hủy phép đo, Escape thoát app.

milliseconds lưu tổng thời gian các đợt của từng lượt. Sau bảy lượt, median lấy số giữa của bảy tổng ấy, không phải median của từng đợt. Thời gian thực từ lúc nhấn T tới khi xong thường dài hơn vì có cả input/render/nghỉ giữa các lần gọi.

Nếu quá 30 giây, active về false nhưng complete vẫn false. Chương trình phải báo chưa hoàn thành và **không công bố median**. Đây là giới hạn an toàn, không phải cách bỏ những mẫu chậm rồi vẫn báo đạt.

### Bước 6 — Chạy bản hoàn chỉnh và ghi nhận đúng loại bằng chứng

```bash title="Terminal — build tất cả checkpoint và kiểm cả hai cấu hình"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --parallel 2
ctest --test-dir build -C Debug --output-on-failure --timeout 30
cmake --build build --config Release --parallel 2
ctest --test-dir build -C Release --output-on-failure --timeout 30
```

Với Ninja/Makefiles, dùng thư mục build riêng và CMAKE_BUILD_TYPE tương ứng. Không mở thêm một lượt build khác trong khi lượt này đang chạy.

```bash title="Terminal — ứng dụng và benchmark không cần window"
.\build\Release\project_4_final.exe
.\build\Release\project_4_final.exe --benchmark
```

Bản final có 1: Line, 2: Rectangle, 3: Circle, 4: bảng hình mẫu. Bảng này dùng chính drawLine/drawRect/fillRect/drawCircle/fillCircle, không phải ảnh dựng sẵn. Z ẩn/hiện zoom; F đổi viền/đặc; D/B chọn thuật toán line; [/] đổi bán kính. Các điều khiển kéo/phím của bài trước vẫn hoạt động.

T chạy cùng benchmark như --benchmark nhưng theo từng đợt trong event loop. Hãy đo Release, đọc số đoạn/lượt, đơn vị ms, phạm vi đo và checksum; lưu nhiều lần chạy nếu muốn so. Kết quả trên một máy không chứng minh Bresenham luôn nhanh hơn trong mọi chương trình.

```bash title="Terminal — kiểm đường hiển thị SDL hữu hạn"
.\build\Debug\project_4_final.exe --smoke
```

Smoke mở window ẩn, chạy 12 frame, đổi tool/kiểu tô, resize, upload/present rồi thoát. Khi tự động hóa, luôn đặt timeout ngoài 15 giây để bảo vệ cả trường hợp driver kẹt. Smoke không nhận chuột vật lý, không thay thế kiểm tra thao tác desktop.

## Ghép các phần lại

Bộ công cụ cuối cùng có hình học thuần, các hàm ghi ảnh, trạng thái thao tác, inspector đọc ảnh thật và một benchmark hữu hạn. CMake dùng C++20/SDL 3.4.8; ZIP gồm starter, sáu checkpoint, final và tests độc lập.

Sau khi CTest qua, thử riêng trên desktop: kéo cả hai tay nắm; chọn đủ công cụ; F/[ và ]; Z/Left/Right; resize khác tỉ lệ, mất focus, rời vùng ảnh và thử HiDPI nếu có. Nhấn 4 để quan sát bảng hình mẫu, rồi T để xác nhận ứng dụng vẫn nhận lệnh hủy.

Ghi ba loại kết quả riêng: kiểm CPU, smoke SDL, thao tác desktop. Không lấy một loại để tuyên bố cả ba đã đạt.

## Thử làm sai để hiểu đúng

1. Xóa một tọa độ ở giữa vector line nhưng giữ hai đầu. Kiểm tra số lượng/liên thông phải báo lỗi dù ảnh lớn có thể khó nhận ra khe nhỏ.
2. Đổi consumePixels thành chỉ đọc size. Bạn sẽ không còn phát hiện việc một pixel giữa đoạn đổi tọa độ mà số lượng giữ nguyên; kiểm checksum riêng trong tests phải báo lỗi.
3. Chuyển benchmarkData vào giữa hai lần đọc đồng hồ. Số đo giờ bao gồm sinh dữ liệu, không còn là phạm vi đã công bố.
4. Bỏ kiểm complete trước khi in median. Hủy bằng T; nếu vẫn xuất một kết quả “đầy đủ”, báo cáo đã dùng các lượt chưa hoàn thành.
