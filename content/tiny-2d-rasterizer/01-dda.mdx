# Vẽ đường thẳng đầu tiên bằng DDA

## Vấn đề cần giải quyết

Ở Mini Paint, bạn đã nối những mẫu chuột bằng nhiều dấu bút. Bây giờ ta cần một công cụ khác: đưa vào hai điểm A, B và nhận lại **một chuỗi pixel rộng một ô**, đại diện cho đoạn thẳng giữa chúng.

Đừng bắt đầu bằng việc học thuộc DDA. Trước hết, hãy mở được một cửa sổ nền trống; sau đó tự tính một đoạn ngắn, viết hàm tạo pixel và đưa kết quả ấy lên đúng cửa sổ đó. Kết thúc bài, checkpoint 1 sẽ có một đường xanh cố định từ A(220,270) tới B(740,150).

## Hiểu ý tưởng trước khi viết code

Pixel được đánh chỉ số bằng số nguyên. Còn điểm trên đoạn thẳng có thể nằm giữa hai ô. DDA giải quyết việc này theo hai bước: lấy những điểm cách đều trên đoạn, rồi làm tròn từng tọa độ.

Nếu A = (0,0), B = (7,3), ta cần đi qua bảy cột. Chọn bảy bước, không phải ba, để không bỏ cột nào:

$$
n = \max(|d_x|, |d_y|),\qquad
t_i = \frac{i}{n},\qquad
P_i = A + t_i(B-A)
$$

Với i chạy từ 0 đến n, có n + 1 điểm. Bảng dưới là kết quả cần tự tính được:

| i | X liên tục | Y liên tục | Pixel |
|---:|---:|---:|---|
| 0 | 0 | 0 | (0,0) |
| 1 | 1 | 0,429 | (1,0) |
| 2 | 2 | 0,857 | (2,1) |
| 3 | 3 | 1,286 | (3,1) |
| 4 | 4 | 1,714 | (4,2) |
| 5 | 5 | 2,143 | (5,2) |
| 6 | 6 | 2,571 | (6,3) |
| 7 | 7 | 3 | (7,3) |

Với đường dốc cao, Y sẽ là trục đi từng ô; công thức không đổi. Nếu hai đầu trùng nhau, n = 0: kết quả là một pixel, không được chia cho n.

Trong mô phỏng, đỏ là đoạn lý tưởng, trắng là pixel ở bước đang xét. Chọn một bước, đọc tọa độ liên tục bên dưới rồi thử tự làm tròn trước khi nhìn ô trắng. Mô phỏng dùng lưới nhỏ để dễ đếm; chương trình C++ vẫn có ảnh 960 × 540.

## Viết code từng bước

### Bước 1 — Chạy bộ khung trước khi thêm thuật toán

Giải nén ZIP của Project 04, mở terminal tại thư mục có CMakeLists.txt:

```bash title="Terminal — build và chạy starter bằng Visual Studio"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_4_starter --parallel 2
.\build\Debug\project_4_starter.exe
```

Bạn phải thấy nền xanh đen, resize được, thoát được bằng Escape hoặc nút đóng. Nếu chưa đạt, hãy sửa phần SDL trước. DDA không thể chữa một texture chưa được hiển thị.

Starter đã có Framebuffer trong include/framebuffer.hpp, phần texture trong include/presentation.hpp và event loop trong src/main.cpp. Ảnh logic luôn là 960 × 540; SDL dùng letterbox để giữ tỉ lệ khi đổi kích thước window. Hàm ghi pixel vẫn là kiến thức Project 01:


```cpp title="include/framebuffer.hpp — ghi đúng một ô của ảnh CPU"
void putPixel(int x, int y, std::uint32_t color) {
    if (x < 0 || y < 0 || x >= width || y >= height) {
        return;
    }
    const std::size_t index = static_cast<std::size_t>(y) * width + x;
    pixels[index] = color;
}
```

Kiểm tra biên khi x, y còn là int. Sau đó mới đổi Y sang size_t và tính chỉ số row-major. Những pixel hình học nằm ngoài ảnh sẽ không được ghi; đây là kiểm tra vùng nhớ, **không phải** thuật toán cắt đoạn thẳng.

### Bước 2 — Mô tả một điểm và một bước DDA

Tạo hai kiểu trong namespace lab của include/lab.hpp:


```cpp title="include/lab.hpp — tọa độ pixel"
struct Point {
    int x{};
    int y{};
    friend bool operator==(Point, Point) = default;
};
```


```cpp title="include/lab.hpp — pixel và tọa độ trước khi làm tròn"
struct LineStep {
    Point point{};
    double x{};
    double y{};
};
```

Point chứa chỉ số ô. LineStep giữ thêm x, y dạng double để sau này inspector có thể trả lời: “Vì sao bước này chọn ô đó?”. Đây là dữ liệu quan sát, không phải tọa độ window.

Hàm validPoint ngay trước LineStep giới hạn mỗi tọa độ trong ±4.096. Hợp đồng này đủ rộng cho bảng vẽ 960 × 540, đồng thời ngăn phép trừ/abs bị tràn và ngăn một đầu vào rất lớn tạo hàng triệu bản ghi. Giá trị ngoài hợp đồng bị từ chối bằng kết quả rỗng, không bị ép thành một đường khác.

### Bước 3 — Viết trọn hàm DDA

Trong cùng header, thêm hàm dưới đây. Nó cần algorithm, cmath và vector:


```cpp title="include/lab.hpp — toàn bộ hàm dda"
inline std::vector<LineStep> dda(Point start, Point end) {
    if (!validPoint(start) || !validPoint(end)) {
        return {};
    }
    const int dx = end.x - start.x;
    const int dy = end.y - start.y;
    const int steps = std::max(std::abs(dx), std::abs(dy));
    if (steps == 0) {
        LineStep step;
        step.point = start;
        step.x = start.x;
        step.y = start.y;
        return {step};
    }

    std::vector<LineStep> output;
    output.reserve(static_cast<std::size_t>(steps) + 1);
    for (int index = 0; index <= steps; ++index) {
        const double t = static_cast<double>(index) / static_cast<double>(steps);
        LineStep step;
        step.x = start.x + static_cast<double>(dx) * t;
        step.y = start.y + static_cast<double>(dy) * t;
        step.point = {static_cast<int>(std::lround(step.x)), static_cast<int>(std::lround(step.y))};
        output.push_back(step);
    }
    return output;
}
```

Hàm nằm trong namespace lab; khi gọi từ bên ngoài, tên đầy đủ là `lab::dda`. Các helper trong view.hpp đã ở cùng namespace nên gọi `dda` trực tiếp.

Đọc theo thứ tự:

- dx, dy giữ cả độ lớn lẫn hướng; max của hai trị tuyệt đối chọn số bước.
- Đoạn dài 0 trả ngay một bản ghi, trước mọi phép chia.
- reserve chỉ chuẩn bị dung lượng, chưa tạo phần tử. push_back mới thêm từng bước.
- Hai phép static_cast sang double làm t là phép chia số thực, không phải phép chia số nguyên.
- lround làm tròn nửa đơn vị ra xa 0: −0,5 thành −1. Ép kiểu trực tiếp sang int chỉ cắt phần lẻ, không thay thế được quy tắc đó.
- Vòng lặp lấy cả index = steps, nên có đúng n + 1 điểm và giữ điểm cuối.

Ta tính lại từ A và t ở mỗi bước, thay vì cộng dồn một lượng nhỏ vào X/Y. Bài tập cuối sẽ cho bạn so hai cách này.

### Bước 4 — Ghi danh sách bước vào framebuffer

Thêm phần sau trong include/drawing.hpp:


```cpp title="include/drawing.hpp — vẽ dữ liệu DDA qua putPixel"
inline void plotSteps(Framebuffer& framebuffer, const std::vector<LineStep>& steps, std::uint32_t color) {
    for (const LineStep& step : steps) {
        framebuffer.putPixel(step.point.x, step.point.y, color);
    }
}

inline void drawLine(Framebuffer& framebuffer, Point start, Point end, std::uint32_t color) {
    plotSteps(framebuffer, dda(start, end), color);
}
```

plotSteps không tính hình học. Nó chỉ lấy point của mỗi bản ghi và ghi màu. drawLine ghép hai việc: tính danh sách bằng dda, rồi vẽ danh sách ấy. Không có API vẽ đường của SDL ở đây.

Để không phải tính DDA thêm một lần chỉ cho inspector, màn hình chính giữ vector vừa tính trong SceneFrame. Bản checkpoint 1 trong include/view.hpp là:


```cpp title="include/view.hpp — ghép DDA vào cảnh đang hiển thị"
inline SceneFrame renderScene(Framebuffer& framebuffer, Scene& scene) {
    framebuffer.clear(kBackground);
    SceneFrame frame;
        frame.line = dda(scene.a, scene.b);
        plotSteps(framebuffer, frame.line, kLineColor);
        for (const LineStep& step : frame.line) {
            frame.points.push_back(step.point);
        }

    return frame;
}
```

Scene giữ A/B; SceneFrame giữ kết quả của lần vẽ hiện tại. points là danh sách tọa độ dành cho inspector các bài sau; line giữ thêm dữ liệu DDA.

Khác với Mini Paint, cảnh ở đây được **dựng lại từ hình học**. Khi A/B thay đổi, ta xóa ảnh cũ rồi vẽ lại. Với Paint, tranh chính là dữ liệu cần giữ; ở đây A/B mới là dữ liệu cần giữ.

### Bước 5 — Đưa ảnh mới lên cửa sổ

Trong main, phần khởi tạo SDL giữ nguyên. Khi dirty bằng true, chương trình gọi renderScene rồi chép ảnh sang texture:


```cpp title="src/main.cpp — vẽ lại khi hình học thay đổi"
if (dirty) {
    frame = lab::renderScene(framebuffer, scene);
    if (!lab::uploadFramebuffer(texture, framebuffer)) {
        std::cerr << "SDL_UpdateTexture: " << SDL_GetError() << '\n';
        failed = true;
        break;
    }
    updateTitle(window, scene, frame);
    dirty = false;
}
```

uploadFramebuffer gọi SDL_UpdateTexture với pitch bằng 960 × sizeof(uint32_t). Sau khối này, presentFramebuffer xóa render target, vẽ texture và present. SDL_RenderClear không thay đổi vector chứa ảnh CPU.

dirty chỉ yêu cầu tạo lại ảnh khi dữ liệu thay đổi, không phải mỗi lần window cần present. Bài này A/B cố định nên chỉ cần rasterize ở lần đầu.

Build và chạy phần vừa học:

```bash title="Terminal — chạy checkpoint 1"
cmake --build build --config Debug --target project_4_checkpoint_1 --parallel 2
.\build\Debug\project_4_checkpoint_1.exe
```

## Ghép các phần lại

A/B trong Scene → dda tạo vector LineStep → plotSteps ghi framebuffer → SDL_UpdateTexture chép ảnh → renderer hiển thị texture. Thuật toán không cần include SDL, nên có thể kiểm thử riêng mà không mở window.

Đừng chỉ nhìn đường dài mặc định. Đổi A/B trong include/scene.hpp lần lượt thành đoạn ngang, dọc, dốc cao và một điểm, rồi build lại checkpoint 1. Phần mã hoàn chỉnh ở cuối trang gồm cả main và các header; bạn không cần tự đoán những dòng nối giữa các đoạn trích.

## Thử làm sai để hiểu đúng

1. Đổi max thành min khi tính steps. Với đoạn (0,0) → (7,3), chỉ còn ba bước, nhiều cột không được lấy mẫu. Hoàn tác trước thử nghiệm tiếp theo.
2. Đổi `index <= steps` thành `index < steps`. Kiểm tra vector trong debugger: B biến mất vì không còn lần lặp t = 1.
3. Bỏ static_cast khi chia index / steps. Hầu hết t trở thành 0; nhiều bản ghi cùng nằm ở A.
4. Thay lround bằng ép int. Thử (0,−1) → (2,0): điểm giữa có Y = −0,5 sẽ bị chọn sai theo quy tắc làm tròn đã thống nhất.

## Tự kiểm tra kết quả

- Starter chạy được trước khi thêm DDA; checkpoint 1 hiển thị đường xanh thật.
- Đoạn (0,0) → (7,3) cho đúng tám pixel trong bảng.
- Đường ngang, dọc, dốc cao/thấp và đảo chiều đều giữ hai đầu, không nhảy quá một ô trên mỗi trục.
- Hai đầu trùng nhau tạo một điểm; đầu vào ngoài ±4.096 bị từ chối trước phép trừ.
- Bạn chỉ được nơi tính hình học, nơi ghi framebuffer và nơi gọi SDL_UpdateTexture.
