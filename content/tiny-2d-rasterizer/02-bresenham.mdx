# Chọn pixel bằng sai số nguyên

## Vấn đề cần giải quyết

DDA đã vẽ được đoạn thẳng, nhưng mỗi bước phải tính tọa độ số thực rồi làm tròn. Có cách nào chỉ dùng cộng, trừ và so sánh số nguyên mà vẫn chọn được một chuỗi pixel sát đoạn lý tưởng không?

Bresenham làm được điều đó bằng cách giữ lại một giá trị qua các bước. Trước khi xem vòng lặp tổng quát, ta sẽ hiểu một lựa chọn rất nhỏ: **cột tiếp theo dùng hàng hiện tại hay hàng bên dưới?**

Checkpoint 2 giữ nguyên window, framebuffer và hai điểm của bài trước. Bạn chỉ thêm một thuật toán, rồi dùng D/B để so chúng trên cùng chương trình.

## Hiểu ý tưởng trước khi viết code

Xét A(0,0) → B(7,3). X tăng nhiều hơn Y. Tại cột X = 1, đường lý tưởng có Y = 3/7, nhỏ hơn 0,5 nên chọn (1,0). Tại cột X = 2, Y = 6/7 đã vượt nửa ô nên chọn (2,1).

Một cách kiểm là thay trung điểm giữa hai ứng viên vào hàm đường thẳng:

$$
G(x,y)=d_y(x-A_x)-d_x(y-A_y)
$$

Với đường đi sang phải/xuống đang xét, dx và dy trong công thức hình học đều dương. G bằng 0 tại A. Ta giữ một đại lượng tương đương, gọi là error:

$$
e=d_x-d_y-G(x,y)
$$

Vì vậy, tại A, error bắt đầu bằng dx − dy. Khi X tăng một, G tăng dy nên error giảm dy. Khi Y tăng một, G giảm dx nên error tăng dx. Đó chính là hai phép cập nhật trong vòng lặp, không phải hai hằng số được chọn theo kinh nghiệm.

Để chọn bước Y ở cột kế tiếp, xét trung điểm (x+1,y+1/2). Đường đã vượt nửa ô khi:

$$
G(x+1,y+1/2)\geq 0
\quad\Longleftrightarrow\quad 2e\leq d_x
$$

Đổi vai hai trục, phép thử trung điểm (x+1/2,y+1) cho điều kiện bước X:

$$
G(x+1/2,y+1)\leq 0
\quad\Longleftrightarrow\quad 2e\geq -d_y
$$

Code dưới dùng cách đặt tên hơi khác để gộp hai công thức: dx không âm, còn dy lưu **âm của độ thay đổi Y**. Vì vậy error ban đầu thành dx + dy, điều kiện bước X là `e2 >= dy`, bước Y là `e2 <= dx`. Hướng đi được giữ riêng trong stepX/stepY, nên khi đảo hướng vẫn dùng cùng hai phép thử.

Đừng hiểu error là khoảng cách từ pixel tới đường theo đơn vị pixel; đó là biến quyết định vừa suy ra từ G.

Với đoạn (0,0) → (7,3), dx = 7, dy = −3:

| Pixel hiện tại | error trước bước | e2 = 2 × error | Trục sẽ đi |
|---|---:|---:|---|
| (0,0) | 4 | 8 | X |
| (1,0) | 1 | 2 | X và Y |
| (2,1) | 5 | 10 | X |
| (3,1) | 2 | 4 | X và Y |
| (4,2) | 6 | 12 | X |
| (5,2) | 3 | 6 | X và Y |
| (6,3) | 7 | 14 | X |
| (7,3) | 4 | 8 | Dừng |

Hai phép thử là `e2 >= dy` và `e2 <= dx`. Chúng cùng đọc **error ở đầu bước**. Chẳng hạn tại (1,0), cả hai đúng nên bước tiếp theo là (2,1).

## Viết code từng bước

### Bước 1 — Bổ sung dữ liệu để giải thích mỗi quyết định

Trong include/lab.hpp, LineStep có thêm các trường số nguyên và hai cờ:


```cpp title="include/lab.hpp — dữ liệu bước dùng chung cho DDA và Bresenham"
struct LineStep {
    Point point{};
    double x{};
    double y{};
    int error{};
    int doubledError{};
    bool movesX{};
    bool movesY{};
};
```

DDA vẫn dùng point/x/y; Bresenham dùng point/error/doubledError/movesX/movesY. Những trường không cần dùng được khởi tạo bằng 0 hoặc false.

Mỗi bản ghi mô tả trạng thái **trước khi di chuyển sang pixel tiếp theo**. Bản ghi cuối giữ B và hai cờ false. Vì vậy inspector không báo rằng thuật toán còn bước tiếp sau khi đã tới đích.

### Bước 2 — Viết toàn bộ Bresenham


```cpp title="include/lab.hpp — vòng lặp Bresenham duy nhất"
inline std::vector<LineStep> bresenham(Point start, Point end) {
    if (!validPoint(start) || !validPoint(end)) {
        return {};
    }
    int x = start.x;
    int y = start.y;
    const int dx = std::abs(end.x - start.x);
    const int dy = -std::abs(end.y - start.y);
    int stepX = -1;
    int stepY = -1;
    if (start.x < end.x) {
        stepX = 1;
    }
    if (start.y < end.y) {
        stepY = 1;
    }
    int error = dx + dy;

    std::vector<LineStep> output;
    output.reserve(static_cast<std::size_t>(std::max(dx, -dy)) + 1);
    for (;;) {
        LineStep step;
        step.point = {x, y};
        step.error = error;
        step.doubledError = 2 * error;
        if (x == end.x && y == end.y) {
            output.push_back(step);
            break;
        }

        // Hai quyết định đều đọc error của đầu bước, trước mọi cập nhật.
        step.movesX = step.doubledError >= dy;
        step.movesY = step.doubledError <= dx;
        output.push_back(step);
        if (step.movesX) {
            error += dy;
            x += stepX;
        }
        if (step.movesY) {
            error += dx;
            y += stepY;
        }
    }
    return output;
}
```

Có bốn chi tiết cần đọc kỹ:

1. dx là trị tuyệt đối; dy là âm của trị tuyệt đối. Dấu âm này thuộc cách viết công thức, không biểu thị đoạn đang đi lên hay xuống.
2. stepX/stepY mới là hướng: −1 hoặc +1. Với một trục không cần thay đổi, điều kiện bước sẽ không chọn trục đó.
3. Điểm hiện tại được lưu trước khi đổi X/Y; nếu đã tới B thì dừng ngay. Đoạn dài 0 vì thế có đúng một bản ghi.
4. Cả hai cờ được tính từ doubledError cũ. Chỉ sau khi lưu bản ghi ta mới thay error và tọa độ.

Bresenham không có phép chia hoặc số thực trong vòng lặp chính. Vector vẫn cần cấp phát bộ nhớ, còn CPU vẫn phải thực hiện nhánh và ghi dữ liệu; chưa thể từ đây kết luận toàn bộ chương trình sẽ nhanh hơn bao nhiêu.

### Bước 3 — Chọn thuật toán tại một chỗ

Thêm enum Algorithm và hàm chọn trong cùng header:


```cpp title="include/lab.hpp — hai thuật toán"
enum class Algorithm { Dda, Bresenham };
```


```cpp title="include/lab.hpp — chọn nguồn dữ liệu của đường thẳng"
inline std::vector<LineStep> lineSteps(Point start, Point end, Algorithm algorithm) {
    if (algorithm == Algorithm::Dda) {
        return dda(start, end);
    }
    return bresenham(start, end);
}
```

Không có một hàm “vẽ đúng” và một hàm trace viết lại để minh họa. Cả vẽ hình, đọc sai số và benchmark sau này đều đi qua các bản ghi do dda/bresenham thật trả về.

drawLine chỉ đổi nơi lấy dữ liệu:


```cpp title="include/drawing.hpp — drawLine sau khi có hai thuật toán"
inline void drawLine(Framebuffer& framebuffer, Point start, Point end, std::uint32_t color, Algorithm algorithm = Algorithm::Bresenham) {
    plotSteps(framebuffer, lineSteps(start, end, algorithm), color);
}
```

Đối số cuối có giá trị mặc định Bresenham. Khi muốn DDA, truyền Algorithm::Dda. Màu và cách ghi pixel không thay đổi.

### Bước 4 — Nối phím D/B với trạng thái rồi vẽ lại

Scene có thêm algorithm, ban đầu là Bresenham. Phần bàn phím trong main gọi:


```cpp title="src/main.cpp — chọn thuật toán bằng hai phím"
void handleKey(SDL_Keycode key, bool shift, lab::Scene& scene) {
    if (key == SDLK_D) {
        scene.algorithm = lab::Algorithm::Dda;
    }
    if (key == SDLK_B) {
        scene.algorithm = lab::Algorithm::Bresenham;
    }
    (void)shift;
}
```

Sau một phím hợp lệ, main đặt dirty = true. renderScene chọn danh sách theo scene.algorithm, còn plotSteps, texture và present giữ nguyên:


```cpp title="include/view.hpp — dựng lại đường bằng thuật toán đã chọn"
inline SceneFrame renderScene(Framebuffer& framebuffer, Scene& scene) {
    framebuffer.clear(kBackground);
    SceneFrame frame;
        frame.line = lineSteps(scene.a, scene.b, scene.algorithm);
        plotSteps(framebuffer, frame.line, kLineColor);
        for (const LineStep& step : frame.line) {
            frame.points.push_back(step.point);
        }

    return frame;
}
```

shift chưa được dùng ở checkpoint 2 nên có dòng (void)shift để diễn đạt rõ và tránh cảnh báo. Bài tương tác sau mới dùng Shift khi chọn tay nắm A; bạn chưa cần bổ sung input chưa được học.

## Ghép các phần lại

D/B thay Scene.algorithm → dirty yêu cầu tạo ảnh mới → lineSteps chọn DDA hoặc Bresenham → plotSteps ghi cùng framebuffer. Tiêu đề cho biết thuật toán hiện tại, nên bạn không phải đoán mình đang xem bản nào.

Thử A(0,0) → B(7,3) trong debugger và so từng dòng của bảng. Đừng vội so pixel giữa hai thuật toán trên mọi đoạn: khi đường đi đúng giữa hai ứng viên, quy tắc chọn có thể khác mà cả hai vẫn hợp lệ.

## Thử làm sai để hiểu đúng

1. Đổi nhánh if thứ hai thành else if. Tại bước cần đi cả X lẫn Y, chỉ một trục được cập nhật; đường không còn đi theo chuỗi mong đợi.
2. Tính lại movesY từ error đã bị nhánh X thay đổi. So bước (1,0) trong bảng: bạn đã đổi phép quyết định chứ không chỉ đổi cách viết code.
3. Bỏ dấu trừ trước abs khi tạo dy. Điều kiện bước không còn đúng với công thức này; có thể đi sai hoặc không tới B. Chỉ thử trên dữ liệu nhỏ và dùng debugger/timeout, không để một vòng lặp lỗi chạy vô hạn.
4. Đưa kiểm tra tới B xuống sau khi cập nhật tọa độ. Đoạn dài 0 không còn được xử lý đúng.
