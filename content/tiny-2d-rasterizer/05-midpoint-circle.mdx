# Vẽ và tô đường tròn

## Vấn đề cần giải quyết

Ta muốn thêm hai hàm vào bộ công cụ: drawCircle vẽ viền một pixel và fillCircle tô đặc. Cả hai phải hoạt động trong ứng dụng C++, không chỉ có công thức hoặc bài tập để người học tự bổ sung.

Có thể xét mọi pixel trong hình vuông bao như brush của Mini Paint, nhưng vẽ **viền** theo cách đó vừa tốn công vừa khó thống nhất độ dày. Midpoint circle chỉ tính một phần tám chu vi rồi phản chiếu; sau khi có viền, ta dùng các hàng ngang để tô tới chính viền ấy.

## Hiểu ý tưởng trước khi viết code

Xét đường tròn tâm gốc với hàm:

$$
F(x,y)=x^2+y^2-r^2
$$

F âm ở trong, dương ở ngoài. Bắt đầu tại (r,0) và đi xuống từng hàng. Ở hàng tiếp theo chỉ cần chọn một trong hai điểm: giữ X tại (x,y+1), hoặc giảm X tại (x−1,y+1).

Trung điểm giữa hai ứng viên là M = (x−1/2,y+1). Ta giữ X khi F(M) âm; ngược lại giảm X. Vì x,y nguyên, F(M) luôn có phần lẻ 1/4. Đặt:

$$
d = F(x-1/2,y+1)-1/4,\qquad d_0=1-r
$$

d là số nguyên. F(M) âm tương đương `d < 0`; **d = 0 vẫn có F(M) = 1/4 ở ngoài**, nên phải chọn nhánh giảm X. Đây là lý do code dùng `<`, không phải `<=`.

Sau mỗi bước, công thức cập nhật chỉ còn phép cộng:

- Tăng Y trước; nếu giữ X, cộng 2Y + 1 vào decision.
- Nếu giảm X, giảm nó trước rồi cộng 2(Y−X) + 1.
- Dừng khi `X < Y` vì đã đi qua đường chéo 45 độ.

Với r = 5, các trạng thái trước bước là:

| Offset | decision | Chuyển tiếp |
|---|---:|---|
| (5,0) | −4 | Giữ X → (5,1) |
| (5,1) | −1 | Giữ X → (5,2) |
| (5,2) | 4 | Giảm X → (4,3) |
| (4,3) | 3 | Qua đường chéo rồi dừng |

Mỗi offset tạo các điểm (±x,±y) và (±y,±x). Trên trục hoặc đường chéo, một số điểm trùng nhau và phải được loại.

## Viết code từng bước

### Bước 1 — Tạo tám điểm đối xứng

Trong include/lab.hpp, dùng lại Point và sortUnique:


```cpp title="include/lab.hpp — phản chiếu một offset quanh tâm"
inline std::vector<Point> symmetricCirclePoints(Point center, int x, int y) {
    std::vector<Point> points{
        {center.x + x, center.y + y},
        {center.x + y, center.y + x},
        {center.x - y, center.y + x},
        {center.x - x, center.y + y},
        {center.x - x, center.y - y},
        {center.x - y, center.y - x},
        {center.x + y, center.y - x},
        {center.x + x, center.y - y},
    };
    sortUnique(points);
    return points;
}
```

Hàm nhận offset, không nhận tọa độ tuyệt đối trên window. Cộng center vào từng hoán vị mới tạo được pixel trên ảnh.

Khi y = 0, tám công thức chỉ cho bốn vị trí khác nhau. Khi x = y, đổi chỗ X/Y cũng trùng. sortUnique bảo đảm mỗi bước chỉ chứa các điểm duy nhất.

### Bước 2 — Đi qua một phần tám chu vi

Mỗi bản ghi giữ offset, decision trước bước và các điểm phản chiếu:


```cpp title="include/lab.hpp — dữ liệu một bước midpoint"
struct CircleStep {
    int x{};
    int y{};
    int decision{};
    std::vector<Point> points;
};
```


```cpp title="include/lab.hpp — toàn bộ vòng lặp midpoint"
inline std::vector<CircleStep> circleSteps(Point center, int radius) {
    if (!validPoint(center) || radius < 0 || radius > 256) {
        return {};
    }
    int x = radius;
    int y = 0;
    int decision = 1 - radius;
    std::vector<CircleStep> steps;
    while (x >= y) {
        steps.push_back({x, y, decision, symmetricCirclePoints(center, x, y)});
        ++y;
        if (decision < 0) {
            decision += 2 * y + 1;
        } else {
            --x;
            decision += 2 * (y - x) + 1;
        }
    }
    return steps;
}
```

Đọc theo đúng thứ tự đã suy ra: lưu trạng thái → tăng y → xét decision cũ → cập nhật decision và x nếu cần. Không đưa công thức cập nhật lên trước ++y mà vẫn dùng cùng biểu thức.

Bán kính hợp lệ là 0–256. Bán kính âm hoặc quá giới hạn trả kết quả rỗng, không bị tự đổi thành một hình khác. Với radius = 0, vòng lặp đầu tạo tâm; sau đó dừng, không cần một thuật toán riêng.

### Bước 3 — Gộp thành đường viền hoàn chỉnh


```cpp title="include/lab.hpp — lấy tập pixel của cả đường tròn"
inline std::vector<Point> circle(Point center, int radius) {
    std::vector<Point> points;
    for (const CircleStep& step : circleSteps(center, radius)) {
        points.insert(points.end(), step.points.begin(), step.points.end());
    }
    sortUnique(points);
    return points;
}
```

sortUnique ở đây loại trùng **giữa các bước**, ngoài bước loại trùng bên trong từng phép phản chiếu. Thứ tự sau sắp xếp không phải thứ tự chạy quanh chu vi; cần quan sát diễn tiến thì đọc circleSteps.

Với r = 1, đường viền có bốn điểm ngoài cùng. Nếu dùng `decision <= 0`, thuật toán còn thêm bốn điểm chéo: ảnh nhỏ này giúp phát hiện khác biệt mà đường tròn lớn dễ che đi.

### Bước 4 — Tô đặc bằng độ rộng của từng hàng

Để hình đặc chứa đúng đường viền đã tạo, ta tìm pixel xa tâm nhất trên mỗi hàng. Nếu hàng có extent = 2 thì tô từ center.x−2 tới center.x+2.


```cpp title="include/lab.hpp — tô mọi hàng tới viền midpoint"
inline std::vector<Point> filledCircle(Point center, int radius) {
    const auto outline = circle(center, radius);
    if (outline.empty()) {
        return {};
    }
    std::vector<int> extents(static_cast<std::size_t>(2 * radius + 1), -1);
    for (Point point : outline) {
        const std::size_t row = static_cast<std::size_t>(point.y - center.y + radius);
        extents[row] = std::max(extents[row], std::abs(point.x - center.x));
    }

    std::vector<Point> points;
    for (int row = 0; row <= 2 * radius; ++row) {
        const int extent = extents[static_cast<std::size_t>(row)];
        for (int x = center.x - extent; x <= center.x + extent; ++x) {
            points.push_back({x, center.y - radius + row});
        }
    }
    return points;
}
```

extents có 2r + 1 phần tử, tương ứng các hàng từ center.y−r tới center.y+r. Ban đầu −1 nghĩa là chưa có điểm biên. Các pixel outline cập nhật độ vươn xa nhất bằng max.

Lượt duyệt cuối tạo một span liên tục trên mỗi hàng. Các hàng khác nhau có Y khác nhau nên không lặp pixel; lần này không cần sortUnique cho kết quả tô.

Một ví dụ quan trọng với r = 2:

| Độ lệch Y | Bề rộng hàng theo viền midpoint |
|---:|---:|
| −2 | 3 |
| −1 | 5 |
| 0 | 5 |
| 1 | 5 |
| 2 | 3 |

Tổng là **21 pixel**, còn đường viền có 12 pixel. Brush Project 03 dùng điều kiện tâm pixel nằm trong đĩa, `dx² + dy² <= r²`, nên cùng r = 2 chỉ có **13 pixel**. Hai kết quả dùng hai quy tắc khác nhau, không phải sai số do Canvas hoặc SDL.

Ở đây ta chọn tô tới viền midpoint để drawCircle/fillCircle khớp nhau. Nếu muốn diện tích theo quy tắc tâm trong đĩa, hãy đặt tên và kiểm thử riêng; đừng thay âm thầm một hàm rồi vẫn cho rằng nó chứa cùng viền.

### Bước 5 — Ghi vào ảnh và thêm công cụ Circle

Trong include/drawing.hpp:


```cpp title="include/drawing.hpp — vẽ viền đường tròn"
inline void drawCircle(Framebuffer& framebuffer, Point center, int radius, std::uint32_t color) {
    plotPoints(framebuffer, circle(center, radius), color);
}
```


```cpp title="include/drawing.hpp — tô đặc đường tròn"
inline void fillCircle(Framebuffer& framebuffer, Point center, int radius, std::uint32_t color) {
    plotPoints(framebuffer, filledCircle(center, radius), color);
}
```

Hai hàm dùng lại plotPoints/putPixel. Không có SDL_RenderPoint hoặc API circle ở giữa.

Checkpoint 5 có Tool::Circle, phím 3 chọn công cụ này. A là tâm; tay nắm thứ hai ở bên phải tâm, cách radius pixel. Kéo tay nắm ấy đo khoảng cách tới tâm rồi làm tròn/giới hạn về 0–256. Phím [ và ] thay bán kính từng đơn vị; F đổi viền/đặc.

Phần render chọn circle hoặc filledCircle giống cách rectangle chọn viền/đặc ở bài trước:


```cpp title="include/view.hpp — vẽ kiểu circle đang chọn"
if (scene.tool == Tool::Circle) {
    if (scene.filled) {
        frame.points = filledCircle(scene.a, scene.radius);
    } else {
        frame.points = circle(scene.a, scene.radius);
    }
    plotPoints(framebuffer, frame.points, kLineColor);
}
```

Ảnh được xóa rồi dựng lại khi hình học đổi, nên kéo tâm không để lại vệt. Một phần hình có thể nằm ngoài ảnh; vector hình học vẫn chứa phần đó, còn putPixel chỉ ghi phần trong ảnh. Số pixel báo trên title là số pixel sinh ra, không nhất thiết là số ô còn nhìn thấy sau khi bị cắt.

## Ghép các phần lại

Tâm/bán kính → circleSteps tính một octant → phản chiếu và loại trùng → circle tạo viền → filledCircle tạo các span khi cần → plotPoints ghi ảnh. Inspector vẫn đọc màu từ framebuffer, không tự đoán pixel theo công thức circle.

Thử r = 0, 1, 2, 5 trước khi tăng lên hàng trăm. Các trường hợp nhỏ có thể đếm tay nên hữu ích hơn việc chỉ nhìn một vòng tròn lớn có vẻ cân.

## Thử làm sai để hiểu đúng

1. Đổi `decision < 0` thành `decision <= 0`. Với r = 1, kiểm lại số điểm và bốn ô chéo; so với quy tắc F(M) = decision + 1/4.
2. Chỉ phản chiếu (±x,±y), bỏ các hoán vị X/Y. Đường tròn mất những phần gần trục dọc.
3. Bỏ sortUnique. Hình có thể giống nhau nhưng tập kết quả chứa pixel lặp, làm sai số đếm.
4. Trong filledCircle, chỉ ghi hai đầu mỗi hàng thay vì duyệt cả span. Hình không còn đặc dù đường viền vẫn đúng.

## Tự kiểm tra kết quả

- Circle ở tâm bất kỳ có đủ bốn điểm ngoài cùng, đối xứng qua hai trục và đường chéo.
- r = 0 cho một điểm; r = 1 có viền bốn điểm; r = 2 có viền 12 và hình đặc 21 pixel.
- Không trùng pixel; mỗi hàng hình đặc liên tục và chứa các pixel của viền tương ứng.
- 3/F/[ và ] hoạt động trong SDL3; kéo được tâm/bán kính; resize không đổi hình học.
- Bạn giải thích được vì sao hình đặc ở đây khác brush Project 03, thay vì chỉ nhớ con số 21.
