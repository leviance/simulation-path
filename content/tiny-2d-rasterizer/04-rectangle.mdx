# Ghép đường viền, tô hình chữ nhật

## Vấn đề cần giải quyết

Ta đã có drawLine và kéo được hai điểm. Dùng chính hai điểm ấy làm hai góc đối diện, chương trình sẽ vẽ được hình chữ nhật mà không cần thêm một API đồ họa nào.

Có hai việc khác nhau: vẽ **viền** chỉ lấy các pixel trên bốn cạnh; **tô đặc** lấy mọi pixel bên trong lẫn trên biên. Checkpoint 4 thêm công cụ Rectangle, phím F đổi kiểu tô và giữ nguyên thao tác kéo/inspector của bài trước.

## Hiểu ý tưởng trước khi viết code

Hai góc không nhất thiết được nhập từ trên trái tới dưới phải. Người dùng có thể kéo qua nhau hoặc bắt đầu từ góc nào cũng được. Vì vậy, trước hết tìm left/right/top/bottom bằng min/max.

Ở project này, hai góc là **chỉ số pixel và đều được lấy**. Từ X = 1 tới X = 4 có bốn cột: 1, 2, 3, 4.

$$
w = x_{max}-x_{min}+1,\qquad
h = y_{max}-y_{min}+1,\qquad
N_{fill}=wh
$$

Viền thông thường có 2w + 2h − 4 pixel duy nhất. Nhưng khi w = 1, viền chỉ còn một cột có h pixel; khi h = 1, chỉ còn một hàng có w pixel. Trường hợp một điểm có đúng một pixel, không phải 0.

Đây là quy ước riêng của hàm nhận **hai góc inclusive**. Đừng nhầm nó với một API nhận x, y, width, height và dùng biên phải/dưới loại trừ.

## Viết code từng bước

### Bước 1 — Cho phép sắp xếp và loại pixel trùng

Point có thêm toán tử nhỏ hơn: so X trước, nếu bằng thì so Y. Nó chỉ xác định thứ tự ổn định trong vector, không quyết định cách rasterize.

Hàm dùng lại ở rectangle và circle:


```cpp title="include/lab.hpp — sắp xếp rồi bỏ phần tử trùng"
inline void sortUnique(std::vector<Point>& points) {
    std::sort(points.begin(), points.end());
    points.erase(std::unique(points.begin(), points.end()), points.end());
}
```

unique chỉ dồn các phần tử khác nhau về phía đầu và trả iterator kết thúc mới; erase mới rút ngắn vector. Vì vậy phải dùng cả hai.

Loại trùng không chỉ để hình đẹp. Tô cùng một ô hai lần có thể không đổi ảnh hiện tại, nhưng sẽ làm sai số pixel, số phép ghi và các xử lý dựa trên tập điểm duy nhất.

### Bước 2 — Ghép bốn đoạn thành viền


```cpp title="include/lab.hpp — hình chữ nhật nhận hai góc bất kỳ"
inline std::vector<Point> rectangle(Point first, Point second) {
    if (!validPoint(first) || !validPoint(second)) {
        return {};
    }
    const int left = std::min(first.x, second.x);
    const int right = std::max(first.x, second.x);
    const int top = std::min(first.y, second.y);
    const int bottom = std::max(first.y, second.y);
    const Point corners[] = {{left, top}, {right, top}, {right, bottom}, {left, bottom}};
    std::vector<Point> points;
    for (int edge = 0; edge < 4; ++edge) {
        const Point start = corners[edge];
        const Point end = corners[(edge + 1) % 4];
        for (const LineStep& step : bresenham(start, end)) {
            points.push_back(step.point);
        }
    }
    sortUnique(points);
    return points;
}
```

Mảng corners đi quanh hình: trên trái → trên phải → dưới phải → dưới trái. Chỉ số (edge + 1) % 4 nối cạnh cuối về góc đầu.

Mỗi cạnh dùng lại Bresenham đã học. Các góc xuất hiện ở hai cạnh nên bị lặp; sortUnique bỏ chúng. Với một hàng hoặc một cột, nhiều cạnh chồng nhau nhưng kết quả cuối vẫn là tập pixel đúng.

Không cần một nhánh đặc biệt để “đoán” người dùng kéo theo hướng nào. min/max đã chuẩn hóa hình, còn Bresenham biết đi theo cả hai chiều.

### Bước 3 — Tô từng hàng liên tiếp


```cpp title="include/lab.hpp — tô hình chữ nhật lấy cả hai biên"
inline std::vector<Point> filledRectangle(Point first, Point second) {
    if (!validPoint(first) || !validPoint(second)) {
        return {};
    }
    const int left = std::min(first.x, second.x);
    const int right = std::max(first.x, second.x);
    const int top = std::min(first.y, second.y);
    const int bottom = std::max(first.y, second.y);
    const int width = right - left + 1;
    const int height = bottom - top + 1;
    if (width > 1024 || height > 1024) {
        return {};
    }

    std::vector<Point> points;
    points.reserve(static_cast<std::size_t>(width) * height);
    for (int y = top; y <= bottom; ++y) {
        for (int x = left; x <= right; ++x) {
            points.push_back({x, y});
        }
    }
    return points;
}
```

Vòng ngoài chọn Y, vòng trong đi X từ trái sang phải. Khi putPixel ghi kết quả, những ô trong cùng hàng nằm cạnh nhau trong bộ nhớ row-major.

Mỗi cạnh hình đặc được giới hạn tối đa 1.024 pixel, sau khi đã kiểm tọa độ ±4.096. Hai giới hạn làm những việc khác nhau: giới hạn tọa độ giữ phép tính an toàn, giới hạn diện tích ngăn vector quá lớn. Đầu vào vượt hợp đồng trả vector rỗng; hàm không âm thầm đổi kích thước hình.

Ảnh C++ chỉ 960 × 540, nên mọi rectangle được kéo hoàn toàn trong ảnh đều nằm trong giới hạn này. putPixel vẫn phải kiểm biên vì các hàm hình học cũng được dùng với tọa độ âm trong tests.

### Bước 4 — Tạo hai hàm vẽ và nối công cụ mới

Trong include/drawing.hpp:


```cpp title="include/drawing.hpp — ghi đường viền vào ảnh"
inline void drawRect(Framebuffer& framebuffer, Point first, Point second, std::uint32_t color) {
    plotPoints(framebuffer, rectangle(first, second), color);
}
```


```cpp title="include/drawing.hpp — ghi hình đặc vào ảnh"
inline void fillRect(Framebuffer& framebuffer, Point first, Point second, std::uint32_t color) {
    plotPoints(framebuffer, filledRectangle(first, second), color);
}
```

plotPoints duyệt vector Point và gọi framebuffer.putPixel, tương tự plotSteps nhưng không cần dữ liệu sai số.

Scene có thêm Tool::Rectangle và filled. Trong main, 1 chọn Line, 2 chọn Rectangle, F đổi filled. Hai góc dùng lại A/B và cách kéo của bài 3. Trái/phải/Home/End vẫn chọn pixel để soi, nhưng với rectangle thứ tự này là thứ tự vector kết quả, không phải một diễn tiến vật lý quanh chu vi.

Phần mới trong renderScene:


```cpp title="include/view.hpp — chọn viền hoặc hình đặc trong cảnh"
if (scene.tool == Tool::Rectangle) {
    if (scene.filled) {
        frame.points = filledRectangle(scene.a, scene.b);
    } else {
        frame.points = rectangle(scene.a, scene.b);
    }
    plotPoints(framebuffer, frame.points, kShapeColor);
}
```

Ta giữ frame.points cho inspector và đếm kết quả, rồi plotPoints một lần. Các hàm drawRect/fillRect là cách gọi gọn khi chỉ cần ghi hình, chẳng hạn bảng hình mẫu ở bài cuối; chúng dùng cùng rectangle/filledRectangle, không có công thức thứ hai.

## Ghép các phần lại

Đổi Tool không tạo window hay texture khác. A/B → chuẩn hóa bốn biên → tạo tập pixel viền/đặc → ghi vào cùng framebuffer → dùng lại inspector và presentation.

## Thử làm sai để hiểu đúng

1. Bỏ min/max và dùng first.x như cạnh trái. Kéo A qua bên phải B; vòng lặp tô có thể không chạy hoặc reserve nhận kích thước sai. Chỉ thử với phần cấp phát đã được bảo vệ, không ép kích thước âm sang size_t.
2. Bỏ +1 khi tính width/height, hoặc dùng `x < right` trong vòng tô. Hình (1,1) → (4,3) không còn đủ 12 pixel.
3. Bỏ sortUnique khỏi viền. Ảnh có thể trông giống nhau nhưng số phần tử lớn hơn 10 vì góc/cạnh suy biến bị đếm lại.
4. Áp dụng 2w + 2h − 4 cho mọi trường hợp. Một điểm cho đáp án 0, cho thấy công thức chu vi thông thường không áp dụng ở hình suy biến.

## Tự kiểm tra kết quả

- Hai góc theo bốn thứ tự khác nhau vẫn cho cùng tập pixel.
- Hình (1,1) → (4,3) có viền 10 pixel, hình đặc 12 pixel.
- Một hàng, một cột, một điểm đều có số pixel hợp lý, không lặp.
- 2/F hoạt động trên ứng dụng SDL3; inspector đọc màu hình đã vẽ.
- Tọa độ ngoài hợp đồng và cạnh hình đặc quá 1.024 bị từ chối trước cấp phát lớn.

## Bài tập mở rộng

Tạo đáp án rectangle độc lập bằng một vòng duyệt hình bao: pixel thuộc viền nếu X ở trái/phải hoặc Y ở trên/dưới. So nó với rectangle trên nhiều kích thước, thay vì dùng lại Bresenham để tạo cả kết quả lẫn đáp án.
