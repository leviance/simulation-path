# Lần theo một hạt giữa đài phun một triệu hạt

## Vấn đề cần giải quyết

Chọn một giọt đang rơi ở mép tia nước. Nếu chuyển từ AoS sang SoA đúng lúc ấy, liệu bạn có tìm lại được đúng giọt đó không? Và nếu phần lớn một triệu giọt không được vẽ, làm sao chứng minh chúng vẫn đang già đi? Cùng một vòi phun, ta sẽ dùng ba dụng cụ cho ba câu hỏi khác nhau: camera để xem hình, ID để theo một giọt, và phép kiểm từng ô để đếm phần việc của CPU.

Hãy mở bản C++ hoàn chỉnh: đài phun chạy ngay. Nhấn **Space** để dừng hoặc **R** để quay về khung đầu. Ở khung vừa reset, `alive = 1.000.000`, `updated = 0` là đúng. Các ảnh native trong bài cũng được chụp ở bước 0. Canvas bắt đầu ở trạng thái dừng để bạn tiện làm thí nghiệm.

## Hiểu ý tưởng trước khi viết code

Giữ nguyên khung hình rồi nhấn **F2** để nhìn từ trên. Ta thấy giọt nào đã tỏa xa miệng vòi trên mặt XZ nhưng khó biết nó bay cao bao nhiêu. Vẫn ở thời điểm đó, nhấn **F3** để nhìn ngang: ngọn tia và những giọt đang rơi lúc này dễ phân biệt hơn. **F1** đưa về góc nghiêng. Nếu muốn làm phép đối chứng, đưa độ xòe về 0 rồi nhấn **R**: nhìn ngang vẫn thấy tia cong về phía trước; khi nhìn từ trên, những giọt có cùng tọa độ Z nằm thành dải dọc theo X. Đừng so hai góc camera ở hai thời điểm khác nhau rồi quy tất cả thay đổi cho góc nhìn.

Ánh sáng trắng ngả sang xanh khi hạt già đi, nét ngắn chỉ hướng vận tốc. Chúng giúp mắt đọc chuyển động, không phải màu đo nhiệt độ hay vệt quỹ đạo lưu từ quá khứ. Mặt lưới là mốc độ cao, không phải đáy bể làm nước nảy lại.

## Viết code từng bước

### Bắt đầu bằng một giọt có tên

{/* snippet include/inspection.hpp#slot-reading */}
```cpp title="include/inspection.hpp — Đọc một ID từ chính container đang hoạt động"
inline std::optional<ParticleAoS> readSlot(const Simulation& simulation, std::size_t slot) {
    if (slot >= simulation.active) {
        return std::nullopt;
    }
    // Sau khi đổi layout, cùng số slot vẫn chỉ đúng giọt này.
    return simulation.particle(slot);
}
```

Hãy cho bảng thông tin giữ **số slot**, không giữ con trỏ tới một phần tử AoS. Khi nhấn `L`, cùng chỉ số vẫn phải tìm thấy đúng giọt trong SoA. Khi chưa có hạt nào, không trả về một hạt mặc định có vẻ hợp lệ: `std::nullopt` cho phép ghi “đang chờ vòi phát”.

### Chỉ lấy mẫu để vẽ, không lấy mẫu để tính

{/* snippet include/render.hpp#draw-fountain */}
```cpp title="include/render.hpp — Chọn một tập hạt tái lập từ trạng thái đang hiển thị"
inline RenderStats drawFountain(Framebuffer& image, const Simulation& simulation, const Camera& camera, std::size_t drawBudget = displayBudget, bool debug = false) {
    prepareFountainSurface(image, camera, debug);
    image.spray.clear(image.width, image.height);
    // Camera trigonometry is shared by every sampled particle in this frame.
    const ViewBasis basis = viewBasis(camera);
    RenderStats stats{};
    stats.sampled = std::min(simulation.active, drawBudget);
    const double opacity = std::clamp(30.0 / std::sqrt(double(std::max<std::size_t>(1, stats.sampled))), 0.2, 0.8);
    for (std::size_t sample = 0; sample < stats.sampled; ++sample) {
        // Deterministic display sampling, never a reduction of simulation N.
        const std::size_t index = sample * simulation.active / stats.sampled;
        const ParticleAoS particle = simulation.particle(index);
        if (sample % 4 == 0) lightFootprint(image, basis, particle);
        if (drawWaterParticle(image, camera, basis, particle, opacity))
            ++stats.rendered;
    }
    image.spray.develop(image.pixels, image.width, image.height);
    return stats;
}
```

Phần vẽ đã dùng chung từ bộ khung; hãy đọc nó trước khi đặt quy mô cuối. `sampled` bị giới hạn ở 40.000. Với một triệu hạt sống, phép lấy mẫu chọn một trong mỗi 25 slot. `rendered` chỉ tăng nếu giọt thực sự góp vào hình sau khi xét khung nhìn và mặt lưới. Chuyển camera có thể làm số này đổi mà **không có bất kỳ bước vật lý nào**.

Trong `work/include/application.hpp`, cho vòi khởi động với preset một triệu hạt. Nối **I** để bật bảng, **Tab** đi sang ID tiếp theo và **U** để tìm ứng viên sắp hết tuổi trong tối đa 4.096 ô đầu đang sống. Không cần quét một triệu hạt vì một lần nhấn phím. Trên cảnh đang dừng, nhấn **N** khi thời gian còn lại của hạt không quá một bước: ID giữ nguyên, thế hệ tăng, tuổi mới gần 0. Nếu thời gian còn lại dài hơn một bước, cần nhấn thêm; `U` chỉ **chọn** hạt, không làm nó chết sớm.

### Kiểm phần mắt không nhìn thấy

{/* snippet include/application.hpp#verify-slots */}
```cpp title="include/application.hpp — Kiểm tuổi và thế hệ ở từng slot sau một bước"
for (std::size_t index = 0; index < simulation.count; ++index) {
    const auto& old = simulation.nextAoS[index];
    const auto& next = simulation.aos[index];
    const float remaining = old.lifetime - old.age;
    const bool expired = lab::fixedDt >= remaining;
    float expectedAge = 0;
    if (expired) {
        expectedAge = lab::fixedDt - remaining;
    } else {
        expectedAge = old.age + lab::fixedDt;
    }
    if (next.id != index || next.generation != old.generation + std::uint32_t(expired) || std::abs(next.age - expectedAge) > 1e-6F || !lab::finiteParticle(next))
        throw std::runtime_error("Untouched/invalid slot in full-N workflow");
}
```

Chế độ `--smoke-workflow` đi đủ một bước rồi đối chiếu **từng slot** trong mảng mới với mảng trước bước. Hạt còn sống hết bước phải tăng tuổi đúng `dt`; hạt cũ hết tuổi phải tăng thế hệ và trả phần thời gian dư về cho hạt mới. Một counter tự ghi một triệu không lừa được phép kiểm này. Với `sizeof(ParticleAoS) = 44`, một mảng đủ N có 44 MB dữ liệu; hai bộ đệm AoS sau bước cập nhật có ít nhất 88 MB dung lượng dành cho phần tử, chưa kể bộ vẽ và các cấu trúc khác.

## Ghép các phần lại

```bash title="Terminal — kiểm chương trình người học trước, không chạy nhầm final"
cmake --build build-work --config Release --target project_32_work project_32_tests --parallel 1
ctest --test-dir build-work -C Release --output-on-failure --timeout 20
.\build-work\Release\project_32_work.exe --smoke-workflow
.\build-work\Release\project_32_work.exe
```

Trong cửa sổ, **F** mở báo cáo. `UPDATE` đo vòng tính, `COPY` và `CONVERT` là hai khoản khác; `DRAW/UPLOAD` đo vẽ và gửi texture, không phải thời gian GPU. `STEP-WALL` tính từ lúc bắt đầu đến khi hoàn tất một bước, có cả thời gian nhường cho giao diện. `FRAME-CPU` đo phạm vi của khung SDL. Đọc các tên này trước khi lấy “một triệu chia số mili giây”: mẫu số phải đúng việc bạn định gọi là throughput.

### Chạy bản hoàn chỉnh độc lập

[ZIP đầy đủ của đài phun C++/SDL3](/downloads/project-32-memory-layout-race.zip) có `starter/`, tám `checkpoints/`, `final/` và `tests/`; toàn bộ mã nguồn cũng có thể mở theo tệp ngay cuối trang này. Không cần Node.js để chạy ZIP. Muốn tách bản tham khảo khỏi `work/`, cấu hình vào một thư mục build khác:

```bash title="Terminal — đối chiếu bản mẫu trong ZIP trên Windows với Visual Studio"
cmake -S . -B build
cmake --build build --config Debug --target project_32_tests --parallel 1
ctest --test-dir build -C Debug --output-on-failure --timeout 20
cmake --build build --config Release --target project_32_final project_32_tests --parallel 1
ctest --test-dir build -C Release --output-on-failure --timeout 20
.\build\Release\project_32_final.exe --benchmark
```

Với Ninja/Make, cấu hình `-DCMAKE_BUILD_TYPE=Release` (tách thư mục nếu muốn đo cả Debug) và bỏ đoạn `Release/` khỏi đường chạy. Chạy CTest để kiểm toán và dữ liệu; chạy binary để kiểm điều khiển. Cái này không thay cái kia.

## Thử làm sai để hiểu đúng

1. Đưa camera ra khỏi đài phun rồi nhấn `N`. Số hiện lên có thể xuống rất thấp nhưng `updated` vẫn phải bằng số đang sống. Nếu đổi camera làm hạt ngừng già đi, vòng vật lý đã phụ thuộc nhầm vào bộ vẽ.
2. Trong bản thử, cho vòng cập nhật nhảy 25 slot như bộ lấy mẫu hiển thị. Đài phun có thể trông vẫn động, nhưng `--smoke-workflow` phải báo có ID chưa tiến tuổi. Khôi phục vòng cập nhật đủ N; không giảm yêu cầu của phép kiểm để nó chạy qua.

## Tự kiểm tra kết quả

- Một snapshot có ba góc nhìn khác nhau; giữ nguyên giờ, ID, tuổi và thế hệ khi xoay camera hoặc đổi layout. Chọn giọt sắp sinh lại, tiến đủ bước và giải thích được vì sao ID không đổi.
- Sau một bước ở preset lớn, `allocated = alive = updated = 1.000.000`; `sampled = 40.000`, còn số thực sự vẽ phụ thuộc camera. Canvas chỉ minh họa, tối đa 20.000 hạt, không thay mốc native.
- Chuyển AoS/SoA, phát hạt từ pool trống, thay trọng lực, đặt lại, hủy tác vụ và so hai workload đều dùng được; có thể lưu cả trường hợp SoA không thắng.
- Bản do bạn tự dựng trong `work/` và bản tham khảo trong `final/` cho cùng kết quả với cùng đầu vào. Không dùng ảnh hoặc CTest thay cho việc tự thử chuột và phím.
