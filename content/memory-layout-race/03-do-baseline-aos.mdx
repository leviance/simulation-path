# Đo vòng lặp đầu tiên bằng AoS

## Vấn đề cần giải quyết

Khi đài phun có nhiều giọt, xoay camera sang chỗ trống có thể làm chương trình vẽ nhanh hơn. Nhưng có giọt nào được miễn trọng lực không? Không. Vì vậy, đọc FPS trước và sau khi xoay không trả lời được câu hỏi của bài: **CPU mất bao lâu để cập nhật cùng một nhóm hạt?**

Ta chưa cần viết SoA. Trước hết, hãy làm một chiếc đồng hồ đáng tin cho cách lưu hiện tại: `std::vector<ParticleAoS>`. Nếu sau này có một con số nhỏ hơn, ta còn biết chính xác mình đang so với điều gì.

## Hiểu ý tưởng trước khi viết code

Hãy cho cùng một người hai việc khác nhau. Lần đầu chỉ cộng trọng lực vào `velocityY` của từng hạt. Lần sau vẫn qua bấy nhiêu hạt, nhưng phải tiến vị trí, tiến tuổi và sinh lại hạt hết tuổi. Chúng lần lượt là `gravity-only` và `full lifecycle`. Phép thứ nhất cố ý làm ít việc; **đài phun đang hiển thị vẫn luôn chạy đủ vòng đời**.

Quy ước một mẫu đo gồm **ba pass** qua đủ $N$ hạt. Chọn $N=10.000$ thì cuối mẫu phải đếm được 30.000 lượt cập nhật, không phải 30.000 hạt khác nhau. Nếu đồng hồ trả về 1,8 ms cho mẫu ấy, chi phí trung bình mỗi lượt qua cả mảng là 0,6 ms. Đừng lấy 1,8 ms làm thời gian cho một khung SDL.

## Viết code từng bước

### Chọn chính xác phần việc đem cân

{/* snippet include/particles.hpp#update-aos-range */}
```cpp title="include/particles.hpp — Hai cách đi qua cùng một đoạn mảng AoS"
inline std::size_t updateAoSRange(std::span<ParticleAoS> particles, std::size_t begin, std::size_t end, const FountainConfig& config, float dt, MemoryWorkload workload, std::size_t oldActive) {
    std::size_t respawned = 0;
    if (workload == MemoryWorkload::gravityOnly) {
        for (std::size_t index = begin; index < end; ++index) {
            particles[index].velocityY += config.gravity * dt;
        }
    } else {
        for (std::size_t index = begin; index < end; ++index) {
            if (advanceParticle(particles[index], config, dt, index >= oldActive)) {
                ++respawned;
            }
        }
    }
    return respawned;
}
```

Hai nhánh đều làm trên `[begin, end)`. Chỉ nhánh vòng đời cần biết nhóm ô nào vừa được phát và cần đếm số hạt sinh lại. Chọn việc bằng biến `workload`, không giảm số phần tử hoặc đổi `dt` cho nhánh được đem so.

### Đặt đồng hồ sát hai đầu vòng cập nhật

{/* snippet include/benchmark.hpp#benchmark-kernel-unit */}
```cpp title="include/benchmark.hpp — Đếm lượt cập nhật thay vì đếm số lần gọi hàm"
void kernelUnit() {
    const std::size_t end = std::min(row.count, target + 4096);
    const auto started = Clock::now();
    if (method == 0) {
        updateAoSRange(workAoS, target, end, config, fixedDt, row.workload, row.count);
    }
    kernelMs += milliseconds(started);
    trialUpdated += end - target;
    target = end;
    if (target != row.count)
        return;
    target = 0;
    if (++step < 3)
        return;
    if (trialUpdated != row.count * 3)
        throw std::runtime_error("Incomplete benchmark pass");
    row.updated = trialUpdated;
    if (sample >= 0) {
        if (method == 0)
            aosTimes.push_back(kernelMs);
        else
            soaTimes.push_back(kernelMs);
    }
    ++trial;
    int methodsPerSample = 1;
    if (paired) {
        methodsPerSample = 2;
    }
    if (trial < methodsPerSample)
        chooseMethod();
    else {
        row.checksumAoS = row.checksumSoA = 0;
        phase = BenchmarkPhase::verify;
    }
}
```

Trong `BenchmarkJob`, một lượt xử lý tối đa 4.096 phần tử. `trialUpdated += end - target` cộng số phần tử **vừa làm xong**. Sau ba lượt qua đủ mảng mới được ghi thời gian vào mẫu. Khung SDL có thể nhận input giữa các đoạn; thời gian người dùng xoay camera không bị tính vào tổng `kernelMs`.

Tạo dữ liệu cố định một lần cho ca đo. Trước mỗi mẫu, chép bản đầu vào sang mảng làm việc **trước khi** bấm đồng hồ. Sau khi tắt đồng hồ, duyệt kết quả để kiểm ID, kiểm số hữu hạn và tính `checksum`. Nhờ vậy phép đo có một đầu ra thật. Checksum không thay việc kiểm từng trường: hai sai khác ngược dấu có thể triệt nhau trong một tổng.

### Mô tả năm lần đo thay vì chọn lần đẹp nhất

{/* snippet include/benchmark.hpp#summarize-times */}
```cpp title="include/benchmark.hpp — Báo trung vị và cả hai đầu của khoảng đo"
inline TimingStats summarizeTimes(std::vector<double> samples) {
    if (samples.size() != 5 || std::any_of(samples.begin(), samples.end(), [](double value) {
            return !std::isfinite(value) || value < 0;
        }))
        throw std::invalid_argument("Expected five finite nonnegative timing samples");
    std::sort(samples.begin(), samples.end());
    return {samples[samples.size() / 2], samples.front(), samples.back()};
}
```

Lượt chạy đầu là `warm-up`: nó đi qua đúng lượng dữ liệu nhưng không nằm trong năm mẫu đo. Nếu năm mẫu là 5, 3, 8, 4 và 4 ms, khi sắp xếp ta được 3, 4, **4**, 5, 8. Ghi trung vị 4 ms **cùng khoảng 3–8 ms**. Máy không hứa lặp lại y hệt, kể cả khi dữ liệu hạt giống hệt.

## Ghép các phần lại

```bash title="Terminal — biên dịch chương trình trong work/"
cmake --build build-work --config Release --target project_32_work --parallel 1
.\build-work\Release\project_32_work.exe
```

Với 10.000 hạt, dừng đài phun rồi nhấn **B**. Ghi loại việc, số lượt, checksum và trung vị. Chuyển `T`, lặp lại trên cùng quy mô. Muốn chạy các quy mô đã định từ terminal, dùng `.\build-work\Release\project_32_work.exe --benchmark`. Chữ `Release` quan trọng: bạn đang đo mã đã tối ưu của chính chương trình vừa viết.

## Thử làm sai để hiểu đúng

1. Tạm cho một pass dừng khi mới đến nửa mảng nhưng vẫn coi như đã xong. Đoạn kiểm `trialUpdated` phải bác mẫu ấy; chạy nhanh vì làm thiếu không được tính là tối ưu.
2. Thử dời lệnh chép mảng vào trong khoảng bấm đồng hồ. Kết quả bây giờ là *chép + cập nhật*. Trả việc chép về ngoài timer, hoặc đặt cho phép đo mới một tên khác; không dùng hai số ấy làm một cặp so sánh.

## Tự kiểm tra kết quả

- Hai workload dùng cùng dữ liệu, kiểu `float` và thời lượng bước. Đổi loại phép đo không làm tia nước đổi hình.
- Một warm-up, năm mẫu, ba pass đủ N trong mỗi mẫu; mỗi dòng báo cả min/max và checksum hữu hạn.
- Chưa có số liệu SoA ở bài này. Phép đo trong Canvas dùng JavaScript; không thể lấy nó thay số đo Release của C++.

## Bài tập mở rộng

Chạy cùng một ca hai lần, giữ cả mười mẫu nếu tự bổ sung chỗ ghi lại. Hai lần có cùng checksum không? Khoảng min–max có chồng nhau không? Một kết quả để kiểm tính lặp lại của mô hình; kết quả kia để biết đồng hồ dao động đến đâu.
