# Đổi layout mà không làm đổi trạng thái

## Vấn đề cần giải quyết

Đài phun AoS đã chạy và có baseline. Ta muốn thử SoA nhưng không muốn mỗi lần đổi layout lại tạo một đài phun khác. Nếu chuyển đổi làm mất age, reset generation hoặc đổi vận tốc, phép so sánh sau đó sẽ không còn cùng bài toán.

Bài này **chỉ đổi nơi lưu dữ liệu**. Checkpoint 04 đọc/vẽ được SoA và đổi qua lại mà giữ nguyên state, nhưng chưa có kernel SoA; muốn chạy vật lý hãy trở về AoS. Bài 05 mới nối phần cập nhật SoA. Trình tự này giúp phát hiện lỗi conversion trước khi nghi ngờ solver.

## Theo chân một particle

### Một hạt, hay một field, nằm cạnh nhau?

Trong AoS, toàn bộ record của hạt 0 nằm trước record của hạt 1. Trong SoA, mọi positionX nằm trong một mảng, mọi positionY trong mảng khác, và tương tự với các field còn lại.

```text title="Cùng state, hai cách bố trí"
AoS: [id0 gen0 x0 y0 z0 vx0 vy0 vz0 age0 life0 hue0] [id1 ...]
SoA: id = [id0 id1 ...]   generation = [gen0 gen1 ...]
     positionX = [x0 x1 ...]   positionY = [y0 y1 ...]   ...
```

SoA không cho phép bỏ age, lifetime hoặc hue chỉ vì phép đo hiện tại không chạm tới chúng. Mỗi layout vẫn chứa hai uint32 và chín float cho một slot: payload logic 44 × N byte. Mười một vector có metadata và capacity riêng; tổng RAM thực tế còn phụ thuộc buffer đang giữ.

## Bắt tay xây dựng

### Bước 1 — Tạo container chứa đủ mười một mảng

Thêm ParticlesSoA trong include/storage.hpp, bên trong namespace lab. File này đã include particles.hpp, nơi định nghĩa ParticleAoS và giới hạn N:

```cpp title="include/storage.hpp — container SoA và kiểm độ dài"
struct ParticlesSoA {
    std::vector<std::uint32_t> id{};
    std::vector<std::uint32_t> generation{};
    std::vector<float> positionX{};
    std::vector<float> positionY{};
    std::vector<float> positionZ{};
    std::vector<float> velocityX{};
    std::vector<float> velocityY{};
    std::vector<float> velocityZ{};
    std::vector<float> age{};
    std::vector<float> lifetime{};
    std::vector<float> hue{};

    std::size_t size() const {
        return id.size();
    }

    void resize(std::size_t count) {
        if (count > maximumParticles)
            throw std::invalid_argument("SoA allocation budget");
        id.resize(count);
        generation.resize(count);
        positionX.resize(count);
        positionY.resize(count);
        positionZ.resize(count);
        velocityX.resize(count);
        velocityY.resize(count);
        velocityZ.resize(count);
        age.resize(count);
        lifetime.resize(count);
        hue.resize(count);
    }

    bool valid() const {
        const std::size_t count = size();
        return generation.size() == count && positionX.size() == count && positionY.size() == count && positionZ.size() == count && velocityX.size() == count && velocityY.size() == count && velocityZ.size() == count && age.size() == count && lifetime.size() == count && hue.size() == count;
    }
};
```

`size()` lấy độ dài mảng ID làm chuẩn, còn `valid()` kiểm mọi mảng có cùng size. Phải resize **tất cả**, không chỉ các mảng position/velocity. Nếu một mảng ngắn hơn, đọc cùng index không còn hợp lệ dù hình đài phun đôi khi vẫn trông bình thường.

Hai mảng đầu là uint32 để ID/generation giữ giá trị nguyên chính xác. Không đổi chúng sang float để gom kiểu: float32 không biểu diễn mọi uint32 chính xác.

### Bước 2 — Ghi và đọc một record

Thêm writeParticle ngay sau kiểu container:

```cpp title="include/storage.hpp — ghi đủ field vào cùng slot"
inline void writeParticle(ParticlesSoA& destination, std::size_t index, const ParticleAoS& particle) {
    destination.id[index] = particle.id;
    destination.generation[index] = particle.generation;
    destination.positionX[index] = particle.positionX;
    destination.positionY[index] = particle.positionY;
    destination.positionZ[index] = particle.positionZ;
    destination.velocityX[index] = particle.velocityX;
    destination.velocityY[index] = particle.velocityY;
    destination.velocityZ[index] = particle.velocityZ;
    destination.age[index] = particle.age;
    destination.lifetime[index] = particle.lifetime;
    destination.hue[index] = particle.hue;
}
```

Mọi mảng dùng cùng index. Lỗi copy-paste như ghi velocityZ vào velocityY sẽ tạo một trạng thái khác, không phải một layout khác.

readParticle thực hiện chiều ngược lại:

```cpp title="include/storage.hpp — đọc một record SoA để kiểm hoặc vẽ"
inline ParticleAoS readParticle(const ParticlesSoA& source, std::size_t index) {
    return {source.id[index], source.generation[index], source.positionX[index], source.positionY[index], source.positionZ[index], source.velocityX[index], source.velocityY[index], source.velocityZ[index], source.age[index], source.lifetime[index], source.hue[index]};
}
```

Thứ tự các giá trị trong return phải khớp thứ tự field của ParticleAoS. Đây là một bản ghi tạm để renderer và validator dùng chung cách đọc; không có vector mới nào được cấp phát mỗi lần gọi. Kernel SoA bình thường ở bài sau sẽ truy cập trực tiếp các mảng, không chuyển cả container qua AoS rồi mới tính.

### Bước 3 — Giữ layout cũ cho tới khi copy đủ

Trong Simulation, thêm `ParticlesSoA soa{}, nextSoA{};` bên cạnh các buffer AoS. soa là container của layout hiện tại hoặc đích chuyển đổi; nextSoA dành cho bước vật lý ở bài 05. Phần source đầy đủ ở cuối trang cho thấy chính xác khai báo và vị trí các phương thức.

Thêm beginConversion để chuẩn bị đích:

```cpp title="include/simulation.hpp — bắt đầu một tác vụ conversion"
void beginConversion() {
    cancel();
    if (layout == Layout::aos)
        soa.resize(count);
    else
        aos.resize(count);
    cursor = 0;
    conversionMs = 0;
    pending = PendingWork::conversion;
}
```

`cancel()` hủy công việc dở và pause mô phỏng; nó không xóa snapshot hoàn tất. Nếu đang dùng AoS, ta chuẩn bị soa; nếu đang dùng SoA, ta chuẩn bị aos. Chưa đổi biến layout tại đây.

Tiếp theo, thêm tickConversion:

```cpp title="include/simulation.hpp — đổi layout chỉ sau khi copy hết N slot"
bool tickConversion(double budgetMs = 6) {
    if (pending != PendingWork::conversion)
        return false;
    const auto deadline = Clock::now() + std::chrono::duration<double, std::milli>(budgetMs);
    do {
        const std::size_t end = std::min(count, cursor + 4096);
        const auto started = Clock::now();
        for (std::size_t index = cursor; index < end; ++index) {
            if (layout == Layout::aos)
                writeParticle(soa, index, aos[index]);
            else
                aos[index] = readParticle(soa, index);
        }
        conversionMs += milliseconds(started);
        cursor = end;
    } while (cursor < count && Clock::now() < deadline);
    if (cursor < count)
        return false;
    if (layout == Layout::aos) {
        layout = Layout::soa;
    } else {
        layout = Layout::aos;
    }
    pending = PendingWork::none;
    notice = "Layout changed; ID/generation/fields/time and emission remainder preserved";
    return true;
}
```

Mỗi lần gọi xử lý từng batch tối đa 4.096 slot và nhường lại vòng SDL sau ngân sách khoảng 6 ms. Trong lúc đó, particle() vẫn đọc container được chỉ bởi layout cũ. Chỉ sau khi cursor đi hết count mới đổi layout.

Nếu hủy giữa chừng, một phần destination có thể đã được ghi nhưng **không trở thành state đang dùng**. Vì vậy không cần hoàn tác từng phần tử. Lần chuyển sau sẽ ghi lại toàn bộ destination trước khi công bố nó.

Không sửa time, steps, active hoặc emissionRemainder trong conversion. Đặc biệt, pool cold chưa đầy cũng phải giữ phần lẻ emission; nếu bỏ nó, tốc độ phát có thể đổi sau mỗi lần bấm L dù công thức vật lý không thay.

## Chạy checkpoint và đọc kết quả

Trong include/application.hpp, phím L gọi simulation.beginConversion sau khi hủy tác vụ cũ. Vòng SDL gọi tickConversion khi pending là conversion và jobsPaused chưa bật. Space tạm dừng/tiếp tục tác vụ, X hủy; sau conversion, mô phỏng vẫn pause cho tới khi người dùng cho chạy.

Phương thức particle(index) trong Simulation cũng cần chọn nguồn theo layout: AoS trả aos[index], SoA gọi readParticle(soa, index). drawFountain không phải biết mười một mảng được sắp thế nào. Hai phần ghép này có sẵn trong source checkpoint 04 để bạn đối chiếu khi tự viết, không chép riêng các helper vào main rồi bỏ quên chỗ gọi.

Chỉ đổi layout sau khi copy hết cũng quan trọng với thao tác nhanh: nhấn L rồi X không được làm viewport đọc một nửa dữ liệu mới. Dung lượng buffer cũ có thể vẫn được giữ để dùng lại; logical payload không đồng nghĩa mọi allocation cũ đã biến mất.

### Thử round-trip trước khi chạy kernel mới

Dừng tại một state đã có age/generation khác 0. Ghi lại slot đang xem, đổi AoS → SoA → AoS rồi so ID, generation, mọi field, thời gian và bộ đếm. Mỗi lần chuyển có conversion time riêng; đó là chi phí thật, không được giấu vào một phía của benchmark sau này.

Ở bài này, chọn SoA rồi nhấn chạy sẽ nhắc bạn trở về AoS vì kernel SoA chưa được thêm. Đây là ranh giới checkpoint, không phải lý do reset dữ liệu. Canvas có cùng ranh giới bài học nhưng tối đa 20.000 hạt; bản C++ mới cung cấp preset một triệu.

```bash title="Terminal — checkpoint 04"
cmake --build build --config Debug --target project_32_checkpoint_4
./build/Debug/project_32_checkpoint_4.exe
```

## Cố tình làm sai

Trước khi đổi layout, dự đoán age/generation có đổi không. Conversion không làm thời gian mô phỏng tiến thêm.

1. Tạm bỏ dòng ghi hue hoặc generation trong writeParticle. Màu có thể chỉ khác nhẹ, nhưng so từng field sau round-trip phải phát hiện. Khôi phục dòng copy trước khi học tiếp.
2. Tạm đổi layout ngay trong beginConversion, trước khi copy hết destination. Ở N lớn, viewport có thể đọc các slot chưa được ghi; đây là lý do chỉ flip layout sau cursor = count. Khôi phục điểm commit rồi thử X để kiểm Cancel giữ snapshot cũ.

Không dùng “không crash” làm tiêu chí duy nhất. So cả state và thời gian trước/sau tác vụ.

## Tự kiểm tra kết quả

- SoA có mười một mảng cùng độ dài; ID/generation không bị chuyển sang float.
- AoS → SoA → AoS giữ chính xác các giá trị được sao chép, không cần tolerance để hợp thức hóa việc mất field.
- Active, time, steps và emission carry không đổi do conversion.
- Layout chỉ đổi sau khi copy đủ N; Cancel không làm lộ destination dở.
- Renderer đọc qua particle(index), cho cùng hình khi camera không đổi.
- Conversion time và payload/capacity được tách khỏi update/render.
- SoA tại checkpoint 04 chỉ đọc/vẽ; kernel sẽ được thêm ở bài sau.

## Bài tập mở rộng

Viết một fixture chỉ có ba hạt nhưng mỗi field mang một giá trị dễ phân biệt. Cho một slot đã ở generation 4 và một slot có hue khác hẳn hai slot còn lại. Chuyển hai chiều và so từng field; cách này bắt lỗi đảo mảng tốt hơn việc chỉ nhìn một đài phun nhiều nghìn hạt.
