# Giữ nguyên đài phun khi đổi sang SoA

## Vấn đề cần giải quyết

Dừng đài phun khi một giọt vừa chạm độ cao lớn nhất. Ta muốn đổi cách lưu dữ liệu ngay lúc ấy. Nếu tất cả giọt quay về miệng vòi, đổi màu hoặc nhảy đi một quãng, chương trình đã tạo một đài phun khác. Thử thách của bài là đổi cả mảng trong khi **khung hình và đồng hồ vẫn đứng nguyên**.

Hãy khoan viết vòng cập nhật thứ hai. Ở cuối bài này bạn sẽ đổi sang SoA, xem rồi đổi ngược về AoS. SoA mới chỉ để đọc và vẽ; đến bài 05 nó mới tự tính được bước kế.

## Hiểu ý tưởng trước khi viết code

Hãy ghi ba giọt vào một bảng: mỗi **hàng** là một ID, mỗi **cột** là một trường. AoS đặt trọn hàng 0 cạnh hàng 1. SoA đặt toàn bộ cột `velocityY` trong một mảng, toàn bộ cột `age` trong một mảng khác, và cứ thế. Các bảng biểu diễn cùng dữ liệu; điều thay đổi là đường CPU phải đi để tìm ô tiếp theo.

Có mười một cột, không chỉ sáu cột vị trí và vận tốc. Bỏ quên `generation` có thể không làm hình đổi ngay, nhưng lần sinh sau sẽ dùng sai chuỗi ngẫu nhiên. Bỏ quên `hue` thì phần vật lý vẫn có thể đúng dù sắc độ của giọt bị đổi.

## Viết code từng bước

### Để các cột dùng chung một chỉ số

{/* snippet include/storage.hpp#particles-soa */}
```cpp title="include/storage.hpp — Mười một mảng phải dài bằng nhau"
struct ParticlesSoA {
    std::vector<std::uint32_t> id{};
    std::vector<std::uint32_t> generation{};
    std::vector<float> positionX{};
    std::vector<float> positionY{};
    std::vector<float> positionZ{};
    std::vector<float> velocityX{};
    std::vector<float> velocityY{};
    std::vector<float> velocityZ{};
    std::vector<float> age{};
    std::vector<float> lifetime{};
    std::vector<float> hue{};

    std::size_t size() const {
        return id.size();
    }

    void resize(std::size_t count) {
        if (count > maximumParticles)
            throw std::invalid_argument("SoA allocation budget");
        id.resize(count);
        generation.resize(count);
        positionX.resize(count);
        positionY.resize(count);
        positionZ.resize(count);
        velocityX.resize(count);
        velocityY.resize(count);
        velocityZ.resize(count);
        age.resize(count);
        lifetime.resize(count);
        hue.resize(count);
    }

    bool valid() const {
        const std::size_t count = size();
        return generation.size() == count && positionX.size() == count && positionY.size() == count && positionZ.size() == count && velocityX.size() == count && velocityY.size() == count && velocityZ.size() == count && age.size() == count && lifetime.size() == count && hue.size() == count;
    }
};
```

`ParticlesSoA` có một `resize` chung. Nếu `id.size() == 10.000` mà cột `age` chỉ có 9.999 ô, thao tác trên hạt cuối đã không còn hợp lệ. Chỉ số `i` luôn phải trỏ đến **cùng một hạt** ở mọi cột.

### Viết thử một hàng trước khi chuyển cả đài phun

{/* snippet include/storage.hpp#write-particle */}
```cpp title="include/storage.hpp — Ghi cùng một giọt vào đủ các cột tại index"
inline void writeParticle(ParticlesSoA& destination, std::size_t index, const ParticleAoS& particle) {
    destination.id[index] = particle.id;
    destination.generation[index] = particle.generation;
    destination.positionX[index] = particle.positionX;
    destination.positionY[index] = particle.positionY;
    destination.positionZ[index] = particle.positionZ;
    destination.velocityX[index] = particle.velocityX;
    destination.velocityY[index] = particle.velocityY;
    destination.velocityZ[index] = particle.velocityZ;
    destination.age[index] = particle.age;
    destination.lifetime[index] = particle.lifetime;
    destination.hue[index] = particle.hue;
}
```

`writeParticle` rải các trường của bản ghi vào đúng cột. `readParticle` làm việc ngược lại: gom các giá trị ở cùng chỉ số để bộ vẽ dùng như trước. Đây là phép sao chép `float` sang `float`; nếu chưa tiến thời gian, các số phải giữ nguyên chính xác, không cần cho phép sai số. Hãy thử với ba hạt có ID, thế hệ và màu khác nhau trước.

### Đừng để lộ một mảng mới điền được nửa chừng

{/* snippet include/simulation.hpp#tick-conversion */}
```cpp title="include/simulation.hpp — Chỉ đổi layout sau khi chép xong ô cuối"
bool tickConversion(double budgetMs = 6) {
    if (pending != PendingWork::conversion)
        return false;
    const auto deadline = Clock::now() + std::chrono::duration<double, std::milli>(budgetMs);
    do {
        const std::size_t end = std::min(count, cursor + 4096);
        const auto started = Clock::now();
        for (std::size_t index = cursor; index < end; ++index) {
            if (layout == Layout::aos)
                writeParticle(soa, index, aos[index]);
            else
                aos[index] = readParticle(soa, index);
        }
        conversionMs += milliseconds(started);
        cursor = end;
    } while (cursor < count && Clock::now() < deadline);
    if (cursor < count)
        return false;
    if (layout == Layout::aos) {
        layout = Layout::soa;
    } else {
        layout = Layout::aos;
    }
    pending = PendingWork::none;
    notice = "Layout changed; ID/generation/fields/time and emission remainder preserved";
    return true;
}
```

`beginConversion` đặt con trỏ chép về đầu và chuẩn bị mảng đích. Mỗi lần `tickConversion` chép tiếp vài nhóm ô. Trong lúc đó, bộ vẽ vẫn tra **mảng nguồn**. Chỉ khi `cursor == count` ta mới chuyển `layout`. Nếu người dùng hủy sớm, bản nguồn vẫn là một đài phun nguyên vẹn.

Không có bước vật lý nào giữa ba cảnh. Nếu ở giữa mà **N** chưa làm nước chảy tiếp, đó là đúng phạm vi bài này; đừng giả làm kernel SoA bằng cách chạy trên mảng AoS còn sót lại.

## Thử làm sai để hiểu đúng

1. Trong một bản thử, tạm bỏ dòng chép `generation`. Dùng một hạt đã tái sinh; phép so khứ hồi phải tìm ra khác biệt dù ảnh chụp gần như không đổi. Trả lại cột trước khi đi tiếp.
2. Thử đặt `layout = Layout::soa` ngay khi bắt đầu chuyển một mảng lớn. Hủy giữa chừng: một phần đài phun có thể mất hoặc dùng giá trị cũ của mảng đích. Sửa bằng cách chỉ đổi nhãn ở cuối, không phải bằng cách cấm người dùng hủy.

## Tự kiểm tra kết quả

- AoS → SoA → AoS giữ nguyên từng trường của từng ô, cả khi pool cold chưa đầy.
- Mười một mảng SoA có cùng độ dài. Không thêm một bộ hạt ngẫu nhiên mới khi đổi layout.
- Thời gian, số đang sống và phần hạt lẻ đang tích không đổi; số ms dành cho conversion được báo riêng.

## Bài tập mở rộng

Chọn tốc độ phát 30 hạt/s và nhấn một bước từ pool rỗng: mới tích được 0,25 hạt. Đổi layout đi và về rồi tiếp tục ba bước. Nếu chưa thấy hạt đầu tiên, hãy kiểm phần lẻ mà phép chuyển có thể đã làm mất.
