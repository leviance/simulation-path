# Vẽ hình vuông từ bốn đỉnh local

## Vấn đề cần giải quyết

Ta sẽ làm một editor để biến đổi hình vuông, nhưng chưa cần bắt đầu bằng ma trận. Việc đầu tiên là vẽ được bốn cạnh, đánh dấu các đỉnh và biết điểm nào thuộc local space, world space hay screen space.

Sau bài này bạn có checkpoint 01 chạy độc lập. Hình vuông màu xanh lá nằm trên world grid; hai vector cơ sở ex/ey cho thấy trục riêng của hình. Chưa có co giãn hay xoay.

## Hiểu ý tưởng trước khi viết code

Hình vuông có nửa cạnh 1 world unit. Ta lưu bốn đỉnh quanh local origin theo thứ tự đi quanh biên:

$$
(-1,-1),\ (1,-1),\ (1,1),\ (-1,1).
$$

Local point mô tả hình dạng. World point mô tả vị trí trong cảnh. Ở bài này hai bộ số bằng nhau, **không có nghĩa là hai hệ tọa độ giống nhau trong mọi bài**.

Gốc world xuất hiện tại (450,400) trên bảng logic; một world unit bằng 50 pixel logic. World Y hướng lên, screen Y hướng xuống. Vì vậy P2=(1,1) đi tới (500,350). Resize chỉ thay cách SDL trình bày bảng bằng letterbox, không sửa tọa độ world.

## Viết code từng bước

### Bước 1 — Chạy starter đã có cửa sổ và ảnh CPU

Tải ZIP P09, mở terminal ở thư mục chứa CMakeLists.txt:

```bash title="Terminal — starter trước, editor sau"
cmake -S . -B build -DBUILD_CHECKPOINTS=ON
cmake --build build --config Debug --target project_9_starter --parallel 2
.\build\Debug\project_9_starter.exe
```

Starter có window/event loop, streaming texture, grid/trục và các helper từ Project 04–07. Bảng logic đầy đủ rộng 1280×800; phần bên phải dành cho panel sau này. Mở include/lab.hpp, include/scene.hpp và include/view.hpp trước khi sửa; không tạo thêm một main thứ hai.

### Bước 2 — Đặt tên cho điểm và bốn đỉnh

```cpp title="include/lab.hpp — một điểm có hai thành phần"
struct Vec2 {
    double x{};
    double y{};
};
```

```cpp title="include/lab.hpp — tạo bốn đỉnh theo thứ tự quanh biên"
inline Square makeSquare(double halfExtent) {
    return {Vec2{-halfExtent, -halfExtent}, Vec2{halfExtent, -halfExtent}, Vec2{halfExtent, halfExtent}, Vec2{-halfExtent, halfExtent}};
}
```

Square là `std::array<Vec2,4>`. Vòng lặp sau sẽ nối 0→1→2→3→0, nên không được xáo thứ tự đỉnh.

### Bước 3 — Đổi sang pixel ngay trước khi vẽ

```cpp title="include/scene.hpp — world sang bảng logic"
inline Vec2 worldToScreen(Vec2 point) {
    return {kOrigin.x + point.x * kPixelsPerUnit, kOrigin.y - point.y * kPixelsPerUnit};
}
```

```cpp title="include/view.hpp — vẽ kín bốn cạnh và đánh dấu đỉnh"
inline void drawSquare(Framebuffer& image, const Square& square, std::uint32_t color) {
    for (std::size_t index = 0; index < square.size(); ++index) {
        worldLine(image, square[index], square[(index + 1) % square.size()], color);
        const Vec2 screen = worldToScreen(square[index]);
        disc(image, static_cast<int>(std::lround(screen.x)), static_cast<int>(std::lround(screen.y)), 4, color);
    }
}
```

worldLine dùng worldToScreen rồi gọi Bresenham từ Project 04. drawSquare chỉ nối cạnh; nó không quyết định hình co hay xoay ra sao.

### Bước 4 — Nối cảnh với framebuffer

```cpp title="include/scene.hpp — tính lại từ localSquare"
inline Square transformedSquare(const Scene& scene) {
    const Square localSquare = makeSquare(1.0);
    Square worldSquare{};
    for (std::size_t index = 0; index < localSquare.size(); ++index) {
        worldSquare[index] = worldPoint(localSquare[index], scene);
    }
    return worldSquare;
}
```

Trong checkpoint 01, worldPoint trả nguyên local point. Trong renderScene, gọi drawSquare(image, makeSquare(1.0), kGhost) cho hình gốc, rồi drawSquare(image, transformedSquare(scene), kShape) cho hình hiện tại. Hai hình chồng nhau ở identity là đúng.

Vòng lặp SDL gọi renderScene rồi SDL_UpdateTexture; texture nhận image.pixels.data(), pitch bằng Framebuffer::width × sizeof(std::uint32_t). Bộ khung xử lý lỗi và giải phóng tài nguyên đã có trong starter; xem toàn bộ src/main.cpp ở phần mã chạy được sau bài.

## Ghép các phần lại

Build target project_9_checkpoint_1. Hình phải có đủ bốn cạnh và bốn đỉnh, tâm world không thay đổi khi resize. Đỏ là ex, xanh lam là ey; màu vàng đánh dấu local origin. Chưa có slider hay input kéo, nên đừng chờ hình chạy theo chuột.

Ta đã tách được ba trách nhiệm: makeSquare giữ hình dạng, worldPoint tính world point, drawSquare chỉ vẽ. Từ bài sau, ta thay phần tính mà không phải viết lại vòng lặp SDL.

## Thử làm sai để hiểu đúng

1. Đổi một đỉnh từ (1,1) thành (2,1), rồi chạy lại. Hình không còn vuông nhưng renderer vẫn nối đúng bốn cạnh. Khôi phục dữ liệu: hình dạng do local points quyết định, không nằm trong drawSquare.

2. Đổi chỗ hai đỉnh kế nhau. Dự đoán đường nối trước khi chạy; các cạnh sẽ cắt nhau dù từng tọa độ đều hữu hạn. Đưa thứ tự trở về 0→1→2→3.

3. Bỏ dấu trừ trước point.y trong worldToScreen. P2 chuyển xuống dưới thay vì lên trên. Khôi phục dấu và xác nhận (1,1) trở lại screen(500,350).

## Tự kiểm tra kết quả

- P0..P3 đi quanh biên; cạnh cuối nối về P0.
- P2 local(1,1) và world(1,1) xuất hiện tại screen(500,350).
- Hình chỉ đổi kích thước trình bày khi resize, không đổi dữ liệu local.
- Starter và checkpoint 01 chạy được; không có vòng lặp mở cửa sổ trong CTest.
