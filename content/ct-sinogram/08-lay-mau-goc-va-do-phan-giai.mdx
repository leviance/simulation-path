# Đổi số góc mà không nhầm với độ nét ảnh

## Vấn đề cần giải quyết

Một sinogram phóng to nhìn mượt hơn chưa chắc chứa nhiều thông tin đo hơn. Ta cần phân biệt ba thứ: số pixel detector, số góc thu nhận và kích thước ảnh trên màn hình.

Bài này thêm lựa chọn 30/60/120 góc. Cả ba vẫn dùng 128 detector pixel; mọi phép đo tại cùng góc vật lý phải khớp nhau. Ta không thêm reconstruction để đánh giá chất lượng ảnh CT ở đây.

## Hiểu ý tưởng trước khi viết code

Với detector cố định, thay views chỉ thay bước góc:

| views | Bước góc | Góc cuối | Số ray cả lượt |
| --- | ---: | ---: | ---: |
| 30 | 12° | 348° | 3840 |
| 60 | 6° | 354° | 7680 |
| 120 | 3° | 357° | 15360 |

Hai ảnh cùng cao 520 logical pixel vẫn có thể chỉ chứa 30 hoặc 120 hàng đo. Nearest phóng từng hàng, không thêm góc. Nội suy bilinear có thể làm màu mượt hơn nhưng cũng không tạo phép đo mới.

Đĩa ở tâm là trường hợp kiểm đối xứng tốt, nhưng **không nhạy với thiếu góc**: mỗi hàng vốn giống nhau. Hãy dùng đĩa nhỏ lệch tâm khi quan sát [lấy mẫu góc](/glossary#ct-angular-sampling).

## Viết code từng bước

### Bước 1 — Chỉ cho các độ phân giải nhỏ đã định

validate chỉ chấp nhận views=30,60,120. Phím Q chuyển tuần tự, đưa row đang xem về 0; Canvas dùng select. Không cho input tùy ý hàng triệu góc rồi cấp mảng theo nó.

```cpp title="include/controls.hpp"
    if (key == SDLK_Q) {
        controls.settings.views *= 2;
        if (controls.settings.views > 120) {
            controls.settings.views = 30;
        }
        controls.row = 0;
    }
```

Đổi views thay lưới góc của lượt quét, không chỉ thay chiều cao ảnh. Trong main, giữ nhánh kiểm settings của Bài 06:

```cpp title="src/main.cpp"
if (controls.settings != before.settings || event.key.key == SDLK_R) {
    scan = ct::makeScan(controls.settings);
    controls.paused = true;
    controls.step = false;
}
```

`before` là bản sao controls ngay trước keyDown. Sau Q, scan mới có values toàn NaN và acquired=0. Không resize vector rồi giữ một phần hàng cũ: cùng row 5 nhưng góc của nó đã đổi. Bỏ lệnh step đang treo để thao tác đổi cấu hình không tự đo một hàng ngoài ý muốn.

### Bước 2 — Giữ texture và dữ liệu cùng chiều cao

Texture 128×30 không chứa được dữ liệu của scan 128×120. Ta thêm hàm sau trong view.hpp. Nhận `SDL_Texture*&` để thay con trỏ của caller, và `int&` để chỉ cập nhật textureViews sau khi thay tài nguyên thành công:

```cpp title="include/view.hpp"
inline void resizeSinogramTexture(SDL_Renderer* renderer, SDL_Texture*& texture, int& textureViews, int views) {
    if (views != 30 && views != 60 && views != 120) {
        throw std::invalid_argument("views must be 30, 60 or 120");
    }
    if (textureViews == views) {
        return;
    }

    SDL_Texture* replacement = SDL_CreateTexture(renderer, SDL_PIXELFORMAT_RGBA32, SDL_TEXTUREACCESS_STREAMING, detectorCount, views);
    if (replacement == nullptr) {
        throw std::runtime_error(SDL_GetError());
    }
    if (!SDL_SetTextureScaleMode(replacement, SDL_SCALEMODE_NEAREST)) {
        const std::string error = SDL_GetError();
        SDL_DestroyTexture(replacement);
        throw std::runtime_error(error);
    }

    SDL_DestroyTexture(texture);
    texture = replacement;
    textureViews = views;
}
```

Có ba trường hợp: kích thước đã đúng thì không làm gì; tạo/cấu hình mới thất bại thì giữ texture cũ và báo lỗi; thành công mới hủy texture cũ và nhận replacement. Nếu cấu hình scale thất bại, phải hủy cả replacement vừa tạo. Lưu message trước khi cleanup để không mất lỗi ban đầu.

Trong `if (dirty)` của main, gọi hàm này **trước** upload. Nó cũng xử lý lần đầu khi texture=nullptr và textureViews=0:

```cpp title="src/main.cpp"
ct::resizeSinogramTexture(renderer, texture, textureViews, controls.settings.views);
ct::upload(texture, scan, controls.displayRange, controls.invert);
```

SinogramRect giữ nguyên kích thước trên màn hình. Native dùng logical letterbox, Canvas dùng DPR cho bitmap màn hình; cả hai không tự thay detectorCount theo số pixel cửa sổ.

Các biến này có vai trò khác nhau:

- `scan.settings.views`: số góc thực sự đã chọn để đo.
- `scan.acquired`: số hàng đã đo xong.
- `textureViews`: số hàng mà texture hiện tại chứa được.
- `controls.row`: hàng đang xem, có thể chưa đo.

### Bước 3 — So cùng góc, không so cùng index

Row j của lưới 30 góc ứng với row 4j của lưới 120. Ví dụ j=5 cho 60° ở cả hai, còn row 5 của 120 chỉ là 15°.

```cpp title="include/scan.hpp"
inline double samplingAngle(int coarseRow) {
    return viewAngle(coarseRow * 4, 120) - viewAngle(coarseRow, 30);
}
```

Hàm nhỏ này chỉ kiểm cách gán góc: kết quả gần 0 cho j=0..29. Nó chưa kiểm số đo. Thêm fixture sau vào tests/tests.cpp, dùng **đĩa lệch tâm** để phép so không vô tình đúng chỉ vì đĩa ở tâm đối xứng mọi góc:

```cpp title="tests/tests.cpp"
const auto samplingScene = makeScene(1);
const auto coarse60 = project(viewAngle(5, 30), samplingScene, 1);
const auto fine60 = project(viewAngle(20, 120), samplingScene, 1);
for (int column = 0; column < detectorCount; ++column) {
    check(close(coarse60[column].projection, fine60[column].projection), "same 60 degree measurement on nested grids");
}
```

Cả hai hàng dùng θ=60°, cùng scene, strength và pixel centres. Vòng lặp so cả 128 số p, không chỉ một tổng hoặc ảnh nhìn bằng mắt. `close` là hàm so sai số nhỏ của test runner; tên fixture chỉ rõ đang kiểm điều gì.

### Bước 4 — Quan sát phần thông tin chưa có

Chọn đĩa nhỏ lệch tâm, 30 góc, quét hết và bật trace. Các hàng thưa cho thấy ta chỉ biết tín hiệu tại một số góc rời rạc. Đổi 120 góc sẽ xóa lượt cũ; quét lại có nhiều hàng hơn, không chỉ nhiều byte màu hơn.

Đường trace liên tục là dự đoán hình học từ phantom đã biết. Nó không lấp dữ liệu chưa đo, cũng không chứng minh một thuật toán có thể khôi phục vật thể bất kỳ từ ít góc. Không suy một ngưỡng views tối thiểu phổ quát từ thí nghiệm nhỏ này.

## Ghép các phần lại

```bash title="Terminal — checkpoint 8"
cmake --build build --config Debug --target project_56_checkpoint_8 --parallel 2
.\build\Debug\project_56_checkpoint_8.exe
```

Ghi p của một pixel ở 60° với 30 góc (row 5). Chuyển 120, quét ít nhất tới row 20 rồi chọn cùng pixel ở row 20. Hai số gần bằng trong sai số số thực, dù hình sinogram cao/dày khác nhau. Chọn hàng chưa đo chỉ cho preview, phải đọc stored riêng.

## Thử làm sai để hiểu đúng

1. So row 5 của cả hai lưới và gọi chênh lệch là sai số độ phân giải. Chúng thuộc hai góc khác nhau. Khôi phục mapping j→4j.
2. Giữ nguyên values khi views đổi. Row cũ bị gán nhãn góc mới, khiến dữ liệu sai mà ảnh vẫn có vẻ hợp lý. Tạo lượt mới và quét lại.

## Tự kiểm tra kết quả

30/60/120 tạo đúng 3840/7680/15360 ô. Bước góc 12°/6°/3°, không hàng 360°. samplingAngle gần 0 tại mọi hàng coarse. Projection của các góc chung khớp; display range/resize không đổi số ray. Thiếu góc không được “sửa” bằng smoothing màu.
