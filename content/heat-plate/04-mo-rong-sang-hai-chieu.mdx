# Thêm chiều còn thiếu cho tấm kim loại

## Vấn đề cần giải quyết

Ở bài trước, vùng nóng chỉ dàn sang trái/phải. Các hàng không trao đổi nên tấm kim loại cư xử như nhiều thanh độc lập. Bây giờ ta thêm nhiệt truyền qua hai mặt trên/dưới, giữ nguyên cách lưu dữ liệu, bút vẽ và double buffer.

Bắt đầu từ checkpoint 3; đọc 20 phút, viết 35 phút, kiểm 30 phút. Kết quả cần thấy là một vùng nóng lan theo cả hai chiều, nhưng phép kiểm đầu tiên vẫn chỉ dùng **một ô** để tính tay được.

## Hiểu ý tưởng trước khi viết code

Với tấm đồng nhất, phương trình nhiệt hai chiều là:

$$
\frac{\partial\theta}{\partial t}
=D\left(\frac{\partial^2\theta}{\partial x^2}
+\frac{\partial^2\theta}{\partial y^2}\right).
$$

Đạo hàm ở đây mô tả xu hướng thay đổi liên tục. Solver chỉ biết các mẫu ở tâm ô, nên thay mỗi đạo hàm bậc hai bằng sai phân như bài 3. Kết quả là stencil năm điểm: tâm cùng bốn ô chung cạnh, không có ô chéo.

$$
\theta_{x,y}^{n+1}=\theta_{x,y}^n
+r_x(\theta_{x-1,y}^n-2\theta_{x,y}^n+\theta_{x+1,y}^n)
+r_y(\theta_{x,y-1}^n-2\theta_{x,y}^n+\theta_{x,y+1}^n),\quad
r_y=\frac{D\,dt}{dy^2}.
$$

Nhiệt độ thay đổi tại các tọa độ cố định; ô không di chuyển và không đổi chỗ với hàng xóm như hạt cát. Với dx=dy=0,5, `rx=ry=0,2`: xung 1 thành tâm 0,2 và bốn ô cạnh 0,2. Ô chéo vẫn 0 vì chưa có đường truyền trực tiếp trong một bước.

Trước khi bấm N lần đầu, xóa tấm, đặt radius 0 và tô một ô. Dự đoán cả hình dấu cộng lẫn từng giá trị; đừng chỉ dự đoán “nó sẽ mờ đi”.

## Viết code từng bước

### 1. Thêm sai phân theo y, không thay vòng đời dữ liệu

Trong `diffusion.hpp`, bật hai chiều và thêm `vertical` cùng hệ số `ry`. Toàn bộ hàm ở checkpoint 4 là:

{/* snippet include/diffusion.hpp#diffuse */}
```cpp title="include/diffusion.hpp — stencil hai chiều"
inline StepResult diffuse(Field& field, const Settings& settings) {
    bool twoDimensions = false;
    twoDimensions = true;
    const Stability coefficients = stability(settings, twoDimensions);
    StepResult result;
    if (!coefficients.valid) {
        return result;
    }
    bool allowUnstable = false;
    if (!coefficients.stable && !allowUnstable) {
        result.status = StepStatus::UnstableSettings;
        return result;
    }

    for (int y = 0; y < field.height; ++y) {
        for (int x = 0; x < field.width; ++x) {
            const std::size_t index = field.index(x, y);
            ++result.visited;
            double value = 0;
            bool fixedRim = false;
            if (!fixedRim) {
                const double center = sample(field, x, y);
                const double horizontal = sample(field, x - 1, y) - 2 * center + sample(field, x + 1, y);
                value = center + coefficients.rx * horizontal;
                const double vertical = sample(field, x, y - 1) - 2 * center + sample(field, x, y + 1);
                value += coefficients.ry * vertical;
            }
            if (!std::isfinite(value)) {
                result.status = StepStatus::NonFiniteCandidate;
                return result;
            }
            result.maximumAbs = std::max(result.maximumAbs, std::abs(value));
            field.next[index] = value;
        }
    }
    if (allowUnstable && result.maximumAbs > 16) {
        result.status = StepStatus::ExperimentAmplitude;
        return result;
    }
    // Mọi ô đã được tính xong: publish một mức thời gian, không clamp nghiệm.
    field.current.swap(field.next);
    ++field.tick;
    field.time += settings.dt;
    result.advanced = true;
    result.status = StepStatus::Advanced;
    return result;
}
```

Phần mới quan trọng là `sample(field,x,y-1)` và `sample(field,x,y+1)`. Không dùng cùng `dx` cho mọi hướng khi lưới có hai khoảng cách khác nhau. Mặc định chúng bằng nhau, nhưng test sẽ dùng dx≠dy để bắt nhầm lẫn này.

`fixedRim` vẫn false ở bài này; nhánh biên lạnh chỉ được thêm ở bài 5. Các guard bảo vệ tham số đã có từ bước 1D, không phải một thuật toán khuếch tán khác. Khi bước hợp lệ, mỗi ô được ghi đúng một lần vào `next`.

### 2. Đọc ngoài lưới theo đúng mô hình đang dùng

Ta không truy cập index âm hoặc `width`. `sample` ánh xạ giá trị ngoài tấm về chính ô sát mặt ngoài:

{/* snippet include/field.hpp#sample */}
```cpp title="include/field.hpp — mẫu ngoài tấm cho biên cách nhiệt"
inline double sample(const Field& field, int x, int y) {
    // Cell-centered zero-flux ghost: phản chiếu vào chính ô sát mặt ngoài.
    x = std::clamp(x, 0, field.width - 1);
    y = std::clamp(y, 0, field.height - 1);
    return field.current[field.index(x, y)];
}
```

Ví dụ, ô ở x=0 đọc bên trái bằng chính nó. Chênh lệch qua mặt trái bằng 0, còn trao đổi với ô x=1 vẫn bình thường. Đây là một lựa chọn biên cụ thể, không phải cách “chống out-of-bounds” dùng tùy tiện cho mọi PDE.

### 3. Giữ chỗ gọi trong main

Không cần thêm một lời gọi solver mới. Action N vẫn tạo một yêu cầu, `diffuse` vẫn chạy trước vẽ. Chính nội dung bước tính thay đổi; window, brush và cách present giữ nguyên.

Kiểm lại rằng `field.current.swap(field.next)` nằm **sau cả hai vòng for**. Đặt nó sau mỗi hàng sẽ trộn các mức thời gian và khiến vùng nhiệt nghiêng theo hướng quét.

## Ghép các phần lại

Build/run `project_47_checkpoint_4`. Cảnh mặc định trở lại Gaussian hai chiều; giữ N nhiều lần bằng các lần bấm rời sẽ làm đỉnh thấp dần và vùng ấm rộng dần. Key repeat bị bỏ qua với action step để mỗi lần bấm có ý nghĩa rõ.

Để đo đáp án xung, dùng C → radius 0 → Enter ở giữa → N một lần. Di chuyển cursor lần lượt tới tâm, trái, phải, trên, dưới và ô chéo. Nhìn cả `tick` lẫn số theta trên panel.

## Thử làm sai để hiểu đúng

Thay stencil bằng trung bình vùng 3×3 trong một bản thử. Sau một bước, ô chéo sẽ có nhiệt ngay. Đó là một phép lọc khác, không còn là scheme vừa suy từ phương trình nhiệt. Khôi phục bốn hàng xóm chung cạnh.

Thử đặt `dy` lớn gấp đôi `dx` mà vẫn dùng cùng `ry=rx`. Code có thể chạy, nhưng đang mô phỏng khoảng cách sai. Với dy gấp đôi, ry phải nhỏ đi bốn lần khi D và dt giữ nguyên.

## Tự kiểm tra kết quả

- Xung 1 cho năm ô cùng 0,2 trong sai số số thực; tổng vẫn 1 ở tấm cách nhiệt không nguồn.
- Hình đối xứng trái/phải và trên/dưới; ô chéo vẫn 0 sau bước đầu.
- Mỗi bước xét đủ 1.024 ô ở lưới học 32×32, không chỉ cập nhật vùng đang sáng.
- Đảo hướng quét không đổi kết quả một bước. Resize không tạo thêm tick hoặc làm lại dữ liệu.
