# Tăng dt để nhìn thấy solver mất ổn định

## Vấn đề cần giải quyết

Nhấn N rất tiện để kiểm công thức nhưng không tiện ngắm một tấm kim loại nguội dần. Ta cần chạy liên tục, slider đổi D/dt và một cách cho người học **thấy bất ổn thật**, không chỉ đọc thông báo “tham số sai”.

Bắt đầu từ checkpoint 5; đọc 30 phút, viết 55 phút, thử/kiểm 45 phút. Chạy được không có nghĩa bước thời gian nào cũng đúng. Bài này giữ hai chính sách rõ ràng: chế độ thường bảo vệ người dùng, chế độ thí nghiệm chủ động cho phép vượt giới hạn với chốt dừng hữu hạn.

## Hiểu ý tưởng trước khi viết code

Gom các hệ số của stencil:

$$
\theta^{n+1}_{x,y}=(1-2r_x-2r_y)\theta^n_{x,y}
+r_x(\theta^n_{x-1,y}+\theta^n_{x+1,y})
+r_y(\theta^n_{x,y-1}+\theta^n_{x,y+1}).
$$

Với D≥0, các trọng số không âm khi `rx+ry ≤ 0,5` và tổng bằng 1. Khi đó ứng viên là trung bình có trọng số của các giá trị cũ: không tự tạo cực đại/cực tiểu mới trong bài toán không nguồn với biên phù hợp. Nếu trọng số tâm âm, lập luận này mất hiệu lực; dao động nhỏ có thể lớn dần.

Với dx=dy=h, điều kiện trở thành `D*dt/h² ≤ 0,25`. Ở h=0,5 và D=1,5, dt tối đa là 1/24≈0,041667 s. Mặc định 1/30 nằm dưới ngưỡng; dt=0,05 nằm trên. Đây là điều kiện của **explicit Euler + stencil này**, không phải của mọi solver nhiệt và cũng không bảo đảm sai số rời rạc nhỏ.

## Viết code từng bước

### 1. Tính điều kiện bằng đúng thông số solver đang dùng

`stability` đã được cung cấp từ bước 1D để bảo vệ tham số. Bây giờ ta đọc và hoàn thiện ý nghĩa của nó:

{/* snippet include/parameters.hpp#stability */}
```cpp title="include/parameters.hpp — kiểm hệ số trước khi đổi dữ liệu"
inline Stability stability(const Settings& settings, bool twoDimensions = true) {
    Stability result;
    if (!std::isfinite(settings.diffusivity) || !std::isfinite(settings.dt) || !std::isfinite(settings.dx) || !std::isfinite(settings.dy)) {
        return result;
    }
    if (settings.diffusivity < 0 || settings.dt <= 0 || settings.dx <= 0 || settings.dy <= 0) {
        return result;
    }
    if (settings.boundary != Boundary::Insulated && settings.boundary != Boundary::ColdRim) {
        return result;
    }
    const double squareDx = settings.dx * settings.dx;
    const double squareDy = settings.dy * settings.dy;
    if (!std::isfinite(squareDx) || !std::isfinite(squareDy) || squareDx <= 0 || squareDy <= 0) {
        return result;
    }
    result.rx = settings.diffusivity * settings.dt / squareDx;
    if (twoDimensions) {
        result.ry = settings.diffusivity * settings.dt / squareDy;
    }
    result.sum = result.rx + result.ry;
    if (!std::isfinite(result.sum)) {
        return result;
    }
    result.valid = true;
    result.stable = result.sum <= 0.5;
    result.maximumDt = std::numeric_limits<double>::infinity();
    if (result.sum > 0) {
        result.maximumDt = settings.dt * (0.5 / result.sum);
    }
    return result;
}
```

Guard kiểm finite và khoảng cách dương trước khi chia, rồi kiểm cả bình phương và tổng hệ số. NaN không phải “một số rất lớn”; so sánh thông thường với NaN có thể khiến guard viết thiếu bị lọt. D=0 hợp lệ: không khuếch tán, không có CFL bound hữu hạn từ khuếch tán, nhưng dt vẫn phải dương/hữu hạn.

### 2. Cho phép nghiệm sai mà không treo ứng dụng

Solver giữ hai tầng kiểm. Chế độ thường từ chối khi `coefficients.stable` false. Experiment bỏ qua riêng điều kiện đó, **không bỏ kiểm NaN/Inf**. Mỗi bước vẫn tính ứng viên bằng cùng stencil, không dùng một animation khác.

Ứng viên chỉ được publish khi hữu hạn và không vượt `|theta|>16`; tối đa 400 bước experiment được chấp nhận trên một field. Hết giới hạn thì pause; reset tạo một thí nghiệm mới. Tắt/bật checkbox không xóa bộ đếm để lách giới hạn. Một ứng viên bị từ chối có thể đã ghi dở `next`, nhưng `current`, tick và time phải giữ nguyên; lần thử sau ghi lại toàn bộ candidate.

Palette thí nghiệm cố định [-1,2], tâm 0,5, để đọc hai phía âm/dương. Renderer có thể bão hòa màu ngoài dải đó; raw theta vẫn giữ nguyên. Đừng thêm clamp trong solver để làm hình “ổn” trở lại.

### 3. Đưa slider vào cùng cấu hình

Native có hai track trên panel: D trong 0–6, dt trong 0,002–0,1. `pollInput` hit-test trong logical coordinates, lưu slider đang kéo và chuyển x thành fraction 0–1. `setSlider` cập nhật đúng `state.settings`; nó pause/reset accumulator chứ không gọi một bước solver.

Phím A/Shift+A đổi D, T/Shift+T chọn các dt mẫu. Nếu dùng bàn phím hoặc Canvas slider, các giá trị vẫn đi vào cùng D/dt. Không tự hạ dt khi D tăng: người học cần thấy ngưỡng thay đổi và tự quyết cách sửa.

### 4. Tách đồng hồ mô hình khỏi việc vẽ

Khi chạy, frame chỉ gửi elapsed tới bộ lập kế hoạch bước:

{/* snippet include/timing.hpp#step-plan */}
```cpp title="include/timing.hpp — số bước có giới hạn trong một frame"
inline StepPlan planSteps(double accumulator, double elapsed, double dt, double speed = 1) {
    StepPlan plan;
    if (!std::isfinite(dt) || dt <= 0 || !std::isfinite(elapsed) || elapsed < 0 || !std::isfinite(speed) || speed <= 0) {
        return plan;
    }
    speed = std::clamp(speed, 0.25, 4.0);
    if (!std::isfinite(elapsed * speed)) {
        return plan;
    }
    if (!std::isfinite(accumulator) || accumulator < 0 || accumulator >= dt) {
        accumulator = 0;
    }
    const double accepted = std::min(elapsed, 0.25);
    const double total = accumulator + accepted * speed;
    if (!std::isfinite(total)) {
        return plan;
    }
    const double ratio = total / dt;
    if (!std::isfinite(ratio)) {
        // dt cực nhỏ không được làm phép đếm tick overflow hoặc tạo vòng bù vô hạn.
        plan.steps = 8;
        plan.remainder = std::fmod(total, dt);
        plan.dropped = (elapsed - accepted) * speed + total - plan.steps * dt - plan.remainder;
        return plan;
    }
    const double due = std::floor(ratio + 1e-9);
    plan.steps = static_cast<int>(std::min(due, 8.0));
    plan.remainder = std::clamp(total - due * dt, 0.0, std::nextafter(dt, 0.0));
    plan.dropped = (elapsed - accepted) * speed + (due - plan.steps) * dt;
    return plan;
}
```

`dt` là giây mô hình mỗi tick; `speed` đổi tốc độ mong muốn so với wall time, không đổi công thức một tick. Chỉ nhận tối đa 0,25 s wall time và làm tối đa 8 bước/frame. Phần không làm được được báo bằng `dropped` đã nhân speed; không tích lại thành món nợ vô hạn.

## Ghép các phần lại

Trong `main`, pause/step không tích accumulator. Khi chạy, `planSteps` cho số lần gọi `diffuse`; cùng vòng update từ bài 3 xử lý mọi bước. Solver từ chối thì dừng ngay batch và báo nguyên nhân. Vẽ vẫn dùng mức thời gian được chấp nhận cuối cùng.

Build/run `project_47_checkpoint_6`. Mở ở pause. Space chạy/dừng; P ở mốc này chỉ đổi Gaussian/bàn cờ; U bật experiment, N tiến bước. Mất focus tự pause và bỏ thời gian chờ. Trên máy không theo kịp, mô phỏng có thể chậm hơn thời gian thật: đó là chính sách giới hạn công việc, không phải lý do âm thầm tăng dt.

## Thử làm sai để hiểu đúng

Với bàn cờ 0,25/0,75, h=0,5, D=1,5, dt=0,05, hệ số của dao động bàn cờ gần `1-8r=-1,4` ở vùng trong. Nó đổi dấu và tăng biên độ. Nhấn từng bước để thấy `min < 0` và `max > 1`, rồi dừng trước khi giá trị vượt giới hạn giữ lại. Ở bản 192², ca chuẩn chấp nhận 12 bước, giữ min≈−13,6735/max≈14,6735 rồi từ chối bước tiếp.

Trở lại chế độ thường, reset cùng bàn cờ và giảm dt về 1/30. Max không còn phình ra. Thử đổi FPS hiển thị 15/120 trong Canvas nhưng giữ D/dt: quãng thời gian mô hình được tính không được phụ thuộc số lần vẽ, trừ khi đã chạm budget và báo dropped.

## Tự kiểm tra kết quả

- D/dt slider đổi số trên panel và hệ số thật; đổi tham số pause, không lén tiến tick hoặc sửa dt.
- Cấu hình thường không ổn định bị từ chối trước swap/tick/time.
- Experiment có giá trị ngoài 0–1 thật, không publish NaN/Inf hoặc candidate vượt 16; không có vòng lặp thử lại vô hạn.
- Space, N, pause/mất focus không tạo nợ; số bước mỗi frame ≤8.
- Chuỗi 15/30/120 FPS trong hai giây cho 60 tick ở dt=1/30, speed 1, nếu không bỏ thời gian.
